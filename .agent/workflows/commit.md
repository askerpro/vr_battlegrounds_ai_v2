## Процесс коммита

### Шаг 1 — Посмотреть что изменилось

```
git --no-pager diff --stat
git --no-pager status
```

### Шаг 2 — Проанализировать содержимое изменений

Прочитать `git diff` по каждому изменённому файлу и ответить на вопросы:
- Что было добавлено / изменено / удалено концептуально?
- Это новая функциональность, исправление бага или рефакторинг?
- Затронуты ли игровые механики, архитектура, зависимости?
- Был ли исправлен баг или неочевидное поведение SDK?

```
git --no-pager diff
```

### Шаг 3 — Обновить документацию (ОБЯЗАТЕЛЬНО перед коммитом)

На основе анализа определить и обновить затронутые файлы:

| Что изменилось | Документация |
|---|---|
| Новые скрипты / классы / компоненты | `Assets/Docs/README.md` |
| Игровые механики, режимы, логика матча | `Assets/Docs/gameplay.md` |
| Менеджеры сессий, режимы, flow | `Assets/Docs/game-manager.md` |
| Патч SDK UltimateXR (правки исходников) | `Assets/ThirdParty/UltimateXR/Docs/_context/sdk-patches.md` |
| **Баг или неочевидное поведение компонента** | **`Assets/ThirdParty/UltimateXR/Docs/_context/known-issues.md`** |
| Архитектурные изменения, новые зависимости | `Assets/ThirdParty/UltimateXR/Docs/_context/architecture.md` |
| Значимые фиксы, новые фичи | `Assets/Docs/CHANGELOG.md` |
| Новые правила агента, зависимости | `.agentrules` |

> Если изменения не требуют обновления документации — явно указать причину.

### Шаг 4 — Проверить компиляцию (если доступен MCP Unity)

Использовать инструменты MCP для проверки ошибок компиляции в Unity.

### Шаг 5 — Сформировать commit message

Формат:
```
<тип>: <краткое описание на русском>

<опциональное тело: что и почему изменилось>
```

Типы: `feat` (новая фича), `fix` (исправление), `docs` (документация), `refactor` (рефакторинг), `chore` (вспомогательные изменения)

Примеры:
```
fix: исправлен эффект взрыва при активации UxrAvatar (Precaching)
feat: добавлен режим Elimination с поддержкой SetManager/RoundManager
docs: обновлена архитектура UltimateXR, добавлен known-issues.md
```

### Шаг 6 — Выполнить коммит

```
git add -A
git --no-pager commit -m "<message>"
```

> **ВАЖНО:** Никогда не коммитить сразу после написания кода без проверки в Unity.
> Дождаться подтверждения пользователя что изменения работают в игре,
> или получить явную просьбу закоммитить.
