## Процесс расследования бага

> Никогда не начинать с открытия кода. Сначала — контекст.

### Шаг 1 — Прочитать known-issues.md (ВСЕГДА первым)

Проверить, не является ли проблема уже задокументированным поведением SDK.

**Файл:** `Assets/ThirdParty/UltimateXR/Docs/_context/known-issues.md`

Если проблема там описана — использовать готовое объяснение и решение.
Если нет — продолжить расследование.

### Шаг 2 — Прочитать sdk-patches.md

Проверить, не было ли уже внесено обходное решение для этой области кода.

**Файл:** `Assets/ThirdParty/UltimateXR/Docs/_context/sdk-patches.md`

### Шаг 3 — Прочитать архитектуру

Понять контекст компонентов, участвующих в проблеме.

**Файлы:**
- `Assets/Docs/README.md` — ключевые скрипты проекта
- `Assets/ThirdParty/UltimateXR/Docs/_context/architecture.md` — архитектура UltimateXR

### Шаг 4 — Воспроизвести и локализовать проблему

1. Точно описать симптомы: что происходит vs что должно происходить
2. Определить триггер: когда именно воспроизводится
3. Сузить круг подозреваемых компонентов (на основе доков из шагов 1-3)

### Шаг 5 — Читать код

Только теперь открывать исходники — целенаправленно, зная что искать:
- Методы жизненного цикла: `Awake`, `Start`, `OnEnable`, `Update`
- Обработчики событий
- Места инициализации компонентов

### Шаг 6 — Исправить и задокументировать

После нахождения причины:

1. Исправить баг
2. **Обязательно** добавить запись в `Assets/ThirdParty/UltimateXR/Docs/_context/known-issues.md`:

```markdown
## Issue N: [Название]

**Компоненты:** `ComponentA`, `ComponentB`
**Статус:** ✅ Исправлено
**Дата:** YYYY-MM-DD

### Симптом
[Что наблюдалось]

### Причина
[Почему происходило]

### Исправление
[Что было сделано]
```

3. Если исправление затронуло исходники UltimateXR SDK — добавить в `sdk-patches.md`

### Шаг 7 — ОБЯЗАТЕЛЬНО: Сохранить в документацию всё что пришлось искать в коде

> Если был вынужден читать код — документация была неполной. Исправь это сейчас.

**Для каждого класса / метода / поведения, которое пришлось обнаружить в коде:**

1. **Определить куда записать:**

   | Что обнаружено | Куда |
   |---|---|
   | Неочевидное поведение / побочный эффект SDK | `known-issues.md` |
   | Как работает компонент UltimateXR | `UltimateXR/Docs/_context/<модуль>.md` |
   | Патч или правка исходников SDK | `sdk-patches.md` |
   | Связь между игровыми системами проекта | `Assets/Docs/README.md` или `architecture.md` |

2. **Если подходящего файла не существует — создать новый:**
   - Путь: `Assets/ThirdParty/UltimateXR/Docs/_context/<название>.md` (UltimateXR)
     или `Assets/Docs/<название>.md` (игровая логика)
   - Добавить ссылку в точки входа:
     - `Assets/Docs/README.md` → раздел «Быстрая навигация»
     - `Assets/ThirdParty/UltimateXR/Docs/_context/README.md` (если UltimateXR)
     - `.agentrules` → раздел «Контекст проекта»

3. **Добавить запись в `known-issues.md`** если была обнаружена любая неочевидность SDK:
   ```markdown
   ## Issue N: [Название]
   **Компоненты:** `ComponentA`
   **Статус:** ✅ Исправлено / ℹ️ Поведение SDK
   **Дата:** YYYY-MM-DD
   ### Симптом
   ### Причина
   ### Исправление
   ```

4. **Если исправление затронуло исходники UltimateXR** — добавить в `sdk-patches.md`
