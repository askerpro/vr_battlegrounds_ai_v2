## Процесс добавления новой фичи

> Не писать код до тех пор, пока не понята архитектура.

### Шаг 1 — Прочитать документацию

Прежде чем что-либо создавать:

1. **`Assets/Docs/README.md`** — список существующих классов, чтобы не дублировать логику
2. **`Assets/Docs/gameplay.md`** — как новая механика вписывается в геймплей
3. **`Assets/ThirdParty/UltimateXR/Docs/_context/architecture.md`** — нет ли готового компонента в UltimateXR SDK

### Шаг 2 — Определить место в архитектуре

Ответить на вопросы:
- К какому слою относится фича? (Сеть / Менеджеры / Игрок / UI / GameMode / UltimateXR)
- Какие существующие классы будут затронуты?
- Является ли это новым `GameMode`, новым `Manager`, новым `UxrComponent` или компонентом игрока?
- Нужна ли сетевая синхронизация (Mirror)?

### Шаг 3 — Определить зависимости

| Тип фичи | Что использовать |
|---|---|
| Новый игровой режим | Наследовать `GameMode`, создать `GameModeData` + префаб |
| Новый менеджер | Синглтон `DontDestroyOnLoad`, подписаться на нужные события |
| VR-взаимодействие | Использовать `UxrGrabbableObject` + `UxrGrabber` |
| Оружие | Наследовать `UxrFirearmWeapon` или `UxrGrenadeWeapon` |
| Сеть | `NetworkBehaviour`, `[SyncVar]`, `[Command]`, `[ClientRpc]` |
| Управление здоровьем | Подписаться на `UxrActor.Death` / `UxrActor.DamageReceived` |
| Смена сцены | Только через `MapManager.Instance.LoadMap()` |
| Логирование | Только через `GameLog.*` с категорией из `GameSettings` |

### Шаг 4 — Реализовать

Следовать соглашениям:
- Комментарии и документация — **на русском**
- Не вызывать `Debug.Log` — только `GameLog.*`
- Компоненты UltimateXR — следовать паттернам UXR (наследование от `UxrComponent<T>`)

### Шаг 5 — Обновить документацию (ОБЯЗАТЕЛЬНО)

После реализации обновить:

| Что добавлено | Документация |
|---|---|
| Новый класс / скрипт / компонент | `Assets/Docs/README.md` (таблица ключевых скриптов) |
| Новая игровая механика / режим | `Assets/Docs/gameplay.md` |
| Новый менеджер сессии / flow | `Assets/Docs/game-manager.md` |
| Новый GameMode | `Assets/Docs/game-manager.md` + `Assets/Docs/gameplay.md` |
| Новая зависимость от UltimateXR API | `Assets/ThirdParty/UltimateXR/Docs/_context/architecture.md` |
| Изменение архитектуры | `Assets/ThirdParty/UltimateXR/Docs/_context/architecture.md` |

### Шаг 6 — Предложить проверку перед коммитом

> **Не коммитить сразу.** Предложить пользователю проверить изменения в Unity.
> Коммитить только после явного подтверждения работоспособности
> или после явной просьбы «закоммить».

Если нужен коммит — запустить workflow `/commit`.
