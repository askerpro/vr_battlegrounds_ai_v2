# Правила работы с Документацией

## 📋 Периодическая оценка эффективности документации
> ИИ-помощник **обязан** раз в ~10 значимых задач (или при обнаружении явной неэффективности) предлагать улучшения документации.

### Признаки неэффективной документации
- ИИ-помощник искал информацию в коде, которая уже должна быть в документации
- Расследование заняло больше 3 итераций из-за недостаточного контекста
- Информация оказалась устаревшей или противоречивой
- Задан уточняющий вопрос о структуре проекта (это должно быть в доках)

### Формат предложения улучшений
После задачи добавить раздел:
```markdown
📊 **Оценка документации по итогам задачи:**
- Что помогло: [список]
- Чего не хватало: [список]
- Предложение: [конкретное улучшение]
```

## 📥 Обязательное правило: резюмировать сложную логику проектов и SDK в документацию
> **Если ИИ-помощник разобрался в сложной логике (особенно внутри SDK UltimateXR) или архитектурных связях, он ОБЯЗАН составить краткое техническое резюме и сохранить его в документацию.**
> **ЗАПРЕЩАЕТСЯ** документировать тривиальные методы.

### Что обновлять и когда
| Что изучил / сделал | Файл |
|---|---|
| Как работает конкретный компонент / метод | Соответствующий модульный `.md` в `Docs/UltimateXR/` |
| Неочевидное поведение или баг | `Docs/UltimateXR/known-issues.md` |
| Патч / изменение в исходниках SDK | `Docs/UltimateXR/sdk-patches.md` |
| Связи между игровыми системами | `Docs/UltimateXR/architecture.md` или `Docs/README.md` |
| Геймплейная механика, правила | `Docs/gameplay.md` |

## Правила работы с новыми директориями
Если при создании файла встречается новый путь:
1. **Не создавай наугад** — убедись какие пути существуют.
2. **Уточни документацию** — проверь соответствие путей.
3. **Спроси пользователя** — верны ли пути.
4. **Обнови документацию** после создания новой папки (в `copilot-instructions.md` и др.)
