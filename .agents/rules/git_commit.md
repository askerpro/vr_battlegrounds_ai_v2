# Правила: Управление документацией и Коммиты (Commit Workflow)

> **ВАЖНОЕ ПРАВИЛО:** ИИ-помощник **НИКОГДА** не должен делать git commit сразу после написания кода (исключения: правки документации). **Всегда дожидаться проверки пользователем в Unity.**
> Перед формированием коммита необходимо использовать Unity MCP для проверки ошибок компиляции.

## Шаг 1 — Посмотреть что изменилось
Проверить список измененных файлов:
`git --no-pager status` и `git --no-pager diff --stat`

## Шаг 2 — Проанализировать содержимое (Diff)
`git --no-pager diff`
Определить, является ли это фичей, фиксом, рефакторингом или доками.

## Шаг 3 — Обновить документацию (ОБЯЗАТЕЛЬНО)
Если документация еще не обновлена в ходе работы, обновите её перед коммитом:
- Новые классы / компоненты → `Docs/README.md`
- Игровые механики / логика → `Docs/gameplay.md`
- Патч SDK UltimateXR → `Docs/UltimateXR/sdk-patches.md`
- **Баг или побочный эффект SDK** → **`Docs/UltimateXR/known-issues.md`**
- Архитектура и зависимости → `Docs/UltimateXR/architecture.md`
- Новые правила для агента → `.agents/rules/...` или `.agentrules`

## Шаг 4 — Проверить компиляцию
Использовать доступные инструменты (Unity MCP) для проверки отсутствия ошибок сборки.

## Шаг 5 — Сформировать сообщение коммита
Формат сообщения:
```
<тип>: <краткое описание на русском>

<что и почему изменилось>
```
**Типы:** `feat` (новая фича), `fix` (исправление), `docs` (документация), `refactor` (рефакторинг), `chore` (остальное)

## Шаг 6 — Выполнить коммит (ТОЛЬКО после одобрения пользователя)
```
git add -A
git --no-pager commit -m "<message>"
```
