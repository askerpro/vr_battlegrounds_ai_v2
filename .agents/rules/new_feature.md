# Правила: Добавление новой фичи (New Feature)

> **Не писать код до тех пор, пока не понята архитектура.**

## Шаг 1 — Прочитать документацию
Прежде чем что-либо создавать:
1. **`Docs/README.md`** — список существующих классов, чтобы не дублировать логику
2. **`Docs/gameplay.md`** — как новая механика вписывается в геймплей
3. **`Docs/UltimateXR/architecture.md`** — нет ли готового компонента в UltimateXR SDK

## Шаг 2 — Определить архитектурный слой
Ответить на вопросы:
- К какому слою относится фича? (Сеть / Менеджеры / Игрок / UI / GameMode / UltimateXR)
- Является ли это новым `GameMode`, `Manager`, `UxrComponent`?
- Нужна ли сетевая синхронизация (Mirror)?

## Шаг 3 — Следовать зависимостям и паттернам
| Тип фичи | Что использовать |
|---|---|
| Новый игровой режим | Наследовать `GameMode`, создать `GameModeData` + префаб |
| Новый менеджер | Синглтон `DontDestroyOnLoad`, подписаться на нужные события |
| VR-взаимодействие | Использовать `UxrGrabbableObject` + `UxrGrabber` |
| Оружие | Наследовать `UxrFirearmWeapon` или `UxrGrenadeWeapon` |
| Сеть | `NetworkBehaviour`, `[SyncVar]`, `[Command]`, `[ClientRpc]` |
| Управление здоровьем | Подписаться на `UxrActor.Death` / `UxrActor.DamageReceived` |
| Смена сцены | Только через `MapManager.Instance.LoadMap()` |
| Логирование | Только через `GameLog.*` с категорией из `GameSettings` |

## Шаг 4 — Обновить документацию (ОБЯЗАТЕЛЬНО)
После реализации обновить:
| Что добавлено | Документация |
|---|---|
| Новый класс / скрипт | `Docs/README.md` (таблица ключевых скриптов) |
| Новая игровая механика | `Docs/gameplay.md` |
| Новый менеджер / flow | `Docs/game-manager.md` |
| Зависимость UltimateXR | `Docs/UltimateXR/architecture.md` |

## Шаг 5 — Проверка перед коммитом
> **Не коммитить сразу.** Предложи пользователю проверить изменения в Unity. Коммить только после явного подтверждения или по команде.
