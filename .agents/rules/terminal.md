# Терминал: PowerShell и Bash

В проекте доступны обе оболочки, и синтаксис у них разный. Не смешивай в одном вызове.

## PowerShell (основной)

Windows PowerShell 5.1. Отличия, на которых спотыкаются агенты:

- **Нет `&&` и `||`** — это ошибка парсера. Последовательно: `A; B`.
  По условию успеха: `A; if ($?) { B }`.
- **Нет тернарного `?:`, `??`, `?.`** — только `if/else` и явная проверка `$null -eq $x`.
- **Многострочные строки** — here-string `@'...'@`. Закрывающий `'@` обязан стоять
  в нулевой колонке, иначе ошибка парсинга.
- **`Set-Content` / `Add-Content`** по умолчанию пишут в системной ANSI-кодировке.
  Для файлов, которые прочитают другие инструменты, — явно `-Encoding utf8`.
- **`.ps1` с кириллицей** должен быть сохранён в UTF-8 **с BOM**, иначе PowerShell 5.1
  прочитает его как ANSI и текст превратится в мусор.
- **`2>&1` на нативных `.exe`** ломает `$?` — не перенаправляй, stderr и так захватывается.
- Нет `head`, `tail`, `which`, `touch`, `mkdir -p`, `rm -rf` — есть
  `Select-Object -First/-Last`, `(Get-Command x).Source`, `New-Item`,
  `New-Item -ItemType Directory -Force`, `Remove-Item -Recurse -Force`.

## Bash (Git Bash)

Обычный POSIX-синтаксис. Одно важное ограничение:

- **Bash-инструмент изолирован от сети.** `curl` к `127.0.0.1` падает с кодом 7, хотя порт
  слушает. Любые сетевые проверки — только через PowerShell.

## Git

Пейджер обезврежен через `GIT_PAGER=cat` в `.claude/settings.json` — отдельный `--no-pager`
больше не нужен. Если пейджер всё же открылся, значит настройка не подхватилась: добавь
`--no-pager` вручную и скажи об этом.

Интерактивные флаги (`git rebase -i`, `git add -i`) в этой среде не работают.

## Кодировка вывода

Кириллица в выводе команд обычно проходит корректно. Если пришёл мусор — проблема в
кодировке скрипта или в `[Console]::OutputEncoding`, а не в терминале. Не переключай
кодовую страницу глобально через `chcp` — чини источник.
