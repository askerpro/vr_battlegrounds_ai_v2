# Терминал: PowerShell и Bash

В проекте доступны обе оболочки, и синтаксис у них разный. Не смешивай в одном вызове.

## PowerShell (основной)

Windows PowerShell 5.1. Отличия, на которых спотыкаются агенты:

- **Нет `&&` и `||`** — это ошибка парсера. Последовательно: `A; B`.
  По условию успеха: `A; if ($?) { B }`.
- **Нет тернарного `?:`, `??`, `?.`** — только `if/else` и явная проверка `$null -eq $x`.
- **Многострочные строки** — here-string `@'...'@`. Закрывающий `'@` обязан стоять
  в нулевой колонке, иначе ошибка парсинга.
- **`Set-Content` / `Add-Content`** по умолчанию пишут в системной ANSI-кодировке.
  Для файлов, которые прочитают другие инструменты, — явно `-Encoding utf8`.
- **`.ps1` с кириллицей** должен быть сохранён в UTF-8 **с BOM**, иначе PowerShell 5.1
  прочитает его как ANSI и текст превратится в мусор.
- **`2>&1` на нативных `.exe`** ломает `$?` — не перенаправляй, stderr и так захватывается.
- Нет `head`, `tail`, `which`, `touch`, `mkdir -p`, `rm -rf` — есть
  `Select-Object -First/-Last`, `(Get-Command x).Source`, `New-Item`,
  `New-Item -ItemType Directory -Force`, `Remove-Item -Recurse -Force`.

## Bash (Git Bash)

Обычный POSIX-синтаксис. Одно важное ограничение:

- **Bash-инструмент изолирован от сети.** `curl` к `127.0.0.1` падает с кодом 7, хотя порт
  слушает. Любые сетевые проверки — только через PowerShell.

## Git

Пейджер обезврежен через `GIT_PAGER=cat` в `.claude/settings.json` — отдельный `--no-pager`
больше не нужен. Если пейджер всё же открылся, значит настройка не подхватилась: добавь
`--no-pager` вручную и скажи об этом.

Интерактивные флаги (`git rebase -i`, `git add -i`) в этой среде не работают.

## Кодировка вывода

Кириллица в выводе команд обычно проходит корректно. Если пришёл мусор — проблема в
кодировке скрипта или в `[Console]::OutputEncoding`, а не в терминале. Не переключай
кодовую страницу глобально через `chcp` — чини источник.

## Редактирование файлов и передача кода (находки 2026-10-02)

- Для правки исходников, конфигов и документации сначала использовать нативный редактор агента
  (Codex — `apply_patch`, Claude Code — Edit/Write). Не заменять его командой PowerShell/Python
  ради удобства пакетной обработки.
- Codex: в одном патче — одна операция на путь. Попытка `Delete File` + `Add File` для того же файла
  отклоняется как `multiple operations target`. Переписать в `Update File` или разделить вызовы.
- Windows PowerShell 5.1 кодирует текст для stdin внешней программы через `$OutputEncoding`,
  по умолчанию ASCII. Here-string с кириллицей, переданный `| python -`, превращает её в `?`;
  `Set-Content -Encoding utf8` и `[Console]::OutputEncoding` этот канал не исправляют.
- Если передача текста через stdin необходима: локально задать
  `$OutputEncoding = New-Object System.Text.UTF8Encoding($false)` и вызвать `python -X utf8 -`.
  Предпочтительно сохранить скрипт нативным редактором и запустить файл; после записи проверить UTF-8.
- `python -c '..."..."...'` через Windows PowerShell 5.1 может потерять кавычки при передаче аргумента
  нативной программе. Многострочный код выполнять из `.py`, не собирать сложный `-c`.
- Зависимые шаги запускать последовательно и проверять код возврата каждого. Если пакетная правка
  остановилась, выяснить, какие файлы успели измениться, прежде чем компилировать или продолжать.
- Запуск вне песочницы не выдаёт права администратора Windows. Для симлинка могут потребоваться
  Developer Mode или отдельный UAC. PowerShell `New-Item -ItemType SymbolicLink` может разрешить Target
  относительно текущей папки и записать абсолютный путь: относительные симлинки проверять по `Target`.
