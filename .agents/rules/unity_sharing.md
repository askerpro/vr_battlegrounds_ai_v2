# Доступ агентов к постоянному редактору Unity

Единственный инструмент доступа — `Tools/agents/editor-broker.py`. Каждый агент пишет только
в свой linked worktree; Unity worker всегда открыт на собственном постоянном worktree.
Исходники инструмента находятся в Tools/agents, постоянное состояние и runtime —
в .agent-state/editor-broker основного checkout. tmp — только временные отчёты и стенды.
Полный контракт и команды — `F:/UnityProjects/agent-infra/docs/editor-broker.md`.

Основной checkout для обычного агента доступен только на чтение. Код, ассеты, ProjectSettings,
Packages, Tools, Docs и любые генераторы изменений — только в собственном linked worktree.
Stage/commit/checkout/reset/clean основного worktree запрещены. Интеграция в него — отдельное
поручение пользователя назначенному интегратору. Рабочий каталог проверять до первой записи.
Уже запущенным сессиям требуется перечитать AGENTS.md: старый контекст не разрешает обход протокола.

## Подготовленный пакет

1. Подготовить код, команды, выходные пути и условие освобождения в своём worktree.
2. Сделать checkpoint A от текущей B контроллера, выполнить request с владельцем и выходными путями.
3. Запустить watch-ticket; можно поставить обычный monitor завершения этой команды.
   Предложение доступа резервируется по FIFO. Частота проверки не меняет порядок.
4. Получить token/epoch через claim, выполнить begin. Только контроллер переключает файлы worker.
5. Перед изменяющим Unity MCP вызвать guard, выбрать instance и сверить project root.
6. Выполнить подготовленный пакет и дождаться завершения компиляции, импорта или асинхронного job.
   Выйти только из своего Play Mode и завершить собственные временные изменения.
7. Следующим шагом выполнить finish: сохранить результат R, вернуть B и проверить готовность.
   Анализ ошибок, чтение кода, следующая правка и ожидание человека — уже после finish.
8. Забрать A..R через receive в свой worktree. Ассеты, бинарники и .meta переносятся вместе;
   собственные новые правки не перезаписываются при конфликте.

Ошибка проверки тоже результат. Она не разрешает удерживать аренду для расследования.
renew допустим только для реально продолжающейся операции Unity или её безопасного завершения.
Если broker недоступен или ещё не активирован, изменяющие операции в общем Editor запрещены:
продолжать независимую работу в своём worktree.

## Владение и безопасность

Перекомпиляция, тесты, Play Mode, открытие сцен, bake и сохранение ассетов worker выполняются
только в своей RUNNING аренде. Файлы редакторского worktree вручную не меняются.
Чтение консоли и наблюдение за собственным job допустимы; консоль без clear.
Превью и файловая работа в отдельном agent worktree не требуют аренды общего редактора.

Редактор человека не прерывать: чужой Play Mode, dirty-сцены, prefab stage и чужой прогон
нельзя завершать или сохранять от лица агента. guard закрепляет конкретную сессию, не просто
имя проекта. Raw MCP технически доступен, поэтому все участники обязаны соблюдать маршрут.

Timeout не доказывает завершение Unity. Не повторять изменяющий вызов вслепую: сверить durable
request/native результат. Истечение активной аренды переводит очередь в RECOVERY_REQUIRED;
оно не выдаёт редактор следующему агенту. recover сохраняет результат и проверяет возврат.
Результат остаётся доступен после освобождения аренды; получение ассетов не удерживает Unity.

Внутренний OS mutex контроллера сериализует переходы Git/Unity и записи журнала. Это деталь
реализации, а не второй замок редактора: агенты не захватывают его отдельной командой.
