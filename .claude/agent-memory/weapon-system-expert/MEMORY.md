# Память эксперта по оружию

Уроки процесса и предпочтения пользователя. Архитектура и решения — в `Docs/weapons/`, не здесь.

- Пользователь проверяет механику сам в шлеме; зови его, когда Play Mode со сцены `Assets/Scenes/Offline.unity`
  уже запущен в твоей аренде, и давай чек-лист по стволам/категориям. Пока он смотрит, аренду держи продлением.
- Пользователь называет стволы по названию в арсенале (`WeaponInfo._displayName`), а не по имени префаба: «SRS» — префаб
  `SRM12` (Desert Tech SRS), «AX-50» — префаб `SniperRifle`. Перед работой со стволом сверяй название в `Assets/Data/Weapons/*_Weapon.asset`.
- Вливание после приёмки — прямо в origin/dev (ff) через хаб; статус задачи держать актуальным docs-коммитами.
- Протокол координации не обходить никогда; отказ инструмента — повод спросить, а не искать обход.
- `origin/dev` часто уходит вперёд на коммиты документации — перед каждой арендой fetch + rebase (WIP-коммит →
  rebase → reset --soft), иначе брокер отвечает «устаревшая база»; если опубликованная база отстаёт —
  `editor-broker.py request-base`.
- Один worktree исполняет один этап: чтобы начать другой этап своей задачи, текущий — stop (работа в коммите).
- Субагент, которому нужен перенос ветки, возвращается к тебе — ветку переписывает только главный.
