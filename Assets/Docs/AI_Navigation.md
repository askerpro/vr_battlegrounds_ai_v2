# Инструкции по навигации для ИИ-ассистента (M.A.P. System)

Этот файл содержит критически важные правила работы с кодовой базой для ИИ-помощников (напр. Antigravity), чтобы избежать медленного глобального сканирования и галлюцинаций.

## 1. Точка входа в проект (Docs-First Approach)
Когда пользователь задает вопрос об архитектуре, алгоритмах (например, "какой порядок инициализации менеджеров?") или просит добавить новую сущность — **В первую очередь прочитай `Assets/Docs/README.md` и связанные файлы (game-manager.md, gameplay.md)**.
Там собрана Карта Проекта. В 90% случаев ответ на архитектурный вопрос уже расписан там, и ИИ должен использовать эту базу вместо реверс-инжиниринга исходного кода.

## 2. Использование текстового поиска
- **Никогда** не используй слепой перебор файлов (`list_dir` по всему проекту) для поиска места, где определен класс.
- **Всегда** используй инструмент `grep_search` (текстовый поиск ripgrep) по точному имени класса, интерфейса или структуры. 

## 3. Ограничение зоны поиска
Чтобы не тратить время и память на анализ сторонних библиотек:
- Ищи собственные классы проекта и их использования **только внутри `Assets/Scripts`**.
- Не заходи `grep_search`-ом в директории `Packages` и `ThirdParty` (даже в `UltimateXR`), если только задача не связана с изучением самих этих библиотек напрямую.

## 4. Как вести системную документацию
Проект создается для того, чтобы его понимали и люди, и ИИ. 
- Обязательно пиши **краткие высокоуровневые резюме (Summary)** для сложных модулей SDK или запутанных менеджеров с тысячами строк. Это позволит автору игры сэкономить время и прочитать полстраницы текста вместо изучения гигантского исходника.
- Фиксируй неочевидные баги.
- **СТРОГО ЗАПРЕЩЕНО** переписывать в документацию тривиальные методы, геттеры и простые скрипты. Экономим размер документации.
