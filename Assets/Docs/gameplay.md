## Карты

### Структура файлов

```
Assets/
+-- Scenes/
|   +-- Maps/
|       +-- Arena_Warehouse.unity   -- сцена карты
|       +-- ...
+-- Data/
    +-- Maps/
        +-- MapRegistry.asset       -- единственный реестр карт (MapRegistry SO)
        +-- Map_Warehouse.asset     -- данные карты (MapData SO)
        +-- Map_Warehouse_Preview.png
        +-- ...
```

### Классы

| Класс | Путь | Назначение |
|---|---|---|
| `MapData` | `Assets/Scripts/Maps/MapData.cs` | ScriptableObject с данными одной карты |
| `MapRegistry` | `Assets/Scripts/Maps/MapRegistry.cs` | ScriptableObject-список всех карт; назначить в `AdminMenuController._mapRegistry` |

**Поля `MapData`:**
| Поле | Тип | Описание |
|---|---|---|
| `displayName` | `string` | Название в меню выбора карты |
| `sceneName` | `string` | Имя сцены Unity (совпадает с именем в Build Settings) |
| `preview` | `Sprite` | Превью-скриншот для UI |
| `description` | `string` | Краткое описание (опционально) |
| `arenaSizeMeters` | `Vector2` | Физические размеры зоны в метрах (X = ширина, Z = глубина) |
| `maxPlayers` | `int` | Максимум игроков на карте |

### Как добавить новую карту

1. **Создать сцену:** `Assets/Scenes/Maps/Arena_NewMap.unity`
2. **Добавить в Build Settings:** `File --> Build Settings --> Add Open Scenes`
3. **Создать MapData asset:** правая кнопка в Project --> `Create --> VrBattlegrounds --> Map Data`
   - `sceneName` = точное имя файла сцены без расширения (например `Arena_NewMap`)
   - `preview` = скриншот карты (импортировать как Sprite)
4. **Добавить в реестр:** открыть `Assets/Data/Maps/MapRegistry.asset`, добавить новый `MapData` в массив `maps[]`

Больше ничего менять в коде не нужно — `AdminMenuController.GetMaps()` подхватывает список автоматически.

### Быстрый запуск карты из редактора (отладка)

Используется `DebugOrchestrator` + `DebugBootstrapConfig`. Флоу:

```
Play --> OfflineScene --> NetworkManager поднимает хост --> OnlineScene (Sandbox)
  --> GameNetworkManager.ServerSceneChanged срабатывает
  --> DebugOrchestrator.TryAutoLoadMap() --> ServerChangeScene(autoLoadMapScene)
  --> Arena_NewMap загружается автоматически
```

Чтобы запустить конкретную карту сразу:
1. Открыть `DebugBootstrapConfig` asset в Inspector
2. Заполнить поле `Auto Load Map Scene` именем сцены (например `Arena_Warehouse`)
3. Нажать Play — карта загрузится автоматически после подъёма хоста

Чтобы отключить автозагрузку — очистить поле `Auto Load Map Scene`.

## Инструменты отладки

### DebugOrchestrator

**Файлы:**
- `Assets/Scripts/Debug/DebugOrchestrator.cs` — компонент-оркестратор
- `Assets/Scripts/Debug/DebugBootstrapConfig.cs` — ScriptableObject с параметрами

**Назначение:** автоматизирует ручные шаги при каждом запуске Play в редакторе — назначает команду, загружает карту, стартует матч. Не меняет продакшн-код, использует те же публичные API что и обычная игра.

**Как подключить (один раз):**
1. Создать пустой GameObject в OfflineScene, назвать `DebugOrchestrator`
2. Добавить компонент `DebugOrchestrator`
3. Создать asset: `Create --> VrBattlegrounds --> Debug Bootstrap Config`
4. Назначить asset в поле `Config`

**Чтобы отключить** — деактивировать GameObject или снять флаг `Enabled` в конфиге.

**Поля `DebugBootstrapConfig`:**

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | `bool` | `true` | Включить быструю инициализацию |
| `autoTeam` | `Team` | `Terrorists` | Команда локального игрока |
| `autoStartMatch` | `bool` | `true` | Автостарт матча при достаточном кол-ве игроков |
| `minPlayersToAutoStart` | `int` | `1` | Минимум игроков для автостарта |
| `autoLoadMapScene` | `string` | `""` | Имя сцены карты для автозагрузки (пусто = не грузить) |

**Последовательность событий при старте:**

```
Play
 --> OfflineScene загружается
 --> NetworkManager поднимает хост --> OnlineScene (Sandbox)
 --> GameNetworkManager.ServerSceneChanged --> DebugOrchestrator.TryAutoLoadMap()
 --> ServerChangeScene(autoLoadMapScene)  -- если поле заполнено
 --> Карта загружается
 --> UxrAvatar.LocalAvatarChanged --> назначается команда
 --> PlayerConnected --> N -- если игроков >= minPlayersToAutoStart --> StartMatch()
```

> **Для Copilot:** `DebugOrchestrator` не содержит игровой логики — только вызовы публичных API менеджеров. При добавлении новой механики с параметрами отладки — добавить поле в `DebugBootstrapConfig`, обработать в `DebugOrchestrator`.

## Физическая арена

Игра проводится на **настоящей физической VR-арене** — большом зале, в котором:
- Стены и пол размечены **легко распознаваемыми линиями и углами** для надёжной навигации VR-шлемов (inside-out tracking)
- **Размеры игровой карты в Unity совпадают с реальными размерами помещения** — масштаб 1:1
- Игроки физически перемещаются по арене, а не используют стик для ходьбы

> **Для Copilot:** при создании карт и спавн-точек учитывать реальные физические размеры. Телепортация и smooth locomotion не используются — только физическое передвижение.

## Команды

Игроки делятся на **2 команды:**

| Команда | Enum / ключ |
|---|---|
| Террористы | `Team.Terrorists` |
| Спецназ | `Team.SpecialForces` |

Смена команд происходит **автоматически** между сетами (террористы --> спецназ).

## Режимы игры

Архитектура режимов должна быть **расширяемой** — новые режимы добавляются без изменения базового кода.

### Базовый класс режима
```
GameMode (abstract)
    +-- RespawnMode        -- Режим 1: возрождение при возврате на спавн
    +-- EliminationMode    -- Режим 2: раунд до полного уничтожения команды
```

### Режим 1 — Respawn (приоритет реализации)
- Игрок, погибший в игре, **возрождается сразу**, если **физически возвращается на точку спавна**
- Раунд не имеет ограничения по жизням
- Условие окончания раунда определяется режимом (например, по времени или по счёту)

### Режим 2 — Elimination
- Раунд заканчивается, когда **одна команда ликвидирует всех игроков** другой команды
- После гибели игрок **не возрождается** до следующего раунда

> **Для Copilot:** при добавлении нового режима — создать наследника `GameMode`, переопределить методы `OnRoundEnd`, `CanRespawn`, `CheckWinCondition`. Не менять базовую логику `RoundManager`.

## Структура матча

```
Match (5 карт)
+-- Map (карта x5)
    +-- Set (сет --> 10 на матч = 2 сета на карту x5 карт)
        +-- Сет 1: Команда A = Террористы, Команда B = Спецназ
        +-- Сет 2: Команда A = Спецназ,    Команда B = Террористы  -- смена сторон
        +-- Победитель сета --> +1 очко команде
```

**Подсчёт победителя матча:** команда, набравшая больше сетов из 10, побеждает.

## Роли пользователей

### Администратор
Первый подключившийся игрок (Host) получает права администратора.
Если Host одновременно играет — ему доступны **оба меню**.

#### Меню администратора (`AdminMenuController`)
| Функция | Описание |
|---|---|
| Выбор карты | Список доступных карт, загрузка сцены |
| Выбор режима игры | `RespawnMode` / `EliminationMode` |
| Управление матчем | Запустить / Остановить / Продолжить |

- Управление передаётся `MatchManager` --> `SetManager` --> `RoundManager`
- Только Host видит кнопки управления матчем (проверка `isServer`)

### Префаб игрока

**Путь:** `Assets/Prefabs/Player/PlayerControllersCyborgAvatar.prefab`

Это `PrefabVariant` на основе `CyborgAvatar_URP` из UltimateXR SDK.

Компоненты корневого объекта:
| Компонент | Назначение |
|---|---|
| `UxrAvatar` | VR-тело, руки, камера |
| `UxrStandardAvatarController` | обновление аватара по вводу контроллеров |
| `UxrMirrorAvatar` | сетевая синхронизация аватара через Mirror |
| `NetworkIdentity` | идентификатор Mirror |
| `NetworkTransformUnreliable` | синхронизация трансформа |
| `UxrActor` | система урона UltimateXR |
| `PlayerController` | -- команда, жизни, смерть, возрождение |

> **Для Copilot (MCP):** при добавлении или изменении компонентов игрока — работать с этим префабом, не с объектами сцены:
> `Assets/Prefabs/Player/PlayerControllersCyborgAvatar.prefab`

### Игрок
Каждый подключившийся клиент видит меню игрока.

#### Меню игрока (`PlayerMenuController`)
| Функция | Описание |
|---|---|
| Выбор команды | Террористы / Спецназ (отправляет запрос на сервер) |
| Калибровка VR | Синхронизация позиции шлема с физической ареной |

### Калибровка VR (`VrCalibrationController`)
Игроки физически перемещаются по арене — позиция в Unity должна совпадать с реальной.
Процедура калибровки:
1. Игрок встаёт на **физическую метку** на полу арены (известная точка)
2. Нажимает **"Откалибровать"** в меню
3. `VrCalibrationController` вычисляет смещение между реальной и виртуальной позицией
4. Применяет offset к корневому объекту аватара (`UxrAvatar` tracking origin)

## Архитектура менеджеров матча

```
MatchManager              — управляет всем матчем (5 карт, счёт, победитель)
+-- SetManager            — управляет сетом (смена команд, счёт сетов)
    +-- RoundManager      — управляет раундом (готовность, старт, конец раунда)
```

### MatchManager
- Хранит текущую карту, счёт команд по сетам
- Запускает `SetManager` для каждого нового сета
- Определяет победителя матча после 10 сетов

### SetManager
- Хранит текущий номер сета и распределение команд (кто террористы, кто спецназ)
- После завершения сета **меняет команды местами**
- Передаёт управление `RoundManager`

### RoundManager
- **Проверяет готовность всех игроков** перед стартом раунда
- Запускает раунд
- Слушает **событие конца раунда** (из активного `GameMode`)
- Запускает следующий раунд или завершает сет

## Сетевое взаимодействие

Многопользовательская часть реализована на **Mirror** (NetworkManager, NetworkBehaviour).

| Аспект | Решение |
|---|---|
| Сетевой фреймворк | Mirror (`Assets/Mirror/`) |
| Синхронизация UXR | `UxrNetworkManager` + адаптер под Mirror |
| Авторитетный сервер | Host = администратор арены |
| Синхронизация состояния | `UxrManager.ComponentStateChanged` --> Mirror RPC |

> **Для Copilot:** серверная логика (MatchManager, RoundManager, SetManager) выполняется только на **сервере** (`[Server]` атрибут Mirror). Клиенты получают обновления через `ClientRpc`. Состояние игроков синхронизируется через `NetworkBehaviour` + UltimateXR networking адаптер.
