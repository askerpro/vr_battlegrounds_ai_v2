## Физическая арена

Игра проводится на **настоящей физической VR-арене** — большом зале, в котором:
- Стены и пол размечены **легко распознаваемыми линиями и углами** для надёжной навигации VR-шлемов (inside-out tracking)
- **Размеры игровой карты в Unity совпадают с реальными размерами помещения** — масштаб 1:1
- Игроки физически перемещаются по арене, а не используют стик для ходьбы

> **Для Copilot:** при создании карт и спавн-точек учитывать реальные физические размеры. Телепортация и smooth locomotion не используются — только физическое передвижение.

## Команды

Игроки делятся на **2 команды:**

| Команда | Enum / ключ |
|---|---|
| Террористы | `Team.Terrorists` |
| Спецназ | `Team.SpecialForces` |

Смена команд происходит **автоматически** между сетами (террористы ? спецназ).

## Режимы игры

Архитектура режимов должна быть **расширяемой** — новые режимы добавляются без изменения базового кода.

### Базовый класс режима
```
GameMode (abstract)
    ??? RespawnMode        ? Режим 1: возрождение при возврате на спавн
    ??? EliminationMode    ? Режим 2: раунд до полного уничтожения команды
```

### Режим 1 — Respawn (приоритет реализации)
- Игрок, погибший в игре, **возрождается сразу**, если **физически возвращается на точку спавна**
- Раунд не имеет ограничения по жизням
- Условие окончания раунда определяется режимом (например, по времени или по счёту)

### Режим 2 — Elimination
- Раунд заканчивается, когда **одна команда ликвидирует всех игроков** другой команды
- После гибели игрок **не возрождается** до следующего раунда

> **Для Copilot:** при добавлении нового режима — создать наследника `GameMode`, переопределить методы `OnRoundEnd`, `CanRespawn`, `CheckWinCondition`. Не менять базовую логику `RoundManager`.

## Структура матча

```
Match (5 карт)
??? Map (карта ? 5)
    ??? Set (сет ? 10 на матч = 2 сета на карту ? 5 карт)
        ??? Сет 1: Команда A = Террористы, Команда B = Спецназ
        ??? Сет 2: Команда A = Спецназ,    Команда B = Террористы  ? смена сторон
        ??? Победитель сета ? +1 очко команде
```

**Подсчёт победителя матча:** команда, набравшая больше сетов из 10, побеждает.

---

## Администратор игры

- Перед стартом администратор:
  1. Выбирает **карту**
  2. Выбирает **режим игры**
  3. Нажимает **"Запустить игру"**
- После старта управление передаётся `MatchManager` ? `SetManager` ? `RoundManager`

## Архитектура менеджеров матча

```
MatchManager              — управляет всем матчем (5 карт, счёт, победитель)
??? SetManager            — управляет сетом (смена команд, счёт сетов)
    ??? RoundManager      — управляет раундом (готовность, старт, конец раунда)
```

### MatchManager
- Хранит текущую карту, счёт команд по сетам
- Запускает `SetManager` для каждого нового сета
- Определяет победителя матча после 10 сетов

### SetManager
- Хранит текущий номер сета и распределение команд (кто террористы, кто спецназ)
- После завершения сета **меняет команды местами**
- Передаёт управление `RoundManager`

### RoundManager
- **Проверяет готовность всех игроков** перед стартом раунда
- Запускает раунд
- Слушает **событие конца раунда** (из активного `GameMode`)
- Запускает следующий раунд или завершает сет

## Сетевое взаимодействие

Многопользовательская часть реализована на **Mirror** (NetworkManager, NetworkBehaviour).

| Аспект | Решение |
|---|---|
| Сетевой фреймворк | Mirror (`Assets/Mirror/`) |
| Синхронизация UXR | `UxrNetworkManager` + адаптер под Mirror |
| Авторитетный сервер | Host = администратор арены |
| Синхронизация состояния | `UxrManager.ComponentStateChanged` ? Mirror RPC |

> **Для Copilot:** серверная логика (MatchManager, RoundManager, SetManager) выполняется только на **сервере** (`[Server]` атрибут Mirror). Клиенты получают обновления через `ClientRpc`. Состояние игроков синхронизируется через `NetworkBehaviour` + UltimateXR networking адаптер.
