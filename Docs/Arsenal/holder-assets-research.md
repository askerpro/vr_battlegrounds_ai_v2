## Рекомендуемый узкий путь

Новая независимая альтернатива: [DDD Printable Wall Control System — Allen Derusha](https://github.com/aderusha/DDD-Printable-Wall-Control-System), [первичная MIT License](https://github.com/aderusha/DDD-Printable-Wall-Control-System/blob/main/LICENSE), [готовые Quickhooks](https://github.com/aderusha/DDD-Printable-Wall-Control-System/tree/main/Quickhooks). Публичный репозиторий содержит готовые STL длиной1/2/3дюйма, Light/Medium/Heavy и отдельный retainer; коммерческая адаптация допускается с сохранением copyright/license. Есть SketchUp/FreeCAD sources. Это готовая модульная геометрия, но ещё не осмотренный Unity module: нужны реальная доступность файла, форма, размер, конверсия mesh, URP material/budget. Не импортирован, UV/PBR и Quest пригодность не подтверждены.

Использовать готовый FBX-крючок как исходный модуль: проверить единицы и pivot после импорта, укоротить вылет25см до измеренного контакта конкретного оружия/магазина, при необходимости поставить пару одинаковых упоров. Не заменять корпус и перфопанели проекта, не создавать новую модель держателя с нуля. Общий URP-материал металла вместо двух исходных материалов, без отдельной текстуры на каждый экземпляр. Уменьшение числа сегментов допускается как адаптация готового исходника после осмотра mesh; конкретный бюджет и силуэт ещё не утверждены.

2,3k tris одного модуля нельзя автоматически считать бюджетом для четырёх стен с десятками держателей. До массового применения нужны реальные mesh/material counts, варианты объединения/инстансинга, Android compile и измерение Quest. glTF наличие не доказывает наличие импортера в проекте; FBX — предпочтительный проверяемый маршрут. Сейчас скачивание требует входа в Sketchfab; логин/скачивание не выполнялись.

## Каноническая композиция и подсветка: открытые контракты

DDD Quickhook2inMedium реально доступен без login: `tmp/arsenal-holder-candidate/DDD/Quickhook-2in-Medium.stl` (55784bytes) и LICENSE (1070bytes). Binary STL1114triangles. При интерпретации единиц как mm размер63.8×37.9×9.1mm; единицы STL сами не кодируют, это явное допущение конверсии. Изолированный URP render осмотрен: `tmp/arsenal-holder-candidate/DDD/preview.png`, `metrics.json`. Плоский выступающий держатель с загнутым tip и креплением подходит для пары опор; нужны slot-contact fit и многократный бюджет. Конверсия готового mesh в Unity asset вместо предпочтительного FBX предложена root; native import pending. Самодельная геометрия с нуля не предлагается.

- Принят один `ArsenalPresentationStyle`: defaults фактической зоны Entry.Zone и exact `(WeaponInfo, Zone)` исключения в том же asset. Item/Mag/Card targets — абсолютные slot-local poses, Item/Mag задают effective SDK AlignTransform. Root предмета и anchor root выводятся из SDK DropAlign/AlignTransform; масштабы сохраняются.
- Styled branch не прибавляет WeaponInfo offsets и не делает runtime contact fit. Старые offsets/custom card cache остаются одним явным legacy adapter для null-style. Edit-only Fit/Bake может предложить изменение того же canonical target; сцена не является вторым master.
- Базовые Style/Resolver/Applicator, runtime и builder source скомпилированы. Native Style ещё не назначен; Preview/Save/Reset и все refresh/hash consumers завершаются до native styled batch. Наличие класса не означает завершённую композицию.
- SDK `UxrGrabbableObjectAnchor.ActivateOnCompatibleNear` — существующий механизм локальной подсветки. Оружейный `AcceptsItem` уже проверяет допустимый возврат; именно weaponanchor должен показывать готовность при поднесении автомата. `ArsenalMagazineOffer` сохраняет `RejectManualPlacement => false`: складской якорь не принимает возвращаемые магазины. Магазин получает визуальный держатель, без нового stockreturn/refund/refill/adoption. Hint не обходит существующий validator. Insertion-ready якоря магазина НА ОРУЖИИ относится к существующему отдельному feedback. Новый возврат в stock — незапрошенная futurefeature, не блокирует визуальный срез.
- Исходные20 фотографий получены и вручную осмотрены: `tmp/arsenal-visual-photos/before/manifest.json`, `manual-review.md`. Композиция ещё не исправлена: after20/regen20, метрические bounds и bake в канонический style pending. Масштабы оружия, магазинов, карточек и SDK grips остаются прежними.
