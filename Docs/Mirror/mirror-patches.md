# Патчи Mirror

> Mirror вендорится в `Assets/ThirdParty/Mirror/`. Любая правка там обязана попасть сюда,
> иначе потеряется при обновлении. Места правок в коде помечены `VR Battlegrounds patch`:
> после обновления Mirror поиск по этой строке должен найти все места из списка ниже.

## Патч 1: серверные сокеты не наследуются дочерними процессами

**Файлы:**
- `Core/SocketInheritance.cs` — **новый файл**, в апстриме его нет;
- `Transports/KCP/kcp2k/highlevel/KcpServer.cs` — `Start()`, вызов после `CreateServerSocket`;
- `Components/Discovery/NetworkDiscoveryBase.cs` — `AdvertiseServer()`, вызов после `new UdpClient`.

**Симптом.** В редакторе `StartHost` падает с `SocketException: Обычно разрешается только
одно использование адреса сокета` (`KcpServer.CreateServerSocket`). `Get-NetUDPEndpoint`
показывает, что порт 7778/47777 держит **сам Unity.exe** — других процессов на порту нет.
Не помогают ни повторный Play, ни перезагрузка домена. Помогает перезапуск MCP или редактора.

**Причина.** В Windows процесс, созданный через `CreateProcess` с наследованием дескрипторов,
получает копии всех наследуемых дескрипторов родителя, а Mono создаёт сокеты наследуемыми.
MCP for Unity запускает свой сервер дочерним процессом Unity
(`cmd.exe → uvx → uv → mcp-for-unity → python`). Если это произошло посреди Play Mode,
python унаследовал сокеты KCP и обнаружения. Mirror при выходе закрывает свои копии
корректно, но порт остаётся за python. Windows показывает владельцем процесс, создавший
сокет, — отсюда ложный след «порт держит редактор». Разобрано 2026-09-27 по `Editor.log`:
MCP стартовал внутри сессии, остановка Mirror дошла до `ServerStop` без исключений.

**Правка.** `SocketInheritance.Disable(socket)` снимает `HANDLE_FLAG_INHERIT` через
`SetHandleInformation` сразу после создания серверного сокета. Код под
`UNITY_EDITOR_WIN || UNITY_STANDALONE_WIN`: в Android-сборке Quest вызов пустой.
Неудача вызова глотается — сервер стартует как раньше.

Клиентские сокеты не патчены: у них случайный порт, конфликта при повторном старте нет.

**Проверка.** `SocketInheritanceTests` (EditMode): открыть сокет → запустить дочерний
процесс → закрыть сокет → порт свободен. До правки оба теста красные с той же ошибкой,
что в редакторе.

**При обновлении Mirror.** Скопировать `Core/SocketInheritance.cs`, вернуть два вызова.
Если в апстриме появилось своё решение (`WSA_FLAG_NO_HANDLE_INHERIT` или аналог) —
патч удалить, тест оставить.
