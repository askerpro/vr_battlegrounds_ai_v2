# UltimateXR: Аватар (UxrAvatar) и Главный Менеджер (UxrManager)

В этом модуле описаны ключевые аспекты работы с аватаром игрока и глобальным менеджером состояния фреймворка UltimateXR.

## 1. UxrManager (UltimateXR.Core.UxrManager)
Глобальный синглтон (`UxrSingleton<UxrManager>`), который управляет обновлением всех сущностей (аватаров, захватываемых объектов и т.д.) в правильном порядке. Доступен через `UxrManager.Instance`.

### Ключевые возможности:
- **Перемещение Аватара:** Методы `MoveAvatarTo` и `TeleportLocalAvatar` позволяют изменять позицию и вращение аватара без нарушения работы VR-камеры.
- **Синхронизация Состояния:** Менеджер может обрабатывать события синхронизации компонентов среды (например для мультиплеера).
- **События:** Предоставляет события этапов обновления (`AvatarsUpdating`, `StageUpdating` и т.д.).

### Примеры API:
```csharp
// Мгновенное перемещение аватара в новую позицию с заданным поворотом (forward).
UxrManager.Instance.MoveAvatarTo(avatar, newFloorPosition, newForwardVector);

// Плавная или мгновенная телепортация локального аватара (с поддержкой затемнения экрана).
UxrManager.Instance.TeleportLocalAvatar(newFloorPosition, newRotation, UxrTranslationType.Fade);
```

## 2. UxrAvatar (UltimateXR.Avatar.UxrAvatar)
Центральный компонент, представляющий VR-пользователя (локального или сетевого). Он не должен управляться напрямую через изменение `Transform` из других скриптов, так как UltimateXR имеет собственную логику обновления положения камеры и рук.

### Ключевые особенности работы:
- Для получения локального аватара используется `UxrAvatar.LocalAvatar`.
- Запрещено менять `transform.position` у объекта с `UxrAvatar` напрямую (особенно для телепортации или спавна). Это приводит к рассинхронизации камеры и трекинга.
- Необходимо использовать методы `UxrManager` (см. выше), передавая в них ссылку на `UxrAvatar`.
- Аватар содержит ссылки на руки (`LeftHandBone`, `RightHandBone`), конфигурацию рендера и режимы (Local/UpdateMode).
- Взаимодействие с объектами осуществляется через компоненты контроллеров и грэббинг (`UxrGrabManager`).

## 3. Этапы обновления (Update Stages)

`UxrManager` управляет жизненным циклом кадра через несколько этапов, чтобы гарантировать правильный порядок вычислений:
- **AvatarUsingTracking**: Считывание позиций с VR-устройств. Выполняется **только для локальных аватаров**.
- **Manipulation**: Обработка взаимодействия с предметами (`UxrGrabManager`, `UxrWeaponManager`). Выполняется для всех активных аватаров.
- **Animation**: Обновление анимаций рук и позы. Для удаленных аватаров обновляются только трансформы кистей (`UpdateHandPoseTransforms`).
- **PostProcess**: Финальная стадия, включающая расчет IK (Inverse Kinematics). Выполняется для **всех** аватаров с контроллерами, чтобы обеспечить корректное отображение тела удаленных игроков.

## 4. Режимы работы аватара (UxrAvatarMode)

- **Local**: Аватар контролируется текущим пользователем.
- **UpdateExternally**: Аватар управляется внешним источником (сеть, реплей). 
    - Его `Transform` и кости кистей обычно синхронизируются через сетевой SDK.
    - Его IK (тело, локти) рассчитывается локально на основе синхронизированных позиций головы и рук.
    - **Важно**: Для корректного расчета IK через `UxrBodyIK` требуется наличие (пусть и отключенной) камеры или корректного `CameraTransform`, так как алгоритм опирается на позицию глаз/головы.

---

**Правило при спавне / телепортации:**
Если в сетевой игре требуется заспавнить игрока в новой точке, необходимо получить `UxrAvatar` и использовать `UxrManager.Instance.MoveAvatarTo(...)`. Если это происходит по сети, вызов должен быть в `ClientRpc` (на клиенте), чтобы VR-камера корректно обновила свое положение относительно новой точки на полу.
