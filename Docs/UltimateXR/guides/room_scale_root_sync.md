# Синхронизация реальных шагов (Room-Scale) с виртуальным корнем (World-Scale) в UltimateXR

В стандартном поведении большинства VR SDK (включая UltimateXR), объект аватара (`UxrAvatar` / `Root`) остается на месте спавна или последней телепортации. Когда игрок делает физические шаги по своей реальной комнате, перемещается только вложенный объект камеры (`CameraController`) и рук.

В некоторых играх (например, где важен физический капсюль персонажа для столкновений, получения урона или хождения по лестницам) необходимо, чтобы `Root` аватара всегда находился строго под головой игрока. 

Ниже описаны три подхода к решению этой архитектурной задачи.

---

## Подход 1: Текущий (Стандартный UXR)
Аватар спавнится в (0,0,0) или перемещается только при аппаратном телепорте. Физические шаги в реальности смещают локальную камеру внутри рута.

* **Плюсы:** Стандартное, нативное поведение SDK. Нет проблем с застреванием коллайдеров при случайных физических шагах. Сетевые библиотеки (типа Photon/Netcode) обычно синхронизируют сами руки и голову, так что другие игроки видят корректные движения.
* **Минусы:** Корневой объект не отражает реальное физическое положение тела игрока. Если ИИ-враги целятся или стреляют в Root-коллайдер, они будут стрелять в пустоту, пока игрок физически отошел в сторону.

---

## Подход 2: Глубокая интеграция в SDK (Использовался в старом проекте)
В старом проекте применялся хардкорный метод привязки координат драйверов шлема напрямую к перемещению аватара.

* **Как это работало:**
  1. Был создан кастомный `TrackedPoseDriverExt.cs` (наследник стандартного юнити-драйвера), перехватывающий `_lastDeviceOutput` и применяющий к нему свой `m_OriginPose`.
  2. В ядре локомоции `UxrManager.TeleportLocalAvatar` был изменен код: вместо стандартного перемещения рута вызывался `TrackedPoseDriverExt.MoveTo()`, который жестко задавал новые мировые координаты матрице драйвера шлема.
  3. В `UxrControllerTracking` переопределялись свойства `SensorLeftPos` / `SensorRightPos`, чтобы они считывали кастомный `origin`.
* **Плюсы:** `Root` аватара идейно перемещался по сцене, при этом учитывая и физические шаги (если это было реализовано), и телепортации.
* **Минусы:** Очень высокая связанность (High Coupling). Прямое вмешательство в ядро локомоции `UxrManager` и трекинга, что блокирует обновление UltimateXR до новых версий. Высокий риск конфликтов со стандартными компонентами.

---

## Подход 3: Легковесный конвейер смещения (Best Practice для будущей реализации)
Если в будущем потребуется, чтобы `Root` всегда ползал за физической головой игрока, рекомендуется использовать изолированный скрипт-компенсатор. Модифицировать исходники UXR не придется.

* **Как это работает:**
  Создается один компонент `AvatarRootSync.cs`, который вешается на любой менеджер и работает в `LateUpdate`:
  1. Измеряется локальное смещение `CameraController` по осям X и Z относительно `Root`'а аватара.
  2. Если локальные X или Z не равны нулю (игрок сделал шаг в комнате), скрипт сдвигает глобальный `Root` аватара на этот вектор в мировых координатах.
  3. В тот же самый момент скрипт сдвигает `CameraController` в обратную сторону в локальных координатах.
* **Результат:** 
  Для игрока в шлеме картинка остается абсолютно неподвижной (векторы скомпенсировали друг друга), но в иерархии Unity `Root` аватара подтянулся ровно под координаты головы, а локальный X/Z камеры обнулился.
* **Плюсы:** Абсолютно изолированное решение. Не ломает ядро UltimateXR. Легко включается и отключается галочкой компонента. Надежно работает с коллайдерами (можно плавно двигать `Root` через CharacterController, чтобы игрок не проходил сквозь стены).

### Пример концепта кода для Подхода 3:
```csharp
void LateUpdate()
{
    var avatar = UxrAvatar.LocalAvatar;
    if (avatar == null || avatar.CameraController == null) return;

    Vector3 localCamPos = avatar.CameraController.localPosition;
    
    // Если камера ушла по X или Z (физические шаги)
    if (Mathf.Abs(localCamPos.x) > 0.001f || Mathf.Abs(localCamPos.z) > 0.001f)
    {
        Vector3 flatOffset = new Vector3(localCamPos.x, 0, localCamPos.z);
        
        // 1. Двигаем сам Root аватара в мире
        avatar.transform.Translate(flatOffset, Space.Self);
        
        // 2. Возвращаем камеру обратно в центр рута
        localCamPos.x = 0;
        localCamPos.z = 0;
        avatar.CameraController.localPosition = localCamPos;
    }
}
```
*Примечание: в реальном внедрении нужно учитывать повороты, работу UxrTeleportLocomotion и физические препятствия/стены.*
