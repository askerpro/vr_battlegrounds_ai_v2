# Контракт изолированной работы агентов с Unity

Пользователь 2026-10-05 разрешил реализацию этого протокола в отдельном worktree.
Основной checkout и общий редактор при разработке не переключаются.

## Владение и база

- Каждый агент пишет только в собственный worktree. Unity имеет постоянный отдельный worktree.
- Внешний Python-контроллер — единственный писатель состояния редакторского checkout.
- Принятая база B публикуется контроллером. Заявка содержит B, неизменяемый входной SHA A,
  владельца, исходный worktree, ожидаемые выходные пути и ключ идемпотентности.
- A обязан включать текущую B; устаревшую заявку обновляют вне редактора. Ветка агента
  не переключается в редактор: используется detached HEAD конкретного A.
- Технические checkpoint разрешены до пользовательской проверки. Они закрепляются под
  codex/tmp, не меняют HEAD/index агента, не вызывают хуки и не переносятся в Plastic.
  Принятый коммит и пользовательская проверка остаются отдельным этапом.

## Очередь и восстановление

- SQLite хранит FIFO, владельцев, постоянные адресные события и журнал транзакции.
  Координация общая для всех worktree одного git-common-dir и не лежит в переключаемых файлах.
- Состояния: QUEUED -> OFFERED -> LEASED -> SWITCHING -> RUNNING -> CAPTURING -> RESTORING -> DONE.
  FAILED/CANCELLED терминальны; RECOVERY_REQUIRED блокирует новых владельцев.
- Первому готовому участнику резервируется очередь; claim требует владельца. Срок предложения
  ограничен, пропущенное предложение не удерживает очередь. Повторная заявка не дублируется.
- Для операции выдаются непредсказуемый token и возрастающий epoch. Каждая изменяющая команда
  проверяет ticket/token и сериализуется отдельным OS/file mutex на весь переход.
- Истечение активной аренды переводит контроллер в RECOVERY_REQUIRED, а не разрешает кражу.
  Renew не переставляет заявки. Повторный пакет идёт в хвост. Ожидание возвращает адресное
  событие и резервирование, поэтому частота проверки не определяет победителя.
- Перед SWITCHING на диске сохранены B, A, конфигурация сцен и состояние возврата.
  После сбоя контроллер не объявляет редактор свободным до проверенного восстановления.
- Очередь контроллера — единственный источник аренды редактора; отдельный старый lock удалён.
  Raw MCP-вызовы не становятся технически запрещёнными автоматически.

## Unity и выходные данные

- Исходники инструментов находятся в Tools/agents; постоянное состояние и закреплённый
  runtime — в .agent-state/editor-broker основного checkout, вне переключаемого worktree.
  tmp предназначен только для временных диагностических файлов и проверочных стендов.

- Локальный мост устанавливается из Tools/agents в игнорируемую папку
  Assets/Editor/VR_Battlegrounds/Debug/EditorBrokerLocal; его исходники/config и журнал стабильны.
  Мост имеет собственную Editor asmdef и не зависит от игровой сборки.
- Канал файловых запросов содержит уникальный request id. Мост обрабатывает только операции
  inspect, park, refresh, save_outputs, restore; отсутствует произвольное исполнение кода.
- Проверяются root, отсутствие Play/compile/import/tests, dirty-сцен/ассетов/prefab. Перед checkout
  сцены паркуются в пустую, автообновление подавляется; после checkout баланс восстанавливается,
  выполняется refresh, ответ выдаётся после завершения компиляции/импорта, включая domain reload.
- Агент пользуется Unity MCP только после guard своего ticket/token, закрепления instance и root.
  Таймаут не считается завершением операции; broker не повторяет изменяющий запрос вслепую.
- save_outputs сохраняет только согласованные пути, отказывает при чужих dirty-объектах.
  Все изменения на диске фиксируются в выходной checkpoint R с родителем A, включая новые
  ассеты, удаления, бинарники и .meta. Неожиданные изменения сохраняются, но не принимаются.
- R закрепляется до отката. Его доставка AVAILABLE -> IMPORTED независима от редакторской
  аренды. Нельзя удалять ref результата до подтверждения получения либо явной отмены.
- Агент забирает дельту A..R с проверкой исходного содержимого затронутых файлов. Посторонние
  правки/index/HEAD не перезаписываются. Конфликт разрешается у агента, не в редакторе.
- Library/Temp и кэши не коммитятся и не копируются. Отдельные отчёты доставляются как артефакты.
  Возврат гарантирует файлы B, согласованную конфигурацию сцен и готовность, но не Undo/статики.

## Приёмка

Python 3.10+, стандартная библиотека; Windows/PowerShell и Git без shell-интерполяции.
Тесты используют настоящий Git и несколько процессов: FIFO, отмена, идемпотентность,
просрочка, fencing, конкуренция, checkpoint без хуков, новые .meta/бинарники, конфликт получения,
неожиданные выходы, сбой между этапами, сохранение R и возврат B. Unity-мост отдельно компилируется
и проверяется в минимальном изолированном Unity-проекте. Игровые механики не меняются.
