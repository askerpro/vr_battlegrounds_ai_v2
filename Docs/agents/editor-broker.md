Контроллер `Tools/agents/editor-broker.py` передаёт технические Git checkpoint между
worktree агента и постоянным отдельным worktree Unity. SQLite FIFO резервирует право
захвата, файловый мост паркует сцены и подтверждает завершение refresh, внешний Python
сохраняет результаты до возврата базы. Python 3.10+ использует только стандартную библиотеку;
требуется Git 2.43+ с `--attr-source` для корректных clean/smudge фильтров целевого снимка.

Состояние реализации и проверки приведены в [плане](editor-broker-plan.md), обязательные
инварианты — в [контракте](editor-broker-spec.md). Автоматическая установка или переключение
общего редактора при разработке не выполняются. Игровой код и механики не меняются.

Git-контроллер технически проверяет token, SHA, root и сохраняет данные, но старый raw Unity MCP
не становится недоступным. Для гарантии единственного владельца все агенты должны перейти
на этот маршрут. `guard` — обязательная проверка перед MCP; `set_active_instance` и чтение
project root относятся к конкретной Unity-сессии. Пользовательский Play Mode не прерывается.

## Постоянные файлы

По умолчанию каталог координации вычисляется из общего Git-каталога:
`<git-common-dir>/../.agent-state/editor-broker`. Он один для всех linked worktree. Редакторский
worktree должен находиться отдельно, поэтому каталог состояния находится вне его root.
Можно явно указать `--state-dir` во всех командах. Не создавать разные state-dir на один Editor.

Версионируемые инструменты находятся в `Tools/agents/`. `.agent-state/` — постоянное
локальное состояние и закреплённый runtime, исключённые из Git. `tmp/` используется только
для временных диагностических файлов и стендов; удаление `tmp/` не удаляет очередь и runtime.

- `config.json` — зарегистрированные editor root, принятая база и локальный мост.
- `broker.sqlite3` — FIFO, capability token/epoch, постоянные адресные события, журнал переходов.
- `transaction.lock` — OS mutex на весь Unity/Git переход; процессная смерть отпускает mutex,
  но не объявляет незавершённую транзакцию безопасной.
- `runtime/` — закреплённая копия Python-контроллера и шаблонов, которая не переключается
  вместе с гостевым SHA. После init CLI переходит в эту копию.
- `unity/requests`, `responses`, `journals`, `heartbeat.json` — канал моста и состояние reload.
- `artifacts/<ticket>/` — отдельно сохранённые отчёты с SHA256; кэши Library не передаются.

Мост устанавливается только в ignored папку
`Assets/Editor/VR_Battlegrounds/Debug/EditorBrokerLocal`. Собственная Editor asmdef не зависит
от игровой сборки. Installer отказывает при неизвестной версии файлов; source/config/asmdef
проверяются по SHA256 перед операциями. Неизвестные изменения не перезаписываются.

## Активация

1. Завершить прежние операции Unity. Все участники используют один контроллер;
   отдельного инструмента захвата редактора нет.
2. Выбрать принятую базу B, содержащую инструменты и `.gitignore` локального моста. Сначала
   разнести накопленные чужие изменения основного checkout; не использовать dirty HEAD как B.
3. Создать отдельный linked worktree редактора на B, предпочтительно detached. Не использовать
   рабочую папку человека или агента. Перед init он должен быть чистым, worker Editor закрыт.
4. Выполнить init из worktree инструментов. Он устанавливает локальный мост и фиксирует
   runtime; запуск нового worker Editor выполняется отдельно на зарегистрированном root.

Перед первым запуском восстановить локальные зависимости, которые Git не переносит:
embedded MCP 10.2.0 с патчами проекта. Ассеты с отслеживаемой .meta должны находиться в Git;
fallback-ассет TextMesh Pro возвращён под контроль Git с сохранением исходного GUID.
Иначе Unity удаляет orphan .meta и worker перестаёт соответствовать базе. Library не копировать.
Установщики MCP используют ticket/token либо явный -OfflineEditor с проверкой закрытого root;
основной checkout для них запрещён. [Установка MCP](../unity-mcp.md#установка-на-другой-машине).

`python Tools/agents/asset_pairs.py --source index --report tmp/asset-pairs.json` проверяет
весь класс: tracked file .meta без версионируемого owner asset. Папки определяются по Git tree
prefix; пустые допускаются по folderAsset: yes. init отвергает базу с нарушенными парами.
Перевод formerly-ignored файла под контроль Git допускает существующий локальный файл только
при совпадении с целевым объектом после clean/smudge и повторной проверке перед checkout.
Различающийся кэш не перезаписывается.

Чтобы worker подключался к существующему HTTP MCP без изменения общих EditorPrefs,
установить шаблон Tools/agents/unity_bridge/WorkerMcpBootstrap.cs.txt как
Packages/com.coplaydev.unity-mcp/Editor/WorkerMcpBootstrap.cs только в локальном package worker.
Он проверяет root по локальному мосту и общей регистрации, дожидается readiness и уважает
reload-resume MCP. Результат — unity/mcp-bootstrap.json в постоянном состоянии.

Пример (пути и SHA заменить на выбранные):

```powershell
python Tools/agents/editor-broker.py --state-dir F:/UnityProjects/Vr_Battlegrounds_ai/.agent-state/editor-broker init --editor-root C:/UnityWorktrees/editor --baseline <B>
```

`--no-install` существует только для независимых стендов с fake-adapter. В production мост
обязателен. Смена принятой базы не выполняется скрытым merge: завершить очередь, проверить
совместный результат и явно выполнить `publish-base --sha <C>` из его исходного worktree.
Контроллер отказывает при ожидающих/активных заявках, проверяет новую базу Unity и публикует
её одним атомарным config переходом. При сбое используется тот же журнал/recovery. Старые
результаты остаются доступны. Принятые коммиты и перенос в Plastic — обычный процесс проекта.

Состояние очереди показывает `python Tools/agents/editor-broker.py status`.
Старый инструмент захвата удалён. Если контроллер ещё не активирован или недоступен,
изменяющие операции в общем редакторе не выполняются; независимая работа идёт в worktree агента.

## Один пакет работы

Обычный агент использует основной checkout только на чтение. Изменения любых файлов,
генерация, stage/commit/checkout/reset/clean выполняются только в собственном linked worktree.
Приём в основной checkout — отдельное поручение назначенному интегратору, не часть editor lease.
Уже работающим сессиям нужно перечитать AGENTS.md перед следующей записью.

Агент пишет только в свой linked worktree. Технический checkpoint не меняет его HEAD/index:
private index и `commit-tree` создают снимок фактических файлов, закреплённый под `codex/tmp`.
Обычные Git/hooks не вызываются; Plastic не получает временную историю. Git clean/smudge
фильтры и `.meta` сохраняют контракт проекта. Новые/изменённые symlink и служебные пути запрещены.

```powershell
python Tools/agents/editor-broker.py checkpoint --label T-123-input
python Tools/agents/editor-broker.py request --owner T-123 --input <A> --base <B> --output Assets/Generated/T-123 --key T-123-attempt-1
python Tools/agents/editor-broker.py wait --ticket <ticket> --owner T-123 --timeout 60
python Tools/agents/editor-broker.py claim --ticket <ticket> --owner T-123
python Tools/agents/editor-broker.py begin --ticket <ticket> --token <token>
python Tools/agents/editor-broker.py guard --ticket <ticket> --token <token>
```

`request` включает текущую принятую B. Если B устарела, обновить собственный checkpoint вне
редактора. Вход A неизменяем: редактор получает SHA, пока агент продолжает владеть своей веткой.
`wait` — адресное оповещение через результат ожидающего tool/CLI, а не массовый сигнал
«свободно». Первому участнику место уже зарезервировано; остальные не могут обойти его.
CLI не отправляет сообщений другим чатам самостоятельно. `events --owner ... --after ...`
позволяет читать постоянные события с курсором.

### Обычный монитор завершения команды

Агент может поставить стандартный монитор на этот ожидающий процесс:

```powershell
python Tools/agents/editor-broker.py watch-ticket --ticket <ticket> --owner T-123 --until offered
```

Без `--timeout` команда остаётся запущенной до значимого события; ожидание выполняет Python,
не модель. Для получения созданных ассетов доступно `--until result`. Коды возврата:
0 — предложение/результат получены; 3 — отмена или терминальное состояние без нужного события;
4 — требуется recovery; 5 — заданный общий timeout; 2 — ошибка параметров/владельца/контроллера.
Timeout не означает получение доступа. Монитор не захватывает Unity автоматически: после
пробуждения агент проверяет актуальное OFFERED и подтверждает claim. Повторный poll не меняет FIFO.

Если среда возобновляет агента при завершении monitor-команды, отдельная периодическая
автоматизация не требуется. Для собственного клиента [Codex App Server](https://learn.chatgpt.com/docs/app-server)
поддерживает `turn/start` с `toolOutput`, которым можно доставить событие зарегистрированному
чату. Это внешний адаптер среды, а не самовольная отправка сообщений из Python-контроллера.
Периодический heartbeat возможен как запасной вариант, но его интервал и время пробуждения
нужно согласовать со сроком OFFERED. Не обещать универсальную событийную подписку у любой среды.

`claim` возвращает token; публичный status/events/wait его скрывают. До переключения проверяются
чистые файлы, отсутствие незаписанных сцен/ассетов/prefab и Play/compile/import/tests.
Сцены паркуются, auto-refresh подавляется на время файлового перехода и затем восстанавливается.
Ответ refresh приходит после завершения операций, включая reload. Ошибка/таймаут требует recovery.

После begin выполнить только подготовленные Unity MCP действия. Перед изменяющим вызовом
проверить guard, закрепить instance и сверить root с guard. Не держать аренду во время анализа,
написания следующей правки, ожидания человека или другого агента. Для реально продолжающегося
прогона доступен `renew`; завершение асинхронного job обязательно дождаться.
guard сообщает занятость собственного Play/тестов и допускает их наблюдение и завершение
владельцем. begin/finish/recover сохраняют строгий запрет переключения занятого редактора.
Перезапуск Unity меняет session_id и переводит прежнюю аренду в recovery.

```powershell
python Tools/agents/editor-broker.py finish --ticket <ticket> --token <token> --artifact tmp/T-123/report.json
```

finish сохраняет только согласованные dirty-ассеты/сцены, фиксирует полный дисковый diff A..R,
закрепляет R и отчёты, затем возвращает B, refresh и исходную конфигурацию сцен. Неожиданные
изменения сохранены в R, но `accepted=false` запрещает их автоматическую доставку. Эта отметка
означает соответствие выходных путей, а не принятие игровой механики или успешность тестов.

## Возврат созданных ассетов

Файловые клиенты каталога ассетов используют общий client_guard.py: main checkout запрещён,
закрытый linked agent worktree не требует аренды; запись в worker требует ticket/token
и совпадения project root в guard. Offline допускается только для bootstrap package.
Process inventory подтверждает состояние на момент проверки; агент сохраняет исключительное
владение своим worktree и не запускает параллельный редактор во время файловой операции.

Результат редактора и его аренда независимы. После проверенного возврата B редактор уже доступен
следующему участнику; R остаётся доступен отсутствующему агенту.

```powershell
python Tools/agents/editor-broker.py receive --ticket <ticket> --owner T-123
```

Получатель использует зарегистрированный worktree. Перед первой записью проверяются все
затронутые файлы на соответствие A и отсутствие коллизий. Доставляется только A..R; исходные
HEAD/index и посторонние файлы сохраняются. Новые ассеты, folder.meta и asset.meta переносятся
вместе, GUID не генерируются повторно. При пересечении со свежими правками операция отказывает:
разрешать конфликт у агента, не в редакторе. Успех receive подтверждает IMPORTED автоматически.
На время receive агент приостанавливает собственные редакторы/генераторы этих файлов.
Контроллер сериализует приём в один worktree OS mutex и повторно проверяет содержимое после
фильтров и перед публикацией; Git не предоставляет kernel CAS против произвольного внешнего
писателя между последней проверкой и rename. Исключительное владение файлами — часть протокола.
`ack` предназначен для явного подтверждения другого проверенного способа получения.

Нельзя удалять refs результата до получения или явной отмены. Library/Temp/build caches
не коммитятся и не копируются. Отдельные отчёты доступны по stored_path/SHA256 в metadata job.
Генераторы должны обновлять собственные файлы идемпотентно и сохранять существующие GUID.

## Отказ и восстановление

Истечение активной аренды не выдаёт новую: возникает RECOVERY_REQUIRED. Token/epoch остаются
за аварийной транзакцией; её результат, вход и база доступны в журнале. При таймауте нельзя
повторять изменяющий MCP/bridge вызов: сначала получить response/native результат по request id.

```powershell
python Tools/agents/editor-broker.py recover --ticket <ticket> --token <token>
```

Обычный recover дожидается осиротевшего запроса, сохраняет аварийный R, возвращает B и проверяет
готовность. Если процесс Editor действительно завершился, разрешён отдельный дисковый этап:

```powershell
python Tools/agents/editor-broker.py recover --ticket <ticket> --token <token> --editor-stopped
```

PID проверяется средствами ОС; живой процесс не завершается и его файлы не переключаются.
Старые mailbox-запросы получают cancellation response, аварийный R закрепляется, B возвращается
на диск. Очередь остаётся заблокированной. Запустить worker и выполнить обычный recover для
проверки Unity и выдачи следующей аренды. Чужой HEAD/неизвестные изменения требуют разбора
журнала, а не force checkout или `git clean -fdx`.

Возврат восстанавливает базовые файлы, согласованные сцены и готовность, но не Undo и статики
произвольной интерактивной сессии. FIFO гарантирует порядок готовых живых заявок; срок ожидания
зависит от длительности операций, восстановления и работы человека.

## Производительность и эксплуатационные ограничения

Основная цена пакета — два перехода B -> A -> B с refresh, возможными импортом,
компиляцией и domain reload. Постоянный root сохраняет Library worker, но возврат изменённых
скриптов и настроек всё равно может повторно инвалидировать кэш. Группировать подготовленные
операции одного агента в короткий пакет; не переключать редактор для каждой мелкой правки.
Пропуск возврата B изменил бы контракт изоляции и в этот протокол не входит.

Checkpoint и проверка перед откатом требуют обхода Git-состояния и обработки изменённых
файлов. Большие бинарные ассеты и LFS добавляют дисковый I/O и стоимость clean/smudge.
Утилизация refs, архивов запросов и отчётов требует отдельной политики хранения после
подтверждения получения; автоматического удаления единственной копии результата нет.
SQLite сериализует короткие переходы очереди; ожидание monitor не удерживает транзакцию.
Завершённые mailbox-записи архивируются и не сканируются в idle.

Полная миграция проекта на LF или CRLF не нужна. Новые Python/Bash/шаблоны используют LF,
остальные пути сохраняют действующую политику `.gitattributes`. Снимки и доставка применяют
атрибуты целевого состояния и Git-фильтры: временные массовые EOL-диффы не должны попадать в A/R.

Нативный smoke проверен на минимальном проекте. Время импорта полного игрового проекта,
пиковая память Unity и пропускная способность очереди под реальными задачами не измерены.
Перед активацией измерить длительность begin/finish, reload/import и ожидания на типичных
пакетах; отдельно проверить реально запущенный TestRunner job и Unity MCP reconnect.

## Проверки

```powershell
python -m unittest discover -s Tools/agents/tests -p "test_editor_broker*.py" -v
```

Стенды используют настоящий Git, CRLF/LFS/symlink fixtures, несколько процессов SQLite и
fake Unity для аварийных границ. Компиляция моста и отдельный минимальный Unity smoke не
подменяют принятие протокола в общем редакторе или пользовательскую проверку игровых задач.

Проверено 2026-10-05: 96 инфраструктурных тестов, включая три проверки legacy-замка
(один OS symlink fixture пропущен из-за прав Windows), и 11 нативных Unity smoke-сценариев. Мост с harness
