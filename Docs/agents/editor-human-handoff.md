# Передача редактора человеком

Подготовлено отдельно; установка в действующий worker и смена runtime не выполняются.

Брокер остаётся единственным владельцем Git-переходов и очереди. Человек может работать
в worker только вне активной аренды. Для параллельной работы человек использует свой
Unity на основном worktree, агенты — отдельный worker.

## Панель Unity

`Tools/VR Battlegrounds/Debug/Редактор и агенты` (шаблон `Tools/agents/unity_bridge/EditorBrokerHumanPanel.cs.txt`,
ставится вместе с мостом в ignored-папку `EditorBrokerLocal`). Состояние панель читает из
`<state>/human-ui.json`, который CLI пишет после каждой команды, поэтому оно переживает domain reload.
Команды панель запускает фоновым процессом CLI, главный поток Unity не блокируется
(CLI ждёт ответов моста в этом же Editor).

- Во время аренды: заголовок окна `[ЗАНЯТ АГЕНТОМ: owner · phase]`, Scene view затемнён и не
  принимает мышь/клавиатуру. Это защита от случайной правки: Inspector, Hierarchy, внешние IDE
  и процессы не блокируются, проверки dirty-состояния брокера остаются основной защитой.
- Отказ агенту из-за dirty worker: окно «Агент просит редактор» всплывает один раз на эпизод
  (`human-blocked.json`), в заголовке — число ожидающих.

## Кнопки и команды CLI

| Кнопка | Команда | Что делает |
|---|---|---|
| Сохранить и передать агентам | `human-release` | Unity сохраняет сцены (новой — запрос пути) и ассеты; брокер паузит очередь, park, `stash push -u`, резервный ref `refs/editor-broker/human/<id>`, refresh, проверка чистоты, снятие паузы |
| Вернуть мои изменения и продолжить | `human-resume` | Пауза выдачи сразу; после окончания текущей аренды (`human-status` панели продолжает) — только на прежнем SHA и чистом worker: `stash apply --index`, refresh, восстановление сцен, drop своей записи stash по точному SHA |
| Ещё 10 минут | `human-defer --minutes 10` | Оффер возвращается в QUEUED с прежним id: заявка остаётся первой, остальные не обгоняют. После срока — новый эпизод уведомления, если worker всё ещё dirty |
| Отказать без срока | `human-defer --minutes 0` | Очередь на паузе до «Сохранить и передать»; заявка первая, повторных окон нет |
| Я разобрал вручную — снять передачу | `human-clear` | Только для HUMAN/RECOVERY_REQUIRED; резервный ref не удаляется |

Stash сохраняет только файлы на диске; игнорируемые (включая Library) и Play Mode не переносятся.
При ошибке apply запись переходит в RECOVERY_REQUIRED, повторный apply запрещён, stash и ref остаются.
Нельзя считать произвольный dirty результат stash успешным возвратом.

## Проверка базы main

HEAD main проверяется при request, claim, begin и human-release: он должен входить и в принятую
базу worker, и во входной checkpoint. Dirty main не переносится. Новую базу публикует интегратор;
устаревшие заявки отменяются/пересоздаются, автоматический rebase не выполняется.
