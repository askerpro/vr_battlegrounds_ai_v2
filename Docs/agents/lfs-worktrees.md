# LFS и быстрые ворктри агентов

## Действующая политика

Полные оружейные и солдатские паки используются игрой и сохраняются целиком. Их бинарники под `Assets/ThirdParty/KINEMATION`, `Hands_Weapons_Animations_Pack_Update` и `Military Soldier Mega Bundle` хранятся в LFS. Код, `.meta`, текстовые материалы, префабы, сцены и анимации остаются в обычном Git. Охват расширений и роли задаются `Tools/agents/lfs-worktree-policy.json`; атрибуты — `.gitattributes`.

Старые коммиты не переписываются. На новой базе большой файл представлен Git LFS-указателем; оригинальные байты остаются в общем `.git/lfs/objects` и в полной основной копии. Для удалённой воспроизводимости перед push требуется успешная выгрузка LFS-объектов на настроенный LFS remote. Этот переход не включает push и не меняет Plastic.

## Роли

| Роль | Фильтр checkout | Работа с ассетами |
|---|---|---|
| Новый агент | `git-lfs filter-process --skip` | Указатели; адресное извлечение только для задачи |
| Основной checkout | `--skip`, затем post-checkout | Сохранённые полные файлы; hook извлекает объекты из локального кеша |
| Зарегистрированный Unity worker | Полный filter-process в worktree config | Настоящие файлы перед импортом Unity |

`git worktree add` использует настройки вызывающей рабочей копии. Поэтому основной checkout также оставляет smudge выключенным: его полное извлечение выполняется отдельно после checkout, а создаваемый из него агент не получает гигабайты файлов. Worker имеет отдельное полное переопределение. При ручном создании из worker использовать `git worktree add --no-checkout`, настроить роль целевого worktree, затем выполнить checkout из него.

В `.git/config` интегратор включает `extensions.worktreeConfig=true` и общий skip; в `config.worktree` задаются исключения ролей. Нельзя глобально экспортировать `GIT_LFS_SKIP_SMUDGE`: переменная перекрывает и полное извлечение worker.

## Настройка машины и нового агента

На новой машине, из основной копии:

```powershell
python -X utf8 Tools/agents/configure_lfs_worktree.py apply --install-defaults
```

В новом агентском worktree:

```powershell
python -X utf8 Tools/agents/configure_lfs_worktree.py apply
python -X utf8 Tools/agents/configure_lfs_worktree.py status
```

`.githooks/post-checkout` вызывает этот маршрут автоматически, когда helper есть в выбранной версии. В старых ветках helper может отсутствовать; Git defaults всё равно пропускают smudge, а профиль задаётся явно перед работой. `.codex/config.toml` содержит ссылку на этот маршрут; вымышленных настроек Codex для Git не используется.

Для конкретного ассета: `git lfs pull --include="Assets/путь/к/файлу"`. Не выполнять полный pull по умолчанию. Не открывать агентский Unity-проект с LFS-указателями: импорт будет некорректен. Основной post-checkout не загружает сеть: при отсутствующем кеше сообщает, что нужен адресный pull. Для нового зарегистрированного worker интегратор повторяет install-defaults и выполняет извлечение до открытия Unity.

## Checkpoint и проверка

Checkpoint агента должен сохранять LFS-указатели; `git add` использует clean-фильтр. При materialization в worker используются его собственные full-фильтры (`git cat-file --filters`). Запрещено подменять этот маршрут сырым `cat-file -p`, иначе Unity получит текст указателя вместо ассета. Профили проверяются на настоящих LFS-объектах и linked worktree; main/worker сравниваются по исходным байтам.

Интеграционная проверка:

```powershell
python -X utf8 -m unittest discover -s Tools/agents/tests -p test_lfs_worktree_policy.py -v
```

В Windows-песочнице один ранний запуск Git завершился аварийно; повторные проверки проходят вне песочницы. Нельзя считать отсутствие stderr доказательством корректности процесса. Проверка включает контроль до политики (полный файл), создание нового лёгкого worktree, worker materialization и настоящий main post-checkout.

Общий объектный кеш нельзя чистить отдельно от всех worktree и веток. `git lfs prune`, переписывание истории и общая переменная окружения не входят в обычную настройку. Замеры создания/переключения относятся к проверенной новой базе; старые коммиты с обычными большими блобами остаются тяжёлыми.
