# Unity MCP через брокер

`unityMCP` в `.mcp.json` (Claude Code) и `.codex/config.toml` (Codex) — stdio-прокси
`Tools/agents/unity_mcp_proxy.py`, запускаемый `uv run` (зависимость `mcp>=1.20,<2` ставится uv).
Прокси подключается к общему хабу `http://127.0.0.1:8080/mcp` (`UNITY_MCP_URL` / `--url`) и перед
каждым вызовом инструмента спрашивает брокер: `editor-broker.py mcp-gate` (логика — `editor_broker/mcp_gate.py`).
Цель — удобная оркестрация локальных агентов, а не защита от злоумышленника: прямой доступ к хабу
технически остаётся.

Агентом считается worktree, где лежит запущенный скрипт прокси (`--repo` переопределяет).

| Кто | Чтение | Изменение |
|---|---|---|
| Агент с своей арендой `RUNNING` | в worker | `guard`, затем в worker (`unity_instance` подставляется) |
| Агент без аренды / с чужой | как запрошено | отказ с владельцем аренды и порядком действий |
| Человек в основном checkout | как запрошено | в свой Unity (по умолчанию его экземпляр); в worker — отказ |

Чтение — таблица `READ_TOOLS`/`READ_ACTIONS`; всё, чего там нет, включая новые инструменты сервера,
считается изменением. Пометки `readOnlyHint` сервера неточны и не используются.
Экземпляр worker вычисляется как MCP for Unity: `<папка>@sha1(<root>/Assets)[:16]`.

Изменяющий вызов при обрыве связи не повторяется. Ресурсы (`resources/*`) проходят без проверки.
Если брокер в репозитории не инициализирован или его runtime-копия старше `mcp-gate`,
прокси работает как прямой MCP; после обновления runtime проверка включается без перезапуска агентов.
Недоступный брокер: чтение проходит, изменение отклоняется.

Проверки: `Tools/agents/tests/test_editor_broker_mcp_gate.py`.
