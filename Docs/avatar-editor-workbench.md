# Редактор аватара

Единая точка входа: **Tools → VR Battlegrounds → Avatars → Редактор аватара**.
Выберите `AvatarData`, prefab, экземпляр или FBX. Окно показывает состав выбранной цели;
просмотр и смена вкладки не запускают настройку, сохранение или регистрацию.

Отрисовка кнопок не собирает зависимости и не сканирует папки ассетов. Эти операции запускаются
после нажатия кнопки при подготовке плана; полный SHA и проверка аренды перед записью сохранены.
Список вариантов ног для обслуживания кэшируется до обновления контекста: смены цели,
изменения проекта/иерархии, Undo/Redo или кнопки «Обновить».

## Перенос меню

Все 42 прежние команды имеют маршрут внутри окна. Во внешнем меню остаётся один пункт.
Раскройте **«Найти прежнюю команду меню (42)»**, введите прежнее название и перейдите в нужный раздел.
Каталог хранится в `AvatarEditorCatalog.cs`; проверки сверяют количество маршрутов каждого исходного файла
с инвентаризацией аудита. Это проверка покрытия интерфейса, а не подтверждение каждого модельного рецепта.

| Раздел | Возможности |
|---|---|
| Обзор | Цепочка prefab, данные скина, состав, renderers/LOD, диагностика скелета и камер; рабочий экземпляр в отдельной preview scene |
| Подготовка | Копия FBX; Native/SDK; отдельный UXR rig; Blender по шагам или полный маршрут; шаги wizard; сохранение рабочего экземпляра; новый игровой вариант из базы и модели |
| Руки и позы | Унаследованные и собственные позы, штатный редактор SDK, Hand Pose Review; сброс tracking calibration; перепривязка выбранных мешей перчаток |
| Тело | Renderers, хитбоксы одного prefab, общий владелец тела и его locomotion controller, пересадка skinned meshes |
| Оснащение | Fingertips, карманы, часы с явным эталоном, иконка AvatarData, экспорт шаблонов карманов и runtime capture/apply |
| Обслуживание | Hand Bases, прямой rebase вариантов, общий batch hitboxes/corpses/ghost, часы зарегистрированных аватаров, миграции старых ног, новый независимый каркас, рецепты Cyborg Legs и MEF Team Color |

`Check Skeletons` и `Inspect Cyborg Avatar` объединены в диагностику выбранного аватара.
`Extract Player Base` и `Create PlayerBase from CyborgAvatar` объединены в создание **нового** независимого
каркаса: источник выбирается явно, удаляемый дочерний объект модели задаётся отдельно, пустое поле сохраняет
всю копию. Существующий `PlayerBase` не перезаписывается.
`Create Base Avatars` заменён созданием варианта из явно выбранных базы и Humanoid-модели.
Прежний фиксированный набор четырёх soldier prefab больше не является скрытой областью запуска.

## Запись и область действия

Кнопка записи сначала готовит план: цель, назначение и список входов/выходов. SHA файлов и `.meta`
снимается в фоне, затем повторяется под общей арендой непосредственно перед writer.
Изменение цели отменяет план; изменение файлов или рабочего экземпляра отвергает устаревший план.
Варианты ног и аватары для установки часов захватываются списком при подготовке.
Запрещена запись в vendor-prefab: создайте собственный вариант в `Assets/Prefabs`.

Guard использует существующие `ArsenalEditorActions.Lease` и `ArsenalFileSnapshot`, включая запрет
Play, compilation, Prefab Stage, dirty scenes и dirty assets. Продление долгой операции находится в
самой общей аренде (`Lease.Renew`), а не в отдельном владельце замка аватаров. Blender проверяет аренду
в процессе, при отмене завершает собственный процесс и только затем освобождает её.
Перед завершением фонового этапа повторяются SHA входов и проверки dirty assets.

Команды не обещают транзакционный откат: ошибка может оставить частичные изменения **в показанной области**.
Результат и область сохраняются после release в `tmp/avatar-editor-workbench/*.json`.
Общие сборщики используют широкую область, указанную в плане; обычные действия работают с одним prefab.
`Setup Legs` отдельно от миграции старых legs: конфликтующий прежний writer блокирует включение нового.
Сохранение вариантов проверяет собственный canonical Mirror `assetId` и результат записи.

## Кисти и подготовка

Native сохраняет родные кисти. Ампутация и замена на `BigIKHand` доступны для SDK-маршрута;
отдельные SDK-шаги заблокированы для подтверждённого Native-контекста. Отметка подготовленного SDK-источника
привязана к его GUID; NonSdkHands явно запрещает SDK-шаги даже при сохранившихся настройках окна.
Blender работает с **новой копией FBX**, имеет журнал и останавливает pipeline на первом отказе процесса.
Частичные копии после отказа сохраняются для диагностики; исходник не перезаписывается.
Используются текущие Python-рецепты проекта: произвольный скелет не считается автоматически совместимым.
Исполняемый файл Blender настраивается в EditorPrefs через кнопку раздела подготовки.

Rig и игровой вариант — разные выходы. Generic игровой вариант принимает пустую базу NonSdkHands
и модель с полным Humanoid finger mapping; регистрировать AvatarData и manager надо отдельным действием.
Кандидаты поз из SDK-клипов требуют проверки на конкретном скелете. Генератор меняет переданный root
и новые pose assets, а сохранением конкретного prefab владеет внешний writer; `ApplyPrefabInstance`
из typed пути удалён. Штатный SDK-редактор поз остаётся отдельным окном, открываемым для выбранной цели.

## Карманы

Повторная установка сохраняет калибровку существующих карманов и обновляет их теги.
Экспорт четырёх отдельных шаблонов сохраняет межкарманные ссылки в `Pockets/Bindings.json`:
grab proxy и proximity восстанавливаются после создания всех шаблонов. Ссылки за пределы экспортной
группы отвергаются до первой перезаписи. Существующие карманы не перепривязываются при обычном upsert.

В Play Mode можно снять зоны **локального** аватара. SessionState сразу хранит значения и исходный prefab;
выход из Play ничего автоматически не применяет. Применение требует отдельного плана и неизменного
исходного GUID/SHA. Снимок удаляется только после проверенного сохранения; незавершённый SHA после reload
блокирует применение, но оставляет JSON для копирования. Во время capture отбрасывание заблокировано.

## Проверки и приёмка

- Исправление задержек UI 2026-10-05: native `EditorPerformanceTracker` показал средний Repaint 1,49 с, пик 8,03 с.
  Контроль на открытом `MEF_Base_Avatar`: RED — пять вкладок превышают 100 мс; GREEN — шесть вкладок
  с раскрытыми группами SDK/обслуживания проходят. Прогретая пара Layout + Repaint занимает 11–20 мс
  вместо 1,5–9,6 с на проблемных вкладках. Первый проход после исправления — максимум 78 мс.
  Отчёты: `tmp/avatar-editor-implementation/window-perf-red.json`, `window-perf-green.json`.
  Выделение, цель, dirty-состояние пользовательской сцены и исходный prefab сохранены.
  Дополнительный plan probe **5/5**: подготовка без writer, SHA-изменение, смена цели и сброс кэша;
  повторный Android PASS (`window-plan-probe.json`, `window-perf-android.json`).
- Unity UI probe: **12/12**, включая шесть вкладок при двух ширинах, pin, read-only registry и сохранение SHA ассетов/состояния пользовательских сцен.
- Scoped writer probe: **12/12**, включая идемпотентность fingertips, сохранение калибровки, freshness pending и canonical Mirror ID; временный variant удалён.
- Каталог: **42/42**, внешний пункт меню **1**; Editor и Android compilation PASS.
- Guard probe: **4/4** — продление сохраняет свой owner/token, Native veto и чужой SDK source GUID проверены на рабочих экземплярах.
- Прогон существующих prefab тестов: **105/113**, восемь отказов: четыре ожидания прежнего LegsAnimator/bridge, одна цепочка Cyborg → PlayerBase, три проверки совместимости карманов с MagAK105/MagR08.
  Игровые prefab этой задачей не мигрировались. Эти ожидания/ассеты требуют отдельного согласованного решения; тесты не переписывались под непринятую механику.
- Дополнительный fixture — PASS: экспорт/восстановление обеих межкарманных ссылок Cyborg, создание Native rig из валидного Humanoid MEF.fbx, отсутствие replacement SDK hands, exit-code отказ и отмена процесса, сохранение SHA исходников. Отчёт: `tmp/avatar-editor-implementation/advanced-probe.json`.
  Оптимизированный MEF_Optimized.fbx служит источником геометрии для пересадки, а не автоматически готовым Humanoid для сборки рига.

Пользовательская приёмка: открыть рабочий экземпляр и SDK-позу; проверить доступность нужной команды через
каталог; на копии аватара проверить prepare/apply/cancel и позиции карманов/часов. Реальный Blender-маршрут,
SDK-риг конкретной модели, движения тела и касания UI в шлеме остаются отдельной практической приёмкой.
Коммит разрешён пользователем 2026-10-05; это разрешение не заменяет перечисленную практическую приёмку.
