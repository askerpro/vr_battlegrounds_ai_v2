# Анализ посадки кисти

## Назначение

### SDK grip preview и игровой skinning

SDK preview исправлен [патчем45](UltimateXR/sdk-patches.md#патч-45-grip-preview-использует-игровое-применение-позы-и-скиннинг-unity):
он применяет универсальные ориентации текущей Fixed/Blend позы штатным runtime методом
к целевому ригу и запекает Unity skinning. Старые матрицы исходного пака больше не участвуют.
Для MEF/AK105 основной и поддерживающий хват, обе руки и контроль Cyborg проверены
по всем вершинам; 15/15 постоянных Editor NUnit методов и Android PASS.
Это совпадение деформации той же позы; игровое wrist/controller/IK размещение и Quest отдельно.

Уже открытое grip preview пересоздаётся у Grabbable: `Preview Grip Pose Meshes` → `None`
→ нужная рука. Для будущего адаптера доступен `UxrPreviewHandGripMesh.BuildForAvatar`:
явные actual avatar/pose/side/Blend, без фактического удержания. SDK разрешение avatar GUID,
GrabPoint и snap/proxy transform остаются частью контекста. Привязка выполнена через общий frozen snapshot; камера не входит в geometry key. Новая UI-приёмка рентгена ещё открыта.

Окно Hand Pose Review открывается через `Tools/VR Battlegrounds/Avatars/Редактор аватара` → «Открыть Hand Pose Review для аватара» и снимает фактическую поверхность кисти целевого аватара и предмета. Статический вход использует временную копию после применения Fixed/Blend к целевым костям и `BakeMesh(false)`; игровой вход читает уже обновлённые SDK живые объекты. Инструмент не назначает позы и не управляет хватом; SDK preview не используется.

Основной результат — измерения по пальцам/фалангам/ладони, нормали и связность контакта, пересечения, суставы, JSON и 24 изображения. Итогового балла качества пока нет. Первая [база калибровки Cyborg/BigHands](hand-pose-fit-sdk-calibration.md) содержит 24 неоружейных случая и контрольные смещения. [Сравнение MEF с оригиналами и SDK-оружием](hand-pose-fit-mef-comparison.md) содержит 123 отчёта по основным хватам/поддержке, 33 описательные пары и галерею; нормы качества требуют проверки масок и игровых источников.

## Как запустить

1. В редакторе аватара выбрать аватар и нажать «Открыть Hand Pose Review для аватара». В открывшемся окне выбрать сохранённые префабы аватара и предмета.
2. Выбрать конкретный `UxrGrabbableObject` внутри предмета, точку, сторону. Пустой путь означает корень; для вложенных объектов API использует последовательность sibling indices.
3. Оставить штатную позу и Blend либо указать кандидат/коэффициент явно. Default-запись SDK требует явного разрешения.
4. Для первого просмотра оставить исследовательский профиль всей поверхности. Он показывает дистанции, но не подтверждает хороший контакт.
5. Для анализа рукоятки включить ладонную маску, выбрать направление нормалей и контактную область предмета. Проверить маску на снимках: серые участки исключены из расстояний; для пересечений используется вся выделенная кисть и весь видимый предмет.
6. Оставить контакт **0–2 мм включительно** или изменить обе границы. Включить подсветку точек; в дополнительных настройках доступны лимит пар и радиус маркера.
7. Запустить анализ. Кнопки результата открывают каталог или HTML-галерею.

По умолчанию результат хранится в `Temp/HandPoseFit/<уникальный каталог>/`. Это рабочие отчёты, не ассеты Unity. Сохранять результат в `Assets` запрещено.

Калибровочные материалы 2026-10-05 сохранены вне Temp: [архив и галереи](tasks/report/hand-pose-fit-quality-2026-10-05/index.html), [mapping путей, SHA256 и размеров](tasks/report/hand-pose-fit-quality-2026-10-05/archive-manifest.json). Архив содержит 195 исходных JSON, fixtures, входные данные и 48 свежих PNG BigHands/Battery и Cyborg/LaserGrip. Байты, исходные метки и metadata не изменены; исторические пути внутри JSON остаются прежними, открывать архив следует через относительные ссылки его галерей/mapping. PNG остальных прежних случаев в этот архив не включены. Независимая проверка точных копий и всех 301 ссылки прошла также без чтения Temp.

## Встроенная диагностика SDK Hand Pose Editor

В правой колонке штатного окна находится «Диагностика текущего хвата». Выбрать сценовый предмет, конкретный Grabbable, точку (основная/поддержка) и сторону. Активный Target Avatar/поза принадлежат SDK окну. При отличии от штатной позы точки панель предупреждает: анализируется текущий кандидат. Основной хват и поддержка снимаются отдельно; фиктивная вторая кисть не добавляется.

«Рентген · контакт 0–2 мм» показывает кисть из единственного SDK HandRenderer, размещённую на rigid snap выбранной точки. Читаются текущие bones, включая несохранённые вращения; transient Fixed descriptor применяется исправленным runtime preview core. Asset позы не сохраняется. Object geometry использует LOD0 и исключает SDK proxy/подсветку. Вторая кисть в этом режиме не размещается.

`HandPoseSdkPreviewSession` владеет одним frozen snapshot. Ключ входа проверяется не чаще раза в100 мс: mesh dirty revisions, bone/renderer/snap matrices, skin quality/rootBone/blendshapes, LOD membership и настройки. Камера исключена; служебная Renderer dirty revision от forceRenderingOff тоже исключена. На неизменном входе нет BakeMesh, topology, чтения mesh vertices или повторного mesh hash. При правке пальцев object geometry/hash и GPU-поле переиспользуются. «Обновить геометрию» принудительно читает mesh для стороннего кода, который изменил vertices без уведомления Unity.

GPU-поле строится порциями. Оно автоматически охватывает исходную кисть; шаг по умолчанию1 мм. При превышении8 млн voxel/512 по оси шаг увеличивается в пределах5 мм, фактический шаг/ошибка показаны. Настройки позволяют менять центр/размер и повторно центрировать. Вне поля точки помечены неоценёнными. Async readback имеет generation guard: ответ предыдущего snapshot не публикуется после A→B→A. Готовое неизменное поле не заставляет SceneView постоянно перерисовываться.

Оригинальные renderer предмета и SDK preview proxies подавляются только во время SceneView camera через forceRenderingOff; затем восстанавливаются. Аватар в другой точке сцены не скрывается. Game camera, Renderer.enabled, shared materials/property blocks, hierarchy и Undo сохраняются. Выключение/закрытие/Play/reload/удаление входного объекта освобождают свои buffers/materials/meshes/preview scene; удаление работает и после анализа без рентгена.

«Анализировать и записать отчёт» запускает полное CPU-ядро по тому же frozen snapshot. Источник `editor_sdk_grip_preview`; `EditorSnapshotHash` одинаков у overlay/export. `EditorPoseStateJson` хранит состояние asset, `EditorAppliedPoseStateJson` — transient descriptor текущих bones, `EditorObjectSnapshotHash`/`EditorContactObjectHash` — object geometry. Результат устаревает при смене входа. Выгрузка: JSON,24 стандартных PNG, текущий camera view и HTML в `UserReports/HandPoseFit/<timestamp-id>/`, вне Assets/Git. Текущий ракурс — xray frozen geometry, не screenshot всего Unity UI. GPU preview приблизительный; inside неизвестен для открытой/многокомпонентной поверхности, полный CPU report сохраняет эту неизвестность.

Проверено в native Editor: binding/cache11/11, query state11/11, invalid-input cleanup5/5, GPU30/30, математика37/37, camera ownership14/14 и Android PASS. На100 неизменных проверках read-only MEF/AK105: CaptureCount1, median1,628 мс/P951,686 мс, первый capture189 мс. Это input polling, не замер полного UI FPS. Export25PNG имеет одинаковый snapshot/report fingerprint; контактные метки0–2 мм визуально просмотрены. Стандартный NUnit runner с dirty сценой не запускался. [План и UI-приёмка](plans/2026-10-05-sdk-preview-diagnostics-binding.md).

## Ограничения пользовательского рентгена, подтверждённые 2026-10-05

Первый UI-срез имел CPU Tick443 мс, смешивал LOD и читал сценовую кисть за1,81 м от оружия. Причины устранены cache/snap binding выше; камера и временное скрытие renderer не инвалидируют geometry. Пользователь принял исправленное MEF SDK preview, но новую панель рентгена/навигацию ещё не принимал. Native fixtures используют read-only prefab bones на snap; они не подтверждают качество авторского хвата, реальный UI FPS, game IK/controller/Quest. ## Изображения и показатели

- `normal`: нейтральные поверхности кисти и предмета; видны только не закрытые геометрией контактные метки.
- `xray`: прозрачный предмет и его рёбра; видны скрытые пальцы и все выбранные контактные пары.
- `distance`: расстояние до выбранной контактной поверхности; пурпурное смешивание отмечает неизвестный знак, яркий пурпурный — касание/пересечение граней, красный — установленное нахождение внутри.
- `section`: удалена передняя половина обеих поверхностей по плоскости через центр хвата. Сечение не добавляет фиктивную закрывающую грань.

Для каждого режима сохраняются шесть ортографических направлений в осях предмета. PNG содержит сторону, точку, Blend, легенду и линейку; параметры камеры и плоскости — в JSON. Для сравнения одного объекта фиксировать одинаковую высоту и центр кадра. Числа в миллиметрах, площади в мм²; точки выбраны по площади, не по плотности вершин.

Контактная пара — точка на поверхности кисти и ближайшая точка разрешённой поверхности предмета. Маркер кисти зелёный для установленного внешнего положения, красный для установленного нахождения внутри, жёлтый при неизвестном знаке. Голубое кольцо отмечает точку предмета, короткая линия соединяет пару. Кольцо больше точки, поэтому обе метки читаются и при нулевом зазоре. Сечение оставляет только пары с обоими концами в сохранённой половине.

По умолчанию сохраняются и показываются до 300 равномерно выбранных по порядку пар из детерминированной выборки; это ограничение читаемости, не число всех контактов. `ContactCandidateCount` содержит полный счёт точек выборки в диапазоне, `ContactMarkers` — выбранные пары с координатами обоих концов в метрах, дистанцией, зоной, весом площади и `Inside`. При отключённой подсветке JSON сохраняет эти пары. Точки не являются вершинами меша и не доказывают сплошное прилегание между ними.

`P10/P50/P95` — unsigned расстояния до контактной поверхности. Близость не отличает внешнее касание от вложения. `ContactDistanceMinMm` и `ProximityMm` задают включительные границы диапазона (по умолчанию 0 и 2 мм); `NearSurfaceFraction` учитывает тот же диапазон. Для округления float допускается численная погрешность 0,0001 мм на границе. Пользователь принял 2 мм как контакт для визуализации; это не откалиброванная норма качества всего хвата. Пересечение граней включает касание и само по себе не является глубиной проникновения. Полное вложение определяется отдельно только на пригодной закрытой поверхности.

Если знак неизвестен, `ExteriorNearAreaMm2`, `PenetrationAreaMm2` и `PenetrationMaxMm` имеют `null`, а причина и число неизвестных точек остаются видимыми. Неизвестность не считается хорошим хватом.

## Вход для агента

Публичный API — `VrBattlegrounds.Editor.HandPoseReview.HandPoseFitAnalyzer.Analyze(HandPoseFitRequest)` или `RunJson(string)`. При работе через MCP соблюдать Unity lock; запуск синхронный, временная preview-сцена очищается в `finally`.

Пример JSON-запроса:

```json
{
  "AvatarPath": "Assets/ThirdParty/UltimateXR/Samples/FullScene/Prefabs/Avatars/CyborgAvatarExample.prefab",
  "ObjectPath": "Assets/ThirdParty/UltimateXR/Samples/FullScene/Prefabs/ShootingRange/Weapons/Gun.prefab",
  "GrabbableIndexPath": "",
  "GrabPoint": 0,
  "Side": 1,
  "AlignmentMode": "grip_reference",
  "RenderImages": true,
  "ImageSize": 1024,
  "SampleCount": 6000,
  "Seed": 42,
  "ContactDistanceMinMm": 0,
  "ProximityMm": 2,
  "ShowContactMarkers": true,
  "MaxContactMarkers": 300,
  "ContactMarkerRadiusPixels": 3
}
```

`Side`: 0 — Left, 1 — Right. `PoseOverridePath` передаёт сохранённого кандидата без его назначения оружию. `HandOffsetMm` позволяет исследовать временное ухудшение, например `[10,0,0]`. Это смещение не сохраняется в ассеты.

`ObjectPrefabLocalFileId` выбирает сохранённый GameObject внутри prefab-файла вместо корня. Это позволяет анализировать встроенный лабораторный инструмент без всей комнаты. Поле записывается в нормализованные настройки; `GrabbableIndexPath` и пути Renderer тогда относительны выбранному предмету. Идентификатор нужно получать через AssetDatabase, целочисленный JSON fileID нельзя округлять через JavaScript number.

## Игровой снимок и дополнительные данные (0.3)

`IncludeOtherHand` сохраняет геометрию противоположной видимой кисти. Сейчас отчёт не подтверждает через `GetGrabbingHands`, что эта кисть удерживает тот же точный экземпляр `UxrGrabbableObject`, и не записывает её grab point/held identity. Поэтому видимую кисть нельзя автоматически считать поддержкой оружия; статические пары также не доказывают игровой двухручный IK.

Пакет проверки двух удерживающих рук 2026-10-05 остановлен до Play/source edits: read-only снимок подтвердил уничтоженные managed singleton-ссылки `UxrManager`/`UxrGrabManager` и 1507 retained SDK UID-записей без живых компонентов. Штатный `UxrSingleton.Instance` проверяет managed null, а `TrySetInstance` отвергает второй экземпляр; безопасный runtime-контекст не доказан. C# и SDK не менялись, глобальные ссылки/UID не очищались, native контроли не запускались. [Фактический результат и ограничения](tasks/report/hand-pose-fit-quality-2026-10-05/execution-receipt.json). Этот NO_GO не означает дефект математической диагностики и не измеряет точность реальных хватов.

В верхнем блоке окна выбрать живой `UxrGrabber` в Play Mode, уже удерживающий предмет, и нажать «Снять игровой хват после SDK update». Захват выполняется на `UxrManager.AvatarsUpdated`, после manipulation/animation/IK SDK. Кости повторно не применяются, snap не симулируется: BakeMesh и координаты копируются до следующего кадра. Тяжёлый анализ выполняется позднее из замороженных данных. Источник `runtime_after_sdk_update`, номер кадра, игровое время, фактические имя позы/Blend и модель контроллера записаны в JSON/PNG. Эффект AlignToController уже содержится в наблюдаемой геометрии.

По умолчанию предметом является именно `GrabbedObject`. Для помпы/вложенной детали можно явно указать сценовый корень геометрии оружия: он должен содержать удерживаемый объект. При скрытой кисти, отсутствии SDK update или прекращении хвата снимок не выдаётся за успешный. На паузе новый кадр не захватывается. Выход из Play Mode/reload отменяет очередь и очищает preview-сцены.

Серия — 1–30 снимков через заданный интервал кадров. Пользователь сам выполняет действие (спуск, помпа, вторая рука); инструмент только записывает наблюдаемое состояние. Название серии и состояние задаются в окне. Поза/Blend override и смещение запрещены для живого захвата. Отчёты лежат в отдельных `frame-NNN` каталогах; этот режим не создаёт игровые команды.

Дополнительные поля:

- `Joints`: позиция каждого сустава в метрах в осях предмета и `localRotation`. Анатомические ограничения не назначаются по виду перчатки.
- `Segments`: показатели по metacarpal/proximal/intermediate/distal и ладони. Разметка по весам костей приблизительная; не считать distal автоматически точной подушечкой.
- `DistanceBinAreaMm2`: площади выборки в диапазонах [0;0,5], (0,5;1], (1;2], (2;5], >5 мм; это описательные интервалы, не нормы качества.
- `ContactMarkers`: дополнительно нормали обеих поверхностей, ближайшая грань, `NormalOppositionDot=-dot`, фаланга и имя региона. Значение +1 означает противоположные нормали; ориентацию импорта нужно проверить.
- `ContactPatches`: связность граней с контактными точками и взвешенная площадь. Это оценка по выборке, не точная сплошная граница контакта.
- `HandSelfIntersectionPairs` / `OtherHandIntersectionPairs`: касания/пересечения несоседних граней. Общие вершины исключены, соседние складки не сертифицированы. В статическом режиме другая кисть остаётся в исходной позе prefab; игровой двухручный хват из этого не следует.
- `SamplingConvergence`: изменения P50 и доли близости при удвоенной выборке; не гарантирует обнаружение каждого маленького дефекта.
- `Reliability`: по каждому показателю measured / approximate / unknown с причиной. Глобальный `analysis_incomplete` может быть корректным результатом полезных измерений.

Контактные регионы задаются в окне: имя/назначение, AABB в метрах, пути Renderer, допустимые пальцы/фаланги, ожидаемый или запрещённый контакт и подтверждение разметки. `Regions`/`Findings` отделяют близость к назначенной рукояти от случайной близости к иной детали. Пустой список допустимых зон означает все зоны. Рамки зелёные в рентгене; окончательную полезность разметки нужно подтвердить по изображениям.

Для локального знака можно указать отдельный сохранённый mesh аналитического объёма и его transform в метрах. Оранжевые рёбра показывают объём в рентгене для проверки совпадения с рукоятью. В `mesh-fit-0.4-local-volume` одного `AnalysisVolumeReviewed` недостаточно: `AnalysisVolumeReview` должен содержать явное ручное `Accepted`, непустые `ReviewId`/`Scope`, `Units=meters`, `Frame=object_root` и совпадающие `GeometrySha256`/`ContextSha256`. `LocalVolumeReviewAudit` возвращает причину отказа и непринятый `Draft`; скопировать его в запрос недостаточно без проверки объёма человеком. API `HandPoseFitVolumeReview.CreateDraft(snapshot, report)` также создаёт только черновик.

SHA геометрии записывает фактические треугольники после transform; SHA контекста включает идентичность/64-bit fileID/dependency hash предмета и объёма, масштаб, точку/сторону хвата, состояние, источник, выравнивание и TRS объёма. Топология повторно вычисляется по тем же треугольникам. Изменённая привязка, неизвестное происхождение, нечисловые координаты/масштаб или открытый объём оставляют знак неизвестным. Для математических fixtures разрешено отдельное явное допущение `synthetic_fixture_explicit_assumption` только с `CaptureSource=mathematical_fixture`; оно не является ручным принятием реального объёма.

`LocalVolumeZones` теперь измеряет unsigned-расстояние, интервалы, близость, внешний контакт и проникновение относительно **одного AnalysisVolume**. Ранее локальные P50/near брались до видимой контактной поверхности предмета, а знак/глубина — до объёма. Это знак относительно заданного объёма: он не закрывает отверстия всего оружия и не превращает неизвестный whole-object знак в известный. Граница остаётся неизвестной; исходные игровые коллайдеры не меняются. Принятие объёма рукояти/цевья и пригодность масок для игрового хвата остаются ручными.

`ReferenceReportPath` и `ReferenceAccepted` включают сравнение зон с явно принятым отчётом. Неподходящие конфигурации отклоняются. Дельты P50/доли близости не являются итоговым баллом и не переносят автоматически эталонные нормы на другую руку или другое оружие.

Сравнение учитывает источник/состояние/Blend, выравнивание/модель контроллера, масштаб по трём осям, идентичность предмета, hash, маски, объёмы и диапазон контакта. У старых статических отчётов scalar scale допустим благодаря проверке uniform scale; старый runtime без полного масштаба не считается сопоставимым. В Play Mode Unity может потерять prefab-происхождение экземпляра: тогда GUID остаётся неизвестным и идентификационное сравнение недоступно. Геометрические измерения при этом сохраняются.

## Пределы версии

Статический вход поддерживает `PositionAndRotation`, Fixed/Blend; dynamic snap shapes, переходы, полный IK и ограничения двух рук он не симулирует. `grip_reference` воспроизводит сохранённый трансформ; при `AlignToController` отчёт неполон относительно игры. `controller_reference` статического входа возвращает `unsupported_context`. Игровой вход наблюдает результат SDK, включая фактически применённые выравнивание/IK/динамический snap, но не доказывает правильность модели или полезность хвата в шлеме.

Ладонная маска и зоны по костям приблизительные и требуют просмотра на новом риге. `palm_wrist` включает граничные грани запястья. Наличие активного слоя не доказывает, что он является наружной контактной поверхностью; дополнительные слои нужно рассматривать отдельно. Статический снимок использует LOD0, игровой — enabled Renderer; выбор LOD камерой остаётся отдельным ограничением. Контактная AABB отбирает целые треугольники по центру; она не обрезает треугольник по границе области.

Проверка топологии объединяет точно совпадающие позиции и анализирует края/ориентацию/невырожденность и самопересечения не соседних граней. Она консервативна на швах; пары с общей вершиной требуют отдельной расширенной проверки. Это не сертификация корректности импортированного объёма.

Новый игровой хват принимается пользователем отдельно; этот инструмент не меняет контракты тестов извлечения исходных поз.
