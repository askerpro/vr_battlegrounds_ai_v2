# Анализ рига кисти (Hand Rig Quality)

## Назначение

Editor-инструмент проверяет **саму кисть аватара** — скелет пальцев и скиннинг — против
положительных эталонов SDK UltimateXR: Cyborg и BigHands. Предметы, хваты и контакт с рукоятью
он не оценивает; для посадки кисти на предмет есть [анализ посадки кисти](hand-pose-fit-tool.md).
Коротко: Hand Rig Quality отвечает на вопрос «правильно ли устроена кисть», Hand Pose Fit — «правильно ли
она держит предмет».

Анализатор работает только со временными копиями в preview-сцене: игровые MonoBehaviour, сеть, IK и Play
не запускаются, префабы, позы и импортёр не меняются. Результат — статический срез одной позы.
Он не заменяет проверку в Play и в шлеме.

Инструмент появился в задаче hand-rig-quality и показал непропорциональные фаланги MEF; после этого
кисть MEF заменили пересадкой кисти Cyborg. Итог исследования — в [hand-rig-quality-mef-research.md](hand-rig-quality-mef-research.md).

## Когда использовать

- Новый аватар с собственной кистью: до записи поз и хватов, чтобы вовремя увидеть неверные длины
  фаланг, толстую перчатку или смещённые суставы.
- Пересадка кисти (как `MEF_cyborg_hands`): подтвердить, что пересаженная кисть совпадает с донором.
- Правка весов или костей кисти в Blender: сравнить отчёты до и после.

Для готовых аватаров на кисти SDK повторный прогон нужен только после изменения рига или меша кисти.

## Требования к префабу

- Корень содержит `UxrAvatar` с полной разметкой кисти: запястье и все пять пальцев.
- `RigInfo` и универсальные оси сохранены текущей версией SDK. Устаревший `RigInfo` анализатор отклоняет
  (`unsupported_context`), чтобы getter SDK не переписал persistent asset. Аватар нужно собрать
  штатным сборщиком: [редактор аватара](avatar-editor-workbench.md#кисти-и-подготовка) или скилл `/setup-avatar`.
- `UxrStandardAvatarController` с итоговым `_bodyIKSettings._eyesBaseHeight` больше нуля. Рост нормализуется
  как «высота глаз игрока / `_eyesBaseHeight`». У MEF и `MEF_cyborg_hands_Player` это принятое значение
  1,7202504 (визуальные глаза), а не высота костей глаз: они расположены на уровне носа.
- Масштаб корня одинаковый по осям и положительный.
- На LOD0 есть включённый `SkinnedMeshRenderer`, скинованный на кости кисти. Видимость определяется
  по `activeSelf` всей ветки prefab; рендереры только старших LOD исключаются.
- Предплечье в разметке желательно: без него манжета (M7) недоступна, остальной захват работает.
- Эталон для балла — точный канонический `CyborgAvatar_URP` из SDK. Его prefab variant или копия
  не считаются эквивалентом, и калибровка их отвергнет.

## Запуск через окно

Меню: `Tools/VR Battlegrounds/Avatars/Hand Rig Quality`. По умолчанию цель — `MEF_cyborg_hands_Player`,
эталон — `CyborgAvatar_URP`. Кнопки недоступны во время Play, компиляции и импорта.

1. Выбрать исследуемый prefab, сторону кисти и рост до глаз (по умолчанию 1,72 м).
2. Оставить «Общая поза SDK Default», Blend = 0 и рамку запястья (переключатель «Рамка датчика S» выключен).
   Только в этом режиме применима калибровка. Общая поза — descriptor Cyborg `Default`, применённый
   к обеим кистям через оси каждого рига; длины и положения костей сохраняются.
3. Нажать «Откалибровать на Cyborg и BigHands». Измеряются оба SDK-префаба, обе стороны, путь к
   `sdk-calibration.json` подставляется в поле «JSON калибровки». Калибровку повторяют при смене роста,
   версии алгоритма, SDK-префабов или позы `Default`.
4. Нажать «Измерить и сохранить пакет». В окне появятся статус, балл и список метрик; кнопка
   «Открыть папку отчёта» ведёт к `index.html` и PNG.

Дополнительно: собственные позы Rest/Fixed/Blend (при выключенной общей позе), авторская рамка датчика S
по пути Transform и параметры цилиндра манжеты. Эти режимы дают raw-числа, но не балл.

## Запуск через API

Сборка `VrBattlegrounds.HandRigQuality.Editor`, пространство имён `VrBattlegrounds.Editor.HandRigQuality`.

```csharp
using UltimateXR.Core;
using VrBattlegrounds.Editor.HandRigQuality;

var calibration = HandRigQualityCalibration.CalibrateSdk(1.72f);
// calibration.Status == "calibrated_static_sdk"; путь к файлу — calibration.Path
var report = HandRigQualityAnalyzer.Analyze(new HandRigQualityRequest {
    AvatarPath = "Assets/Prefabs/Player/Avatars/CyborgHands/MEF/MEF_cyborg_hands_Player.prefab",
    ReferenceAvatarPath = HandRigQualityCalibration.Cyborg,
    Side = UxrHandSide.Right,
    EyeHeightMeters = 1.72f,
    CalibrationPath = calibration.Path
});
```

Значения запроса по умолчанию: `CommonSdkPose = true`, `Blend = 0`, `Frame = "wrist"`, `RenderImages = true`.
Константы `HandRigQualityCalibration.Cyborg`, `BigHands` и `CommonPose` указывают на SDK-префабы и позу
`Assets/ThirdParty/UltimateXR/Runtime/Art/Avatars/Cyborg/HandPoses/Default.asset`.
Агенты запускают Unity только через штатный worker брокера.

Статус отчёта и статус калибровки читаются отдельно:

| Поле | Значения |
|---|---|
| `Status` | `measured_static` — захват завершён; `invalid_configuration`, `unsupported_context`, `analysis_incomplete` — отказ с текстом в `Error` |
| `CalibrationStatus` | `calibrated_static_sdk` — балл посчитан; `not_calibrated` — путь не задан; `no_covered_metrics` — нет покрытых метрик; `invalid_calibration: …` — калибровка несовместима, raw-измерения сохранены |

## Метрики и шкала

Алгоритм `hand-rig-static-0.5`. Неприменимая метрика получает статус и причину, а не ноль.
`unreviewed` означает, что число получено, но способ измерения не подтверждён; такие значения в балл не входят.

| ID | Что измеряется | Статус в 0.5 | В балле |
|---|---|---|---|
| M1 | Положение запястья относительно эталона | В рамке запястья `unavailable` по определению; есть только в рамке S | Нет |
| M2 | Рамка ладони по PCA поверхности против эталона | `unreviewed`: сопоставимость зон ладони не подтверждена | Нет |
| M3 | Оси SDK против PCA ладони | `unreviewed`: SDK-диапазон оказался нечувствительным (около 100°) | Нет |
| M4 | Смещение сустава от центра сечения пальца / эквивалентный радиус | `measured` при единственном замкнутом контуре пальца, иначе `unavailable` | Да |
| M5 | Положение перехода веса дочерней кости через 0,5 | Найденное значение `unreviewed` (поиск ±10 мм, шаг 1 мм) | Нет |
| M6 | Глубина MCP под дорсальной стороной | Только при явно выбранной позе Fist, `unreviewed` | Нет |
| M7 | Утечка веса кисти на манжету | `unreviewed`; `measured` только с флагом «Область проверена». Без предплечья `unavailable` | Нет: калибровка не строит для M7 диапазон |
| M8, M11, M14 | Кручение, жёсткость ладони, паразитный twist | `unavailable`: нужен динамический прогон запястья | Нет |
| M9 | Излишек толщины: разность эквивалентных радиусов сечений | `measured` там же, где M4 | Да, штраф только за положительный излишек |
| M10 | Длины сегментов пальцев и запястье → MCP среднего | `measured`; у distal нет следующего сустава — `unavailable` | Да |
| M12 | Зазор до рукояти | `unavailable`: это задача Hand Pose Fit | Нет |
| M13 | Энергия разности весов на рёбрах | Raw-число по каждому рендереру; зависит от сетки и LOD | Нет |

Калибровка строит диапазон для каждой стороны, метрики и сустава:
`goodLimit = max(начальный допуск, 1,25 × максимальное отклонение SDK)`, `badLimit = 3 × goodLimit`.
До `goodLimit` — 100, дальше линейно до 0 на `badLimit`. Начальные допуски: M4 — 0,15; M9 — 2 мм;
M10 — 3 %; для M1/M2/M3/M5/M7 они тоже заданы, но в действующей wrist-калибровке эти метрики не оцениваются.
`StaticScore` — среднее по семействам M4/M9/M10, чтобы многочисленные суставы одного семейства
не вытесняли остальные. `ScoredMetrics` и `CriterionScores` показывают покрытие.

Шкала обучена на двух положительных примерах. Где Cyborg и BigHands сильно различаются,
диапазон получается широким: для пястных и длины запястье → MCP среднего (`goodLimit` около 56 %)
большое отклонение всё ещё даёт 100. Это не доказательство допустимости произвольной геометрии.

## Артефакты

Каждый прогон пишет отдельную папку `Docs/tasks/report/hand-rig-quality/<UTC-время>-<6 hex>/` в том
checkout, где работает Unity (для агентов — worker). Папка `Docs/tasks/report/` в `.gitignore`;
явный `OutputDirectory` вне этого корня отклоняется.

| Файл | Содержимое |
|---|---|
| `report.json` | Запрос, идентичность ассетов (GUID, fileID, dependency hash), скелеты, метрики, балл, ограничения |
| `geometry-target.json`, `geometry-reference.json` | Полные вершины, нормали, submesh, все влияния костей и пути костей |
| `front.png`, `back.png`, `side.png`, `top.png` | Ортографические каркасные виды в рамке запястья |
| `index.html` | Статус, балл, PNG, таблица всех метрик с причинами и пределы проверки |

Пакет калибровки содержит `sdk-calibration.json` и полные SDK-прогоны в подпапках
`CyborgAvatar_URP-Left` и т. д. `CalibrationPath` в отчёте — абсолютный путь в checkout,
где выполнялась калибровка.

На PNG оранжевая сетка — цель, голубая — эталон. Кости и суставы: салатовые — цель, пурпурные — эталон.
Белое кольцо — запястье, оси по 25 мм (X красная, Y зелёная, Z синяя), розовые отрезки — смещения
соответствующих суставов. Это диагностическая проекция, а не снимок игрового освещения. Сечения и
маски весов на изображениях не показаны.

## Как читать результат

Пример — последний полный прогон 0.5 (2026-10-07), до замены кисти MEF:

| Кисть | StaticScore | M4 | M9 | M10 | Оценено значений |
|---|---:|---:|---:|---:|---:|
| SDK Cyborg, BigHands (обе стороны) | 100 | 100 | 100 | 100 | 31–32 |
| MEF, левая / правая | 75,77 / 75,87 | 100 (6 суставов) | ≈ 46 | ≈ 81 | 23 |

Балл 75,8 не означает «кисть почти хорошая». Raw-значения MEF:

- M10: проксимальная фаланга большого пальца длиннее эталона на 25,8 %, промежуточная указательного —
  на 13,8 %, промежуточная безымянного — на 9 %, у мизинца фаланги короче на 6–8 %. Отклонения разного
  знака и величины: кисть непропорциональна, равномерный масштаб её не исправит.
- M10 запястье → MCP среднего: +26,7 %, но SDK-диапазон для этой длины широкий, поэтому балл 100.
- M9: перчатка толще эталона на 2,2–5,9 мм во всех шести измеренных сечениях.
- M4/M9 измерены только для 6 из 15 суставов: остальные сечения неоднозначны. Семейство M4 = 100 говорит
  лишь об этих шести суставах.
- M2/M3/M5/M7 видны в отчёте как `unreviewed`; это справочные числа.

Правило чтения: сначала покрытие (`ScoredMetrics`, `CriterionScores`, число `unavailable`), затем
raw-значения и их диапазоны в `sdk-calibration.json`, и только потом итог. Среднее семейства может
оставаться высоким при одном плохом суставе. Высокий балл при малом покрытии не означает приёмку кисти.

## Ограничения

- Только статика одной позы в Editor. Игровой IK, калибровка роста на сервере, трекинг контроллера
  и Quest не проверяются. Динамические M8/M11/M14 не реализованы: программы запястья для стенда нет.
- Балл покрывает только M4/M9/M10. PCA ладони (M2/M3), переход весов (M5), манжета (M7) и M13 —
  неподтверждённые оценки.
- M9 — разность эквивалентных радиусов `sqrt(A/π)` сечений, а не точная толщина перчатки над кожей.
- Сечение принимается, если у кандидата не меньше 80 % периметра с весом цепи своего пальца не ниже 0,1
  и подходящий контур единственный. У MEF 9 из 15 сечений, включая все MCP, отвергнуты как неоднозначные
  или вырожденные.
- Калибровка привязана к GUID и dependency hash SDK-префабов и позы `Default`, к версии алгоритма,
  росту, рамке запястья и Blend = 0. Калибровки версий 0.1–0.4 несовместимы с 0.5.
- M6 доступна лишь при выключенной общей позе и выбранной позе Fist; тогда калибровка неприменима.
- Постоянных тестов принятого поведения (`HandRigQualityTests`) нет. Диагностические проверки
  математики и захвата — `Assets/Editor/VR_Battlegrounds/Avatars/HandPoseReview/Tests/HandRigQualityDiagnosticTests.cs`.

## Устройство

- `Assets/Editor/VR_Battlegrounds/Avatars/HandRigQuality/`: окно, запрос/отчёт, временный захват,
  математика сечений и весов, калибровка, PNG/HTML.
- Общий слой геометрии `VrBattlegrounds.HandGeometry.Editor`
  (`Assets/Editor/VR_Battlegrounds/Avatars/HandPoseReview/Core/`, пространство имён
  `VrBattlegrounds.Editor.HandGeometry`): `HandFrame`, `HandAssetIdentity`, `HandMeshSample`, `HandMeshCapture`.
  Его же использует Hand Pose Fit; от анализаторов слой не зависит.
- Захват: `BakeMesh(true)` с полной матрицей `localToWorld`, scale renderer учитывается один раз,
  действующие blend shapes включены. Координаты ранее сверены с независимым LBS по bindposes (расхождение
  меньше 0,001 мм).

## Перед первым использованием на новом аватаре

1. Обновить рабочую ветку на свежий `origin/dev`; через worker выполнить новую калибровку
   (`CalibrateSdk`) с тем ростом, который будет использоваться.
2. Контрольный прогон: SDK Cyborg и BigHands против Cyborg должны дать 100 на обеих сторонах; иначе это
   регрессия инструмента или SDK, и сначала её разбирают. Затем снять `MEF_cyborg_hands_Player` как базу
   для сравнения. Ожидаемый результат для него не установлен: кисть та же, что у Cyborg, но нормализация
   по `_eyesBaseHeight` (1,72 против 1,84 у Cyborg) может дать отличие масштаба около 7 %.
3. Проверить, что пути из кода и примеров существуют: `HandRigQualityCalibration.Cyborg`, `BigHands`,
   `CommonPose`, цель окна по умолчанию. Устаревший путь исправить отдельным этапом.
4. Решить вопрос экспорта: перевести `OutputDirectory` в `tasks/<task-id>/reports/` отдельным этапом или
   явно сохранять пакеты из `Docs/tasks/report/hand-rig-quality/` в материалы задачи.
5. Убедиться, что новый аватар собран штатным сборщиком (свежий `RigInfo`) и имеет принятое `_eyesBaseHeight`.
6. Прогнать обе кисти и смотреть raw-значения M10/M9/M4 и покрытие, а не только итог.
