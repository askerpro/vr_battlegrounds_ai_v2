### Левел-дизайн: от замысла к проверке

Карту оценивают по опыту и эмоциям игроков. Разнообразие, асимметрия, обзор и темп —
элементы замысла; единственного главного принципа и общего рейтинга качества нет.
Технические проверки помогают находить дефекты и измерять выбранные свойства.

| Цель | Мы здесь | Осталось выполнить | Технические подробности |
|---|---|---|---|
| Согласованные требования и единый порядок проверки | LD-01…55; метрики упорядочены P0/P1/P2, полнота явно указана | Калибровать диапазоны по любимым картам и плейтестам | [Требования](level-design-principles.md), [реестр метрик](map-evaluation.md) |
| Сборка на реальной арене | Связанный Environment, проверенные коллайдеры; предложения неперешагиваемого Tall без сравнения высоты столба, материал выбирается отдельно | Назначение ручной сборки защитой без автозамены; мастер создания карты | [Геометрия](level-design.md), [арена](physical-arena.md), [T-31](../tasks/T-31-maps-inherit-physical-arena.md) |
| Строительство на сетке | Шесть форм с Low/Mid/Tall, превью и отдельным редактированием; поворот целой геометрии 15°, затронутые клетки вычисляются отдельно | Пользовательская проверка обновлённой палитры; перенос старых зависимостей и уточнение разметки позиций | [Сетка](blockout-grid.md), [Scene painter](blockout-editor.md) |
| Одна оценка для ручной карты и генератора | MapEvaluation, D/C, объявленные P→Q и пути | Адаптер разметки, ограничения нарисованных коридоров, поиск всех контактов | [Метрики](map-evaluation.md), [формат входа](position-impact-mvp.md) |
| Получение 5–10 вариантов | Контракт: ручные позиции → связи/контакты → обязательная геометрия → выращивание; блок не равен позиции | Реализовать ввод описания пары, поиск и отбор через общий оценщик | [Выращиватель](map-growth.md) |
| Калибровка на любимых картах | TestMap1 — ручной ориентир; ReferenceMap04 — частичная реконструкция | Подтвердить перенос, разметить контакты, пересчитать измерения | [TestMap1](maps/testmap1-review.md), [карта 04](maps/reference-map-04.md) |
| Довести ServiceYard 4×4 | Паспорт, блокаут и JSON существуют | Актуальный аудит, композиция, плейтест, арт-пасс | [Паспорт](maps/service-yard.md) |
| Арена в мрачном автоматизированном цеху-кузнице | Приняты визуальные ориентиры; подготовлен план декораций с существующими и внешними ассетами | Отобрать модели, собрать художественный стенд, проверить Quest; затем паспорт и блокаут карты | [Концепция](maps/automated-assembly-hall.md), [план и ассеты](maps/automated-assembly-hall-decoration-plan.md) |
| Добавлять обратную связь без расходящихся критериев | Общий контракт развития метрик описан | Закреплять подтверждённые изменения сопутствующими тестами | [Развитие правил](map-rule-development.md) |

Статусы метрик читаются одинаково: **есть / частично / можно автоматизировать / ручная оценка**.
Приоритет — порядок технического ревью, не иерархия ценности карты.
Статус реализации проверки и результат конкретной карты разделены.

Принятые выводы аудита включены в тематические документы; отменённые предложения
не образуют дополнительные обязательные этапы. Результаты конкретной версии —
в паспорте карты, история изменений — отдельно.
