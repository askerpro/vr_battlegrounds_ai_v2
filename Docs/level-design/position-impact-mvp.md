# Разметка позиций: формат данных и ограничения измерителя

Это справочник исходного PositionImpactLayout JSON и его вычислительного ядра.
Основной маршрут: [обзор](README.md#левел-дизайн-от-замысла-к-проверке),
[требования](level-design-principles.md), [процесс](level-design-workflow.md),
[геометрия](level-design.md), [общая оценка](map-evaluation.md).
Генератор, автоматическое выделение всех позиций и вероятность побед не реализованы.

## Разметка и запуск

Исходная разметка — JSON вне Assets, например [position-impact-example.json](maps/position-impact-example.json). Это пример трёх областей и двух путей ServiceYard, **не проверенная полная разметка этой сцены**. Координаты и доступность нужно проверить после текущих правок геометрии. Образцы тела и веса демонстрационные, а не измеренный аватар.

Позиция содержит уникальный `id`, прямоугольник `min/max` в мировом XZ и массив явных `states`. В Vector2 поле `y` означает мировой Z. Состояние содержит центр тела, `yaw` в градусах, локальные `eyeOffset`, `muzzleOffset`, взвешенные образцы `body`. Высоты отсчитываются над полом сетки. Нулевой yaw смотрит вдоль +Z; поворот +90 — вдоль +X. Образцы тела/глаза/ствола поворачиваются вокруг центра.

Все позы (стоя, присев, выглядывание) размечаются отдельно. Анализатор не создаёт бесплатного выглядывания из стены и не выбирает лучший возможный угол автоматически. `radius` — радиус проверяемого горизонтального диска, `speed` — постоянная скорость, **параметры профиля**, не утверждённые пороги качества.

Необязательное поле позиции `protectedState` задаёт ID её явной закрытой позы. Тогда для каждой атаки сравнивается поражаемость текущей и закрытой позы от **того же состояния противника**. Без этого поля цена изменения открытости не считается автоматически.

Маршрут задаёт `from/to`, точные ID `fromState/toState` и при необходимости `via` — порталы. Dijkstra соединяет их проходимыми центрами клеток с clearance ≥ radius и не срезает углы по диагонали. `via` определяет вариант пути, но не доказывает независимость подходов. Разные направления маршрута задаются отдельно. Во время движения используется тело исходного состояния, повёрнутое по пути; переходы между позами не моделируются.

Разметка v2 во вкладке «Позиции» передаёт `allowedCellIndices` и `requireDirect` через
общий адаптер. `null` сохраняет прежний путь по всей сетке; пустая маска не разрешает
выход за коридор. Новый путь включает реальные концы/порталы и проверяет проход диска
на присоединениях и рёбрах. Direct проверяет прямой сегмент, включая истинный зазор
до квадратных клеток и границы сетки. Разные шаги авторской/аналитической сетки
допустимы, но аналитическая клетка должна целиком находиться в коридоре.
`inputFingerprint` связывает результат с числовым входом/сеткой/профилем/сценой;
потребитель отчёта замысла отклоняет старые данные. Живую Physics отпечаток не замораживает.

Запуск и выбор JSON описаны в [общей оценке](map-evaluation.md#запуск-и-совместимость).
Имя `map` совпадает со сценой; агент использует общий Unity-замок. Отчёт не меняет геометрию.

Результаты: `Temp/LevelDesign/<scene>_position-impact.json`, `.txt`, `_input.json`. Входной снимок нужен для воспроизведения профиля, но не является полным снимком геометрии. Физическая сцена должна оставаться открытой во время лучевых расчётов. Общий результат содержит пары/маршруты в поле `contacts`; прежний PositionImpactResult вложен в него. Формат экспорта и статусы — в [общей оценке](map-evaluation.md#запуск-и-совместимость).

Поле `profile`: 1 Open, 2 Closed, 0 Unspecified. Оно должно совпадать с заявленным паспортом.
Наличие поля не подтверждает соответствие геометрии; D/C и ревью описаны в общей оценке.

## Что означают значения

| Поле | Значение |
|---|---|
| `visibleShare` | Взвешенная доля образцов цели, видимых из глаз источника |
| `shotShare` | Доля образцов, доступных ShotLine из ствола источника |
| `visibleShotShare` | Доступная траектория ствола одновременно проходит LineOfSight |
| `hiddenShotShare` | Доступная траектория ствола не проходит LineOfSight; остаток shotShare |
| `sourceExposure` | Обратная поражаемость источника со стороны **того же выбранного состояния цели** |
| `sourceBaselineExposure/openingExposureDelta` | Поражаемость явной закрытой позы и разница с текущей. Действительны только при `hasProtectedBaseline=true`; отрицательная разница означает снижение открытости |
| `targetProtection` | 1 − shotShare для этой пары, а не универсальная защищённость позиции |
| `length/duration` маршрута | Длина между центрами клеток, делённая на заданную скорость |
| `minimumClearance` | Минимальный clearance центров клеток пути; не точный 3D габарит коридора |
| `shotLength/shotDuration` влияния | Длина/время рёбер, в середине которых поражаем хотя бы один образец движущегося тела |
| `longestShotLength` | Самая длинная непрерывная такая последовательность рёбер |
| `firstVisibleDistance/firstShotDistance` | Начало первого найденного ребра; −1 означает отсутствие воздействия |

`hiddenShotShare` не является историей пробитий и не гарантирует, что цель не видна глазами: глаза и ствол расположены отдельно. Существующий boolean ShotLine не возвращает список материалов; поэтому код не называет `visibleShotShare` гарантированным «огнём без пробития». В реальной сцене ShotLine учитывает текущие правила толщины/количества Soft; в искусственной сетке Soft пропускается по упрощённому правилу MapGrid.

На каждый маршрут и **каждое фиксированное состояние** стрелка выдаётся отдельный профиль. Выгодные участки разных состояний не объединяются. Все доли — геометрия выбранной выборки, не точность попадания/урон/фактическое подавление. Суммарные длины считаются по длине сегмента, а не числу клеток.

## Проверки и ограничения

Валидируются данные, уникальные ID, конечность координат/весов, границы области для центра состояния, размер диска и ссылки маршрутов. Максимум 32 позиции, 64 состояния суммарно, 16 образцов тела на состояние, 32 маршрута и 16 промежуточных порталов на маршрут. Бюджет влияния — 50000 рёбер по всем сочетаниям; при превышении `complete=false`, отсутствующие строки не подменяются нулями.

`complete=true` означает завершение запрошенных вычислений, а не принятую карту. Недоступные пути сохраняются с `reachable=false` и объяснением. Счётчики показывают доступные клетки в областях, пересечения и неразмеченные клетки. Неразмеченные клетки пока не считаются автоматически маршрутами; полного покрытия карты или обнаружения новых сильных удержаний этот срез не доказывает.

Диск не проверяет полный объём тела/оружия, физическую цену выглядывания или фактическую возможность расположить ствол вне коллайдера. Состояния дизайнер обязан проверить вручную. Несколько образцов не доказывают, что все части тела скрыты. Точный габарит оружия, цена приседа, скорость поворота, телеметрия и динамические двери — следующий этап. Сетка рассчитана на плоскую арену, результаты имеют точность её шага и выборки середины ребра.

## Независимая проверка без Unity

`dotnet run --project Tools/LevelDesign/PositionImpactHarness/PositionImpactHarness.csproj`

Харнесс компилирует реальные исходники MapGrid/MapAnalyzer и измерителя против локальных DLL Unity 6000.4.1f1, вызывает NUnit-тесты через reflection и проверяет ненулевое число тестов. Путь установки меняется параметром `-p:UnityManaged=...`. Нужны ранее собранная `Library/ScriptAssemblies/VrBattlegrounds.dll` и установленный NUnit-пакет проекта. Editor-экспортёр компилируется, но его меню/JsonUtility/реальная физика в этом процессе не вызываются.

## Связь с клеточным редактором

[BlockoutMarkup](blockout-editor.md) сохраняет клеточные области, многократные memberships,
кандидатов позиций и связи укрытий. Это не тот же JSON, что PositionImpactLayout.
Адаптер явных поз/пар и allowed-corridor mask для Dijkstra пока не реализованы.
Порталы via не гарантируют движение только внутри нарисованного маршрута.

Потенциальные контакты всей карты и влияние новых групп требуют повторной оценки,
включая позиции в одной геометрической половине. Автоматическое обнаружение таких пар
не реализовано. Проект интеграции — [выращивание карты](map-growth.md).

Проверки ядра покрывают направленные глаза/ствол, Hard/Soft, веса, достижимость,
порталы, воздействие и неполный результат при лимите. Они не подтверждают текущую
сцену и её баланс. Постоянные тесты новой геометрии/поведения меняются после
подтверждения пользователем согласно AGENTS.md.
