# План механического ремонта тестов

> Исполнение: независимые области через superpowers:dispatching-parallel-agents, итоговая проверка основным агентом. План конкретизирует уже порученное пользователем исправление.

**Цель:** устранить подтверждённые дефекты харнесса и обработки бинарных ассетов, не менять игровую механику ради старых проверок.

**Архитектура:** каталог оружия остаётся каталогом; ассортимент выбирает MapData.arsenalPreset. Тесты должны использовать владельца проверяемого контракта. Бинарные Unity-ассеты должны проходить Git без преобразования байтов. Изменения аватаров и оружия не входят в ремонт ожиданий.

**Стек:** Unity 6, NUnit EditMode, Git, Python для проверки Git-атрибутов.

**Основание:** пользовательское поручение и Docs/tasks/report/red-tests-2026-10-07/report.md.

## Ограничения

- Основной checkout подтверждён; worker и состояние брокера не изменять.
- Коммит не делать до человеческой проверки Unity.
- Тесты ремонтировать в пределах подтверждённых структурных контрактов; баланс и новые механики не придумывать.
- Не заменять отсутствующие кейсы молчаливым успехом, не подавлять неожиданные Unity errors.
- Перед run_tests проверить отсутствие dirty пользовательских сцен и Play Mode.

## Области и проверки

1. **Git и бинарные ассеты, основной агент.** .gitattributes и отдельная проверка репозитория: обнаружить бинарные .asset, подтвердить text unset/eol/filter и неизменность smudge. На исходном состоянии воспроизвести повреждение через Git без записи worker; после правки та же проверка должна пройти.
2. **Арсенал и геометрический харнесс, основной агент.** ArsenalMapGeometryTests, ArsenalWallCoversRegistryTests, GameModeWiringTests: Lobby ожидает две станции; стены проверяются относительно пресета; спавн проверяется отдельно против каждой станции, с контрольным кейсом свободного пространства между станциями. Пересечение TestMap1 расследовать отдельно и править лишь подтверждённую мелкую настройку, не увеличивать допуск.
3. **Оружейные проверки, отдельный агент.** HandsPackWeaponTests, KinemationWeaponTests, WeaponScaleTests, HitsToKillTests, WeaponBalanceTests и узкий общий helper при необходимости. Сопоставить старые ожидания с документированными принятыми изменениями. Не выдумывать отсутствующие роли CS2 или числа HTK. Сохранить строгие проверки исходных данных и явное покрытие выбранного игрового пресета.
4. **Аватары, отдельный агент.** LegsGroundingTests, AvatarLoadoutTests, PrefabCompositionTests, AvatarHandPoseChainTests: устранить некорректные источники кейсов и устаревшее требование отсутствующей legacy системы. Не возвращать SDK-компоненты и не мигрировать префабы; отдельно перечислить действительные нарушения карманов и наследования.
5. **Интеграция.** Основной агент проверяет diff, запускает профильные NUnit-проверки, затем доступный полный EditMode и AndroidCompileGate. Новые неожиданные отказы расследуются; оставшиеся реальные дефекты отделяются от отремонтированных проверок. Свежий агент проводит итоговое ревью без доступа к Unity.

## Риски для ревью

- Диагностические копии не должны скрывать отсутствие баланса реально выбранного игрового оружия.
- Кейс без подходящих аватаров должен быть явным результатом NUnit, а не Invalid или молчаливым PASS.
- Bounds нескольких станций не должны превращать проход между ними в препятствие.
- Бинарный header и содержимое не должны меняться при новом checkout.
- Проверки не сохраняют пользовательские сцены и не меняют авторские позы.
