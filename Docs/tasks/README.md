## Правила для агента, который берёт задачу

1. **Проверь, что задача разблокирована** — в колонке «Блокирована» таблицы ниже все
   перечисленные задачи должны быть `✅ готово`. Если нет — не брать, взять другую.
2. **Читай только свой файл задачи** и то, на что он ссылается. Весь аудит читать не нужно.
3. **Не выходи за границы задачи.** В каждом файле есть раздел «Границы» — там написано,
   что трогать нельзя. Соседние баги в том же файле — чужие задачи.
4. **Не коммить.** Жёсткое правило проекта: пользователь сначала проверяет в Unity.
   Исключение — задачи, меняющие только документацию (помечены `только доки`).
5. **Проверь на своём уровне.** У каждой задачи указан уровень из [`../testing.md`](../testing.md).
   Если уровень требует Unity — сформулируй, что пользователю проверить руками.
6. **Обнови статус** в таблице ниже и допиши строку в [`../CHANGELOG.md`](../CHANGELOG.md).

Статусы: `⬜ не начата` · `🔧 в работе` · `✅ готово` · `⏸ отложена`

## Как выполнять: один агент или субагенты в воркри

**Решение: последовательно, один агент. Отдельные worktree — нет.**

Причины, по убыванию веса:

1. **Unity Library.** Каждый worktree требует своего `Library/` — полный реимпорт
   1383 сторонних скриптов, FBX-аватаров и текстур. Десятки минут и гигабайты на копию.
2. **Один редактор — один MCP.** Unity MCP цепляется к одному экземпляру редактора.
   Параллельные агенты не смогут проверить свою работу, а сетевой код без запуска
   не проверяется никак.
3. **Пользователь — узкое место.** Правило проекта: проверка в Unity до коммита.
   Пользователь один. Параллельные ветки просто выстроятся в очередь на его проверку,
   и выигрыш от параллелизма съест ожидание.
4. **T-05 конфликтует со всем.** Переделка логгера трогает ~200 мест почти во всех файлах.
   Любая параллельная ветка с ней конфликтует, а идёт она второй по очереди.
5. **Ядро линейно по существу.** T-11 → T-12 → T-13 — это одна и та же зона кода,
   разрезать её на параллельные ветки нельзя без переделки одного и того же дважды.

**Где параллель оправдана.** Только [T-23](T-23-decision-lag-compensation.md)
и [T-24](T-24-decision-projectile-simulation.md) — исследовательские задачи, производящие
документ, а не код. Их можно отдать субагентам параллельно с любой другой работой:
они ничего не блокируют, ни от чего не зависят и не трогают код.

Волна 0 формально параллелится, но это пять правок на час суммарно — накладные расходы
на координацию больше выигрыша.

```
         T-15 T-19      (←T-13)

В любой момент: T-20  T-21  T-22  T-23  T-24
```
