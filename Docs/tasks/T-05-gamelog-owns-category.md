## Зачем это первым

Сейчас каждая строчка лога выглядит так:

```csharp
GameLog.Info(GameSettings.Instance.LogLevelMatch, "...");
```

Категорию передаёт вызывающая сторона, поэтому **каждая из ~200 строк тащит зависимость
от синглтона-ассета**. Именно из-за этого `SetManager` и `RoundManager`, при всей их
чистоте, нельзя запустить в EditMode-тесте: первый же лог обратится к `GameSettings.Instance`,
которого в тесте нет.

Одно решение о форме API логгера блокирует весь первый уровень тестирования.

## Что делать

### 1. Категория переезжает внутрь логгера

Целевая форма вызова:

```csharp
GameLog.Match.Info("...");
GameLog.Network.Warning("...");
GameLog.Player.Verbose("...", this);
```

Конкретную реализацию выбирает исполнитель — подойдёт вложенный класс-обёртка или
статические свойства, возвращающие структуру с методами. Требования:

- вызывающая сторона не упоминает `GameSettings`;
- сигнатура с `UnityEngine.Object context` сохраняется (используется в `PlayerController`);
- уровни `Verbose` / `Info` / `Warning` / `Error` остаются как есть.

### 2. `GameSettings.Instance` не падает без ассета

В `Assets/Scripts/Core/GameSettings.cs` — если `Resources.Load` вернул `null`, отдавать
созданный на лету экземпляр со значениями по умолчанию вместо `null`. Это то, что
позволяет логам работать в тесте.

### 3. Заодно — BUILD-02

Перевести на `GameLog` ~25 прямых `Debug.Log*` в девяти файлах: `GameNetworkDiscovery`,
`PlayerHUDManager`, `MenuController`, `LocalMenuManager`, `MenuSessionSetup`, `TeamRegistry`,
`AvatarRegistry`, `WeaponRegistry`, `LocalClientProfile`.

Законное исключение — сам `GameLog.cs`. Точки загрузки реестров из `Resources` после шага 2
уже безопасны, поэтому их тоже переводить.

## Границы

Механическая замена формы вызова. **Не менять** тексты сообщений, уровни и категории —
иначе диффы станут нечитаемыми, а поведение логов изменится незаметно.

Не трогать `.Custom.cs`-файлы UltimateXR и вообще ничего в `Assets/ThirdParty/`:
там своя система логирования (`UxrGlobalSettings.LogLevelNetworking`).

## Как проверить

1. Консоль редактора чистая.
2. Прогнать игру и убедиться, что переключение уровней в `GameSettings.asset` по-прежнему
   глушит и включает нужные категории.
3. Быстрая проверка главного: временный EditMode-тест, создающий `new RoundManager()`
   и вызывающий `Tick(0.1f)`, не должен падать на обращении к `GameSettings`.

## Готово, когда

- Ни один вызов `GameLog` вне `Core/` не упоминает `GameSettings`.
- `Debug.Log*` остались только в `GameLog.cs`.
- `GameSettings.Instance` не возвращает `null` без ассета.
- `new RoundManager().Tick(0.1f)` выполняется вне игрового цикла без исключений.
