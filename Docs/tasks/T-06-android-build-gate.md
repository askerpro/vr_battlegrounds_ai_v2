## Зачем

BUILD-01 — код, который компилируется в редакторе и падает в плеере — единственный класс
ошибок, который не ловится вообще ничем, кроме сборки под целевую платформу. За историю
проекта он встречался дважды (коммит `3f74bb6` и находка BUILD-01).

## Почему после T-01

Пока `using static Codice...` в `PlayerController.cs` не удалён, ворота будут красными
с первого запуска, и отличить «инструмент работает» от «инструмент сломан» не выйдет.

## Что делать

Editor-скрипт в `Assets/Editor/VR_Battlegrounds/Debug/` (категория обязательна —
см. `.agents/rules/editor_scripts.md`).

Пункт меню — с пробелом в имени, как требует жёсткое правило проекта:

```csharp
[MenuItem("Tools/VR Battlegrounds/Debug/Проверить сборку под Android")]
```

Внутри — компиляция скриптов под Android без полной сборки игры. Варианты по возрастанию
стоимости:

1. `UnityEditor.Build.Player.PlayerBuildInterface.CompilePlayerScripts` с
   `BuildTarget.Android` — быстро, ловит именно ошибки компиляции;
2. `BuildPipeline.BuildPlayer` во временную папку — медленнее, но ближе к реальности.

Начать с первого. Результат выводить через `GameLog` (после T-05 — `GameLog.Debug.*`),
ошибки — списком, с именем файла и номером строки.

## Границы

Только проверка компиляции. Не настраивать CI, не трогать `ProjectSettings`, не добавлять
хуки git — это отдельная задача, если понадобится.

## Как проверить

1. Запустить пункт меню на текущем состоянии — должно быть зелено (T-01 уже закрыт).
2. Временно вернуть `using static Codice...` в `PlayerController.cs`, запустить снова —
   должно быть красно с внятным сообщением. Убрать обратно.

Второй шаг обязателен: инструмент, который никогда не показывал красный, не проверен.

## Готово, когда

- Пункт меню есть и отрабатывает за разумное время.
- На заведомо сломанном коде даёт красный результат с указанием файла и строки.
- Способ запуска описан в [`../testing.md`](../testing.md).
