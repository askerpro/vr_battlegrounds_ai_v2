## Зачем

`SetManager` и `RoundManager` — обычные C#-классы, а `RoundManager.Tick(float deltaTime)`
принимает шаг времени параметром. Весь раунд прогоняется в памяти за миллисекунды.
После этой задачи цикл «правка → проверка» для логики матча становится секундным вместо
пятиминутного прогона живого матча.

## Что делать

### 1. Сборки для тестов

```
Assets/Tests/
  EditMode/VrBattlegrounds.Tests.EditMode.asmdef
  PlayMode/VrBattlegrounds.Tests.PlayMode.asmdef
```

EditMode-сборке обязательно `"includePlatforms": ["Editor"]`. Иначе тесты попадут
в плеер и повторится ситуация BUILD-01.

Ссылки: `VrBattlegrounds`, `UnityEngine.TestRunner`, `UnityEditor.TestRunner`, `Mirror`.

### 2. Снять оставшиеся зависимости от сцены

`GameSettings` уже обезврежен в T-05. Осталось два места в `RoundManager`:

- `AreAllPlayersReady` ходит в `PlayersManager.Instance`;
- `StartRound` ходит в `FindObjectsByType<TeamSpawnZone>`.

Ввести два узких интерфейса и передавать их в конструктор `RoundManager`:

```csharp
public interface IPlayerRoster   { IEnumerable<PlayerSession> GetAlivePlayers(TeamData team); }
public interface ISpawnZoneSource { IReadOnlyList<TeamSpawnZone> GetZones(); }
```

В игре реализации — обёртки над `PlayersManager.Instance` и `FindObjectsByType`.
В тесте — заглушки на несколько строк.

> Синглтоны в остальном проекте **не трогать**. Задача — сделать тестируемыми два класса,
> а не переводить проект на внедрение зависимостей. Порядок инициализации — отдельная
> задача [T-17](T-17-explicit-init-order.md).

### 3. Пять тестов

Все пять сейчас должны быть **красными** — они фиксируют существующие баги. Зелёными
их сделают T-08 и T-09.

| Тест | Что утверждает | Находка |
|---|---|---|
| `Победа_в_сете_даёт_одно_очко` | за один `SetEnded` победителю добавляется ровно 1 | MATCH-01 |
| `Раунд_проходит_все_шесть_фаз` | последовательность `RoundState` при прогоне `Tick` содержит `Resolution` и `Scoreboard` | MATCH-02 |
| `Scoreboard_длится_пять_секунд` | число тиков в фазе `Scoreboard` соответствует `ScoreboardDuration` | MATCH-02 |
| `Счёт_2_1_это_победа_а_не_ничья` | `SetManager.OnRoundEnded` при 2:1 отдаёт победителя, не `null` | MATCH-04 |
| `Матч_из_пяти_сетов_кончается_на_третьей_победе` | порог `_maxSets / 2 + 1` соблюдается | MATCH-01 |

Имена тестов — на русском, как и остальные комментарии в проекте.

## Границы

Не чинить найденное. Красный тест — результат этой задачи, а не проблема. Починка —
в T-08 и T-09, и смысл порядка именно в том, чтобы увидеть переход красного в зелёный.

Не писать PlayMode-тесты — сборку создать, наполнение оставить на потом.

## Как проверить

`Window → General → Test Runner → EditMode → Run All`. Пять тестов, все красные,
время прогона — доли секунды. Ни один не падает с `NullReferenceException`
на `GameSettings` или `PlayersManager` — только на проверяемых утверждениях.

Разница принципиальная: падение по NRE означает, что зависимости сняты не до конца.

## Готово, когда

- Обе сборки созданы, EditMode ограничена редактором.
- Пять тестов видны в Test Runner и падают на утверждениях, а не на NRE.
- Прогон занимает меньше секунды.
- Способ запуска дописан в [`../testing.md`](../testing.md).
