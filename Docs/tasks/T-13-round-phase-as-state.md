## Проблема

Фаза раунда раздаётся подписчикам через `[ClientRpc] RpcOnRoundStateChanged`, который
поднимает статическое событие `OnRoundStateChangedLocal`. На него завязаны арсенал,
видимость зон спавна и HUD.

При этом фаза **уже существует** как реплицируемое состояние:
`[SyncVar] private RoundState _roundState`. Источником правды служит не она, а RPC.

Три следствия:

| Ситуация | Что происходит |
|---|---|
| Выделенный сервер | `ClientRpc` в `ServerOnly` локально не исполняется. `ArsenalWallController` с веткой `case Setup → if (isServer) ReplenishWeaponsNetwork()` не срабатывает — оружие в слотах не появляется (NET-06). |
| Позднее подключение | Событие — это момент. Кто не был подписан во время перехода, не узнает никогда. |
| Клиент | `GameplayManager.Update` читает серверное поле `_gameMode`; на клиенте `null`, поэтому оружие не блокируется вне боя (MATCH-03). |

## Что делать

**Правило: если это нужно знать вновь подключившемуся — это состояние, а не событие.**

1. `OnRoundStateChangedLocal` раздаётся из хука `SyncVar` на `_roundState`, а не из RPC.
   Тогда он срабатывает одинаково на всех машинах, включая выделенный сервер, а новый
   клиент получает актуальную фазу начальным значением бесплатно.
2. Серверные реакции (например, `ReplenishWeaponsNetwork`) вызываются напрямую из
   серверного кода при смене фазы, а не через клиентское событие. Убрать `if (isServer)`
   изнутри клиентского обработчика в `ArsenalWallController`.
3. `GameplayManager.Update` читает фазу из синхронизированного источника вместо поля
   `_gameMode`. Нужна доступная клиенту ссылка на заспавненный объект режима.
4. `RpcOnRoundStarted` больше не присваивает `_currentRound` (NET-08) — присваивание
   переезжает на сервер, RPC остаётся только для UI-уведомления.

`ClientRpc` оставить там, где он уместен: разовые уведомления со звуком и текстом,
которые не нужно знать задним числом.

## Границы

Только фаза раунда и её подписчики. Структуру машины состояний не трогать — это уже
сделано в [T-09](T-09-explicit-round-fsm.md).

Состояние арсенала (`ArsenalState`) — отдельная задача
[T-15](T-15-arsenal-state-replication.md); здесь только убрать `if (isServer)` из
клиентского обработчика и завести серверный путь.

Таймеры раунда — [T-19](T-19-round-timers-networktime.md).

## Как проверить

Уровень 4, headless-сервер плюс два клиента:

1. Начать раунд — оружие появляется в слотах арсенала **на выделенном сервере**, не только
   на хосте (NET-06).
2. Подключить третьего клиента в середине фазы `Equipment` — он видит арсенал открытым,
   а не закрытым (эффект «состояние вместо события»).
3. На обычном клиенте попробовать выстрелить в фазе `Countdown` — не должно получиться
   (MATCH-03).

## Готово, когда

- `OnRoundStateChangedLocal` раздаётся из хука `SyncVar`.
- Серверные реакции на фазу вызываются серверным кодом.
- Оружие в арсенале появляется на выделенном сервере.
- Поздно подключившийся клиент видит правильную фазу.
- Стрельба вне `Combat` заблокирована на обычном клиенте.
