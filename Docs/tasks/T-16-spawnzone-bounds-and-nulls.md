## Что делать

`Assets/Scripts/Maps/TeamSpawnZone.cs` — две независимые проблемы.

### 1. Устаревшие границы

`_shrunkenBounds` считается один раз в `Awake` (`RebuildShrunkenBounds`, строки 104–111)
из мирового AABB коллайдера. Зона, которую двигают, поворачивают или масштабируют после
`Awake`, проверяется по старым границам — игрок «внутри» там, где его нет.

Пересчитывать при изменении трансформа. Варианты: `OnTransformParentChanged` +
`OnValidate`, либо публичный `RebuildShrunkenBounds()` с вызовом из кода, который двигает
зоны. Простейший надёжный путь — сравнивать `transform.hasChanged` в `OnTriggerStay`
и пересчитывать при необходимости.

Заодно: комментарий в коде обещает точность «±HeadHalfExtents (5–12 см)», но `Bounds`
не учитывает поворот зоны. Для повёрнутых зон проверка неверна — либо зафиксировать
ограничение комментарием, либо считать в локальных координатах коллайдера.

### 2. Обращения к `Session` без проверки

Строки 169 и 322: `_localPlayer.Session.Team` и `p.Session.Team` вызываются без проверки
на `null`. `Session` возвращает `null`, если сессия ещё не заспавнена или уже уничтожена.

После [T-11](T-11-session-avatar-link.md) `Session` кэшируется, но `null` в момент
между спавном аватара и сессии остаётся возможным.

## Границы

Только `TeamSpawnZone`. Поиск локального игрока (строки 131–139) уже исправлен
в [T-11](T-11-session-avatar-link.md) — не переделывать.

Логику видимости зоны (`UpdateVisibility`) не менять по существу, только добавить
недостающие проверки.

## Как проверить

1. В редакторе подвинуть зону спавна в Play Mode и убедиться, что срабатывание
   соответствует новому положению.
2. Multiplayer Play Mode: зайти в зону и выйти, проверить `IsInSpawnZone` на `PlayerSession`.
3. Быстро переподключиться, чтобы поймать момент рассинхрона спавна сессии и аватара —
   `NullReferenceException` быть не должно.

## Готово, когда

- Границы пересчитываются при перемещении зоны.
- Ограничение по повёрнутым зонам либо снято, либо явно записано комментарием.
- Обращения к `Session` защищены.
