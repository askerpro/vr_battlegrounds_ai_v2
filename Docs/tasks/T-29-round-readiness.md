# T-29 · Готовность игрока к раунду как явное состояние

| | |
|---|---|
| Находки | новая (RDY-01), плюс снимает блокер автопрогона матча |
| Блокирована | — |
| Блокирует | сквозной сценарий матча на ярусе C |
| Уровень проверки | 1 + C |
| Оценка | 1–2 дня |

## Что сейчас

Готовность — две булевы переменные на `PlayerSession`:

```csharp
[SyncVar] public bool IsInSpawnZone;
[SyncVar] public bool HasGrabbedDogTag;
public bool IsReadyForRound => IsInSpawnZone && HasGrabbedDogTag;
```

Читает их только `RoundManager.AreAllPlayersReady` (две точки). Жетон выставляет
`HasGrabbedDogTag` через `CmdSetDogTagGrabbed`, зона — `ServerSetInSpawnZone`.

## Что не так

**1. Жест подменяет намерение.** «Схватил жетон» используется как «я закончил»,
но отменить готовность нечем: передумал — уже нет.

**2. Общая стена блокирует остальных.** После T-15 состояние стены реплицируется
и едино для всех. Значит один игрок берёт жетон → арсенал закрывается **у всех**,
и второй не успевает экипироваться. Это настоящий игровой дефект, заведён как
**RDY-01**.

**3. Никто не знает, кого ждут.** Нет списка неготовых и нет предела ожидания:
один отошедший игрок стопорит матч навсегда. Отладочный `GetPendingReadinessStatus`
в `RoundManager` существует только под `#if UNITY_EDITOR`.

**4. Матч не прогоняется автоматически.** Ярус C доходит до фазы `Equipment`
и встаёт: `AreAllPlayersReady` требует физически стоять в зоне и взять жетон.
Это последняя непокрытая часть игры.

## Что сделать

Развести три вещи, слитые сейчас в одну.

### Готовность — явное состояние

`ReadyState` на `PlayerSession` вместо вывода из двух флагов. Серверный
`ServerSetReady(bool)` как единственная точка записи, клиентский `CmdSetReady`
для намерения игрока. Жетон остаётся жестом, который выставляет готовность,
но появляется и отмена — до старта отсчёта.

Нахождение в зоне спавна остаётся **условием**, а не готовностью: вышел из зоны —
готовность снимается. Это разные вещи, и их стоит различать явно.

### Закрытие арсенала — следствие общей готовности

Стена закрывается, когда готовы все живые игроки, либо когда пошёл отсчёт.
Не по первому жетону. Это чинит RDY-01.

Опирайся на разделение из T-13: у `ArsenalWallController` есть визуальный
обработчик фазы и серверный `ServerHandleRoundStateChanged`. Решение о закрытии
принимает сервер.

### Видимость и предел ожидания

Сервер отдаёт состав неготовых для HUD — это состояние, а не событие
(урок Корня 3: вновь подключившийся должен узнать его сам).

Предел ожидания: через N секунд либо автоготовность, либо старт без отошедших.
**Правило матча выбирает пользователь** — реализуй настраиваемым полем
с разумным умолчанием и опиши выбор в `Docs/gameplay.md`.

## Границы

- Не трогать машину состояний раунда (T-09) сверх точки, где читается готовность.
- Не трогать канал состояния (T-12) и раздачу фазы (T-13).
- `TeamSpawnZone` — только то, что касается сигнала о входе и выходе.
- Префабы и сцены правит оркестратор: нужна правка — описать.

## Как проверить

**Уровень 1.** `RoundManager` уже развязан через `IPlayerRoster`, готовность
проверяема юнит-тестами: не все готовы — фаза не двигается; все готовы — двигается;
вышел из зоны — готовность снялась; предел ожидания сработал.

**Уровень C — главное.** Серверный `ServerSetReady` делает возможным сквозной
сценарий матча: сценарий выставляет готовность обоим игрокам и прогоняет раунд
целиком — `Equipment` → `Countdown` → `Combat` → смерть → `Resolution` →
`Scoreboard` → следующий раунд.

Такого сценария в проекте нет, и это последняя непроверенная часть игры.
**Построить его — часть задачи.** Он же докажет, что фазы `Resolution` и
`Scoreboard` действительно проживают свою длительность в живой игре, а не только
в тиках EditMode (единственный пункт T-09, закрытый косвенно).

Отдельно проверить RDY-01: два клиента, первый объявляет готовность — арсенал
у второго обязан остаться открытым.

## Готово, когда

- Готовность — явное состояние с отменой, зона спавна — условие.
- Арсенал закрывается по общей готовности, а не по первому жетону.
- Состав неготовых виден клиентам, предел ожидания работает.
- Сквозной сценарий матча на ярусе C зелёный, **5 прогонов подряд**.
