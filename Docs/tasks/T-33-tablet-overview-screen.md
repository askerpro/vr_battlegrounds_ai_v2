## Требование

Сформулировано пользователем:

> Главное меню планшета должно быть некой альтернативой кнопки TAB в CS: показывает всю полезную
> информацию текущего режима или текущей ситуации. Например, во время игры там таблица счёта, игроков,
> время, хп игроков и т.д. На карте лобби можно сделать другое меню, т.к. там нет счёта (пока не продумал).

## Что сейчас

- `Screen_Main` (`MenuMain`) — хаб из кнопок-переходов: «Команда», «Статистика», «Калибровка», админские
  «Матч», «Игроки и команды», «Играть», отладочная «Отладка». Информации о ситуации на нём нет.
- Сведения о матче разбросаны: счёт и таймер — HUD (`HUDWidget_EliminationMode_TeamRoundScore`,
  `HUDWidget_RoundTimer` через `RoundClock`), своё хп — HUD и часы на руке (`WristDisplay`), статистика
  серии — отдельный экран «Статистика» (`MenuStatistics` + чистый `SeriesStatsTable`). Чужого хп,
  состава команд с «жив/выбыл», готовности и калибровки других игроков не показывает никто.
- Из «Статистики» переиспользуется: источник (`Series.PlayerStats`/`TeamStats`/`Results` — реплицированы)
  и приём «перестроение раз в 0,5 с и только при изменении». `SeriesStatsTable` считает сумму по карте
  и TOTAL — «Обзор» берёт статистику **текущей** карты тем же ключом игрока (`Series.PlayerKey`).

### Хп чужих игроков

`UxrActor.Life` — синхронизируемое свойство UltimateXR (`BeginSync` / `EndSyncProperty`). Жизнь меняет
только сервер (`NoSessionOrSessionOwner`), событие уходит через `NetworkStateRelay` **всем** клиентам —
одно событие на каждое изменение хп. Значит, `Health` любого аватара на клиенте уже актуален,
и новой репликации «Обзору» не нужно: **трафик экрана — ноль**, он только читает локальное значение.
Сегодняшняя цена самого хп (уже оплачена): одно событие состояния на попадание, порядка 40–60 Б
на получателя; при 20 игроках — ~1 КБ исходящего с сервера на попадание.

**Дыра — поздний клиент.** `UxrActor` не переопределяет `SerializeState`, поэтому `Life` не попадает
в начальный снимок (`NetworkStateRelay.CmdRequestInitialState` → `SaveStateChanges`). Подключившийся
посреди матча видит у раненых хп префаба (100), у выбывших — «жив», пока не придёт следующее изменение.
Аватары пересоздаются на каждой карте, так что расхождение живёт максимум до конца карты. Это вывод
из чтения кода — **не прогнано**. **Вынесено в отдельную задачу [T-34](T-34-late-join-state-snapshot.md)**
(решение пользователя 2026-09-29), в T-33 не чинится. Варианты, найденные здесь:

| Вариант | Как | Трафик | Минусы |
|---|---|---|---|
| **А. Патч SDK** (рекомендую) | `UxrActor.SerializeState` пишет `_life` (`SerializeStateValue`) | +4 Б на аватар один раз, в начальном снимке | правка `ThirdParty` → запись в `sdk-patches.md` |
| Б. SyncVar на `PlayerController` | `byte hp` с сервера, `Health` читает его | ~8–12 Б на изменение на получателя, пачкой раз в `syncInterval`; при 20 игроках — единицы КБ/с в разгар боя | второй источник того же факта; `PlayerController.OnActorDied` прямо объясняет, почему второго канала жизни быть не должно |

Проверка для любого варианта — сценарий яруса C «поздний клиент видит хп раненого».

## Решения пользователя (2026-09-29)

1. **Хп соперников видно всем** — `OverviewInput.ShowEnemyHealth = true` по умолчанию. Выключенная
   политика оставлена (у соперника «жив / выбыл», своя команда, наблюдатель и игрок без команды видят всех).
2. **Лобби — информация о себе первой**: блок «Вы» (команда, скин, калибровка), ниже выбор админа
   на следующую серию, итог прошлой серии и весь зал.
3. **Админ на «Обзоре» — все полезные кнопки ситуации**: главное действие справа внизу, остальные
   команды карты и переходы — строкой кнопок, «Стоп серии» — роль Danger, последней.
4. **Хп позднего клиента** — отдельная задача [T-34](T-34-late-join-state-snapshot.md).

## Раскладка (каркас T-32)

Шапки планшета нет. Слева — колонка разделов (`MenuFrame.Rail`): «Обзор · Команда · Статистика ·
Калибровка · Админ* · Отладка*», внизу «‹ Назад» / «✕ Закрыть». Справа — область контента со скроллом
(луч и стик), ~1476 × 1030 px видимой части; экран кладёт элементы через `MenuKit` в `Content`,
столбец растёт вниз. Главное действие (`SetPrimary`) закреплено справа внизу области контента.

«Обзор» — экран раздела «Обзор» (`MenuScreenType.Main`), открывается по умолчанию. Хаб `Screen_Main`
с кнопками-переходами больше не нужен: переходы — разделы колонки.

Содержимое «Обзора» сверху вниз:

1. **Шапка ситуации** — `MenuKit.Title` (карта или «Лобби»); строка-контекст `Label` TextSecondary:
   «Раунд 5 из 12 · Бой · 1:05» (часы правятся на месте раз в 0,5 с); счёт `Label` Title/Accent
   «Военные 3 : 2 Повстанцы»; пометка про смотрящего («Вы выбыли — наблюдение до конца раунда»).
2. **Кнопки админа** (только админу) — строка `MenuKit.Button`; главное действие — `SetPrimary`.
3. **Секции** — `MenuKit.Section` (заголовок) + `MenuKit.TableRow` (заголовок колонок и строки игроков)
   или `Label` для пояснений. Бюджет — ~8–12 строк до скролла, поэтому порядок секций по приоритету.

## Архитектура

```
Реплицированное состояние ──► OverviewStateReader ──► OverviewInput ──► OverviewBuilder ──► OverviewSnapshot ──► MenuOverview
 (MapReferee, режим, Series,   (адаптер, OverviewSources (простые данные)   (контекст +         (шапка + секции       (рисует через MenuKit)
  SessionManager, сессии,        .Current() — живые                           стратегии)          строк с ключами)
  аватары)                       объекты машины)                                                                       ▲
                                                                   OverviewAdminActions.Plan(context, lastMap, IsAvailable) ┘
```

- **`OverviewStateReader`** + **`OverviewSources`** — единственное место, знающее сетевые объекты.
  Команды — правилом `MenuTeamSelection.ResolveAvailableTeams` (активный режим → выбор серии → реестр;
  команда 0 «без команды» отбрасывается). У/С/А — `Series.GetKills/Deaths/Assists` по индексу текущей
  карты. Скин — `TeamData.GetAvatar(AvatarIndex).displayName`. Лобби — имя сцены равно
  `MapRegistry.LobbyScene`. Таймер — `RoundClock.TryGetTimeRemaining` (тот же источник, что HUD).
- **`OverviewContextResolver`** — сеть → лобби → пауза → итог карты → матч → разминка. Итог карты —
  разминка с записанным итогом текущей карты или `EliminationState.Finished` до возврата разминки.
- **`IOverviewSectionProvider`** — стратегия на контекст/режим; `OverviewBuilder.Default` — список по
  порядку секций. Новый режим добавляет свою стратегию, а не `if` в экране.
- **`OverviewAdminActions`** — план кнопок админа по контексту; доступность — функция
  `AdminMapCommands.IsAvailable`, поэтому план проверяется без сцены.
- **`MenuOverview : MenuScreen`** — только рисует. Раз в 0,5 с (`RefreshDue`) читает и строит снимок:

  | Что изменилось | Проверка | Экран делает |
  |---|---|---|
  | только часы | `SameContent` | меняет одну строку-контекст |
  | хп, счёт, готовность, тоны | `SameLayout`, не `SameContent` | правит текст и роль цвета в существующих TMP |
  | состав, порядок, контекст, набор кнопок админа, появился/пропал счёт | не `SameLayout` | `MenuKit.Clear` и строит заново |
