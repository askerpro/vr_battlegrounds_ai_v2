# T-48 · Матч с ботами

2026-10-15. Описание текущей реализации перехода на штатный поток игрока (player-flow).
Игровая приёмка ещё не завершена. Результаты и открытые проверки —
[Readme задачи bots-fix](../../tasks/bots-fix/Readme.md); исторические прогоны T-48 не принимают новый код.

## Игровая функция

Планшет → «Обзор» → «Матч с ботами»: одиночный игрок может запустить матч без режима отладки
и админской сборки. При других людях запуск доступен админу. Из лобби выбирается подходящая карта
Elimination; команды дополняются ботами. Один человек получает матч 2×2 с союзником-ботом.
Правила урона, смерти, призрака, возрождения, денег и счёта общие с людьми.

| Фаза | Задание директора |
|---|---|
| Подготовка, итог раунда, табло | Вернуться в свою зону и ждать |
| Закупка | Вернуться на базу, купить по бюджету, предложить оружие стрелку, объявить готовность |
| Отсчёт | Вернуться на базу и ждать |
| Бой | Передать тактическое движение и запросы огня Blaze |
| Призрак | Вернуться в свою зону; возрождение выполняет игровой режим |

## Решения и владельцы

- `BotDirector` владеет сессиями, решениями по фазам, командой и закупкой. `BotMind` хранит память,
  переживающую замену тела. `AvatarManager` остаётся фабрикой тел; удаление бота — через
  `BotDirector.RemoveBot(session)`.
- Единственный путь тела — player-flow: сессия получает калибровку до спавна, затем событие
  `AvatarSpawned` приводит к сборке `BotKit`. Директор сохраняет комплект один раз на тело;
  повторное событие для того же тела не создаёт второй комплект.
- `BotKitKind.Live` включает тело/навигацию, стрелка, драйвер позы, адаптер Blaze, хват, наведение и порядок кадра.
  `BotKitKind.Passive` для призрака и контрольной цели использует тот же драйвер позы, без хвата, наведения,
  Blaze и выстрелов. Переход Passive → Live на том же теле выполняет `BotKit.Upgrade`.
- `BotBody` поставляет ноги, курс и взгляд; `BotAvatarDriver` единолично записывает корень, камеру и кисти
  сервера перед UXR Manipulation. Далее работают штатные Manipulation, Animation и IK.
  Корень движется вместе с ботом. На клиентах бот-компонентов нет: позы приходят обычным
  `NetworkTransform` через `ServerAuthoredAvatar`.
- `BotRuntimeController` задаёт порядок кадра. `BotHands` выполняет штатный SDK-хват,
  `BotWeaponAim` рассчитывает позу оружия. `BotGunner` проверяет фактическое направление дула,
  препятствия, авторство `StateEventAuthority.IsAuthorOfItem` и готовность оружия, затем вызывает
  настоящий `UxrFirearmWeapon.TryToShootRound`. Blaze только запрашивает выстрел.
- `BotCombatDriver` создаёт минимальный серверный прокси Blaze только в Combat.
  Animator имеет шесть пустых состояний `Idle/Move/Back/Left/Right/Shoot`; root motion отключён.
  Запасной generic-клип требует отдельного подтверждения причины остановки движения.
- Вне боя маршрут задаёт `BotNavigator` по серверному NavMesh окружения.
  Неполный или отсутствующий путь останавливает движение. Смена команды/сторон меняет домашнюю зону.

## Закупка и снаряжение

Бюджет выбирают `BotBuyPlan` и `BotShopper` через штатную экономику: в начале половины —
пистолет по карману, при достаточном бюджете — основное оружие, иначе эко или форс по ситуации.
В Respawn снаряжение бесплатно. Покупка поступает в `BotGunner.OfferPurchase` один раз на пару
«тело, токен закупки», даже при отказе стрелка; тик директора не повторяет предложение.
`Arm()` обслуживает стартовое снаряжение. При замене стартового пистолета покупкой бот сначала
убирает его в свою кобуру штатным хватом, затем берёт покупку.

`BotAddOptions.AutoEquip=false` отключает автоматические покупки и вооружение директора для стенда:
сценарий сам задаёт оружие, директор не подменяет его бесплатным стволом.

## Как проверить

Нужны свежая Unity-компиляция и существующие проверки, эталонные выстрелы и снаряжение на
[BotCombatStand](bot-combat-stand.md), затем матч Elimination минимум на четыре раунда:
закупка по экономике, огонь по видимому врагу, смерть → призрак → возрождение, конец матча,
ноль ошибок. Отдельно проверяются M8, сервер с наблюдателями, поздний вход, визуальная посадка рук
и Quest. Эти проверки остаются открытыми; локальная компиляция и отдельный успешный тестовый набор
не означают приёмку игры. Тесты изменённого gameplay обновляются после пользовательской проверки.
