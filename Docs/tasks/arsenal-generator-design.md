## Принятый результат и границы

`ArsenalPreset` — единственный источник упорядоченных `WeaponInfo/Entry.Zone`; Style из этого пресета — единственный источник target-поз. Генератор создаёт ровно нужные слоты и их контейнер. Внешний корпус/рамка/материалы/декорации — обычные авторские префабы фиксированного размера, выбираемые из каталога. Генератор не растягивает artwork. Повторная сборка читает исходные assets, а не предыдущие generated children. Отдельных вручную синхронизируемых FullDemo/Demo составов нет.

Художник открывает внешний prefab в обычном Prefab Mode, выбирает preview preset и сохраняет свои материалы, текстуры и decor штатным workflow. Weapon/mag/card/slot previews полностью transient, не сохраняются в этот prefab и не вызывают gameplay, SDK, physics или stock events. Состав и якорные позы правятся через Preset/Style. Обязательных assembled prefabs для каждого пресета нет.

Не входят: новая торговля, экономика, readiness жетона, боезапас, magazine supply/stock return, reload, аватары, изменение weapon/mag prefabs и текущая ручная SDK correction. Геометрический переход обязан сохранить их существующие контракты. Live regeneration с удерживаемым/купленным оружием запрещён; новый состав принимается на новой загрузке карты.

## Авторские входы и workflow художника

Внешний prefab содержит только artwork и descriptor с явными Transform refs. Descriptor редактируется визуальными handles: SlotFrame — место контейнера в фиксированном корпусе; usable bounds — область для двух рядов; artwork bounds — фактический корпус. Serialized refs не ищутся по именам объектов. На puredecor ресурсе запрещены ArsenalWall/Supply/Offer, NetworkIdentity, UxrComponent/grabbables, Rigidbody и произвольные gameplay behaviours. Статические artwork colliders допускаются как часть корпуса; preview их не клонирует.

Functional templates — обычные prefab assets фиксированных слотов; их visual panel/module — тоже authored reusable assets. Template владеет формой и физическими элементами слота, Style — позами Item/Mag/Card/Supports. Количество/WeaponInfo в template не авторится. Ширина Shelf 0,4 м, глубина 0,66 м, gap 0,03 м; размеры не достигаются scale корня. Surface/Collider authoring проверяется на эти размеры до build. Художник может открыть template/module по ссылке из preview и сменить материал/добавить украшение; derived preview недоступно для сохранения изменений.

| Правка художника | Единственное место сохранения | После reorder/add/remove |
|---|---|---|
| Материал панели/корпуса, декорация рамки | Открытый внешний prefab или общий referenced material | Остаётся в artwork, refresh не перезагружает author prefab |
| Декор каждой ячейки | Visual subtree functional template/module, открываемого в отдельном Prefab Mode | Клонируется для каждого нужного slot; перестановка не стирает asset edits |
| Оформление только одного пресета | Отдельный authored decoration variant и явный DecorationId в запросе/выбранном визуальном наборе | Variant сохраняется как ресурс, не появляется копия entries; exact override выбирает его с capacity validation |
| Смещение magazine/item/card anchor | Draft handle целевого pose → явный Save в exact WeaponInfo/Zone Style exception | Следует предмету/зоне; Reset удаляет exception; offsets в WeaponInfo не добавляются |
| Состав и перенос MP5K на Shelf | ArsenalPreset Entries | Следующая description пересчитывает ряды, без category inference |

Unique visual variant выбирается в station/run authoring input как предпочтение визуала; это не второй состав. Не вводить скрытый поиск по имени preset. Если впоследствии понадобится prefab artwork attachment к конкретному LogicalSlotKey, это отдельное расширение: в текущем flow нестабильным transient children нельзя добавлять persistent decor. Полностью произвольное редактирование generated preview дерева не обещается.

Выбор preview preset, view pose и debug toggle хранятся в SessionState/EditorPrefs; не в Preset/scene. В Prefab Mode preview показывает текущий открытый ресурс, даже если automatic catalog selection для этого preset выбрал бы другой; UI явно показывает Fits/TooSmall/Universal и фактический automatic winner. Это позволяет оформлять 4/4 ресурс на preset 5/2, видеть overflow и не потерять edits из-за автоматического перехода в другой prefab. Production/runtime preview станции использует фактически выбранный resolver variant.

## Единый layout и выбор оформления

Layout profile в catalog задаёт row rest frames, Pegboard width/depth/gap из принятых template dimensions, Shelf 0,4/0,66/0,03, deployment closed/open frames и empty extent policy. Этот один profile используется pure resolver обоими materializers; decoration не меняет pitch/targets. Не копировать `.425` и старую `.65` из legacy Builder без measured accepted input: Pegboard профиль импортируется из accepted template baseline и валидируется отдельно. Этап runtime включается лишь после фиксации этого профиля.

В каждом ряду фильтруются Entries по actual Zone с сохранением относительного preset порядка. Для N>0: width = N*panelWidth + (N-1)*gap; x(i) = (i-(N-1)/2)*(panelWidth+gap). Для N=0 ряд имеет width=0 и не создаётся. Required container width — max widths двух рядов; вертикальные frames и depth определяются profile. Empty preset допустим: ноль slots, нулевой functional envelope, стабильная shell и decor; выдачи нет. Нет резервных runtime slots для выравнивания 3/2 в корпусе 4/4.

Resolver возвращает структурный container envelope и separately occupied bounds предметов/магазинов/cards/supports в open/closed/swept poses. Occupied bounds берутся из build-validated asset metadata с исходным physical scale и canonical alignment; runtime не требует readable meshes. Editor может дать более точную geometry диагностику, но не другой placement. В runtime консервативный объём обязателен; отсутствие mandatory geometry metadata — failure, не свободное размещение. Ни rotating AABB, ни внешние artwork bounds не считаются доказательством контакта.

1. Sized candidate в выбранном VisualSet должен иметь capacityPegboard>=neededPegboard и capacityShelf>=neededShelf; SlotFrame/usable bounds должны вмещать resolved required envelope и проверенные occupied extents. Сравнение выполняется в его frame без масштабирования artwork.
2. Из подходящих выбирается самый маленький: ascending usable-envelope volume, затем суммарная capacity, затем capacityPegboard, capacityShelf, затем ordinal DecorationId. IDs уникальны; ties не зависят от AssetDatabase/FindObjects порядка. Повторный выбор с теми же inputs возвращает тот же ID. Эта метрика «маленький» — рекомендуемое техническое решение для root; не измеренный критерий качества artwork.
3. Явный DecorationId выбирается при таком же fit. Missing/undersized explicit artwork даёт видимый diagnostic и проходит тот же fallback, не ломает gameplay. Corrupt metadata ресурса исключает candidate с точной ошибкой; invalid functional template/Style не лечится выбором bare.
4. Если подходящего sized нет, выбирается единственный catalog DefaultUniversal: дизайн не зависит от размера/количества slots, capacity/usable envelope не притворяются бесконечной sized рамой. Его frame имеет тот же unit-scale контракт, artwork коллизии проверяются. Если универсального ресурса нет — Bare. Catalog может быть пуст по decor.

Universal/Bare получают тот же functional description и slot manifest для данного input; внешний визуал не участвует в identity derivation. Bare использует profile default SlotFrame в station placement; universal использует явно authored frame. Различие frame pose разрешено и отражено в resolved geometry/hash; новые targets не пересчитываются contact correction. Descriptor `FallbackKind=Universal/Bare`, selected ID и diagnostic публикуются, asset не сохраняется автоматически.

4/4 sized ресурс: 4/4 и3/2 подходят при bounds fit; 5/2 и2/5 требуют другого sized или fallback. Placement safety отдельно: station available bounds, соседние станции, проходы и BoundaryOpening должны вмещать весь итоговый объём. Fallback по artwork не разрешает geometry overflow; при actual placement overflow — typed Failed до выдачи, без перемещения игрока/соседей. Runtime не перестраивает baked Environment/проёмы на лету: build preflight должен подтвердить declared envelope для каждого разрешённого run input.

## Поза и масштаб

Canonical defaults выбираются по Entry.Zone; exact overrides — по `(WeaponInfo, Zone)` в том же Style. ItemTarget/MagazineTarget описывают effective SDK AlignTransform, CardTarget — slot-local pose реальной карточки. Материализатор переносит whole anchor и сохраняет authored nested Align/proxy relative TRS. Root предмета выводится из его DropAlign; исходный world physical scale сохраняется при SDK parenting. SlotFrame/station/group transforms — unit scale; negative/nonuniform scale в функциональной цепочке отклоняется. Artwork children могут иметь authored mesh scale, но он не родитель functional anchors.

Styled runtime не прибавляет WeaponInfo offsets и не выполняет surface fitting. Contact Fit/Bake — явное Editor действие, сохраняющее результат в тот же Style target; обычный refresh только проверяет/показывает stale. Nested DropAlign/Align, smooth return и supports требуют visual handoff proof. New generator рекомендуется включать для styled presets; legacy null-style остаётся только в authored migration branch до explicit one-time conversion. Нельзя вывести canonical targets из предыдущего generated output при каждом запуске.

## Input/result и bootstrap seam

Предлагаемые сигнатуры:

```csharp
ArsenalStationDescription ArsenalStationResolver.ResolveDescription(ArsenalStationBuildInput input);
ArsenalCompositionHandle ArsenalStationComposer.PrepareComposition(
    ArsenalStationDescription description, ArsenalCompositionScope scope);
ArsenalReadyReport ArsenalStationComposer.ValidateReady(ArsenalCompositionHandle handle);
void ArsenalStationComposer.Activate(ArsenalCompositionHandle handle, ArsenalAdmissionToken token);
void ArsenalCompositionHandle.Dispose();
```

`ArsenalStationBuildInput` содержит stable StationKey, source ArsenalPreset, catalog, immutable visual request (VisualSetId/optional DecorationId), station placement, explicit Zone/ref StandingPoint/ArenaFacing, available placement envelope. Runtime MapRunKey передаётся отдельно в composition scope и не нужен pure layout/preview. StationKey сериализуется единожды в ArsenalStationCompositionBinding; MapRoot содержит ссылку на binding, а не независимо editable копию key. Source Style разрешается только через Preset. Bootstrap adapter разделяет MapStationBuildInput на эти authoring данные и shared map scope; generator не вводит свой MapRunConfig или Selection singleton.

Description — immutable frozen copy: source IDs/fingerprints, compiler/layout/identity schema versions, selected decoration/fallback, ordered slots, slot-local positions и presentation snapshots, template role metadata, occupied/open/closed/swept bounds и logical/role manifest hashes. Expected runtime UXR IDs вычисляет отдельный identity resolver только после shared MapRunKey handoff, из description+scope; Editor не выдумывает synthetic run/authority. UObject refs допускаются только в локальном resolved view; сетевой descriptor несёт IDs/hashes, frame и ordered logical/index data. Изменение asset во время run не меняет description; требует новой загрузки.

Handle содержит owned root/container/decor, exact ordered slots, SDK manifest/readback, gate status, disposal handle. Все error paths typed с StationKey/WeaponId/role/stage; GameLog.Arsenal/Network. Handle не становится author asset и не содержит mutable второй entries master. Bootstrap записывает выбранные decoration/layout hashes в immutable resolved MapRunConfig; генератор только возвращает данные. Режим принадлежит прежнему владельцу; generator получает только внешний admission.

`ArsenalCompositionScope` адаптирует shared MapRunScope: MapRunKey, monotonically changing local Epoch, целевую loaded Scene, CancellationToken и список owned resources для Dispose. `ArsenalAdmissionToken` — generator adapter внешнего MapRunAdmission result с неизменяемыми `(MapRunKey, Epoch, description hash, admission kind)`; Composer сверяет его со scope, сам не выдаёт допуск. `ArsenalReadyReport` содержит Success, exact stage, список typed failures и actual layout/identity hash: это contribution в CompositionReady, не server Ready или remote LocalPlayable. Не добавлять автономные mutable ready flags в каждой службе. Предлагаемые адресные методы существующих owners: `ArsenalWallController.InstallGeneratedSlots(IReadOnlyList<ArsenalSlotController> slots, ArsenalStationDescription description)` устанавливает manifest array/подписки один раз; `ArsenalStationPresetBinding.PrepareGenerated(ArsenalStationDescription description, IReadOnlyList<ArsenalSlotController> slots)` публикует уже проверенные snapshots без нового zone matching. Они доступны только Composer во время PreparingInactive; legacy Prepare сохраняется отдельной веткой. Exact owner visibility оформить internal API той же assembly, не public context-menu writer. На cutover единственный controller переименуется в ArsenalController; сейчас actual source name остаётся ArsenalWallController.

Producer dependency: bootstrap владеет будущими `MapRunKey { SessionEpoch, LoadSequence }`, MapRunConfig/MapRunAuthority/MapRunScope и MapRunAdmission (bootstrap tasks2/3; gameplay admission tasks4/5/7). Пока это только написанный контракт, не runtime API. До dependent runtime source/компиляции root должен получить primitive handoff либо согласованный узкий shared contract от этого владельца. Generator не создаёт temporary RunKey, shadow authority или fake admission ради компиляции. Независимые pure resolver/preview/resource probes получают только authoring input без map lifetime. Минимальная CompositionBinding schema с StationKey/exclusive mode передаётся bootstrap раньше runtime composer, разрывая взаимную зависимость MapRoot↔generator; этот handoff не разрешает production opt-in.

## Идентичности и сетевые индексы

Рекомендация — authored station shell с прежним scene NI и внешними links; dynamic local child slots без NI; выдаваемые items остаются Mirror-spawned через NetworkUxrIdentity. Server/client строят children из одного validated descriptor. StationKey сохраняется явно и уникален в карте; не выводится из hierarchy path, siblingIndex, netId или InstanceID. Scene NI identity station остаётся отдельной Mirror адресацией.

LogicalSlotKey = точный ordinal WeaponId, поскольку Preset сейчас запрещает его дубликаты. Zone — layout data, не часть logical identity; изменение зоны не превращает оружие в другой предмет. NetworkIndex = индекс Entry в immutable ordered preset; `_allSlots[index]` строго следует manifest. Ряды используют фильтр этого порядка, а не child enumeration. Reorder на следующей загрузке меняет индексы, но не logical keys; add/remove изменяют mapping явно. Индексы неизменны в run. Legacy arrays до opt-in миграции сохраняют прежний mapping: переход на новый порядок — версия нового manifest, не обещание сохранить старый array index.

Для каждого SDK component template содержит stable RoleKey и source UniqueId; все anchors/дочерние SDK/proxy компоненты объявлены ровно один раз, пустые/повторные роли/UID отвергаются. Key не зависит от имени Transform и child order. Puredecor не содержит UXR, поэтому новая рамка/fallback не меняют этот manifest.

RoleBaseUID = deterministic Guid от length-prefixed UTF-8 tuple `(role-base domain, project namespace, IdentitySchemaVersion, RoleKey)`, одинаковый для роли Peg/Shelf. SemanticSeed использует отдельный domain и canonical tuple `(project namespace, IdentitySchemaVersion, SessionEpoch:N, LoadSequence:invariantDecimal, StationKey, LogicalSlotKey, RoleKey)`. SHA-256(first16), byte order и version/variant masking фиксируются schema и golden vectors; исходный candidate byte contract приведён в `tmp/arsenal-generator-proofs/task2-identity-contract-review.md`, native proof ещё обязателен. ExpectedUniqueId = `GuidExt.Combine(RoleBaseUID, SemanticSeed)` действующей vendored версии. Template sourceUID/GUID/localFileID остаются provenance/preflight и не входят в semantic base/seed: перенос между зонами не должен менять итоговый UID. Layout/raw provenance fingerprint отдельно от semantic manifest hash. Identity schema version — версия алгоритма/role contracts; RunKey отличает повтор карты и не позволяет старому SDK action адресовать новую generation. Изменение исходного source ID меняет provenance/content fingerprint; изменение semantic schema/role contracts меняет identities явно.

Source audit важен для выбора реализации:

- CreateInstance действительно удерживает Awake под inactive родителем; это не означает «SDK вообще не регистрирует при Align».
- `UxrUniqueIdImplementer<T>.InitializeUniqueIdIfNecessary` сохраняет OriginalUniqueId до initial collision handling. Поэтому CombineUniqueId может использовать исходный template ID даже после временной collision при регистрации клона.
- `CombineUniqueId` регистрирует IDs и переписывает OriginalUniqueId; операция не идемпотентна. Повторную комбинацию нельзя применять при retry.
- `ChangeUniqueId` в EditMode игнорирует requested GUID и делает случайный; runtime тоже проходит registration. SetEditorUniqueId — только Editor. Ни один из них не выбирается runtime staging setter.

Предлагается узкое расширение существующего identity layer: `NetworkUxrIdentity.PrepareGeneratedIdentities(IReadOnlyList<NetworkUxrIdentityAssignment> assignments)`. Assignment содержит target IUxrUniqueId, template source ID, semantic seed, expected ID. После полной inactive настройки layout/frame/poses метод проверяет весь manifest и существующие регистрации, затем вызывает `CombineUniqueId(seed, recursive:false)` один раз на каждый объявленный компонент, проверяет actual ID==expected и lookup==target. Все assignment mutations принадлежат этому network layer; ArsenalGeneratedIdentityManifest только вычисляет значения. Existing `Align(instance, netId)` не вызывается для generated subtree: netId station не является slot seed, а повторный recursive Align shell опасен для уже созданных anchors.

Стартовый template component нигде не активируется и не проходит precache до этого этапа. Повторная Prepare того же handle возвращает прежний validated result; если target уже combined другим seed или actual UID отличается — Failed, а не дополнительная комбинация. Коллизия expected с чужим component — Failed до registration; SDK CollisionN после вызова — тоже Failed с rollback всего owned stage. Не полагаться на SDK автоматический collision repair. После настройки registration/Awake initial rest transform readback проверяется снова, включая disabled components на dedicated.

Это source hypothesis, не runtime proof. Native probe должен переставить creation order, создать много одинаковых templates, сравнить server/client/late-join manifest, transient SDK registration/state-save effects, exact requested ID и initial transform data. Если existing API не даёт безопасного поведения, остановить именно этот runtime path. Тогда root выбирает узкий SDK pre-Awake assignment seam с записью в sdk-patches либо конкретно необходимый derived bake cache. Новый SDK patch сейчас не требуется/не поручается и не добавляется в текущую manual correction.

## Lifecycle, admission и поздний клиент

Stages: Unprepared → Resolved → PreparingInactive → Registered → Bound → Ready → Active; terminal Failed/Cancelled/Disposed. Composer — единственный владелец своего stage. Его Ready подтверждает локальную сборку, manifest, references, role registrations и initial/deployment poses и даёт только CompositionReady contribution. Server Ready приходит от bootstrap после policy lifecycle gates, независимо от remote snapshot; remote LocalPlayable — после current generation fresh Relay snapshot. Activate принимает внешний token соответствующего допуска: серверные stock writers требуют server Ready, remote interaction/local policies — LocalPlayable. Awake/OnStartServer scene shell может произойти раньше: никаких refill/bind/SDK stock действий из него до соответствующего gate. Empty массив не повод GetComponentsInChildren и не «не подготовлено».

Prepare создаёт inactive owned scope через существующий dormant factory и переносит root в map scene. После создания exact slots и проверки refs/frames он устанавливает inert `_allSlots` и Binding snapshots под закрытым gate, затем ConfigureWeapon/PriceTag/views/compatibility/equipment refs; только после полной настройки идут identities и activation/readback. Такой порядок нужен, потому что Create карточки разрешает presentation через Binding; отсутствие контекста нельзя обходить legacy offsets. Wall subscriptions должны иметь явные Install/UninstallSlots: нынешний OnEnable foreach над старым массивом не обновляет новые children. Rollback удаляет installed staged refs/context и owned subtree. Generated shell до install имеет явный empty array и закрытый gate; Awake/OnEnable/OnDisable не могут итерировать null или выводить готовность из отсутствия children. State hooks могут сохранять latest state до готовности; pending item/mag indices очередятся до наличия manifest, после него валидируются, а не теряются ранним range check. Configure/PriceTag после handoff вызываются только с установленным snapshot; на preview этот код не вызывается.

Сервер создаёт один состав и после общего admission выдаёт оружие/магазины прежними методами. Host client half принимает тот же instance, не генерирует снова. Remote client получает server selected descriptor, разрешает assets по IDs/fingerprints, готовит свой местный subtree и verifies manifest. Unknown ID/hash mismatch — local Failed, не локальный выбор другого оформления. Stock objects могут прийти раньше description/anchors: сохраняя существующую manipulation history, потребители ждут local Ready. Late join не телепортирует уже взятый/брошенный магазин при позднем binding.

Отдельный обязательный seam с bootstrap/network owner: SDK initial snapshot нельзя применить до локальной регистрации generated anchors и нужных spawned item IDs; stale ответ прежней загрузки не должен применяться в новую generation. `NetworkStateRelay` сегодня не проверяет такую готовность и именно отбрасывает incremental RPC до `_initialStateLoaded`; общей incoming очереди нет. `AvatarStateEventGate` касается outgoing avatar IDs и эту проблему не закрывает.

Минимальная рекомендация — перенести существующий RequestInitialState за current local registration/manifest/reference barrier; сам request сообщает готовность клиента, отдельная ACK-система не нужна. Network owner предъявляет observable reference closure текущего сериализуемого SDK snapshot: persistent SDK, уже существующие anchors/items/avatars и actual spawn-before-state/capture cut. Требование относится к реально упомянутым IDs, не ко всем будущим avatars. Server Ready после composition+policy gates допускает avatar/stock creation, не ожидая remote snapshot; объекты, созданные позже, проходят existing identity/spawn/state transport. Remote LocalPlayable открывается после fresh apply. Поэтому нет цикла avatar creation → map ready → snapshot → ещё не созданный avatar. Если reference inventory/ordering ещё нет, runtime gate остаётся unresolved; таймер и ожидание будущих объектов его не заменяют.

Запросить свежий snapshot, а не задерживать application уже полученного старого snapshot. При гарантированном reliable ordered transport server TargetLoadInitialState и последующие RPC могут обеспечить snapshot-before-increments; это проверяется raw permutations, включая existing refs и post-admission spawns, а не предполагается по одному wall callback. Требуются generation-scoped cancellation/проверка stale request completion и доказательство, что все упоминаемые snapshot SDK IDs разрешимы. Нужен ли wire correlation token или bounded queue/resync — техническая развилка network owner по результатам probes: это варианты, не принятый новый transport protocol. Барьер не может потерять события между отложенным snapshot application и opening. Эти гарантии — acceptance gate runtime генератора, не новый relay внутри Composer.

Disable не означает rebuild: gate закрыт, signatures unsubscribed, owned identities сохраняются для той же generation до явного dispose; re-enable либо idempotent activate того же handle, либо named failure stale run. Unload/cancel сначала закрывает admission и pending callbacks, затем supply/wall перестают писать. Generator уничтожает только owned decor/slots/container и unregister своих UXR components. Spawned weapons/mags принадлежат прежним stock/network owners; held/bought/removed items не уничтожаются recursive child cleanup. Disposal перед уничтожением anchor обязан получить подтверждение equipment/stock retirement, отдельно обработать ещё anchored stock прежним владельцем; не вызвать ReleaseObject от имени неавтора. Async callbacks сверяют scope epoch/RunKey; повторный Dispose безопасен. Persistent UxrManager/SessionContext не уничтожаются.

## Preview lifecycle и сохранение

ArsenalPrefabStagePreview строит sibling overlay root в текущей PrefabStage scene вне author prefab subtree, с рекурсивными DontSaveInEditor/DontSaveInBuild/NotEditable flags и transient editor ownership marker/token. Никакого Instantiate functional/weapon runtime prefab: клонируются только permitted visual MeshFilter/MeshRenderer (и поддержанный baked visual snapshot для skinned sources), materials и activeSelf/TRS. Anchor/proxy markers — visual guides; card — render-only backing/TMP view из общего card-data formatter. Нет UxrComponent, NetworkIdentity, Rigidbody/Collider, SlotController/Supply/Offer в overlay. Pure resolver читает assets, preview не трогает physics/stock.

Artist save сериализует author root; overlay flags и отсутствие membership в его subtree дают две защиты. Raw save/reopen YAML readback обязателен: отсутствие generated preview names/components/refs и отсутствие dirty side effects доказывается, а не выводится только из HideFlags. Preview выбор/refresh не использует Undo author root, глобальный SaveAssets или source-card Create/Show. Ошибка resolve сохраняет authored edits и показывает diagnostic, не переоткрывает prefab.

Owner lifecycle: prefabStageOpened/Closing, sceneClosing/Closed, beforeAssemblyReload, playModeStateChanged, quitting, target destruction, exceptions и cancellation. Cleanup ищет свои markers/tokens в permitted stage, включая orphan sibling roots после domain reload; не удаляет объекты только по имени и не обходит чужие helper PreviewScenes. Registry переустанавливается после reload, source selection из SessionState; fingerprint refresh заменяет только overlay. Coalesced delayCall проверяет stage identity/epoch перед apply. Automated preview mutations используют existing editor/UI lease и deferred refresh при чужом Unity owner; lease не обходится потому, что результат transient. При Save refresh получает текущие in-memory authored materials/transforms, не LoadPrefabContents из диска. Destroy временных materials/TMP meshes явно принадлежит overlay.

## Миграция Common/Lobby и внешние связи

Рекомендация — opt-in transition через существующие authored logical station roots. Сначала functional шаблоны и fixed artwork копируются в собственные resources из accepted visual baseline без StretchHousing, готовятся artist preview и dry run; production stations в этой подготовке не меняются. Shell сохраняет scene NetworkIdentity/sceneId, root world pose, ArsenalStationAnchor.Zone/StandingPoint/ArenaFacing и внешние ссылки политики/табло/deployment/openings. Common и Lobby остаются работающим legacy authored branch. Destructive removal authored slots и переключение production на generated допустимы только после GREEN complete bootstrap/Relay admission задачи6 плана генератора на isolated generated fixtures, включая server Ready/remote LocalPlayable, current snapshot reference closure и stale-generation rejection. Production cutover — отдельная задача7, не часть ранней resource preparation задачи5; generator никогда не использует прежние children как скрытый fallback master.

Dry run фиксирует все serialized references к каждому старому slot/anchor/card/support, source localFileID/scene UID/provenance и mappings. External reference к removed child должна перейти на typed `(StationKey, LogicalSlotKey, RoleKey)` resolver либо owner-level shell reference. Runtime object reference cannot survive удаление своего target; такие ссылки нельзя объявлять «сохранёнными» численно. Unmigrated external child reference блокирует opt-in. Старые anchored readiness DogTag и его UID сохраняются отдельным существующим functional service; puredecor prefab не содержит DogTag. Никакой новый generator DogTag lifecycle.

После opt-in старые generated slot/card components удаляются адресно, их localFileIDs/UXR IDs заменяются manifest-derived runtime identities. Baseline668/168 остаётся доказательством предыдущего visual среза, не гарантия неизменности этих удалённых children. Сохраняемые shell/DogTag/внешние ссылки имеют отдельный before/after ledger. Новые StationKey задаются один раз под editor lease и сохраняются в scene, не генерируются runtime случайно. NI на functional slot root не нужен: сохраняются два нынешних stock dictionaries station NI.

Catalog registration/build preflight покрывает весь WeaponRegistry для network prefabs; template/decor assets включаются центральными refs. Сценовые группы соблюдают [scene hierarchy](../scene-hierarchy.md): station в Gameplay sibling TeamSpawnZone, Environment — static author content, PhysicalArenaLayout — diagnostic без Collider/переноса игровой геометрии. Generated движущееся оборудование помечается поддержанным dynamic marker и исключается из static occlusion; static station artwork baked как authored geometry либо не становится динамическим окклюдером по ошибке. Runtime arbitrary dynamic geometry не добавляет новый baked occluder. Проверить стоимость Quest, количество Renderers/material instances/TMP и generation frame spikes.

## Имена Arsenal на planned cutover

Пользователь выбрал общий термин Arsenal: одна станция содержит Pegboard и Shelf. При production cutover существующий единственный `ArsenalWallController` переименуется в `ArsenalController`; station prefabs получают convention `Arsenal[id].prefab`, например `ArsenalCommon.prefab`/`ArsenalLobby.prefab`. Эти имена будущие; текущие source pointers, baseline и legacy asset paths сохраняют фактические названия до миграции. Не создавать одновременно active WallController и ArsenalController и не запускать конкурирующий bulk rename.

Scoped naming inventory включает C# filename/class/API/type refs; public/editor/MCP/execute_code callers; nameof/reflection/type-name/string paths/menu/test fixtures; serialized managed type refs и field links; scene/prefab object names, asset paths, addressable/resources/build registry если используются; docs labels. Rename C# script и существующего prefab выполняется с сохранением их `.meta` GUID и проверкой MonoScript/component/scene refs; source localFileIDs/root scene NI и promised external links проверяются отдельно. При необходимости compatibility сохраняется forwarding method/tool entry или явным migration adapter, без второго controller component/владельца состояния. Related historical classes (`ArsenalBoundaryWall`, `ArsenalWallOpenings` и прочие) сначала инвентаризируются по реальной ответственности; этот срез не обещает переименовать весь SDK/проект поисковой заменой.

ArsenalPreset/ArsenalPresentationStyle/ArsenalDecorationDescriptor остаются различимыми по роли. Fixed decorative prefab именуется явно как decoration, например `ArsenalDecorationCommon.prefab`; это artwork resource, не generated composition master и не обязательный prefab состава каждого пресета. Visual concepts в `Docs/Arsenal/concepts/` уже переданы visual owner: их художественная интеграция не входит в generator docs-only correction и не расширяет текущий Style/module writer.

## Derived cache: только по доказанной потребности

Основной вариант — runtime generation + тот же pure description для Editor; cache не требуется. Возможные обоснования cache: native SDK registration не может пройти допустимый identity seam или измеренный startup budget Quest требует precompiled description/geometry metadata. Предпочтительнее data-only compiled manifest/metadata, чем prefab каждого пресета. Cache включает source Preset/Style/catalog/template/decor hashes, schema/compiler versions и stable manifest; stale refusal до stock. Он не редактируется художником, не выбирает состав самостоятельно, не input для regenerate. SDK bake вариант должен явно решить run identity и late-join snapshot admission; сохранённый prefab сам по себе их не доказывает. Если необходимость не подтверждена probe — cache не писать.

## Verification и границы приёмки

Сначала временные RED/GREEN probes на подтверждённые архитектурные инварианты; постоянные gameplay tests только после human Unity/шлем принятия по AGENTS.md. Каждый baseline RED должен фиксировать фактический отказ: старый capacity reject/serialized output, early callback loss, ID collision/path mismatch или source-card write. Намеренно испорченный future input проверяет отказ будущего harness; его нельзя называть baseline RED реализации, которой пока нет.

Минимальный matrix: empty; только Pegboard; только Shelf; оба ряда; current10/current20 (11/9, MP5K+MKR9 Shelf); reorder/add/remove/changed_zone; fixed4/4 с4/4,3/2,5/2,2/5; largest row bounds и crowded targets; universal/bare/полностью отсутствующий decor catalog; corrupt Style/template/frame/catalog IDs; nested align/scaled item/smooth-end; host/dedicated/remote/late join; descriptor до/после scene spawn, stock, SDK snapshot; reload same scene/disable/unload/cancel и held items; artist material/decor/Style Save-Reset/save-reopen/domain reload/dirty refresh.

GREEN означает exact runtime/preview description/manifest parity, отсутствие gameplay компонентов/событий и serialized preview children, неизменный artwork/physical scale, один автор ID/slots/config, правильные SDK lookups и supply revision, no stale-generation apply, closed gates до ready. Geometry checks: open/closed/swept bounds, deployment/no item subtree retraction, BoundaryOpening, соседние станции и occlusion. Unity AndroidCompileGate, console и существующие targeted checks выполняются под собственной lease; source audit/compile не доказательство live клиентов.

Вероятно устареют structural expectations `ArsenalWallCoversRegistryTests`, prefab fixed `_allSlots`/card composition checks, `ArsenalSlotOccupancyTests`, `ArsenalWallStateReplicationTests`, `DogTagSetupTests`, `ArsenalAnimatorTests`, `LobbyLayoutTests`, magazine supply binding fixtures. Перед реализацией уточнить assertions по source; не менять их автоматически и не отменять preserved scene NI/weapon/аватар требования. После принятия закрепить confirmed generation/parity/identity/disposal инварианты и получить raw GREEN. Во время этого design-only этапа таких результатов нет.

## Root decisions и зависимости

1. Рекомендуется stable authored station shell + local generated children и semantic seed, существующий dormant/Combine seam. Alternate NI на каждом slot увеличивает network registry/payload/spawn-order стоимость и меняет stock API без необходимости; не выбирать по умолчанию. SDK extension только по failed native probe.
2. Рекомендуется описанный deterministic smallest-fit ranking, fallback explicit undersized→universal→bare, empty preset allowed. Это routine технические решения root в рамках уже принятого product intent; повторных вопросов об artist/single-source flow не требуется.
3. Snapshot admission seam требует согласования bootstrap/network owner до runtime gate; не выдавать geometric parity за сетевую готовность. Принятый Series mode capture не создаёт дополнительного mode владельца у генератора.
4. Visual handoff должен стабилизировать Style/Resolver/Applicator/Binding и доказать current20 native poses/scale/identity baseline. Существующий partial batch не является gate completion. Writer generator начинается только после освобождения общих файлов.

Предлагаемая строка registry для root после review: «Генератор станции — Preset/Style → общий layout, fixed decorative catalog и transient Prefab Mode preview; здесь: принятый дизайн/план либо source-only review; осталось: runtime identity/snapshot gates, migration, probes/Android и Unity/шлем; Docs/tasks/arsenal-generator-design.md».
