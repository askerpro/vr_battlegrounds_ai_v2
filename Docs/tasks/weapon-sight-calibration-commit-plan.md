# План сохранения текущей работы по прицелам

> **Для следующего агента:** выполнять последовательно через superpowers:executing-plans. Этот документ разрешает подготовку плана; staging, коммиты и операции Unity сейчас не выполняются.

**Цель:** сохранить воспроизводимое текущее состояние калибровки, стрельбища Lobby и ручного стенда, чтобы продолжить работу без истории чата.

**Уточнение пользователя:** сохранить как есть и продолжить после коммита. Поэтому
checkpoint не ждёт нового прогона Unity и не очищает диагностические остатки.
Непроверенные изменения обозначаются PENDING. Смешанные арсенальные части сохраняются
как исходные дельты уже применённой работы, остальные собственные файлы — напрямую.
Состав и порядок продолжения описывает [handoff](weapon-sight-calibration-handoff.md).

**Архитектура:** исходники, ассеты и краткий статус передаются через Git. Подробные отчёты и доказательства сохраняются отдельно в игнорируемом каталоге отчётов. Незавершённая работа явно обозначается как WIP.

**Технологии:** Unity 6, UltimateXR, Mirror, Git и Plastic SCM.

**Контракт:** [калибровка](weapon-sight-calibration-design.md), [игровое стрельбище](weapon-sight-playmode-review.md), [ручной стенд](weapon-sight-manual-calibration.md).

## Ограничения

- Пользователь перезапускает Unity: до окончания паузы редактор не трогать.
- Чужие изменения сохранить; пустой на момент подготовки индекс не заполнять целиком через `git add .`.
- Коммиты сохраняют прогресс, но не означают пользовательскую приёмку или завершённую калибровку.
- Новые тесты игровой механики до пользовательской приёмки не писать.
- Операции редактора выполняются только под собственным замком Unity.
- JSON/XML, изображения, логи и отчёты конкретных прогонов не добавлять в Git, включая `git add -f`.
- Сохранить `.meta`, GUID и ссылки всех включаемых ассетов.

- [ ] **2. Пробы, существующие только в памяти инструментов, экспортировать: следующий агент должен запускать их из файлов. Добавить manifest отчётов и подробный handoff со статусами PASS/FAIL/PENDING.
- [ ] **3. Подготовить переносимый статус под Git.** Создать `Docs/tasks/weapon-sight-calibration-handoff.md`: принятые решения, состав ассетов, выполненные проверки и их границы, известные дефекты, зависимости, порядок продолжения, пути локальных доказательств. Обновить действующие task-документы и наши разделы README/gameplay/CHANGELOG. Ссылки на отчёты обозначить как локальные. Отменённые варианты и планшетное меню не возвращать.
- [ ] **4. Разрешить зависимость SDK.** `ManualSightCalibrationAuthoring` и `SightGameplayReviewBuilder` вызывают `UxrComponent.SetEditorUniqueId`, которого ещё нет в HEAD. Не сохранять набор, который компилируется только благодаря исключённому чужому диффу.
- [ ] **5. Убрать диагностические данные из рабочих ассетов после сохранения доказательств.** Сохранить снимок ручной сцены и неуспешного `MKR9_NativeProbe_b1bbb91d.prefab` в локальный отчёт. Удалить только принадлежащий этой проверке неуспешный prefab; очистить синтетические Rear/Front под Base/Stock и временное назначение сохранения в сцене стенда. Реальные незавершённые правки пользователя сохранять. Подготовить чистую открываемую сцену; дальнейшую реализацию ради checkpoint не расширять.
- [ ] **6. Проверить комплект.** После возобновления Unity получить актуальную компиляцию, включая AndroidCompileGate, проверить GUID/ссылки и отсутствие временных диагностических ассетов. Недоведённые проверки Save/Undo/rollback и игровая приёмка остаются PENDING, если не выполнены. Записать точную версию файлов, к которой относится каждый PASS; при ошибке компиляции исправить её до коммита.
- [ ] **7. Подготовить staging по логическим частям.** Проверить каждый `git --no-pager diff --cached`, `git --no-pager diff --cached --check`, список путей и зависимости. Для смешанных файлов отделить наши изменения, сохранив чужую рабочую версию. Не применять весь общий YAML без проверки происхождения объектов.
- [ ] **8. Создать коммиты только на этапе выполнения поручения.** Проверить текущую ветку. Последний SHA должен восстанавливать весь наш комплект; после каждого коммита проверить результат Git→Plastic, а не считать его автоматическим успехом.

## Предлагаемое разбиение коммитов

1. Если нужен: `chore: сохранить зависимость редакторских копий UltimateXR` — только согласованный минимальный патч и его SDK-документация.
2. `feat: сохранить WIP калибровки оружия и стрельбище Lobby` — Settings/Profile/OpticView, аудит и геометрические инструменты, материалы/шейдеры, пять Sight Review и настройки каталога, диагностический bench, Lobby/photo/display и соответствующие документы.
3. `feat: сохранить WIP ручного сведения прицелов и статус передачи` — маркеры/сессия, Manual Authoring/Geometry/Window, чистая сцена ручного стенда, handoff и финальный статус документов.

В описаниях явно перечислить подтверждённые результаты и оставшиеся проверки. Связанные документы распределить по соответствующим коммитам, без захвата чужих разделов.

## Риски передачи

- **Отчёты не входят в Git.** В текущем workspace следующий агент их увидит. Для другого checkout/компьютера передавать каталог отчёта отдельным архивом; tracked handoff должен быть самодостаточен даже без изображений и логов.
- **Смешанные файлы и Plastic.** Если после частичного Git-коммита в том же файле остаётся чужой дифф, post-commit hook может пропустить весь перенос. До выполнения выбрать изолированный способ переноса выбранного HEAD; не делать check-in всего Plastic workspace.
- **Непроверенные визуальные вопросы.** Донорный масштаб/крепление прицела SniperRifle и геометрия Viper/SRM12 остаются предметом осмотра. Успех геометрической пробы не подтверждает полноценную калибровку.
