# Дизайн-система меню планшета

Как выглядит и из чего собирается любое меню на VR-планшете. Почему так — аудит
[`audit/ui-menu-audit-2026-09.md`](audit/ui-menu-audit-2026-09.md) и задача
[`tasks/T-32-menu-design-system.md`](tasks/T-32-menu-design-system.md). Как устроены контроллер,
реестр и экраны — [`ui-menu-architecture.md`](ui-menu-architecture.md). Новый экран — скил
`/add-menu-screen`.

## Раскладка

Планшет держат в альбомной ориентации: высоты мало (1080 px), ширины много (1920 px). Поэтому
навигация — в левой колонке, а контенту отдана вся высота.

```
┌─ колонка (380 px) ─┬─ область контента ───────────────────────────────┐
│ Обзор              │ Заголовок экрана                                   │
│ Команда            │ …строки, таблицы, плитки — прокручиваются          │
│ Статистика         │   (палец/луч: перетаскивание; стик любой   │
│ Калибровка         │    руки, пока меню открыто)                                  │
│ Админ*             │                                                    │
│ Отладка*           │                                                    │
│────────────────────│                       [второе действие] [ГЛАВНОЕ]  │
│ × Закрыть / Назад  │                                                    │
└────────────────────┴────────────────────────────────────────────────────┘
```

| Зона | Правило |
|---|---|
| **Разделы** (колонка сверху) | Глобальные категории, видны всегда (с учётом прав). Игровые разделы объявляет активный режим (`GameModeData.menuTabs`), системные (Калибровка, Админ, Отладка) есть всегда. Не больше 6. Текущий раздел залит акцентом, в том числе во вложенных экранах. «Админ» и любые кнопки админа — по единому правилу `MenuPermissions.ShowAdminUi`: права **и** (админская сборка-планшет **или** режим отладки). |
| **«Назад / Закрыть»** (колонка снизу) | Всегда одно место. На корне раздела — «Закрыть», во вложенном экране или на внутреннем шаге — «Назад» ровно на один уровень. |
| **Контент** | Всё, что зависит от данных. Растёт вниз и прокручивается, вбок не растёт никогда. Первая строка — заголовок экрана. |
| **Главное действие** (контент справа внизу) | «Начать», «Далее», «Применить». Закреплено, не прокручивается; появляется только у экранов, где оно есть. Рядом слева — одно второе действие. Остальные действия — в контенте. |

Контент — 1476 × 1032 px (≈ 11 строк списка, ≈ 16 строк таблицы без прокрутки); с полосой
действия — на 116 px ниже.

**Многоуровневость.** Экран может проваливаться вглубь (`Push`), мастер — идти «Далее → Далее»;
«Назад» каждый раз возвращает на один уровень. Глубже 6 уровней — предупреждение в логе.

## Токены (`Assets/Resources/MenuTheme.asset`)

Единственное место, где заданы цвета, размеры и шрифт. Код и префабы берут значения только
отсюда: графика — через `MenuThemed` (роль цвета и текста), кнопки — `KitButton` по роли и
состоянию.

| Цвет | Значение | Где |
|---|---|---|
| `Surface` | `#15161C` | фон планшета (непрозрачный) |
| `SurfaceRaised` / `SurfaceHover` | `#2A2D38` / `#3A3E4C` | кнопка, строка / под лучом |
| `Accent` / `AccentPressed` | `#FFAF00` / `#F0A500` | главное действие, выбранное, скроллбар |
| `TextPrimary` | `#FFFFFF` | основной текст, текст доступной кнопки |
| `TextSecondary` | `#C9CCD6` | подписи, пояснения, заголовки групп |
| `TextOnAccent` | `#15161C` | текст на акценте |
| `Danger` / `DangerHover` | `#7A2620` / `#9A3028` | необратимое: «Стоп серии», «Убрать ботов» |
| `Success` | `#4FD17A` | «готов», победитель |
| `DisabledFill` / `DisabledText` | `#1E2027` / `#8A8E9A` | недоступное |

Правила (проверяет `MenuKitLogicTests`): текст доступной кнопки и основной текст — контраст
≥ 7:1 к фону (в VR строже веба); недоступное ≥ 4,5:1; выбранное отличается от недоступного
заливкой, а не видом «серой» кнопки.

| Типографика (Roboto Condensed, только `TextMeshProUGUI`) | px | ≈ dmm на 1 м |
|---|---|---|
| `Title` (Bold) | 60 | 20 |
| `Body` | 46 | 16 |
| `Caption` | 40 | 14 |
| `Button` (Bold, авторазмер 32…44, многоточие) | 44 | 15 |
| `TableHeader` (Bold) | 38 | 13 |

Строка и кнопка — 88 px (≈ 30 dmm): цель луча. Шаг отступа — 16 px, отступ каркаса от края — 24 px.
Символы — только те, что есть в шрифте: `·`, `—`, `×`, `−`, `…`, `«»` есть; `→ ‹ › ✕ ✓` — нет.

## Набор элементов (`MenuKit`)

Экран строит содержимое только через фабрику `MenuKit` — она берёт всё из темы, поэтому
экран не может собрать серую кнопку или строку шире планшета.

| Элемент | Для чего |
|---|---|
| `Title`, `Section`, `Label`, `EmptyState` | Заголовок экрана, заголовок группы, текст (переносится, при нехватке места — многоточие), «здесь пусто, потому что…» |
| `Row` | Строка фиксированной высоты: подпись забирает свободное место, кнопки сжимаются до минимума |
| `Button(role)` | `Secondary` (обычная), `Primary`, `Danger`; `Selected = true` — выбранный вариант |
| `Grid` + `Tile` | Плитки с картинкой (карты, команды, скины): N колонок во всю ширину, растут вниз |
| `TableRow` | Таблица: ячейки делят ширину по весам, заголовок приглушённый |
| `Input` | Поле ввода (на планшете — системная клавиатура) |

Главное действие — `SetPrimary(label, onClick, interactable, role)`, второе —
`SetSecondary(...)`; каркас сбрасывает их при смене экрана.

## Префабы

```
Assets/Prefabs/UI/Menu/
├── Tablet/   Tablet_Base.prefab   планшет: физика, хват, MenuView, каркас (MenuFrame)
│             Tablet.prefab        вариант: + все экраны; его ставит MenuPrefabRegistry
└── Screens/  Screen_Base.prefab   база экрана: столбец содержимого
              Screen_*.prefab      варианты Screen_Base со скриптом экрана
```

Каркас и раскладка экранов **генерируются**: `Tools/VR Battlegrounds/UI/Rebuild Menu Frame`
(`MenuKitBuilder`) строит каркас в `Tablet_Base` по токенам и кладёт в каждый планшет реестра
все экраны из `Screens/`. Руками в `Tablet.prefab` ничего не добавлять — пересборка удалит.

## Превью и снимки

- **Инспектор `MenuView`** (открыть `Tablet.prefab`): выбрать экран → «Показать превью». Экран
  строит содержимое тем же кодом, что в игре, на образцовых данных (`MenuScreen.BuildPreview`).
  Превью не сохраняется в префаб (флаг `DontSave` и снятие перед сохранением).
- **Снимки** всех экранов в PNG: `Tools/VR Battlegrounds/UI/Render Menu Snapshots` (в
  `Temp/MenuSnapshots`) или `MenuPreview.RenderSnapshots(папка)` из `execute_code` — так агент
  проверяет раскладку глазами без шлема.

## Проверки

| Тест | Ловит |
|---|---|
| `MenuDesignRulesTests` | экран вне каркаса или не вариант `Screen_Base`; 3D-текст; чужой шрифт; самодельные кнопки; цвет литералом; «Назад»/разделы вне колонки; `overflowMode = Overflow`; потерянные скрипты |
| `MenuContainmentTests` | стресс (60+ строк, широкие строки, сетка, таблица, длинные подписи) и превью каждого экрана: ничего не выходит за планшет; у каждого символа есть глиф |
| `MenuKitLogicTests` | контраст темы, минимальные размеры, стек навигации (в т.ч. многоуровневый), видимость разделов, скролл стиком |
| `MenuWiringTests` | экраны на месте, разделы ведут на экраны, экраны админа и «Перф-тесты» — только из своих разделов |

Тесты идут по реестру планшетов и по всем их экранам: новый экран проверяется без правки тестов.
Шлем нужен только для скролла лучом/стиком и читаемости на расстоянии.

## Подводные камни Unity (уже наступали)

- **Один `MonoBehaviour` — один файл с тем же именем.** Иначе в префабе компонент становится
  «потерянным скриптом» (так было с `KitButton`, `KitGrid`, `MenuThemed` в общем файле).
- **Пересоздание объекта базы рвёт вариант.** Объекты, добавленные в вариант под пересозданный
  объект базы, Unity переносит в корень префаба. Поэтому сборщик кладёт экраны заново каждый раз,
  а `Screen_Base` правит на месте, не пересоздаёт.
- **NUnit и `Transform`:** `Assert.AreEqual(transformA, transformB)` сравнивает их как коллекции
  детей. Сравнивать `Assert.IsTrue(a == b)`.
