# Архитектура UI меню (планшет)

Внутриигровое меню — VR-планшет. Как оно выглядит и из чего собирается (раскладка, токены,
набор элементов, превью, проверки) — [`ui-design-system.md`](ui-design-system.md). Здесь — кто
чем управляет и что делает каждый экран. Шрифты и кириллица — [`ui-fonts.md`](ui-fonts.md).
Новый экран — скил `/add-menu-screen`.

## Общая схема

### Глобальные компоненты (DontDestroyOnLoad)

1. **`MenuController`** — синглтон на всё время работы.
   - Открыть/закрыть планшет: ставит его перед лицом игрока (`OpenMenu`), прячет (`CloseMenu`).
   - **Навигация — стек** (`MenuNavigation`, чистый класс): раздел колонки — корень стека
     (`OpenTab`), вложенный экран — `Push`, «Назад» — `Back` (сначала шаг внутри экрана
     `MenuScreen.HandleBack`, потом стек; на корне — закрыть меню). `SwitchTo` — совместимость:
     раздел → `OpenTab`, иначе `Push`.
   - Раз в 0,5 с, пока меню открыто, пересчитывает видимость разделов по правам; раздел стал
     недоступен (сняли админа, выключили отладку) — уводит на раздел по умолчанию.
2. **`MenuPrefabRegistry`** (`Assets/Data/UI/Menu/MenuPrefabRegistry.asset`) — какой префаб
   планшета для устройства и контекста: `DeviceType (VR / Tablet) → Offline / Lobby / InGame →
   режим => префаб`. Сейчас везде `Tablet.prefab`.

### Локальные компоненты

1. **`LocalMenuManager`** — при загрузке сцены определяет контекст (Offline / Lobby / InGame по
   именам сцен `GameNetworkManager`), берёт префаб из реестра, инстанцирует выключенным и
   отдаёт `MenuController.Initialize(MenuView)`.
2. **`MenuView`** — корень префаба планшета: `MenuRoot` (канвас), `Frame` (каркас),
   `Tabs` (разделы колонки), `DefaultScreen` (раздел при открытии — «Обзор»). В инспекторе —
   превью экранов на образцовых данных.
3. **`MenuFrame`** — каркас: левая колонка (разделы, «Назад/Закрыть»), прокручиваемая область
   контента (`ScrollRect` → `Viewport` с маской → `Screens`), полоса главного действия.
   Строится кодом по токенам темы; `MenuStickScroll` на нём листает контент стиком любой руки,
   пока меню открыто, и на это время выключает телепорт (он тоже на стике).
4. **`MenuScreen`** — экран: только содержимое в `Content`, строится через `MenuKit`. Главное
   действие — `SetPrimary`, вложенный экран — `Push`, внутренний шаг назад — `HandleBack` +
   `HasInnerBack`, превью — `BuildPreview`, перестроение «раз в 0,5 с и только при
   изменении» — `RefreshDue`.

Префабы: `Assets/Prefabs/UI/Menu/Tablet/` (`Tablet_Base` — каркас, `Tablet` — вариант с
экранами) и `Assets/Prefabs/UI/Menu/Screens/` (`Screen_Base` + варианты). Раскладку генерирует
`Tools/VR Battlegrounds/UI/Rebuild Menu Frame`.

## Разделы и экраны

| Раздел колонки | Экран | Префаб | Кому |
|---|---|---|---|
| Обзор | `MenuOverview` (`Main`) | `Screen_Overview` | всем — аналог TAB: ситуация матча, счёт, игроки, хп, время; у админа — кнопки ситуации ([T-33](tasks/T-33-tablet-overview-screen.md)) |
| Команда | `MenuTeamSelection` | `Screen_Team` | всем |
| Статистика | `MenuStatistics` | `Screen_Statistics` | всем |
| Калибровка | `MenuPhysicalSpaceSync` | `Screen_Calibration` | всем |
| Админ | `MenuMatchManager` (`MatchManager`) | `Screen_Admin` | админу |
| ↳ Игроки и команды | `MenuPlayersTeams` | `Screen_AdminPlayers` | вложен в «Админ» |
| ↳ Новая серия | `MenuSessionSetup` | `Screen_AdminSeries` | вложен в «Админ» |
| Отладка | `MenuDebug` | `Screen_Debug` | в режиме отладки |
| ↳ Перф-тесты | `MenuPerfTests` | `Screen_DebugPerf` | вложен в «Отладку» |

**Список разделов объявляет режим.** Игровые разделы — поле `GameModeData.menuTabs` (порядок и подписи
режима; пусто — Обзор · Команда · Статистика), системные (Калибровка · Админ* · Отладка*) добавляются
всегда — `MenuTabs.Resolve`. Режим — активный на карте (`MapReferee.ActiveGameMode.ModeData`, в лобби —
разминка); сменился — колонка пересобирается, а если текущего раздела в новом наборе нет, открывается
первый раздел режима. Разделов не больше 6, все ведут на экраны планшета — `MenuTabsTests` по каждому
режиму реестра. Таблица выше — набор по умолчанию.

Видимость разделов — `MenuTab.Visibility` (`Everyone` / `AdminOnly` / `DebugOnly`). `AdminOnly` и
все кнопки админа на экранах решает одно правило `MenuPermissions.ShowAdminUi`: права админа **и**
(админская сборка-планшет `BUILD_ROLE_ADMIN` **или** режим отладки). Игроки на шлемах — обычные
права; настоящий админ — на отдельной сборке; на шлеме админка появляется вместе с отладкой.
Это не права: права проверяет сервер, здесь — только не показывать лишнего. Сторож —
`MenuPermissionsTests` (в коде меню нет других проверок «админ ли»). Входы во вложенные экраны —
`MenuMatchManager.Links` и `MenuDebug.Links` (проверяет `MenuWiringTests`).

**Команда (`MenuTeamSelection`).** Два шага на одном экране: команды (плитки) → скины команды
(плитки); «Назад» со скинов — к командам. Выбор скина отправляет запрос и **закрывает меню**.
Какие команды предлагать, решает `MenuTeamSelection.ResolveAvailableTeams`: команды **активного
режима сцены** (`MapReferee.Instance.ActiveGameMode.Teams`), иначе команды режима, выбранного
на матч (`SessionManager.SelectedGameModeData`), иначе все команды `TeamRegistry`. Активный
режим — первым: выбор администратора описывает следующий матч, и в лобби планшет предлагал бы
команды, которых в лобби нет. Если команда одна (`OffersTeamChoice == false`) — шаг выбора
команды пропускается. У разминки (лобби и любая карта до «Начать матч») своих команд нет,
поэтому предлагаются команды выбранного на серию режима, иначе реестра — Военные и Повстанцы.
Сервер отклоняет запрос команды, которой нет в активном режиме (`TeamChangeRequests.ServerPlayerRequest`);
скин в своей команде разрешён всегда. Когда матч начался (`GameMode.TeamChoiceLocked`), экран
предлагает только собственную команду игрока (сменить скин), а игроку без команды — пояснение:
команду выдаёт админ. Подпись скина — имя без технического префикса `Avatar_`.

**Новая серия (`MenuSessionSetup`).** Режим — ряд кнопок (только режимы матча, `TabModes`:
разминка — отдельное поле `GameModeRegistry.warmup`). Карты под режимом — плитки совместимых
карт (`MapsForMode`), лобби среди них нет. Клик по плитке ставит карту в конец очереди серии,
повторный — убирает (`MapQueue`); номер в очереди — в подписи плитки («2 · TestMap»), плитка в
очереди выделена. «Начать» — главное действие, шлёт `PlayerSession.CmdAdminStartSeries(режим,
карты)`; «Очистить» — второе действие; смена режима очищает очередь. Сервер отбрасывает
несовместимые карты и проверяет право админа (`AdminMapCommands.ServerStartSeries`).

**Админ (`MenuMatchManager`).** Команды матча: «Начать матч», «Пауза», «Продолжить», «Следующая
карта» (на последней карте серии — «В лобби»), «Стоп (конец серии)». Серия после конца карты
сама дальше не идёт: карта стоит в разминке, пока админ не нажмёт «Следующая карта». Каждая
команда видна только когда имеет смысл — правило `AdminMapCommands.IsAvailable` по
реплицированному состоянию; сервер проверяет его ещё раз. Главная команда ситуации (первая
доступная из `PrimaryOrder`: начать, продолжить, следующая карта) — главное действие; «Пауза» и
«Стоп» — в контенте, «Стоп» опасная. Ниже — входы в «Игроки и команды» и «Новая серия».
Нажатие — `PlayerSession.CmdAdminMapCommand`.

**Статистика (`MenuStatistics`).** Таблицы из реплицированных строк `Series`, секции собирает
`SeriesStatsTable.Build`: на каждую карту серии и TOTAL — команды (раунды, карты) и игроки
(У / С / А). Длинная серия прокручивается. Перестраивается раз в 0,5 с и только при изменении.
Карта без серии — та же таблица из одной карты с пометкой «Карта без серии».

**Игроки и команды (`MenuPlayersTeams`).** Строка на каждую сетевую `PlayerSession` этой машины:
ник (поле ввода + «Ник»), кнопка на каждую команду активного режима (текущая выделена). Выше —
названия команд на серию. Главное действие — «Распределить автоматически». Кнопки только шлют
команды админа (`CmdAdminAssignTeam` / `CmdAdminAutoBalance` / `CmdAdminRenameTeam` /
`CmdAdminRenamePlayer`); право проверяет сервер (`SessionPermissions.IsAdmin`, входы —
`TeamChangeRequests`), сервер же чистит ввод (`AdminNaming`). Не-админу — пояснение. Список
перестраивается раз в 0,5 с, только при изменении состава и не пока админ печатает.

**Калибровка (`MenuPhysicalSpaceSync`).** «Калибровать пространство» и «Калибровать рост» —
запускают процесс у `PhysicalSpaceSyncManager`; ход показывает HUD.

### Режим отладки и раздел «Отладка»

Скрытый режим на одном устройстве: админ-пункты, стресс-тест, телепорт, оверлей кадра.
Код — `Assets/Scripts/Debug/DebugMode/`, экраны — `MenuDebug` (`Screen_Debug`) и
`MenuPerfTests` (`Screen_DebugPerf`).

**Включение — только жест «оба стика нажаты 2 с»** (таймер `DebugHoldGesture`, чистый класс).
Одно удержание — одно переключение, отпустили раньше — отсчёт с нуля; тот же жест выключает
режим. Подтверждение — вибрация обоих контроллеров и табличка `PerfOverlay`. Ввод читается
напрямую из XR (`DebugGestureInput`) — работает и в ожидании сервера, когда аватара и планшета
ещё нет; в этом состоянии жест при **уже включённом** режиме делает шлем хостом
(`GameNetworkDiscovery.RestartAsHost`). Режим **не сохраняется** между запусками (шлемы общие).

**Состояние** — статическая служба `DebugMode` (`Enabled`, событие `Changed`). Раздел «Отладка»
виден только в режиме (`MenuVisibility.DebugOnly`); выключили режим — контроллер уводит на
раздел по умолчанию.

**Раздел «Отладка»** (строки — `MenuKit`):

| Строка | Что делает |
|---|---|
| Статус | сеть (хост/клиент), права админа, идёт ли стресс-тест, ботов, последний ответ сервера |
| Оверлей кадра | живой кадр на табличке: среднее, худшее, FPS раз в 0,5 с (`DebugPerfReadout`) |
| Разделы | «Перф-тесты»; админу — «Матч», «Игроки и команды», «Новая серия» (`MenuDebug.Links`) |
| Боты | админу: «Добавить бота», «Убрать всех» (`BotNetwork`) |
| Телепорт | зоны спавна команд и места перед стенами арсенала (`DebugTeleportTargets`), сеткой |
| Режим | «Выключить режим отладки» |

**Власть — у сервера.** Сетевые сообщения (`DebugModeMessages`, обработчики — `DebugModeNetwork`,
регистрирует `GameNetworkManager`):

- `DebugClientSync` при включении режима и на каждой новой локальной сессии шлёт
  `DebugAdminRequestMessage`. Сервер решает по `DebugAdminPolicy`: права (`PlayerSession.IsAdmin`)
  выдаются, **только если сервер сам разрешает отладку** — Development-сборка (и редактор) или
  флаг запуска `-vrb-debug-admin`. Прод-сервер без флага отказывает, отказ пишется `Warning` и
  приходит на табличку. Выключение режима снимает только права, выданные режимом; хост админ и так.
- Телепорт — `DebugTeleportRequestMessage` с **id точки**, не координатами. Сервер проверяет
  админа, находит точку в своей сцене тем же правилом и зовёт `PlayerController.ServerDevTeleport`
  для аватара **отправителя**. Переносит владелец (`RpcDevTeleport` проверяет автора —
  `MoveAvatarTo` синхронизируемый). Откалиброванного игрока телепорт отрывает от физической
  комнаты — инструмент разработчика.

**Перф-тесты** (`MenuPerfTests`) — стресс-тест с планшета; вход — из «Отладки», «Назад» ведёт
туда же (стек). Выбор живёт в статических полях экрана и переживает пересоздание планшета.

| Часть | Что |
|---|---|
| Режим | «Обычный», «По скинам», «Короткий (10 с)», «Только по карте» (`PerfRunMode`), выбранный — выделен |
| Описание | фазы и длительность — `StressTestPlan.Describe` |
| Куклы | скин («< Скин» / «Скин >»: вперемешку или префаб по имени; в прогоне по скинам — «все по очереди»), число («− кукла» / «+ кукла», 1..`StressTestConfig.MaxPuppets`) |
| Главное действие | «Старт» / «Стоп» (`StressTestLauncher`) |
| Прогон | «Фаза i из N: имя · осталось X с», живой кадр, итог запроса, ответ сервера, путь perf.log последнего прогона — для `adb pull` |

Проверки: `DebugModeTests`, `StressTestPlanTests`, `MenuWiringTests`.

## Как это работает на практике

1. Сцена загрузилась → `LocalMenuManager` берёт `Tablet.prefab` из реестра, инстанцирует
   выключенным, `MenuController.Initialize` собирает экраны и строит разделы колонки.
2. Кнопка меню на контроллере (`MenuInputHandler`) → `ToggleMenu` → планшет перед игроком,
   открыт раздел по умолчанию («Обзор»).
3. Клик по разделу → `OpenTab`; кнопка в контенте → `Push`; «Назад» → `Back`; на корне —
   «Закрыть».
4. Смена экрана: каркас снимает прежнее главное действие, экран в `Show()` ставит своё и
   строит содержимое; прокрутка — в начало.

## Кастомный планшет для режима

Сделайте вариант `Tablet_Base.prefab` (корень с `MenuView`, `UxrGrabbableObject`/`Rigidbody`,
поворот 0) и привяжите его в `MenuPrefabRegistry.asset → RoleConfigurations → SpecificGameModeMenus`.
Сборщик положит в него все экраны из `Screens/`; `MenuDesignRulesTests` проверят его сами
(идут по реестру).
