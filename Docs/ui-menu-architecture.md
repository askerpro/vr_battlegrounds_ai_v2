# Архитектура UI Меню (MVC)

Система внутриигрового меню в проекте (планшеты и экраны на руках в VR) построена по модульному принципу (близкому к паттерну Model-View-Controller). Она позволяет легко добавлять новые экраны, автоматически менять внешний вид меню для разных ролей и отвязывает логику от жестко заданных названий сцен.

Шрифты и кириллица в тексте меню — [`ui-fonts.md`](ui-fonts.md).

## Общая схема архитектуры

Вся система разделена на **глобальные элементы** (живут всегда) и **локальные элементы** (живут только в пределах загруженной сцены).

### Глобальные компоненты (DontDestroyOnLoad)

1. **`MenuController` (Контроллер)**
   - Синглтон, который существует во время всей работы приложения.
   - Управляет состоянием меню (открыто / закрыто).
   - Обрабатывает логику позиционирования (спавнит планшет прямо перед лицом игрока и поворачивает его под удобным углом).
   - Не знает, *как* выглядит меню — только вызывает общие методы `Show()` / `Hide()`.

2. **`MenuPrefabRegistry` (Модель данных / Реестр)**
   - `ScriptableObject`, хранящийся в `Assets/Data/UI/Menu/MenuPrefabRegistry.asset`.
   - Главное хранилище префабов. Содержит древовидную логику:
     `Role (VRAdmin / Player) -> Scene Context (Offline / Lobby / InGame) -> Game Mode (Elimination / Respawn) => Prefab (GameObject)`.
   - Позволяет разным ролям (Админу и простому Игроку) получать совершенно разные планшеты с разными возможностями, даже находясь в одном и том же матче!

### Локальные компоненты (Сцена)

1. **`LocalMenuManager`**
   - Компонент, присутствующий на сцене или на игроке (LocalPlayer).
   - При старте `Start()` он:
     1. Запрашивает текущий контекст (мы в Offline, Lobby или InGame базе `GameNetworkManager`).
     2. Читает текущий режим у `MapReferee`.
     3. Просит у `MenuPrefabRegistry` дать нужный префаб.
     4. Инстанцирует префаб, скрывает его (чтобы меню не открывалось само по себе) и регистрирует в `MenuController.RegisterView(MenuRoot)`.

2. **`MenuView` (Представление)**
   - Главный компонент инстанцированного префаба меню (например, висит на `TabletMenuBase`).
   - Пассивный контейнер. Хранит ссылки на корень UI-канваса и на дефолтный стартовый экран.

### Экраны (Screens)

**`MenuScreen`**
Базовый класс для каждого отдельного окна (вкладки меню). 
Все специфические вкладки наследуются от него:
- `MenuMain` (Главный экран)
- `MenuSessionSetup` (Выбор режима и карты)
- `MenuTeamSelection` (Выбор команды)
- `MenuPlayersTeams` (Игроки и команды — экран админа)

**Выбор команды и скина (`MenuTeamSelection`).** Какие команды предлагать, решает
`MenuTeamSelection.ResolveAvailableTeams`: команды **активного режима сцены**
(`MapReferee.Instance.ActiveGameMode.Teams`), иначе команды режима, выбранного на матч
(`SessionManager.SelectedGameModeData`), иначе все команды `TeamRegistry`. Активный режим —
первым: выбор администратора описывает следующий матч, и в лобби планшет предлагал бы
команды, которых в лобби нет. Если команда одна (`OffersTeamChoice == false`) — **этап выбора
команды пропускается**, сразу открываются скины этой команды. У разминки (лобби и любая карта
до «Начать матч») своих команд нет, поэтому планшет предлагает команды выбранного на серию
режима, иначе реестра — Военные и Повстанцы. Сервер отклоняет запрос команды, которой нет
в активном режиме, если у режима команды есть (`MatchTeams.ServerPlayerRequest`); скин в своей
команде разрешён всегда. Контекст меню (`Offline/Lobby/InGame`)
по-прежнему определяется именем сцены: появление `MapReferee` в лобби его не меняет.

**Выбор сессии (`MenuSessionSetup`).** Вкладки — только режимы матча (`TabModes`: разминка —
отдельное поле `GameModeRegistry.warmup`, во вкладки не попадает). Карты под вкладкой — совместимые
с режимом (`MapsForMode`), лобби среди них нет. Клик по плитке ставит карту в конец очереди
серии, повторный — убирает (`MapQueue`, чистая логика); номер в очереди — текст `QueueNumber`
в правом верхнем углу плитки (`MapEntry.prefab`), номера пересчитываются. «Начать»
(`Btn_StartSeries`) шлёт `PlayerSession.CmdAdminStartSeries(режим, карты)`, «Очистить»
(`Btn_ClearQueue`) опустошает очередь; смена вкладки тоже её очищает. Сервер отбрасывает
несовместимые карты и проверяет право админа (`AdminMatchCommands.ServerStartSeries`).

**Экран «Матч» (`MenuMatchManager`, `Screen_MatchManager.prefab`, `MenuScreenType.MatchManager`).**
Пять кнопок: «Начать матч», «Пауза», «Продолжить», «Следующая карта» (на последней карте серии —
«В лобби»), «Стоп (конец серии)». Серия после конца карты сама дальше не идёт: карта стоит в разминке,
пока админ не нажмёт «Следующая карта» (только в разминке идущей серии). Каждая видна только
админу и только когда имеет смысл — правило `AdminMatchCommands.IsAvailable` по реплицированному
состоянию (`MapReferee.CurrentState`, `SupportsPause`, совместимость карты, `Series.IsRunning`);
сервер проверяет его ещё раз. Нажатие — `PlayerSession.CmdAdminMatchCommand`. Кнопка перехода
«Матч» на главном экране видна только админу (`AdminOnlyElements` на `Screen_Main`). Так же
только админу видна «Играть» (`Btn_SessionSetup`) — единственный вход в выбор серии (экран по
умолчанию — главный); сервер и так отклоняет не-админа. Проверяет `MatchMenuWiringTests`.

**Экран «Статистика» (`MenuStatistics`, `Screen_Statistics.prefab`, `MenuScreenType.Statistics`).**
У всех игроков, кнопка «Статистика» на главном экране. Таблица — TMP rich text, собирается
`SeriesStatsTable.Build` + `Format` из реплицированных строк `Series`: секция на каждую
карту серии и TOTAL, в секции — раунды и карты команд, игроки «убийства / смерти / ассисты».
Перестраивается раз в 0,5 с и только при изменении. Карта без серии — та же таблица из одной
карты с пометкой «Карта без серии».

**На карте (этап Б)** игрок приходит без команды матча, и тот же экран предлагает команды
режима и скин. Когда матч начался (`GameMode.TeamChoiceLocked`), экран предлагает только
собственную команду игрока (сменить скин), а игроку без команды — ничего: команду выдаёт
админ. Планшет в контексте `InGame` для VR и Tablet — тот же префаб
`PlayerAdminLobbyTabletMenu` (`MenuPrefabRegistry.DefaultGameMenuPrefab`), поэтому экран
выбора команды на карте есть без отдельной настройки.

**Экран админа «Игроки и команды» (`MenuPlayersTeams`, `MenuScreenType.PlayersTeams`).**
Префаб `Assets/Prefabs/UI/Menu/VR/MenuScreens/Screen_PlayersTeams.prefab` лежит в
`PlayerAdminLobbyTabletMenu` рядом с остальными экранами, переход — кнопка
`Btn_PlayersTeams` на `Screen_Main`. Экран строит строку на каждую сетевую
`PlayerSession` этой машины (имя и команда) с кнопкой на каждую команду активного режима
(`SlimButton_IconText`) и кнопку «Распределить автоматически». Кнопки только шлют команды
админа (`PlayerSession.CmdAdminAssignTeam` / `CmdAdminAutoBalance`); право админа проверяет
сервер (`SessionPermissions.IsAdmin`: хост или `IsAdmin`; входы — `MatchTeams`), не-админу экран показывает пояснение.
Список перестраивается раз в 0,5 с и только при изменении состава — чтобы не сбивать
наведение луча в VR.

### Режим отладки и экран «Отладка»

Скрытый режим на одном устройстве: админ-пункты, стресс-тест, телепорт, оверлей кадра.
Код — `Assets/Scripts/Debug/DebugMode/`, экраны — `MenuDebug` (`Screen_Debug.prefab`,
`MenuScreenType.Debug`) и `MenuPerfTests` (`Screen_PerfTests.prefab`, `MenuScreenType.PerfTests`).

**Включение — только жест «оба стика нажаты 2 с»** (таймер `DebugHoldGesture`, чистый класс;
перенесён из прежнего жеста стресс-теста). Одно удержание — одно переключение, отпустили
раньше — отсчёт с нуля; тот же жест выключает режим. Других комбинаций нет: жесты стресс-теста
(оба стика, стики + грипы) убраны. Подтверждение — вибрация обоих контроллеров и табличка
`PerfOverlay`. Ввод читается напрямую из XR (`DebugGestureInput`) — работает и в ожидании
сервера, когда аватара и планшета ещё нет; в этом состоянии жест при **уже включённом** режиме
делает шлем хостом (`GameNetworkDiscovery.RestartAsHost`). Режим **не сохраняется** между
запусками (шлемы общие).

**Состояние** — статическая служба `DebugMode` (`Enabled`, событие `Changed`), не флаг на
синглтоне. На неё подписаны: `DebugOnlyElements` на `Screen_Main` (кнопка «Отладка»
`Btn_Debug` видна только в режиме), `DebugPerfReadout`, `MenuDebug` (при выключении уходит
на главный экран), `DebugClientSync`.

**Экран «Отладка»** строит строки кодом (`MenuRowBuilder`, кнопки из `SlimButton_IconText`),
как «Игроки и команды». Над строками — кнопка префаба `Btn_PerfTests` → экран «Перф-тесты»
(под `DebugOnlyElements` на `Screen_Debug`):

| Строка | Что делает |
|---|---|
| Статус | сеть (хост/клиент), права админа, идёт ли стресс-тест, последний ответ сервера |
| Оверлей | живой кадр на табличке: среднее, худшее, FPS раз в 0,5 с (`DebugPerfReadout`) |
| Админ | переходы на «Матч», «Игроки и команды», «Выбор серии» — только если сессия админ |
| Телепорт | зоны спавна команд и места перед стенами арсенала (`DebugTeleportTargets`) |
| — | «Выключить режим отладки» |

**Власть — у сервера.** Сетевые сообщения (`DebugModeMessages`, обработчики — `DebugModeNetwork`,
регистрирует `GameNetworkManager`), `PlayerSession` не менялась:

- `DebugClientSync` при включении режима и на каждой новой локальной сессии шлёт
  `DebugAdminRequestMessage`. Сервер решает по `DebugAdminPolicy`: права (`PlayerSession.IsAdmin`,
  тот же флаг, что проверяет `SessionPermissions.IsAdmin`) выдаются, **только если сервер сам
  разрешает отладку** — Development-сборка (и редактор) или флаг запуска `-vrb-debug-admin`.
  Прод-сервер без флага отказывает, отказ пишется `Warning` и приходит на табличку. Выключение
  режима снимает только права, выданные режимом; хост админ и так.
- Телепорт — `DebugTeleportRequestMessage` с **id точки**, не координатами. Сервер проверяет
  админа, находит точку в своей сцене тем же правилом (порядок по месту объекта, не по
  `InstanceID`) и зовёт `PlayerController.ServerDevTeleport` для аватара **отправителя**.
  Переносит владелец (`RpcDevTeleport` проверяет автора — `MoveAvatarTo` синхронизируемый).
  Откалиброванного игрока телепорт отрывает от физической комнаты — инструмент разработчика.

**Экран «Перф-тесты»** (`MenuPerfTests`, `Screen_PerfTests.prefab`, `MenuScreenType.PerfTests`) —
стресс-тест с планшета; «Назад» ведёт в «Отладку». Выбор живёт в статических полях экрана и
переживает пересоздание планшета со сценой.

| Часть | Что |
|---|---|
| Режим | «Обычный», «По скинам», «Короткий (10 с)», «Только по карте» (`PerfRunMode`), выбранный — в скобках |
| Описание | одна строка: что входит, число фаз (в сводку), длительность — `StressTestPlan.Describe` |
| Скин кукол | «< Скин» / «Скин >»: вперемешку или префаб **по имени**; в прогоне по скинам — «все по очереди» |
| Кукол | «- кукла» / «+ кукла», 1..`StressTestConfig.MaxPuppets` (20; сервер обрезает запрос тем же потолком) |
| Управление | «Старт» / «Стоп» (`StressTestLauncher`) |
| Панель | «Фаза i из N: имя · осталось X с» (N — план `StressTestPlan.Phases` на момент старта), живой кадр (`DebugPerfReadout`), итог запроса, ответ сервера (`StressTestClientSession.LastServerText`: отказ, «идёт», итог), путь perf.log последнего прогона (`LastLogPath`) — для `adb pull` |

Проверки: `DebugModeTests` (жест удержания, служба, правило прав, точки, скин), `StressTestPlanTests`
(конфиг режима, фазы, длительность, потолок кукол), `DebugMenuWiringTests` (экран «Отладка», кнопка
под `DebugOnlyElements`), `PerfTestsMenuWiringTests` (экран «Перф-тесты», вход только с «Отладки»,
«Назад»).

Каждый наследник отвечает только за свою логику (например, `MenuSessionSetup` сам рисует сетку кнопок карт из `MapRegistry` и управляет своими вкладками). `MenuScreen` предоставляет виртуальные методы `Show()` и `Hide()`, в которых экраны могут запускать анимации, подписываться на эвенты или сбрасывать свое состояние.

## Как это работает на практике

1. **Сцена Грузится**: Игрок подключается к лобби (`Lobby`).
2. **Инициализация**: `LocalMenuManager` понимает, что мы в `SceneMenuContext.Lobby`. Роль игрока — `VRAdmin`.
3. **Реестр**: Из `MenuPrefabRegistry` выбирается префаб `PlayerAdminLobbyTabletMenu`.
4. **Спавн**: Префаб появляется на сцене (но выключен), передается в `MenuController.RegisterView()`.
5. **Взаимодействие**: Игрок нажимает кнопку меню на контроллере.
6. **Открытие**: `MenuController` телепортирует префаб перед игроком, включает его `GameObject` и вызывает `Show()` у активного `MenuScreen`.
7. **Смена панели**: При нажатии кнопки переключения вкладки (например, `SwitchMenuButton`), она вызывает `MenuController.SwitchTo(targetScreen)`. Старый экран вызывает `Hide()`, новый — `Show()`.

## Создание нового меню

Если вам нужно создать **новую панель в планшете**:
1. Дублируйте существующий префаб экрана (например, `Screen_Main`).
2. Измените его Canvas, добавьте свои UI-элементы.
3. Напишите новый скрипт-наследник `MenuScreen` (например, `MenuPlayerStats`).
4. В префабе планшета (например, `TabletMenuBase`) добавьте новую кнопку и повесьте на нее скрипт `SwitchMenuButton`, указав в `Target Screen` вашу новую панель.

Если вам нужно создать **кастомный планшет для нового режима**:
1. Сделайте префаб нового планшета (важно, чтобы в корне были компоненты `MenuView` и `UxrGrabbableObject` / `Rigidbody` для физики в VR, и корень имел поворот 0, 0, 0).
2. Настройте стартовый экран в `MenuView`.
3. Откройте `MenuPrefabRegistry.asset` и в секции `RoleConfigurations -> SpecificGameModeMenus` добавьте привязку: `MyNewModeAsset` -> `MyNewTabletPrefab`.
