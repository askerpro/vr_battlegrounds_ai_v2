# Инварианты оружейной системы

Нарушение любого пункта — повод остановиться и предложить архитектурное решение, а не обход.

## Владение

1. **Одно решение — одно место.** Все решения о механизме принимает `WeaponStateMachine` по одной таблице
   переходов. Новое поведение — новая строка/сигнал машины, а не флаг в компоненте.
2. **Один источник факта.** Учёт патронов — только SDK; машина выводит механическое состояние из `LedgerView`
   на каждом шаге и не хранит копий. Магазин знает только гнездо. Дублированный факт = будущий рассинхрон.
3. **Один писатель на канал.** Поза, звук механизма, вибрация, подсказка — по одному исполнителю внутри хоста.
   Второй компонент, пишущий тот же Transform/звук, запрещён (классы ошибок 1, 2, 4).
4. **Исполнители не решают.** Они получают цель и данные; учёт не читают.
5. **Машина без Unity и SDK** (`noEngineReferences`). Причины отказа — свой `WeaponNotReadyReason`.

## Сеть

6. Команды учёта — только автор (`StateEventAuthority.IsAuthorOfItem`) и вне replay (И9). Синхронизируемое
   действие из Update/таймера/физики/RPC/хука — только с проверкой авторитетности.
7. Никаких новых Mirror Cmd/Rpc в WeaponSystem; передача — фиксации учёта UXR. Имена Cmd `CartridgeIntake` не
   менять.
8. Звуки механизма и поза — у всех (из реплицированных фиксаций); сухой щелчок, отказ, вибрация, подсказка —
   только у автора.
9. Расхождение учёта — `GameLog.WeaponSystem.Error`, игра продолжается (стрельба не блокируется).

## Данные и авторинг

10. Префабы оружия меняет только writer `WeaponSystemAuthoring` с preflight и readback; руками .prefab не
    правится. Ствол без строки таблицы writer не настраивает.
11. Отклик: у ствола только оверрайды, дефолт категории подставляет исполнитель при проигрывании; writer дефолты
    не копирует, оверрайд, равный дефолту, снимает.
12. Звук сигнала не может быть «тишиной» (< −40 dBFS) — ошибка preflight. Одинаковые клипы оттяжки и возврата —
    предупреждение.
13. События не склеиваются ради звука: разные смыслы — разные сигналы, даже если звук один
    (`ActionReturnPartial` и `ActionForwardEmpty`).

## Захват

14. Своя вторая рука не перехватывает огнестрел (`ManipulationConstraints.AllowHandTransfer = false`);
    решение «что запрещено» — в `ManipulationConstraints`, механика — в `TwoHandGrabPolicy`, подключение — одна
    цепочка `GrabRules`.

## Инициализация

18. Учёт ствола инициализируется по готовности ствола, а не однократно: пока `Uninitialized`, автор повторяет
    `Initialize` (хват, магазин, спуск, смена автора, бот). Отказ учёта — законное состояние, «мёртвый» ствол — дефект.

## Процесс

15. Изменённую механику сначала проверяет пользователь в шлеме; тесты на неё пишутся после приёмки, в той же
    задаче. До приёмки — компиляция, существующие проверки, список устаревших ожиданий, шаги проверки.
16. Коммит кода/ассетов — только после проверки пользователем; вливание — через хаб (verify → accept →
    merge-request → merge-execute), fast-forward, без force-push.
17. SHA — только из git. Логи — `GameLog.<Канал>`, никогда `Debug.Log`.
