# Целевое видение оружейной системы

## Для игрока

Оружие ведёт себя как настоящее и предсказуемо: каждый механический жест (оттянуть, отпустить, вставить, дослать,
нажать) даёт понятный отклик — поза, звук, вибрация, подсказка. Ошибка игрока (не дослал, пустой магазин,
нажал в паузе) всегда объясняется откликом, а не молчанием. Другой игрок видит и слышит то же, что и стрелок
(кроме личных подсказок). Руки не делают того, чего игрок не хотел (случайный перехват, хват не за ту точку).

## Для разработки

- Новый ствол — строка таблицы `WeaponSystemAuthoring.Weapons` + данные (профиль, rig, оверрайды), без нового кода.
- Новая механика — новые строки машины и сигналы, один исполнитель на новый канал. Структурные тесты таблицы
  (полнота, инварианты) ловят дыры до шлема.
- Сеть не требует отдельной работы: всё, что реплицируется, — фиксации учёта SDK.
- Боты используют то же оружие через контекст использования (`WeaponUseContext`), а не обходные пути.

## Куда идём (крупно)

1. Весь арсенал на машине, включая револьверы и SDK Shotgun (F5).
2. Визуальная достоверность: вылет патрона и гильзы, позы, звуки без дублей (нарезка клипов Kinemation).
3. Решение о выстреле — в машине (этап E), SDK — только хранилище, транспорт и выпуск снаряда.
4. Вибрация через общий `HapticService`, отдача — сигнал WeaponSystem.
5. Патроны как предметы: ручное заряжание револьвера, пачки (спидлоадер, коробка) для револьвера и дробовиков.
6. Боты на той же системе (use-context).
7. Удаление прежних компонентов (cleanup-h), документация в `Docs/weapons/`.

## Что значит «готово» для этапа

Работает в шлеме у пользователя (и у наблюдателя на втором клиенте, если механика сетевая) → тесты на принятую
механику → влито через хаб → статус и журнал решений обновлены.
