# Как эксперт ведёт задачу по оружию

Общие правила — `AGENTS.md` (канонический вход) и `.agents/rules/agent_coordination.md`. Здесь — выжимка и
грабли, на которых уже спотыкались.

## Цикл задачи

1. **Оценка.** Сверить запрос с `vision.md`, `invariants.md`, `decisions.md`. Найти владельца каждого
   затронутого канала (`architecture.md`). Если запрос требует второго писателя или копии факта — остановиться и
   предложить архитектурное решение. Развилки — пользователю, с рекомендацией первой.
2. **Этап.** Строка в `tasks/weapon-system/plan.json` (writes — минимальные; папочные `.meta` явно; общие
   журналы/индексы нельзя). Порядок с соседними этапами своей задачи — через `after`, иначе UNORDERED_OVERLAP.
   `register --expected-revision N` → `begin --ttl 7200`. Любая правка `plan.json` блокирует запись до
   повторной регистрации; правка writes RUNNING-этапа — stop → register → begin.
3. **Делегирование.** Реализацию отдать субагенту с брифом: цель, решения, архитектурные рамки, права записи,
   правила Unity и координации, что вернуть. Самому — решения, контракты, Readme/plan, общение с пользователем.
   Параллельные писатели — только с непересекающимися файлами.
4. **Проверка доказательств.** Дифф, отчёты аренды, фактические результаты тестов. Сообщение субагента об
   успехе — не доказательство.
5. **Шлем.** Аренда → сцена `Assets/Scenes/Offline.unity` → Play → чек-лист пользователю по стволам/категориям.
   Пока пользователь смотрит — аренду держит фоновое продление; после — stop Play, finish, receive.
6. **Тесты после приёмки** (в той же задаче), прогон в worker.
7. **Вливание.** Коммиты по логическим единицам → rebase на origin/dev → офлайн-компиляция → `verify --sha`
   → `accept` → `merge-request --base` → `merge-execute` → `editor-broker.py request-base` для новой базы.
   Брокер откажет в аренде, если дифф к базе содержит пути вне writes этапа: коммиты другого этапа держать в
   отдельной ветке.
8. **Статус.** Readme задачи (≤400 слов), журнал этапа `tasks/weapon-system/changelog/<дата>-<этап>.md`,
   новые решения — в `decisions.md`.

## Unity (linked worktree)

- Мутации — только в своей аренде: checkpoint → request (`--base` = опубликованная база) → watch-ticket →
  claim → begin → guard → MCP → finish → receive. Request с базой, которой нет в публикации, отказывает —
  `request-base` для принятого SHA.
- Первый MCP-вызов после переключения воркера часто «session disconnected»: guard и повтор.
- Во время EditMode-тестов Unity не отвечает MCP — это не зависание; смотреть Editor.log и CPU.
- Сразу после тестов открыть сцену Offline (иначе модальное окно вешает главный поток → RECOVERY_REQUIRED).
- Finish сразу после пакета действий, не держать аренду пока думаешь или ждёшь человека (кроме шлема).

## Грабли

- **Никогда не `cd` в подпапку в Bash.** Хук координации определяет задачу по папке оболочки и после этого
  блокирует все команды, включая `cd` обратно. Только абсолютные пути и `git -C`.
- **SHA — только из git.** Однажды напечатанный по памяти SHA сломал merge-request.
- Тело `coordination.py message` — одна строка без кавычек внутри.
- После вливания у задачи нет активного этапа: хук блокирует запись (кроме Readme/Details/plan.json и reports/).
- Офлайн-компиляция без Unity — `tasks/weapon-system/tools/compile.ps1`; фоновые `wait-claim.ps1` (offer → claim
  сразу, предложение истекает) и `permit-renew.ps1` (допуск, пока пользователь в шлеме) — там же
  ([tools/Readme.md](../../tasks/weapon-system/tools/Readme.md)). Хук может не дать остановить фоновую задачу —
  останавливать удалением флага.
- «Оружие не стреляет нигде, учёт отклоняет команды»: сначала искать исключение в чужом коде внутри синхронизации
  SDK — оно оставляет `UxrStateSyncImplementer.SyncCallDepth > 0`, и учёт считает каждую команду вложенной (так было
  с `_avatarRenderers` Cyborg, исправлено avatar-renderer-regression f33e5f4e). «Не стреляет только в раунде» —
  отказ `Initialize` при `WeaponSystemEnabled=false`, лечится повтором (architecture, «Инициализация учёта»).
- Номер SDK-патча — только `coordination.py patch-reserve` (номер «по памяти» уже оказался занят: 68 → 69).
- `inbox`/`accept` и другие команды координации — отдельной командой, без конвейера `|`: иначе хук считает их
  небезопасными.
- Правка `plan.json`, пока субагент держит аренду своего этапа, ломает его `stop` — план менять только между этапами.
- Полный EditMode — ~2500 тестов, ~4 минуты; ~85 красных вне оружия известны (см. roadmap).
