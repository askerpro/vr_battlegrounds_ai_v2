# Tools/Perf — инструменты замеров производительности (зона performance)

## quest_gpu_breakdown.py — разбивка времени GPU на Quest

Снимает `ovrgpuprofiler` (системная утилита Quest, `/system_ext/bin/ovrgpuprofiler`) в нужной фазе стресс-теста.
Правок в коде приложения не требует: скрипт слушает logcat и при строке `=== фаза «база»` / «куклы…» ждёт
успокоения и запускает профайлер через adb. Сам прогон запускается отдельно — `Tools/e2e/Run-QuestE2E.ps1`
со сценарием `perf-stress`.

Два прохода:

- `--pass realtime` — метрики реального времени (`-r`): загрузка GPU, доля времени на вершины против фрагментов,
  простои текстур/памяти. Без детального режима — числа годны для оценки.
- `--pass detailed` — детальный режим драйвера (`-e` до запуска приложения, в конце `-d`): трасса поверхностей и
  стадий рендера (`-t`), то же с метриками на стадию. Режим сам нагружает GPU — только доли, не бюджет.
  Трасса drawcall-ов (`-x`) пока не снимается: профайлер отвечает «No metrics to track!».

Порядок: сначала запустить скрипт (он ждёт фаз), затем прогон.

```
python -X utf8 Tools/Perf/quest_gpu_breakdown.py --pass realtime --out <задача>/reports/gpu/A
powershell -ExecutionPolicy Bypass -File Tools\e2e\Run-QuestE2E.ps1 -Scenario perf-stress -Arg "mode=map-only,phase_s=60"
```

Условия каждого замера (сборка, ревизия, шлем, FFR, уровни, сцена, ракурс) записываются рядом с результатом:
число без условий — не факт. Ракурс одного лежащего шлема между прогонами несравним — для сравнения сцен нужны
фиксированные точки обзора (`E2EViews`).
