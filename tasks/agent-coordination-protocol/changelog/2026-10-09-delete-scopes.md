# Допуск операций удаления

Причина: запрет новых материалов в Docs/tasks ошибочно исключал и миграционное
удаление старых документов. Вводится общий список deletes с точными путями.
Это разрешение операции, а не исключение для имён двух файлов arsenal-generator.

Область удаления участвует в проверке пересечений этапов. Нативный хук проверяет
Delete File отдельно от Add/Edit/Move. При интеграции и перед worker фактический
Git diff проверяется по типам изменений, а не только по именам путей.

Пример владельца arsenal-generator:

```json
{
  "id": "legacy-doc-cleanup",
  "writes": ["tasks/arsenal-generator/**"],
  "deletes": [
    "Docs/tasks/arsenal-generator-design.md",
    "Docs/tasks/arsenal-generator-plan.md"
  ],
  "after": [],
  "needs": []
}
```

Владелец проверяет сохранность содержимого и ссылки, регистрирует план, получает
допуск и удаляет файлы нативным Delete File либо через общую команду
coordination.py delete --token <stage-token> --path <точный путь>.
У Claude нет отдельного нативного Delete File: команда позволяет удаление без
расширения допуска на произвольный shell. Мы не удаляем документы за владельца.
Произвольный shell существующих этапов с writes не становится песочницей;
deletes сам по себе такого разрешения не предоставляет. Проверка Git diff —
обязательный барьер перед интеграцией, не доказательство безопасности shell.
