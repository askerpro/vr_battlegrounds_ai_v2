# SDK-патч 73: движение клиповых ботов при старте и стрельбе назад

Дата: 2026-10-10. SDK: BlazeAI. Владелец: bots-fix.
Номер зарезервирован через coordination.py patch-reserve, ключ
`clip-motion-start-and-backwards-fire`.

Независимое source-review выявило два дефекта: ожидание normalizedTime движущегося
клипа блокирует старт при animation rate=0; стрельба во время отхода назад переключает
полнотельную анимацию на статический Shoot при продолжающемся движении корня.

Область: только BlazeAI.cs и Behaviours/CoverShooterBehaviour.cs. Для external Animator
нужен старт движения без ожидания прогресса цикла и сохранение locomotion во время
backward attack. Обычный путь Blaze должен сохранить прежнее поведение.

Статус: реализация выполнена в двух объявленных файлах, diff --check PASS.
External gate проверяет текущий state и завершение CrossFadeInFixedTime без ожидания
normalizedTime. Факт движения снимается с NavMeshAgent.nextPosition в текущем кадре;
disable/невалидный агент сбрасывают или исключают этот сигнал. Backward attack сохраняет
locomotion только при таком движении. Независимое review не выявило critical/important.
Свежая компиляция Blaze/Product/Stand/DebugBootstrap/Editor: exit0, 0 ошибок;
114 overlay-хешей и 99 собственных исходников совпадают. Отчёт —
`reports/armed-context-compile/compile-blaze73.log`; полный SDK72 consumer ещё не включён.
Unity должен проверить startup при rate=0 и совпадение simulation delta с движением корня;
SDK-документация и static review не являются доказательством этого runtime-поведения.
Не является принятым изменением. Gameplay-тесты до пользовательской приёмки не меняются.
