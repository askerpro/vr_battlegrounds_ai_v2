# Mirror SDK patch6: Host authentication на фактически загруженной карте

Задача `bots-fix`, owner `bots`, резервирование `Mirror/6`, key
`host-auth-actual-network-scene` (2026-10-18). Техническая подготовка;
пользовательская приёмка и принятый commit отсутствуют.

Unity793 на input491bf8ec воспроизвёл базовый direct-map дефект: PlayLaunch Host/Player
загрузил TestMap1 при настроенной onlineSceneLobby. Mirror authentication ожидал Lobby,
пропускал обычный Ready; единственное существующее сообщение подключения не отправлялось.
У Host session/avatar0, ClientReadyfalse, ClientSpawned0. Remote Player подключался
и переподключался штатно. Причинный разбор: `../reports/native793/analysis.md`.

Изменение предназначено единственному владельцу pending-scene состояния —
`Mirror.NetworkManager.OnClientAuthenticated`: локальный Host с уже загруженной
фактической networkScene проходит существующую ветку без ожидания новой загрузки.
Ready, connect-message и создание аватара остаются на обычном пути. Loading-флаги
защищают новую ветку; onlineScene/offlineScene не переназначаются патчем.

Сопутствующая игровая policy: HeadlessPrecacheGuard различает pendingHost через
установленный Mirror mode; ещё не активный local client сам по себе не означает
ServerOnly. Configured UsePrecaching сохраняется, SDK запускается от настоящего
LocalAvatar. Уже выключенный флаг пережившего ServerOnly экземпляра здесь
не восстанавливается; этот отдельный переход не проверен.

Ревью направления network не выявило блокеров. После реализации требуются
SHA-review, source compilation свежего Mirror и Unity Host direct-map: собственные
session/avatar, LocalAvatar, прогрев/очистка, remote rejoin и последующая смена карты.
Новых тестов до пользовательской оценки качества не добавлять. Unity793 предшествует
исправлению и не подтверждает его работу.
