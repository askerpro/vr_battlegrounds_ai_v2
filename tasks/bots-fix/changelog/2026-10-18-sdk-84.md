# SDK patch 84 — выбор позы кистей внешнего бота

Дата: 2026-10-18. Задача: `bots-fix`. Резерв номера: principal, ключ
`external-hand-pose-selection`. Статус: исходники подготовлены; общая компиляция,
Unity/сетевая проверка и пользовательская приёмка качества впереди.

## Причина и происхождение

У `UxrAvatarMode.UpdateExternally` стадия Animation применяет уже выбранную позу
через `Avatar.UpdateHandPoseTransforms()`. Выбор через `ProcessControllerEvents`
остаётся в полном проходе контроллера для Local. Событие хвата вызывает
`UpdateGrabPoseInfo`, но этот метод только обновляет event override и blend;
`SetCurrentHandPose` он не вызывает. Дополнительно setter event override ничего
не сохраняет, если у стороны нет grab-event (`GrabEventIndex = -1`).

Патч добавляет в `UxrStandardAvatarController.cs` публичный
`UpdateExternalHandPoseFromGrabState(UxrHandSide)`. Он работает только в режиме
UpdateExternally и вне входящего StateSync. Для фактического `Avatar.GetGrabber(side)`
и его `GrabbedObject` использует существующие `UxrGrabManager.GetOverrideGrabPoseName`
и `GetOverrideGrabPoseBlendValue`: владельцем правил точки/GUID-цепочки остаётся SDK.
Непустое authored имя обязано существовать в runtime-позах аватара; иначе возвращается
false без подмены fallback. При отсутствии authored override используется исходная
grab-поза стороны (`InitialHandGrabPoseName`), включая прежний sentinel blend `-1`
для fallback/Fixed. Пустой fallback также возвращает false. Для свободной руки
очищаются stale grab override/blend и выбирается side default override либо
`Avatar.DefaultHandPoseName`. Пустая или отсутствующая default-поза даёт false.

`BotAvatarDriver.cs` кэширует стандартный контроллер и вызывает selector в
`StageUpdated(Manipulation)`, после штатного выравнивания хвата и перед Animation.
Обе стадии драйвера проверяют `_hasFrame`, `CanDrive`, StateSync и состояние тела:
сервер/хост, автор мира, аватар без владельца, живой бот либо `DrivesDeadBody`.
Tracking-stage `Apply()` сохраняет прежнее место и порядок Transform-записей.
После Manipulation выбирается только состояние позы; пальцы по-прежнему пишет
один штатный проход Animation, руки решает прежний IK. Ввода контроллеров,
TryGrab/TryRelease, полного UpdateAvatarAnimation, второго транспорта и второго
обновления костей нет. `SetCurrentHandPose` сохраняет собственный BeginSync/EndSync.

Диагностика: `HandPoseSelectionFrame`, `LeftHandPoseSelected`,
`RightHandPoseSelected` отражают фактический результат selector, а не качество
контакта пальцев. Отказ журналируется через `GameLog.Player.Warning` один раз на
непрерывный эпизод отказа каждой руки; успешный выбор снимает подавление.

## Фактические проверки и границы

- `git diff --check` для пяти изменённых C# файлов: код выхода 0, whitespace-ошибок нет.
- Физические пять C# файлов и эта запись проверены по байтам: CR отсутствуют, LF.
  У SDK-путей Git предупреждает о возможном LF → CRLF при следующей материализации;
  перед checkpoint principal должен отдельно проверить staged blob согласно EOL-контракту.
- Просмотр scoped diff: только новый selector, вызов в Manipulation, общий guard,
  компактная диагностика и комментарии; `UxrManager` этим патчем не изменён.
- Общую компиляцию выполняет principal после консолидации исходников.
- Unity, host/client, late join, визуализация пальцев и Quest этим этапом не запускались.
  Новые/переписанные тесты, smoke и managed probes не создавались.

## Уточнение по аллокациям после ревью, 2026-10-18

В исходном SDK `SetCurrentHandPose` создавал `UxrAvatarHandPoseChangeEventArgs`
до `HandState.IsChange`, включая неизменную позу. Дополнительно канонические
grip name/blend resolver использовали `GetGripPoseInfo` с yield-обходом GUID-цепочки;
getter default-позы использовал yield `GetAvatarChain`.

После штатного завершения Unity783 scope SDK84 расширен тремя файлами:

- `UxrAvatar.HandState.cs`: перегрузка `IsChange(string, float)` содержит прежнее
  сравнение имени и значимого blend; версия с EventArgs делегирует ей, сохраняя
  прежний немедленный true при отсутствии текущей позы. Порог `BlendEpsilon=0.005f`
  остаётся единственным и не копируется в ботов.
- `UxrAvatar.cs`: после прежней проверки доступности runtime-позы `SetCurrentHandPose`
  вызывает эту перегрузку и создаёт EventArgs только при изменении. Порядок событий,
  BeginSync/EndSync и `HandState.SetPose` сохранён. `GetDefaultPoseInHierarchy` читает
  текущие `_defaultHandPose` прямым проходом this → ParentAvatarPrefab без iterator.
- `UxrGrabPointInfo.cs`: существующий canonical `GetGripPoseInfo(UxrAvatar, bool)`
  обходит ParentAvatarPrefab и список записей напрямую. Сохранены первый match,
  порядок GUID, исходный пустой GUID без обхода родителей, участие пустого GUID
  родителя, поведение `usePrefabInheritance=false` и возврат DefaultGripPoseInfo.

Новые кэши изменяемых данных, события или владельцы выбора не вводятся.
Фактический grab point и живые HandPose/PoseBlendValue по-прежнему получает SDK
на каждом вызове. Release/regrab, reload, смена точки, GUID-цепочки, тела и defaults
не зависят от наличия отдельного события инвалидирования. Сравнение выполняется
с текущим состоянием аватара, поэтому sub-epsilon blend накапливается относительно
реально выбранного значения; чужая смена позы не скрывается last-request кэшем.
Существующие mode/authority/live/входящий StateSync guards selector/driver сохранены.

После замечания ревью о `ParentAvatarPrefab → GetComponent` в том же `UxrAvatar.cs`
добавлен только положительный кэш связи ParentPrefab GameObject → UxrAvatar.
Каждый getter проверяет актуальный ключ ParentPrefab и Unity-null компонента;
смена ключа либо уничтожение компонента вызывает новый GetComponent. Отсутствующий
ParentPrefab очищает ссылки. Отрицательный результат не считается попаданием:
следующее обращение повторяет поиск и видит runtime AddComponent/replace.
`[DisallowMultipleComponent]` исключает второй живой UxrAvatar на том же объекте;
отключённый живой компонент возвращается как прежде. На стабильной корректной
цепочке покадрового GetComponent нет; при отсутствующем компоненте повторный lookup
необходим для сохранения динамической семантики без отрицательного кэша.
Приватные поля кэша не сериализуются, не требуют registry/eventbus и не сохраняют
defaults, GUID, pose, blend или grip entries. Сам direct traversal продолжает
читать эти значения каждый вызов. Пакет исходников готовился отдельно от pinned
Unity785; этот runtime-input не изменялся данным уточнением.

Статически устранены подтверждённые EventArgs/yield-аллокации неизменного пути.
Это не замер общего GC=0: существующие resolver/default getter продолжают читать
Unity `Object.name`; native string marshalling и общий кадр требуют профайлера
на актуальном объединённом input. Изменение позы по-прежнему создаёт штатные
синхронизируемые события. Компиляция и runtime-проверка обновлённого SDK84 впереди.

## Ручная проверка качества

1. На ownerless серверном боте с UpdateExternally записать avatar source GUID,
   оружие, реальный grabber/точку/сторону, authored pose и blend через SDK resolver;
   сопоставить с `GetCurrentRuntimeHandPose(side)` и `GetCurrentHandPoseBlendValue(side)`
   после выбора. Проверить отдельные Fixed и Blend, обе руки.
2. Убедиться, что `HandPoseSelectionFrame` обновляется после Manipulation, результат
   true соответствует найденной позе, а пальцы переходят в неё в штатной Animation.
   Сравнить фактический контакт и проваливания пальцев старого/нового аватара.
3. Проверить authored позу у стороны без grab-event: выбор должен идти по реальному
   хвату. При отсутствующем authored override проверить configured grab fallback;
   пустой fallback и непустая authored поза, отсутствующая у аватара, должны оставаться
   видимым отказом без подмены другой позой и без потока одинаковых предупреждений.
4. После отпускания проверить default override соответствующей стороны либо default
   аватара, отсутствие оставшегося held blend; после следующего успешного выбора новый
   отказ должен снова дать одно предупреждение.
5. Проверить смерть до замены тела, ghost/DrivesDeadBody, respawn и смену оружия;
   сопоставлять кадр диагностик со стадией тела. Входящий StateSync и аватар человека
   не должны становиться источником выбора через BotAvatarDriver.
6. Проверить host и удалённый клиент, включая late join: имя/blend и пальцы приходят
   штатной синхронизацией. Отдельно выполнить Quest/визуальную приёмку пользователем;
   только после неё закреплять принятую механику новыми тестами.
