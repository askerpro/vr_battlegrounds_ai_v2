# SDK patch 86 — кеш discovery конфигурации готовности

Дата: 2026-10-18. Задача: `bots-fix`.
Резервирование: `readiness-provider-discovery-cache` (номер 86 выдан хабом ведущей сессии).

Причина: ревью оружейной зоны `5d0cb2fea9f64d61`, candidate `48b27cf2`, выявило повторный
`GetComponents` в каждом запросе `UsesReadinessLedger` для legacy-спуска без provider,
включая обновления аватаров вне хвата.

В `UxrFirearmWeapon.Readiness.cs` кешируется подтверждённое отсутствие provider.
Обычный запрос использует кеш после проверки индекса и защиты от рекурсии. Установка,
входящая фиксация, поправка и снимок сохраняют принудительный discovery. Свежий claim
удаляет отрицательную запись; принятая конфигурация и sticky-отказ не сбрасываются.

Публичный `RevalidateReadinessConfiguration(int)` повторяет только discovery/классификацию,
не записывая ledger или боезапас. `WeaponSystem.Prepare` вызывает его до проверки данных,
чтобы добавленный невалидный хост закрыл прежнюю legacy-классификацию даже при отказе
установки порта. XML-контракт provider требует явного уведомления после изменения его
конфигурации или состава компонентов для каждого затронутого спуска. Автоматическое
обнаружение произвольного `AddComponent` без уведомления не гарантируется.

Проверка этого изменения ограничена статическим diff и LF; компиляцию объединённого input
выполняет ведущая сессия. Unity/runtime, стоимость кадра и пользовательская приёмка
этого изменения пока не подтверждены. Новые и переписанные тесты не создавались.
