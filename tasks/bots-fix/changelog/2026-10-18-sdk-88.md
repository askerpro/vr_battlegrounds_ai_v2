Unity795 после обычного remotePlayer rejoin сохранил минимум159 Unity-null записей
в сыром UxrComponent GUID dictionary и destroyed UxrLaserPointer при перечислении
EnabledComponents. Два синхронных снимка отстоят на63.956с. SDK77 глобально пропускает
такие записи при перечислении, но прямой UxrComponent getter их видит. Это не ошибка
diagnostic getter и не доказательство, что все159 принадлежат одному конкретному телу.

Recursive CombineUniqueId регистрирует inactive children до Awake. Внешний Mirror
destroy не проходит штатный children.Unregister перед Destroy, а never-active children
не получают Unity OnDestroy. Не менять общий NotifyNetworkDespawn(false): FishNet
вызывает его при обратимом stop, false означает внешнего владельца уничтожения.

Реализован один фиксированный набор участников tracked CombineUniqueId в SDK; адаптер
UxrMirrorAvatar сохраняет managed references ДО регистрационных callbacks и применяет
существующий terminal/idempotent Unregister только в фактическом OnDestroy адаптера.
Тот же набор используется для UID/StateSave/StateSync. Обычный публичный API сохранён.
Cleanup гарантирован finally относительно logging/NotifyNetworkDespawn, проходит всех
участников независимо, освобождает receipt и лишь затем сообщает aggregate failures.
Unity-null wrapper нельзя пропускать обычным component==null. OnStopClient/Server и
reusable UnSpawn не выполняют terminal retirement; receipt не теряется при partial init.

Receipt — локальная квитанция принадлежавшего этому аватару authored registration scope,
не реестр поиска. Reparent сам по себе не передаёт lifetime. Перенос живого authored
участника другому владельцу потребовал бы явной передачи квитанции; такого пути в
просмотренных игровых callers нет. Динамически созданные позже предметы имеют собственный
lifetime и автоматически в набор аватара не входят.

До пользовательской оценки качества новых тестов/expectations нет. Нужны compilation,
неизменённые применимые проверки, actual runtime destroy/rejoin с rawregistry и formal
network review по новому SHA. Исторические795/797 новый патч не проверяют.
