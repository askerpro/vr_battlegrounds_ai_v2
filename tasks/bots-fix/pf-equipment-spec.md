## Цель

В режиме PlayerFlow бот проходит полный цикл снаряжения как игрок:
1. **Пистолет из кобуры.** Стартовый PPK лежит в кобуре (StartingSidearmPolicy). Бот подводит руку к кобуре
   (видимая траектория, не телепорт), берёт пистолет штатным хватом SDK, поднимает на прицел, поддержка — второй рукой.
2. **Без оружия (Unarmed).** Кисти в позе покоя относительно тела (драйвер пишет их как контроллеры, IK штатный);
   Blaze не атакует/не стреляет без оружия; бот может идти к покупке.
3. **Покупка.** Купленный ствол (штатный серверный путь экономики, BotShopper/BuyPlan) появляется у кисти
   (разовая начальная поза до SpawnServerObject — согласовано manipulation 4259). Если в руке пистолет — сначала
   убрать его в кобуру (поднести к якорю кобуры и отпустить штатным путём размещения SDK) или иной штатный путь,
   который есть у человека; затем взять покупку. После перехвата — RequestAutomationPreparation заново.
4. **Смерть.** После `!IsAlive` бот перестаёт хватать и командовать кистями; отпускание при смерти делает сервер
   (gameplay deferred-body: AvatarTeardown.ReleaseBeforeDestroy/ReleaseHandsOnServer) — свой сброс НЕ добавлять.
   Проверить: оружие падает/остаётся как у человека, нет ошибок, драйвер не пишет в уничтожаемое тело.
5. **Призрак и новое тело.** Выяснить, что получает бот после смерти (ghost-аватар как у игрока?). Бот-компоненты
   (драйвер, руки, прицел) — только на живом теле бота; на призраке их нет или они выключены; при новом теле
   (раунд/респаун) компоненты добавляются заново ровно один раз. Призрак бота ничего не пишет и не стреляет.

## Условия зон (из ревью и этапа 0)

- avatar-ik: один писатель на кость; адаптер пишет только корень, камеру, Left/RightHandBone до Manipulation; живой
  скелет не читает; траектория подвода руки — тоже команда драйвера. Diff — avatar-ik на ревью ДО вливания.
- manipulation: хват — CanBeGrabbedByGrabber → GrabObject(..., true) или TryGrab; primary → support; Release/Place
  только автор; без выхвата из чужой руки; геометрию снапа/якоря не кешировать; размещение в кобуру — штатный путь
  SDK (UxrGrabbableObjectAnchor, правила GrabRules/PlayerGrabManager), без прямой записи позы предмета.
  Diff — manipulation на ревью до вливания (якоря/размещение — их зона).
- weapon-system: выстрел только после true от RequestAutomationPreparation, после перехвата — запрос заново;
  профиль готовности — с WeaponSystem префаба.
- gameplay: покупки — штатный серверный путь экономики; смерть/призрак — их правила (deferred-body), без бот-веток в
  AvatarManager/AvatarTeardown/PlayersManager. Правки в их зоне — только через zone-request и diff.
- network: всё действие — сервер, из Update/LateUpdate верхнего уровня, не из обработчиков событий UXR;
  новых SyncVar/Cmd/Rpc нет; на клиентах бот-компонентов нет.
- performance: маркеры на новые подсистемы, без аллокаций в установившемся режиме.
