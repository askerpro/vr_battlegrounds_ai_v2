# G visual: отдельный кандидат для владельца хвата8388

Пакет C#6 execute_code, 2026-10-15. Назначение — reviewable evidence обеих рук old/new в реальном G с Capture=true. `observed` означает только завершение наблюдения. Никакой payload не выдаёт grip/gameplay PASS; ownerDecision всегда UNKNOWN. HandReach/handToSnap и отсутствие ошибок не заменяют визуальную приёмку.

## Источник и маршрут

Исполнитель — главный агент, только через свою RUNNING broker lease и текущий immutable input. SDK-копий пакет не содержит. Во всех пяти payloads выбрать одинаковый новый Root, ещё не существовавший в reports/; в B4/B5/B6 одинаковый Marker. Источник — текущий candidate с фактическими hashes. Snapshot738 уже закончен: его frame/pose/body IDs новым прогоном не восстанавливаются. Новый evidence не называть exact738. После любого timeout сначала B5 и broker durable state; B3/B4 не повторять при неизвестном исходе.

B0/B3/B5/B6 — узкая адаптация canonical cc1 payloads, B4 запускает только G. Полный Blaze-observer из canonical B4 здесь не копируется: штатный стенд пишет playerFlow/damageTrace; этот пакет добавляет руки/capture. Для совместного Blaze-observer нельзя второй раз запустить RunCases. Applicable controller/B1 и broker preflight основной агент выполняет отдельно, как в текущем cc1 маршруте; контроллер payloads не регенерируют.

## Исполнение

1. До worker request: проверить свой checkout/input и source ownership; offline compile пяти snippets как C#6 execute_code. Главный агент использует существующий `tasks/bots-fix/tools/cc1-round1/compile-check.ps1 -PayloadDirectory <полный путь к cc1-visual>`. Тесты/asset writes этим пакетом не предусмотрены.
2. B0: idle EditMode, чистые сцены, нет PrefabStage, PlayLaunch Idle, свободный stand, нет чужой HandPoseFit capture. Пишет preflight.json с SHA256 current dependency assets и bot/stand/fit sources. Play/asset состояние не меняет. При отказе не продвигаться.
3. B3: штатный Prepare→PlayLaunch→warmup с domain reload. Прямой EditorApplication.isPlaying=true не используется. B5 до own warmup finished без InvalidFixture; затем B4 один раз.
4. B4: G T07/101/40с, AK105, kill8/respawn20, normal recoil+spread, Capture=true, HandFit=false, ObserveShotTail=false. Он ждёт фактический Fired>=1 и две текущие SDK primary/support точки одного оружия. Снимает максимум одну пару old и одну new; ghost не инсценирует. Чужие HandPoseFit jobs не создаёт/не отменяет.
5. В одном AvatarsUpdated: runtime pose/asset/blend обеих рук и side/grabpoint/grabber/grabbable/weapon/body/session/source IDs; синхронное замораживание двух runtime HandPoseFitSnapshot; затем штатный BotStandVisualCapture даёт5PNG (front/side/angle/Right/Left). Никакого SetPose/snap/IK или смены live материалов. Pre/post fingerprint child TRS и renderer enabled/shared material IDs выявляет наблюдаемое изменение внутри capture; это не гарантия отсутствия любых внешних render callbacks.
6. Frozen meshes анализируются в Editor.update по одному, всего максимум4 задания. SampleCount1000, PadSamplesPerFinger128, ContactWindowMm2/ProximityMm2, без overrides/offsets/ApplyGripRules/коррекции. Кадры могут удлиниться: прогон не performance evidence и не exact738 timing.
7. B5 до observed+detached+pendingAnalysis0 и currentRun.IsFinished. B3 сохраняет exact launchRunId/owner в launch-identity.json; B4 сверяет его с PlayLaunch/stand и проверяет warmup report этого Root. B6 без этого receipt не выводит ownership из одного owned=true. До B4 он работает только с exact warmup runId/report; после visual-start-intent требует именно сохранённый G runId/report, никогда не подставляет вместо потерянного G id warmup/чужой stand.
8. Cancel (включая B4 watchdog), Stop и Restore предварены FileMode.CreateNew+Flush(true) intent. B4/B6 используют один stand-cancel-intent.json; существующий intent означает inspect-only, не replay. После Cancel подтверждённый exact currentRun.IsFinished позволяет отдельный guarded Stop; существующий stop-intent означает только B5 до terminal. B5 terminal=true означает exact launch, playing/willChange=false, State=Idle, CleanupPassed=true. После этого B6 допускает только идемпотентную свою callback/snapshot cleanup и, если ещё нужна, однократно guarded Restore. Любая ошибка/нехватка пары/неизвестный source остаётся UNKNOWN. B5 дополнительно проверяет owned=false/captureCameras0. После нормального cleanup — штатный finish/receive без ожидания человека в аренде; активную операцию через finish не освобождать.

## Evidence и решение владельца

- `preflight.json` и `visual-state.json` имеют один sourceManifestSha256. B4 проверяет все file hashes против B0 до запуска. Runtime metadata ссылается на manifest; архивировать его вместе с immutable input/provenance. AssetDependencyHash — dependency identity, а не SHA256 содержимого. Неизвестные path/GUID avatarSource/weaponSource/poseAsset не считать подтверждённым sourceID.
- Ровно две пары old/new, разные body/net IDs одной session. В каждой metadata.json: frame==afterFrame==Right.captureFrame==Left.captureFrame; обе руки держат SDK primary/support того же grabbable; runtimePose/poseAsset/GUID/blend заданы. CaptureGuardUnchanged=true обязателен для заявления о пассивном снимке. Иначе evidence disputed/UNKNOWN. PNG filenames привязаны к этому exact frame.
- Открыть реальные frame-N-Right.png и frame-N-Left.png, плюс3 whole-body views и frozen fit renders: кисти/оружие видны, нет occlusion/пустого кадра/неподходящего LOD/обрезанных пальцев. Штатная проверка неодноцветности этого не доказывает. Recorder с Capture=true даёт дополнительные ранние/transient серии — не подменять ими выбранную пару.
- Отдельно для каждой руки открыть report.json и zone-review.json: CaptureSource=runtime_after_sdk_update, exact frame, side/grabpoint/current pose и source manifest; присутствуют Zones/Segments/ContactMetrics/Reliability/Limitations. `zone-review.json` — wrapper этого пакета, не обещание canonical схемы владельца8388. Summary может сохранять pending поля до завершения deferred analysis; окончательные per-pair metadata.json и visual-state.json обязательны.
- `priorityAbsSignedMm=2`, `distancePolicy=priority-only/not-equivalent-to-owner-reference-points`: ±2мм — **только приоритет ревью**. ContactWindowMm2/ProximityMm2 не эквивалентны новому набору fixed-reference phalanges владельца8388; этот пакет его не реализует и не восстанавливает. Владелец должен предоставить/применить свой набор к согласованному snapshot; отсутствие этого доказательства остаётся UNKNOWN. Нельзя трактовать signed sample median либо proximity-area как прохождение ±2мм owner acceptance.
- Владелец8388 оценивает palm/finger contact, gap и penetration обеих рук и записывает своё решение. Положительный signed distance — gap, отрицательный — проникновение по текущему winding-методу; открытые mesh/LOD/выборка могут давать approximate/unknown. SampleCount1000 не гарантирует обнаружение каждого локального дефекта. Уточнение пограничного участка — отдельная работа владельца, без самовольной правки pose.
- Проверить old→ghost→new lifecycle, damageTrace и cleanup по штатному summary. Новый прогон не закрывает historical734 foreign1, не заменяет Quest/user verification, network/performance evidence. HandReach/handToSnap не являются визуальной acceptance.

## Ограничения и cleanup

Runtime snapshot API существует и читает живые meshes без игровых pose edits, поэтому source изменений для этого пакета не требуется. Скрытый HandRenderer, неподдержанная геометрия, неизвестный prefab source, сменившийся frame, отсутствие двух grabs/shot, ошибки freeze/render/analysis оставляют UNKNOWN и явные error поля. Обе руки снимаются в одном frame текущего candidate; состояния разных кадров не объединяются в одну пару. G может не дать обе пары при другой AI траектории; не гарантировать успешную съёмку и не удерживать позу.

Cleanup удаляет ровно свои UxrManager/CaseStarted/CaseFinished/Editor.update/play/reload delegates и Dispose собственных snapshots/cameras/textures. Глобальный HandPoseFitRuntimeCapture.Cancel не вызывается. Чужие камеры/jobs не удаляются. После reload/Play exit observer отмечает aborted; результат не становится PASS. При инфраструктурном блокере обращаться сопровождающему, без локального recovery. Raw PNG/JSON — только reports/, вне Git. До отдельного исполнения существуют payloads/recipe; runtime capture и grip acceptance не получены.
