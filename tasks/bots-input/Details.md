## Итерация 1: прогон 1 демо Input Smoke (2026-10-20, ticket 908, вход cbd81ca5a)

Стенд ботов (сервер, режим respawn), меню «Tools/VR Battlegrounds/Bots/Stand/Run Input Smoke (demo)»,
`BotStandInputSmokeEditor.Prepare` → `BotStandInputSmoke`. Компиляция чистая (0 ошибок консоли).

- PASS device: устройство подключено, `InputDriven=True`, режим `UpdateExternally`, 3 кадра применены сразу.
- PASS walk: голова прошла 2,22 м, корень сдвинулся на 0,0 мм, камера совпадает с позой пилота (0,0 см).
- Кисть подведена к рукояти пистолета в кобуре (`Anchor_Hip_R`): зазор 2,5 мм.
- PASS grab: Grip → штатный `UxrStandardAvatarController` → SDK «Grabbing BrowningHiPower… using Бот 1 right hand
  grabber», предмет снят с якоря, событие ушло по relay (`UxrGrabManager`, 840 Б).
- Наведение замкнутым циклом сошлось до 0,83° за 1,3 с.
- Затем бот погиб до нажатия курка: **WallPass** — при шаге вбок на 1 м голова вошла в препятствие стенда
  (`Clear → Hint → Violating, cause=HeadEmbedded, depth 0,131`; урон 10, затем `Timeout`, kill — урон 90). Это правило
  проходит сквозь стены, которое прежний путь ботов обходил движущимся корнем (сверка «кто читает корень» в
  дизайне): с вводом бот подчиняется ему как человек. Маршрут демо исправлен — только по свободной полосе к цели.
- Смерть → `AvatarManager` сменил тело на GhostAvatar, директор подключил устройство новому телу (`keepHead`), голова
  продолжилась с прежней позы. Скрипт демо упал на уничтоженном грабере старого тела (ожидаемо для демо без смерти).
- Кандидат хвата SDK (патч 67) для внешнего аватара не считается («нет») — расхождение с целью перед Grip пока не
  проверяется; хват по Grip всё равно берёт ближайшую точку.

Журнал: `tasks/bots-input/reports/input-smoke-1/summary.json` (вне Git).

## Итерация 2: Blaze через ввод (2026-10-20/21, ticket 947–977)

- `BlazeInputSource` (мозг прежний: директор, навигатор, прокси Blaze, `BotGunner`) → `AvatarPilot` → устройство;
  тело бота по умолчанию на вводе (`BotKit.AttachInput`, без `BotAvatarDriver`/`BotRuntimeController`/`BotHands`);
  стенд для прежних замеров явно берёт `LegacyBody`.
- Найдено и исправлено по прогонам (Respawn, TestMap2, хост + 4 бота):
  - рука тянулась через полкарты к упавшей покупке → пилот: сенсор не дальше 0,85 м от головы, подход к далёкому
    предмету, присед до 0,6 м, Grip сразу при рукояти в ладони, стойка на месте, пока тянется;
  - прямое решение наведения по позе оружия неверно (AlignToController + KeepGripInPlace: поворот кисти против цели 97°)
    → замкнутый цикл по фактическому дулу (как стрелок скриптового клиента), с креном «верх вверх» (LookUpright, от
    e2e-combat);
  - шаг за ногами мозга доворачивал курс и боролся со взглядом на цель → шаг без доворота (стрейф);
  - двуручный хват: левая к поддержке в позе ствола при заданной правой;
  - дрожание 20–30 Гц вблизи (замечание пользователя) → коэффициент 0,4, предел 4°/кадр, мёртвая зона 0,3°,
    сглаживание точки цели;
  - Grip зажат без хвата (фронт пришёлся до досягаемости) → разжать и сжать снова;
  - погибшее живое тело не ведётся вводом (как в прежнем пути).
- Итог прогона 977: все 4 бота взяли Mk14 двумя руками, стреляли, 2 убийства, 0 смертей от WallPass, 0 ошибок консоли.
- **Принято пользователем 2026-10-21** («боты больше не дрожат»). Как бот держит оружие — пилот-стрелок; доводится в
  общем стрелке после сведения с клиентом (после вливания series у e2e-combat).
- Не в объёме (общее с прежним путём, этап 3 rules-parity): в Elimination тела ботов появляются призраками в начале
  координат (команда ещё не выбрана), а в `WaitingForPlayers` стадия бота «нет матча» — приказа идти в зону нет.
