# UltimateXR patch 89 — внешний аватар с вводом на этой машине (`InputDriven`)

2026-10-20, задача bots-input (этап 2 bots-epic). Резерв: `coordination.py patch-reserve --sdk UltimateXR --minimum 89
--key input-driven` → **89**. Дизайн: [bot-input-design.md](../contracts/bot-input-design.md#точки-патча-sdk).
Состояние: в ветке `task/bots-input`, не скомпилировано и не проверено в Unity.

## Зачем

Бот — аватар `UpdateExternally` на сервере (Local нельзя: `LocalAvatar` один на процесс, к нему привязаны камера и
AudioListener). Чтобы ниже ввода у бота работал код человека, внешнему аватару с вводом на этой машине нужны стадия
Update контроллера (ввод, трекинг, `IsGrabbing`), свой `ControllerInput` и Local-гейты хвата и курка.

## Что

`UxrAvatar.InputDriven` (runtime, не синхронизируется; ставит и снимает только владелец ввода аватара) и
`UxrAvatar.HasInputHere = Local || (UpdateExternally && InputDriven)`. Пути от `Assets/ThirdParty/UltimateXR/Runtime/Scripts/`:

| Файл | Место | Изменение |
|---|---|---|
| `Avatar/UxrAvatar.cs` | `InputDriven`, `HasInputHere`; `ControllerInput` | при `InputDriven` — первый включённый не-dummy/не-gamepad ввод аватара без синхронизируемого `OnControllerInputChanged` |
| `Core/UxrManager.cs` | `LocalAvatarControllers` (стадия Update), `TryGetUpdatableController(localOnly)` (AvatarUsingTracking), стадия Animation | `Local` → `HasInputHere` |
| `Mechanics/Weapons/UxrFirearmWeapon.cs` | `Trigger_Released`/`Trigger_Placed`, чтение курка, блок решения выстрела (патч 23), SyncAmmo full-auto, сброс эпизода курка | `Local` → `HasInputHere`; курок из `grabber.Avatar.ControllerInput` вместо `UxrAvatar.LocalAvatarInput` (на dedicated он null). Хаптика остаётся только Local |
| `Mechanics/Weapons/UxrWeapon.Custom.cs` | `HasLocalTriggerContext` (readiness-ledger) | `Local` → `HasInputHere` |
| `Manipulation/UxrGrabManager.Manipulation.cs` | AlignToController, `ShouldGrabberReleaseFarAwayGrip` | `Local`/`LocalAvatar` → `HasInputHere`/`InputDriven` |
| `Devices/UxrControllerTracking.cs` | `GlobalControllerConnected` (статическое) | устройство чужого аватара не включает/не выключает трекинг этого (иначе отключение одного бота выключало бы трекинг у всех) |
| `Devices/UxrControllerTracking.cs` | `OnEnable` → `RepeatSetupCameraCoroutine` | не запускать при `InputDriven` (камеру пишет владелец ввода; без XR корутина крутилась каждый кадр) |
| `Avatar/Controllers/UxrStandardAvatarController.cs` | патч 84 `UpdateExternalHandPoseFromGrabState` | false при `InputDriven` — позу ведёт `ProcessControllerEvents` |
| `Avatar/Controllers/UxrStandardAvatarController.Custom.cs` | патч 24 `ShouldSolveIKThisFrame` | `InputDriven` решается каждый кадр (хук троттлинга удалённых не применяется) |

Без флага поведение SDK не меняется: `HasInputHere == (AvatarMode == Local)`, фильтр подключения пропускает
устройства своего аватара и устройства без аватара.

## Оставлено как есть

Сопротивление хвата (патч 73 — предмет бота жёсткий), подсветка кандидатов хвата (`UxrGrabManager.cs:844`),
`AvatarMoved` (`UxrGrabManager.cs:412` — корень бота не движется), хаптика выстрела/помпы (только Local).
Игровые потребители ввода только для Local (на потом, rules-parity/weapon-system): `MagazineEjectInput`,
`BarrelObstruction`, `WeaponChamberingReminder`, `WeaponHapticOutput`, `AutomaticWeaponSlideFeedback`.
