# UltimateXR patch 90 — досылание при инициализации учёта без `HasReloaded`

2026-10-20, задача bots-input. Резерв: `coordination.py patch-reserve --sdk UltimateXR --minimum 90 --key
initialize-prepared` → **90**. Состояние: в ветке `task/bots-input`, не проверено в Unity.

## Дефект

Стартовый пистолет, выданный в кобуру (`PlayerLoadoutManager.ServerGiveWeapon`) при включённом оружии (Respawn, стенд,
выделенный сервер), инициализировал учёт ещё в кобуре **без патрона в патроннике** — первое нажатие курка давало
`ChamberingRequired`. Тот же пистолет в Elimination (оружие в Setup выключено) инициализировался при хвате с патроном
и стрелял с первого нажатия. Решение пользователя: дефект, исправить в задаче.

Доказательство — лог WeaponSystem (строки добавлены в этой задаче):
`учёт инициализирован (попытка 1) — патронник=нет … патронов=20, в якоре Anchor_Hip_R, сервер=True; патронник пуст:
проверка досылания не вызвана: патронов в магазине 20 …` — то есть ложно `HasReloaded`: Initialize прошёл до
`UxrFirearmWeapon.Start`, где `HasReloaded` ставится в true. При хвате (B) Start уже прошёл.

## Что

`Mechanics/Weapons/UxrFirearmWeapon.Readiness.cs`, `TryInitializeReadiness`: `prepared = !IsMagazineOnly ∧ Rounds>0 ∧
ValidateChamberCompletion` — условие `capture.HasReloaded` убрано. Контракт T01 (`WeaponTransitions.cs:64`): «SDK сам
решает prepared = M>0 ∧ Action в покое»; проверка покоя Action, магазина в гнезде и автора — в
`ValidateChamberCompletion` (порт `UxrReadinessLedgerPort`). `IsPhysicalValidationCurrent` по-прежнему сверяет
`HasReloaded` захвата и текущий (гонка не допускается).
