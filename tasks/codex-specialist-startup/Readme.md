## Изменение

`agent` из `.claude/settings.local.json` и инструкции `.codex/agents/<agent>.toml`.
Основная сессия принимает роль выбранного эксперта, выполняет startup профиля и
`Tools/experts/session_handoff.py --client all --last 2`, затем сверяет состояние
по Readme, plan и handoff задач, Git и штатным проверкам AGENTS.md.
Отсутствие назначения сохраняет прежнюю роль; некорректное имя или отсутствующий
профиль требуют явного сообщения. Настройка сохраняет owner, решения и ожидания
пользователя, не выдаёт допуск или Unity-аренду и не выбирает новую задачу.

## Исправление SessionStart — 2026-10-14

Проверка новой IK-сессии показала: первое сообщение не знало назначенного эксперта.
В её стартовом контексте были только правила терминала; опубликованная инструкция
из config туда не попала. Текущий хук не читал settings или профиль вообще.
Пользователь поручил: «исправь хук». Этап: `role-sessionstart`.

Codex SessionStart получает отдельный режим `--codex-main-role`: он читает локальное
назначение и передаёт сами инструкции профиля в additionalContext перед терминальными
правилами. Без флага прежний общий скрипт остаётся terminal-only для Claude.
Внешние CLI, хаб, историю сессий и Unity хук не вызывает. Инструкции назначения
условны для основной сессии; делегированная подзадача сохраняет свою роль.
Явные delegated-маркеры и fork не получают назначения. Отсутствие этих маркеров
не заявляется как отдельная машинная граница безопасности; guards остаются прежними.

Проверки: RED воспроизвёл отсутствие роли и сбой на нестроковом source; GREEN —
32 теста Tools/experts (один file-symlink skip из-за прав ОС; NTFS junction PASS).
Независимое ревью и повторные 14 regression-тестов после нормализации LF прошли.
PreToolUse не изменён; режим Claude сохранил stdout побайтно.

Живой Codex CLI в изолированном fixture с prompt «Кто ты?» первым ответом назвал
`avatar-ik-expert` и область IK тела. Инструменты модели, MCP и плагины были отключены;
startup-команды и Desktop этим не проверялись. Одноразовый hook-trust флаг применён
только к внешне проверенному fixture, не к production. Evidence — локально в
`reports/role-hook-live-probe/result.json`; после LF нормализации доказано полное
совпадение исходного текста tested hook и release hook.

После обновления checkout открыть новую сессию. Изменённое определение SessionStart
может требовать нового trust-review клиента; в CLI это `/hooks`. Поведение живых
Desktop resume/compact и runtime-делегирования остаётся отдельной проверкой.
