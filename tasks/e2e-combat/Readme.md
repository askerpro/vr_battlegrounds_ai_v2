# E2E этап 2: бой скриптовыми клиентами

2026-10-20. Задача создана командой `task-new`: один агент ведёт её в собственном worktree в ветке `task/e2e-combat` (схема «задача = агент»).
Этап 2 эпика [e2e-regression](../e2e-regression/Readme.md). Подробности прогонов — [Details.md](Details.md).

## Цель

Скриптовые сетевые клиенты (сервер + 2 клиента в MPPM, TestMap2, Elimination) играют раунд вводом: закупка со стены →
готовность жетоном рукой → Countdown → Combat → клиент наводит взятое оружие на противника и жмёт Trigger (выстрел
штатным путём SDK) → урон → смерть → призрак → Resolution → следующий раунд. Серверный оракул только читает: урон и
здоровье, смерть, деньги за убийство, счёт, фазы. Магазины v1 полные.

## Итерация 1 — что сделано

- `ScriptedGunner` (`Assets/Scripts/Debug/E2E/Input/`): подход к противнику по свободному пути (капсула тела, линия
  огня), наведение ствола замкнутым циклом по фактическому дулу (`ShotSource`) в центр торса (хитбоксы), курок —
  отпущен 2 кадра, нажат 3, отпущен; повтор до попадания. Ничего в SDK не вызывает.
- Сценарий: операции `carry` (оружие опущено, Grip держится), `shoot-enemy`; фильтр `item: pistol`; шаги для одного
  клиента (`client: N`); цель ходьбы `own-spawn-point`. Встроенный сценарий `Scripts/combat-hit.json`.
- Оракул `scripted-combat-hit` (`ScriptedClientScenario`): проверки покупки как в `scripted-wall-purchase`, затем
  Combat, повтор выстрела на оружии стрелка (`UxrProjectileSource.ShotFired`), урон по жертве от актора стрелка
  (`UxrWeaponManager.DamageReceiving`) и падение здоровья.
- Итог показа: клиент 1 с 6,6 м одним нажатием попал Viper в торс, урон 25,6, здоровье 100 → 74,4; сервер 9/9.

## Итерация 2 — что сделано

- Сценарий `scripted-combat-round` (`Scripts/combat-round.json`): закупка пистолетов, жетон левой рукой
  (`grab-dog-tag`), точка спавна, Combat, клиент 1 стреляет до смерти клиента 2 (`shoot-enemy until=kill`), жертва
  проверяет выбывание и перенос ввода на призрака (`expect-eliminated`).
- Оракул: готовность жетонами не по пределу ожидания, PlayerKilled(жертва, стрелок) и смена тела, Kill = KillAward
  оружия из покупки, Resolution — победитель, счёт 1:0, RoundWin 3250 / RoundLoss.
- Пилот «как человек»: оружие ровное (крен вокруг ствола) при переноске и прицеле — переноска и наведение замкнуты по
  фактической оси оружия; при смене тела поза головы сохраняется в пространстве трекинга (шлем не двигается). Шаги
  проваливаются, если оружие несут или стреляют не ровно (< 0,9) или голова прыгает при смене тела (> 0,3 м).
- Показ: 4 нажатия → 4 попадания, 100 → 0, Kill +300 (WK-11 Viper), 1:0, 3250/1900, ровность 1,00, сдвиг головы жертвы
  0,018 м; логи сервера и клиентов без ошибок.

## Итерация 3 — что сделано

- Сценарий `scripted-combat-next-round` (`Scripts/combat-next-round.json`): раунд 1 как в `combat-round`, затем оба
  призрака идут в свою зону (стрелок выбывает молча в Resolution), раунд 2 — покупка заново (снаряжение снято), жетон,
  точка спавна; данные шага `grabbed-2` несут netId покупки раунда 2.
- Оракул раунда 2: Equipment раунда 2 через ≈ 7 с после Resolution, оба живы в своих зонах, готовность сброшена, руки
  пусты; деньги перенесены без сброса (4150 / 2500, транзакций между раундами нет); касса провела вторую покупку
  (−200, чек); Countdown раунда 2 по жетонам, не по пределу ожидания.
- Итог: первый прогон зелёный — сервер 17/17, клиенты 33/33, логи без ошибок; продуктовых исправлений не потребовалось.

## Найдено и исправлено e2e (продуктовые дефекты)

- **IsGrabbable у свежей выдачи стены** (`ArsenalSlotController`, `ArsenalWallController`): стена писала синхронизируемое
  `IsGrabbable` до сетевого спавна предмета — событие уходило с UniqueId префаба (у клиентов 6–12
  `UxrComponentNotFound` в каждом Resolution), сервер и клиенты расходились по доступности ствола. Теперь запись после
  `SpawnServerObject` (`ApplyGrabAvailability`), как у магазинов.
- **Событие предмета, снятого в пути** (`NetworkStateRelay`, `AvatarRootEventAdmission` — контракт
  [avatar-root-event-admission v2](contracts/avatar-root-event-admission-v2.md), решение пользователя «вариант А»):
  клиент кладёт netId предмета в конверт, сервер до декодера тихо отбрасывает событие снятого предмета (Verbose +
  счётчик) — вместо Error `SyncTriggerPressStates` при отпускании курка в момент снятия оружия. Хэш Cmd 43519 → 6239:
  все участники — одна сборка.
