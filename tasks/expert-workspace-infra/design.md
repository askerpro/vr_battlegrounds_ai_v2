# Рабочие зоны экспертов: проект v1

Дата: 2026-10-10. Статус: проект v1 одобрен пользователем; реализация ещё не начата.
База исследования: `1001415bed29124af821a9a641d0bae2a7224a5b`, получена из `origin/dev`.

## Цель и границы

Чистая сессия получает назначение эксперта, границы, обязательные инварианты,
краткую карту архитектуры, состояние направления и явно выбранной задачи за
`awake` и одно-два адресных обращения. История может расти; обязательный пакет
остаётся ограниченным. Без выбора задачи показываются варианты, работа не начинается.

Общий механизм не знает VR, SDK, направлений и task-id. Он не вызывает LLM,
не редактирует файлы, не ACK-ает inbox, не получает допуск/аренду и не выполняет
предложенные действия. Профиль эксперта сохраняет свои предметные обязанности,
но не предоставляет организационные разрешения.

Пилот — навигационная миграция `vr-test-stand`. Игровой код, XR-ввод, сценарии,
профили существующих экспертов, исходные task-id/пути/контракты не меняются.

## Выбор подхода

| Вариант | Цена и ограничения |
|---|---|
| Только Markdown и ручные списки | Простой вход, но списки расходятся и плохо фильтруются; объём трудно гарантировать |
| Компактное ядро + JSON-карточки + адресные источники | Рекомендуется: один каталог, измеримый бюджет, ручная предметная редактура, проверяемая детерминированная сборка |
| Автоматический сбор всех документов/кода и резюмирование | Требует эвристик или LLM, смешивает историю с текущим состоянием и создаёт конкурирующую базу фактов |

Выбран второй вариант. CLI формирует дашборд из каталога; отдельные постоянно
редактируемые backlog/completed/active списки не создаются.

## Расположение и владельцы

Универсальные исходники принадлежат отдельному репозиторию `agent-infra`.
Развёрнутый runtime, broker, hooks и общие launchers этой задачей не ремонтируются.
В согласованном продуктовом worktree готовится работоспособный переносимый candidate:

```text
tasks/expert-workspace-infra/
  Readme.md, Details.md, plan.json, design.md, implementation-plan.md
  tools/candidate/
    awake.py
    expert_workspace/          # модели, каталог, сборка, CLI; без предметного кода
    adapters/                 # отдельно: чтение project coordination hub
    schemas/                  # workspace, task-card, coordination-view
    templates/                # новая зона, карточка, инструкции Codex/Claude
    tests/                    # инфраструктурные проверки, другая предметная фикстура
  reports/                    # результаты и трассировки, вне Git
experts/<workspace-id>/
  Readme.md                   # короткий вход: команда, источник ядра, навигация
  workspace.json              # обязательное ядро и настройки источников
  architecture.md             # адресная подробная карта, без журнала прогонов
  sources.json                # указатель первичных источников
  decisions/                  # только собственные новые решения, когда нужен владелец
  tasks/<card-id>.json         # единый каталог
```

Пилотные данные — `experts/vr-test-stand/`. Большие документы и evidence остаются
в `tasks/vr-test-stand/`, `Docs/test-stand.md` и исходной ignored reports-папке.
Candidate запускается прямо из этой задачи. Штатный выпуск в `agent-infra` и
подключение общего launcher — отдельное действие сопровождающего после проверки;
прямая запись в чужой checkout и изменение deployment не нужны для проверки v1.

## Основные источники фактов

| Факт | Основной источник |
|---|---|
| Назначение/границы конкретной зоны | `workspace.json`; Readme ссылается на него |
| Устройство системы | Код/контракт и существующие предметные документы; карта зоны указывает их |
| Решение | Существующий журнал решения либо один новый документ решения; не две копии |
| Навигационные метаданные карточки | Её JSON в одном каталоге |
| Подробности задачи/следующий шаг | Основная папка задачи; карточка содержит краткую датированную проекцию и ссылку |
| Допуск, owner/session, этапы, ACK, ревизии контрактов | Свежий хаб; локальный план и карточка разрешений не предоставляют |
| Результат проверки | Исходный отчёт конкретного прогона; tracked summary — историческое описание |

Дублируемые краткие выдержки помечаются как проекции с `source`, `captured_at`,
`source_sha` или digest. Они не получают второго писателя. Изменение источника
отмечается `source_changed`; возраст — `review_due`. Исторический результат не
становится текущей проверкой от изменения даты карточки.

## Схемы данных

Все схемы имеют `schema_version: 1`, UTF-8/LF, запрещают неизвестные поля и
проверяют типы/даты/ID/длины. Код не подставляет предметные значения по умолчанию.
Путь источника разрешается относительно явно объявленного `content_root`,
путь каталога — относительно зоны. Каталог не может выйти за зону через `..`
или symlink. URL и внешние evidence-ссылки типизированы отдельно.

### workspace.json

- `id`, `title`, `purpose`, `updated_at`, `review_after`, `reviewed_sha`.
- `responsibilities[]`, `boundaries[]`, `invariants[]`: обязательный полный текст.
- `architecture_summary`: короткие сущности/связи и владельцы соседних систем.
- `content_root`, `catalog`, `sources`: относительные пути.
- `sections[]`: ID, название и ссылка; подробности по умолчанию не читаются.
- `coordination`: ID задач/контрактов, которые относятся к направлению, и настройки
  выбранного read-only адаптера. Здесь нет команд исполнения, owner по умолчанию
  или lease-токенов. Owner для действия проверяется по выбранной задаче в хабе.
- `workflow_ref`: общий регламент начала/решения/блокировки/проверки/передачи.

Ядро — единственный обязательный локальный документ. Архитектурная капсула входит
в него; длинная архитектура, решения и диагностика открываются адресно. Корневой
`AGENTS.md` остаётся обязательным правилом проекта, а не копируется в новую зону.

### Карточка задачи

- `id`: ключ каталога; `canonical_task_id`: существующий task-id или `null` для
  ещё не зарегистрированной инициативы. `stage_id` отдельно, если это этап.
- `title`, `summary`, `status`, `priority` (1–5, 1 выше), `updated_at`, `tags[]`.
- `status`: `backlog`, `planned`, `active`, `blocked`, `verification`, `completed`,
  `archived`. Это локальный навигационный lifecycle; `hub_state` отображается отдельно.
- `context`: цель, граница задачи, обязательные ограничения, краткий следующий шаг.
- `dependencies[]`: карточка либо внешний task/stage, тип связи, ссылка.
- `links[]`: роль ссылки (`task`, `plan`, `handoff`, `decision`, `contract`,
  `source`, `evidence`), путь/URL, точный заголовок для адресного чтения.
- `provenance`: источник краткого состояния, дата снимка, SHA/digest.
- `validation[]`: историческая проверка, дата, полный `input_sha`, `base_sha`
  при наличии, окружение, объём, результат, ограничения, source/evidence-ссылки.
  Неизвестное окружение обозначается `unknown`, не угадывается.
- `validation.result`: `passed`, `failed`, `revoked`, `incomplete`, `not_run`.
  Верификация, пользовательская приёмка и интеграция — разные факты.

Карточка не является новой основной папкой задачи. Максимальный размер файла —
8192 байта; избыточные подробности отправляются в исходный документ. Каталог не
содержит raw logs, секреты, тела inbox-сообщений или lease-токены.

### Указатель источников

`sources.json`: записи `id`, `title`, `kind`, `path|url`, `section`, `topics[]`,
`authority`, необязательные `reviewed_at`/`digest`. Это навигация к источнику,
а не копия его текста. CLI проверяет существование локальных ссылок; evidence
может быть недоступно и не делает всю зону невалидной.

## Интерфейс

```text
python -B -X utf8 <tool> awake --workspace <path> [--task <card-id>]
python -B -X utf8 <tool> tasks --workspace <path> --status backlog --limit 10
python -B -X utf8 <tool> search --workspace <path> --query reconnect
python -B -X utf8 <tool> show --workspace <path> --task <card-id>
python -B -X utf8 <tool> check --workspace <path>
```

Для списков: `--status` (повторяемый), `--tag`, `--sort priority|updated|id`,
`--limit 1..10`, `--cursor`. Для всех чтений: `--format text|json`,
`--as-of YYYY-MM-DD` для воспроизводимых проверок, `--hub auto|off`,
необязательный `--coordination-view <path>` к очищенному датированному JSON.

Поиск нечувствителен к регистру, включает ID/название/summary/tags карточек всех
статусов и метаданные источников. Он не сканирует отчёты и длинные документы.
CLI возвращает точные дальнейшие команды и ссылку на карту поиска источников.

Явный `--task` всегда выигрывает у сортировки и последнего обновления. Неизвестный
ID — ошибка выбора с навигацией, а не автоматический выбор похожей задачи.
Без `--task` CLI показывает количество по статусам и до десяти вариантов;
поле `selected_task` равно `null`, возможные действия только информационные.

При одинаковых данных, дате оценки и снимке хаба результат одинаков. По умолчанию
списки сортируются по priority asc, updated desc, id asc. Cursor фиксирует digest
каталога и фильтры/сортировку; при изменении каталога возвращается `catalog_changed`
и команда начать страницу заново. Пропуски и повторения не скрываются.

## Стартовый пакет и бюджет

**Жёсткий максимум stdout — 16 384 байта UTF-8**, включая JSON/text оформление
и последнюю LF. Это измеримый бюджет вывода, не обещание точного числа LLM-токенов.
Default — не более десяти кратких карточек; `--limit` не увеличивает максимум.

Порядок сборки:

1. Полное обязательное ядро и предупреждение, что пакет не даёт полномочий.
2. Явно выбранная задача: цель/граница/обязательные ограничения/дата проекции,
   ссылки на task/plan/handoff, все прямые dependency ID и ссылки.
3. Контекст до трёх прямых зависимостей; остальные перечислены как нераскрытые.
   Транзитивные ветки раскрываются только отдельным `show`.
4. Ограниченная проекция относящегося к этому выбору хаба.
5. Краткие карточки направления в оставшемся бюджете.
6. Счётчики скрытых карточек/зависимостей/полей хаба, незагруженные разделы,
   точные команды следующей страницы и адресной навигации.

Бюджет измеряется после сериализации. Рендерер исключает целые необязательные
строки в детерминированном порядке и явно считает исключённые. Границы и
инварианты не обрезаются. Если обязательное ядро или обязательная часть выбора
не помещается, команда возвращает ошибку `mandatory_context_over_budget`,
указывает файл для исправления и не утверждает, что контекст восстановлен.
`check` заранее выявляет такую зону. Полные карточки доступны через `show`.

Плохая карточка не исчезает: вывод показывает `invalid_records` и точную ссылку;
валидные локальные данные доступны с признаком неполного каталога. Дубли ID,
отсутствующие зависимости, циклы, сломанные основные ссылки проверяет `check`.
Неограниченной рекурсии при пробуждении нет.

## Граница хаба и read-only

Универсальный сборщик принимает ограниченный `CoordinationView`:
`availability`, `observed_at`, `source`, `snapshot_event_id`, relevant tasks
с owner/worktree/revision/stage states, relevant contracts с revision/state,
метаданные pending inbox (ID/kind/date; без body), counts/omissions/errors.
DTO не содержит spec произвольной длины, routes с адресами, ACK-подтверждения,
capability/lease/token и полные snapshots. Схема верифицируется до рендеринга.

Отдельный проектный адаптер обнаруживает хаб через Git common-dir. Он не
импортирует `CoordinationStore`, не вызывает `inbox`/`events`/`watch-inbox` CLI:
в текущем runtime их CLI-конструктор допускает initialization/write даже
перед читающим методом. `status` имеет read-only handler, но возвращает полный
snapshot; он пригоден для ручного контроля, не для bounded awake.

Для live v1 адаптер использует существующую SQLite схему, URI `mode=ro`,
`query_only=ON`, одну короткую read transaction, параметризованные фиксированные
SELECT/JSON-проекции только нужных полей и timeout до двух секунд. Нет migrations,
mkdir, изменения settings, writable fallback, публикации и SQL из конфигурации.
Отдельно считаются все pending ID, вывод ограничен. Произвольные payload не читаются
для контекста; SQLite может обработать запись task с другими полями, но эти поля
не выбираются, не логируются и не сериализуются.

Для файловой гарантии live чтение требует read-only доступа ОС/песочницы к
каталогу hub и его SQLite sidecars. При неподтверждённой защите от записи либо
отсутствующих необходимых sidecars — `unavailable` и локальный контекст.
`immutable=1` для живого хаба не используется. SQLite WAL может потребовать
sidecars даже при read-only базе: [официальная документация](https://www.sqlite.org/wal.html#read_only_databases).
Portable путь без прямого DB-доступа — явно переданный очищенный JSON снимок;
его формирует владелец хаба вне `awake`, он датирован и не считается live.

Недоступный/заблокированный/неизвестной схемы хаб обозначается `unavailable`;
допуски и revisions — `unknown`, локальный пакет сохраняется. Проекции старше
пяти минут обозначаются `stale`; отсутствие heartbeat не выводится из task.updated.
Снимок не заменяет свежую guard/registration/admission проверку перед действием.
Конфликт карточки и хаба показывается вместе с датами; разрешение даёт хаб.
Режим `off|enforced|unknown` показывается явно: при off действует текущий
legacy маршрут AGENTS, отключение admission не означает передачи ownership.

Все команды candidate запускаются с `-B`; CLI также отключает bytecode до своих
импортов. Не создаются cache/index/log/reports. Файл отчёта создаёт только отдельный
явно запущенный тестовый runner, а не awake. JSON/errors и текст рендерятся по
allowlist; credential-поля/PEM/credential assignments отклоняются без их вывода.

## Сопровождение

Новая зона: выбрать владельца предметных данных, создать шаблон, связать существующие
источники, заполнить компактное ядро, добавить карточки и выполнить `check`/`awake`.
Новую роль устанавливать необязательно. В шаблонах нет названий экспертов или задач.

| Событие | Что обновляется |
|---|---|
| Начало задачи | Основные Readme/plan/handoff и свежий хаб по AGENTS; одна карточка с назначением/ссылкой/датой, без автоматического begin |
| Принято решение | Один основной decision document; архитектура у её владельца; ссылка/проекция в карте зоны |
| Блокировка | Основной handoff: причина, зависимость, условие разблокировки; lifecycle карточки blocked; actual coordination отдельно в хабе |
| Проверка | Исходный ignored report; в карточке provenance SHA/env/scope/result/limits; acceptance не выводится из tool success |
| Завершение | Приёмка и интеграция по штатному маршруту; одна карточка completed, ссылки остаются searchable; историю не добавлять к ядру |
| Передача/конец сессии | Компактный актуальный handoff и следующий шаг; principal обновляет Readme/plan; незавершённые проверки и владельцы явно указаны |

Во время каждой такой операции проверяются собственные ссылки/dates/digests и бюджет.
Крупный backlog не добавляет обязательных документов. Завершённые карточки остаются
в каталоге; архивы подробностей не переносятся без отдельного согласования.

Подключение Codex/Claude — короткий фрагмент startup instructions:
сохранять прежнюю роль/обязанности/skills, следовать AGENTS, запускать `awake`
с явно назначенной пользователем задачей, переходить по нужным ссылкам, проверять
допуск штатно. Ни ACK, ни launch, ни выбор задачи из сортировки не автоматизируются.
Существующие профили не переписываются в пилоте; инструкции подключения выдаются
как шаблоны для их владельцев.

## Проверка и приёмка

| Проверка | Требуемое доказательство |
|---|---|
| Чистая сессия пилота | Свежий subagent без наследования чата выполняет упражнения handoff; путь/число обращений/ответы сохранены в ignored report |
| Объём | Каталоги 10, 100, 1000 карточек: stdout каждого awake <=16384 UTF-8 bytes; optional rows <=10; hidden counts точны |
| Полномочия | Полные boundaries/invariants присутствуют; переполнение обязательной части — явный отказ; selected_task не меняется автоматически |
| Read-only | Снимки содержимого/метаданных zone и fixture hub до/после всех CLI; отсутствующий hub не создаётся; forbidden write/ACK/lease API не вызываются |
| Поиск/списки | completed/backlog, кириллица, tags/status, стабильные ties, следующая страница без duplicates; изменившийся digest отклоняет cursor |
| Зависимости | Missing/cycle/external/широкая ветка: точная диагностика и граница раскрытия; show даёт дальнейшие ссылки |
| Хаб | Live read-only защищённая fixture, unavailable/locked/schema mismatch/stale sanitized snapshot; local core не теряется; никакие токены/body не выводятся |
| Другое направление | Минимальная фикстура, например управление аудио-ассетами: тот же CLI/schema, без special branches в общем коде |
| История | negative377 revoked, SHA/input/env/scope различены; missing raw reports не объявляются проверенными |
| Навигация | Все обязательные ссылки разрешаются; внешние reports обозначены optional; новые зоны создаются из шаблона без ручных правок общего кода |

Это инфраструктурные проверки workflow, не новые gameplay/avatar tests.
Unity для пилота не запускается. Принятые игровые результаты не повторно
проверены этим исследованием. Реализация, тесты, миграция и чистая сессия пока pending.

## Самопроверка проекта

Предметные данные отделены; обязательная часть имеет fail-closed бюджет;
новые индексы фактов/разрешений не создаются; API хаба изолирован; evidence
сохраняет provenance; у каталога один источник; неизвестность явно представлена.
Публикация runtime требует штатного owner route вне candidate, без ремонта shared infra.
Подготовлен отдельный [план реализации](implementation-plan.md) для рассмотрения.
