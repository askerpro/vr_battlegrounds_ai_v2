# Как подготовить рабочее место эксперта

Дата: 2026-10-11. Процедура для агента, создающего `experts/<id>/`. Границы зоны — только из
[expert-map.md](expert-map.md); формат — [design.md](design.md); заготовки — [templates/](templates/);
образец — `experts/launch-infra/`.

## Что создать

1. `experts/<id>/.gitattributes` — копия `templates/.gitattributes`.
2. `expert.json`: `id`; `tasks` — задачи хаба эксперта из карты (пустой список, если их нет);
   `owner` — owner первой задачи в хабе, иначе `<id>`; `reviewed_sha` — SHA origin/dev, на котором сверял
   карту; `reviewed_at`; `watch_paths` — ключевой код/документы зоны (glob). Без задач в хабе свежесть
   AGENT.md держится только на `watch_paths` — перечисли их полно.
3. `AGENT.md` по шаблону — **на английском** (инструкция агенту), цель ≤ 4 КБ, максимум 5 КБ: назначение,
   Owns / Not owned (соседи по карте), инварианты зоны с точными значениями, архитектурная карта
   (сущность → ответственность → путь), Details с точными заголовками документов (заголовки — как в
   документе), правила зоны. Общие правила всех экспертов (оркестрация, ТЗ, проверка, ведение, жизненный
   цикл задач, память) — только в `experts/COMMON.md`, в AGENT.md их не повторять. Что awake показывает
   живьём (этапы, контракты, владельцы, зависимости), в AGENT.md не писать. Базу знаний эксперта не
   копировать — ссылаться на неё.
4. `backlog.md` (на русском): одна строка на пункт `N. \`id\` — суть — источник`; только кандидаты, которых
   ещё нет этапами в хабе (этапы хаба awake покажет сам).
   Источники: «следующий шаг»/открытые пункты Readme задач, известные проблемы в Docs/troubleshooting,
   ограничения в Details, TODO в документах зоны. У каждого пункта — суть и ссылка.
5. `journal/YYYY-MM-DD-<тема>.md` — завершённые результаты зоны (merged/accepted этапы, принятые решения):
   первая строка `# суть`, далее SHA, что реально проверено, ограничения, источники. Только факты из
   источников; неизвестное пишется как unknown. Дата — дата результата.

## Правила

- Пишешь только в свою папку `experts/<id>/` (и в адаптеры профиля, если они явно поручены). Чужие
  профили, папки задач, Docs, код, хаб — только чтение. Коммиты не делать. Unity не запускать.
- Читать адресно: `rg` по заголовкам, нужный раздел; большие Details/логи целиком не читать.
- UTF-8 без BOM, LF; Write/Edit.

## Задачи эксперта

Задачи не переносятся в рабочее место: `tasks/<task-id>/` — контракт AGENTS, хаба (`doc_path`, writes),
`.gitignore` (reports) и SDK-журналов. Связь «эксперт → задачи» — только список `tasks` в `expert.json`.

| Где | Что | Срок жизни |
|---|---|---|
| `experts/<id>/` | зона, карта, backlog кандидатов, журнал итогов | постоянно |
| `tasks/<task-id>/` | Readme, plan, Details, контракты, changelog, reports | пока идёт работа, затем архив |

Цикл: кандидат в `backlog.md` → выбор пользователя → `tasks/<task-id>/` и регистрация в хабе, id в
`expert.json`, кандидат из backlog убрать → работа → после влития запись в `journal/` (итог, SHA, проверки,
ссылка на папку задачи), id из `expert.json` убрать. Если документа задачи нет в checkout, awake показывает
опубликованную хабом копию (`git show agents/status:<doc_path>`). Старые `Docs/tasks/T-xx` не переносятся.

## Проверка перед сдачей

- `python -B -X utf8 Tools/experts/awake.py experts/<id>` — код 0, размер вывода
  ≤ 24 576 байт, обязательная часть не урезана (строк «скрыто» в backlog/журнале допускаются, но лучше без них).
- Каждый путь из архитектурной карты и «где подробности» существует (проверь скриптом/ls).
- `python -B -X utf8 Tools/agents/check_text_eol.py --repo . --path <каждый созданный файл>` — issues пусто.
