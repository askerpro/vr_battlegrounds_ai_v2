# Единый контактный редактор в SDK Hand Pose Editor — v3

2026-10-15. Прямое поручение пользователя: встроить контактное редактирование в существующий
SDK Hand Pose Editor, объединить хорошие инструменты анализа и рентген, добавить непрерывный IK.
V2 solver/материальные точки переиспользуются; отдельные новые окна остаются техническими прототипами.

## Основной интерфейс

В существующем редакторе три способа правки: ручное сгибание, IK к заданным точкам, последовательный
«Обхватить предмет». Источник аватара/позы/стороны — SDK editor; выбранные предмет/Grabbable/GrabPoint
и frozen session принадлежат существующему HandPoseSdkDiagnostics, новый контроллер их не дублирует.

В режиме заданных точек у каждого пальца один перемещаемый surface anchor для конечной фаланги.
Маркеры двигаются через SceneView handles/луч курсора и прилипают к явно выбранной поверхности
предмета. Хранятся source/submesh/original triangle/barycentric, не только world XYZ.
Ладонь получает отдельный контактный anchor. DistalPriority v2 сохраняется.

## Последовательный обхват

После заданной постановки ладони последовательно закрываем proximal → intermediate → distal
каждого пальца до касания соответствующей фиксированной точки кожи. На каждом кандидате —
реальный BakeMesh и повторное измерение всех точек: skinning может сдвинуть предыдущие контакты.
Не подставлять фиктивные distal XYZ targets; отдельный ForwardSurfaceWrap использует permitted surface.
Ограниченные scan/bracket/refine и повторный проход не обещают глобальное решение.

Профили компромисса:
- По умолчанию «Без проникновений»: при известном знаке не принимать точки внутри; допускается
  меньшее число касаний. Unknown sign показывает неподтверждённость, не отсутствие проникновения.
- «Больше касаний»: предпочитать три касания, разрешая только явно заданную малую глубину.
  Число касаний, остаточная ошибка и измеренные проникновения показываются раздельно.

## Непрерывное решение

Opt-in «Непрерывно решать IK»: после обхвата или постановки целей изменение snap position/rotation,
центра ладони либо surface target помечает расчёт устаревшим и запускает пересчёт выбранного режима.
Камера/hover/repaint не являются причиной нового захвата или решения. Только главный Editor thread;
расчёт на временной копии с конечным бюджетом на update, отменой старого поколения и latest-wins
применением результата. Не синхронный полный Solve на каждое движение мыши.
Выключение режима, закрытие окна, смена avatar/pose/side/object, Undo, reload и Play отменяют job,
освобождают копии/handles и восстанавливают видимость. Несохранённая ручная поза — исходное состояние.

SDK остаётся единственным автором working finger pose, Undo и AutoSave. До явного внесения результата
в SDK edit state кандидат живёт на временной копии. Нужен небольшой SDK-owned typed commit endpoint
с проверкой avatar/pose/side/blend/current working state, read-only и Undo; не писать live bones
из EditorApplication.update. SDK83 зарезервирован для этого расширения. Finger descriptor не хранит
palm placement: положение grip/snap передаётся через существующую границу alignment отдельно.

## Единые измерения и рентген

Один authoritative HandMeshCapture: действительный BakeMesh, все weights, original material keys,
после SDK descriptor sync. Существующая frozen session/cache/export сохраняется; extracted SDK preview
не выдаёт свои перенумерованные triangle IDs за original source IDs. Все оценки контакта — только
фиксированные опорные точки, ±2 мм, missing/unknown явно; полная кожа — отдельная диагностика.

HandPoseReview владеет одним renderer/style и одним canonical HandPoseFit.shader. SceneView и PNG —
адаптеры одной политики depth/blend/colors/lighting, а не отдельные «рентгены». Before/after используют
одну камеру и стиль; реальная геометрия и provenance сохраняются. Rig wireframe остаётся проверкой
строения рига и не называется альтернативным рентгеном хвата.

KEEP: общий capture/identity, fixed-point measurement, полезные rig/runtime проверки.
UNIFY: SDK frozen session, point backend, IK, visual renderer и export.
DRAFT/HIDE: площадь, SDK-band/общий StaticScore как вердикт качества хвата, устаревшие curl hints
и экспериментальные отдельные пользовательские входы. Не удалять используемые generic helpers;
сначала перенести зависимости или оставить совместимость. Черновики площади и исторические отчёты сохраняются.

Поддерживающая рука пистолета отложена. Игровые позы/префабы автоматически не применяются.
Новые/переписанные тесты, включая временные smoke/managed probes, только после пользовательской
проверки качества. До неё — компиляция, существующие проверки и диагностические изображения.

## Пользовательская проверка после native импорта

Открыть сценовый экземпляр MEF_cyborg_hands_Player и его позу в SDK Hand Pose Editor. Base хранит
GUID/реестр хватов и исходную модель MEF; Cyborg меши и пястные находятся в Player — его использует rig profile.
Выбрать предмет/GrabPoint/сторону в единой панели. Проверить ручной режим, затем задать ладонь и
пять липнущих surface targets; сравнить priority0 и1. Отдельно проверить последовательный обхват,
затем opt-in continuous при перемещении/вращении snap. Кандидат должен оставаться preview до
явного SDK внесения; проверка включает воспроизведение palm placement и Undo. Сменить сторону,
позу и объект, завершить/отменить gesture и закрыть окно — устаревший расчёт не должен записать позу.
Сохранить отчёт: до/после встроены в документ, расстояния только у фиксированных точек, unknown sign явно.
Это шаги человеческой приёмки, не новые тестовые ожидания и не уже выполненная проверка.
