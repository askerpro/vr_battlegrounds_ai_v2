# Анализатор качества рига кисти

Editor-инструмент: `Tools/VR Battlegrounds/Avatars/Hand Rig Quality`.
Реализация и приёмка отслеживаются в [задаче](Readme.md).
Используется для сравнения MEF с положительными SDK-эталонами Cyborg и BigHands.
Игровые аватары, позы, importer и калибровка этим инструментом не изменяются.

Инструкция находится в задаче до принятия инструмента. Текущий код0.5 ещё экспортирует
в исторический Docs/tasks/report/hand-rig-quality; перевод новых экспортов в reports/
входит в допущенный этап static-analyzer после окончания обслуживания.

## Запуск

1. Выбрать prefab цели и эталона, сторону кисти и высоту глаз игрока.
   По умолчанию включена «Общая поза SDK Default»: один descriptor Cyborg применяется
   к обеим временным кистям через оси каждого рига. Длины и позиции костей сохраняются.
   При отключении можно выбрать авторский Rest или собственные Fixed/Blend позы.
2. Для статической оценки выбрать канонический SDK `CyborgAvatar_URP` как эталон и
   общую SDK-позу с Blend=0 и рамку запястья.
3. Нажать «Откалибровать на Cyborg и BigHands»: измеряются оба SDK prefab и обе стороны.
   BigHands сравнивается с Cyborg, чтобы шкала учитывала различия двух положительных
   эталонов, а не только нулевое сравнение каждого с самим собой.
4. Нажать «Измерить и сохранить пакет», открыть папку отчёта и `index.html`.
   Отчёт и геометрия сохраняются даже без PNG. Play/compile/import блокируют запуск.

PNG — четыре ортографических каркасных вида в указанной рамке. Сетка: оранжевый — цель,
голубой — эталон. Кости и крупные точки поверх сеток: салатовый — цель, пурпурный — эталон.
Точки имеют тёмную обводку и разные радиусы для видимости совпавших суставов.
Белое кольцо — запястье; оси по 25 мм: X красная, Y зелёная, Z синяя.
Розовый — смещение соответствующих суставов. Искусственного разнесения кистей нет.
Это диагностическая проекция, не screenshot игрового освещения или шейдера.

## Что оценивается

| Критерий | Реализация статического среза | Ограничение |
|---|---|---|
| M1, запястье | Расстояние в явно выбранной авторской рамке S | В wrist-рамке недоступно; физический grip pose не подтверждён |
| M2, рамка ладони | Площадная PCA поверхности с доминированием Wrist против эталона | unreviewed, не входит в балл: сопоставимость зоны не подтверждена |
| M3, оси SDK | Максимальное угловое расхождение SDK forward/up с PCA | unreviewed, не входит в балл: SDK-диапазон оказался нечувствительным |
| M4, центровка сустава | Смещение от площадного центра полного замкнутого контура пальца / эквивалентный радиус | Принадлежность задают веса цепи пальца; открытые, несколько подходящих контуров и вырожденное сечение → unavailable |
| M5, переход весов | Единственное пересечение среднего веса дочерней цепи с 0,5 по выбранному контуру | Поиск ±10 мм, шаг1 мм; отсутствие/несколько переходов → unavailable |
| M6, дорсальная глубина | Секционный максимум вдоль SDK Up в явно выбранной Fist | unreviewed: анатомическая вершина костяшки ещё не размечена |
| M7, утечка на манжету | Площадная средняя суммарного веса кисти в цилиндре рукава | Цилиндр требует проверки; треугольники отбираются по центру. Без Forearm → unavailable |
| M9, толщина | Разность эквивалентных радиусов соответствующих сечений | Приближение формы; не точная толщина ткани над кожей |
| M10, размер | Отклонение длин между суставами и wrist→middle/proximal | Distal без следующего сустава не получает придуманной длины |
| M13, плавность весов | Средняя энергия разности всех весов по уникальным рёбрам кисти | Raw по renderer, зависит от сетки/LOD; зональное сравнение ещё открыто |

M8/M11/M14 требуют серии вращений и штатного IK, M12 — реальной рукояти и
[Hand Pose Fit](../../Docs/hand-pose-fit-tool.md). Этот срез возвращает для них unavailable с причиной.

## Шкала и покрытие

Калибровка сохраняет GUID/hash SDK-префабов, версию алгоритма, высоту глаз, сторону,
область и единицы каждой метрики. Сравнительные критерии привязаны к точному каноническому
Cyborg. Его изменённый prefab variant не считается эквивалентным автоматически.
Изменение SDK-источника или общего pose asset, другая поза/рамка/высота или несовместимый
алгоритм отменяет балл. Калибровки версий0.1–0.4 несовместимы с0.5;
после обновления выполнить калибровку заново.

Для применимой метрики `goodLimit=max(начальный допуск, 1,25×максимальное отклонение SDK)`.
В хорошем диапазоне —100; между goodLimit и `3×goodLimit` — линейное снижение до0.
Начальные допуски: M1/M2=3 мм/3°, M3=2°, M4=0,15, M5/M7/M9=2 мм/2%/2 мм, M10=3%.
Это начальная шкала, обученная на объявленных положительных примерах, а не медицинская
норма или доказательство игрового качества. M9 штрафует только положительный излишек радиуса.

Итоговый `StaticScore` — среднее по семействам применимых метрик, чтобы многочисленные
суставы не вытесняли прочие критерии. `ScoredMetrics` и `CriterionScores` показывают покрытие.
M2/M3/M5/M6/M13, unreviewed-области и недоступные метрики в балл не входят.
В актуальной wrist-калибровке оцениваются M4/M9/M10. Без покрытия балл — null.

Сечения0.5 не обрезают треугольники локальным цилиндром. Кандидат должен иметь ≥80%
периметра с интерполированным весом цепи своего пальца≥0,1. Это условие принадлежности
области; оно не является допуском дефекта. При нескольких подходящих контурах или
смешанной области ладони измерение отвергается. M5 интегрирует веса только по выбранному
контуру; соседние пальцы не добавляются к среднему.
Пересечение порога поддержки интегрируется по линейному весу вдоль ребра, а не по его
среднему. Разные renderer сохраняют идентичность даже при совпадении координат;
повторные грани и конфликтующие веса шва не дают скрытого усреднения.
M5 требует полностью измеренного профиля и смены знака; касание/плато не принимаются.
Единственность между сэмплами1 мм не доказана, поэтому найденный M5 — unreviewed,
исключён из балла и показан как оценка.
Высокий статический балл с малым покрытием не означает приёмку всей кисти.

Первый проверенный прогон (2026-10-07, worker123): SDK Cyborg/BigHands —100 обе стороны,
MEF —93,8087/93,8090. У MEF оценены только M2/M3/M10, 13 значений; M4/M5/M9 недоступны.
Авторские Rest-позы отличаются: справа goodLimit M2=130,618°, M3=105,237°.
Такая шкала углов слишком нечувствительна, поэтому исторический итог0.1 нельзя использовать
для решения «кисть качественная». В0.5 общая поза, полные сечения и контроли введены,
а неподтверждённые углы исключены из оценки.
Полный прогон: [статическая проверка](../../Docs/tasks/report/hand-rig-quality/static-verification.json).

## Захват и безопасность

Общий слой `VrBattlegrounds.HandGeometry.Editor` содержит `HandFrame`, `HandAssetIdentity`,
`HandMeshSample` и `HandMeshCapture`. Он не зависит от Hand Pose Fit или HandRigQuality.
Снимок сохраняет полные вершины, нормали, submesh topology/indices, все влияния костей и их
смещения в массиве, пути костей и renderer. `BakeMesh(true)` компенсирует scale SMR перед
полным localToWorld: масштаб учитывается ровно один раз. Действующие blend shapes включены;
normals переводятся inverse-transpose матрицей. Общий capture используется также
`HandPoseFitSnapshot.CaptureHand`, предметный SDK-preview путь и формат Fit остаются прежними.

Анализатор копирует только Transform и выбранные видимые SkinnedMeshRenderer LOD0;
игровые MonoBehaviour, сеть и IK не запускаются. Авторская активность prefab определяется
по activeSelf цепочки, а не scene-only activeInHierarchy. Временные объекты очищаются через
PreviewRenderUtility. Устаревший source RigInfo отклоняется до getter SDK, который мог бы
пересчитать persistent asset. Подготовить такой аватар нужно штатным сборщиком.

Рост нормализуется по итоговому `_bodyIKSettings._eyesBaseHeight` выбранного prefab.
У MEF применяется принятая поправка визуальных глаз из сборщика и override1,7202504
в `MEF_Base_Avatar`. Исходные1,6907823 из MEF_Rig не подменяют его.
Это preview-расчёт роста; серверная калибровка и реальный lossyScale в игре проверяются отдельно.

Для S используются явно заданные sensor Transform исходного prefab либо единственный
активный `_leftHandSensor`/`_rightHandSensor`. Runtime `_localSensor*HandPos/Rot` вычисляются
SDK при SetupSensor и не используются как готовые сериализованные offsets.

## Артефакты и API

Все пакеты — в отдельных подпапках `Docs/tasks/report/hand-rig-quality/`, вне Git:
`report.json`, `geometry-target.json`, `geometry-reference.json`, четыре PNG, `index.html`.
Пакет калибровки содержит `sdk-calibration.json` и полные SDK-прогоны.

Публичные входы:

```csharp
HandRigQualityCalibration.CalibrateSdk(1.72f);
HandRigQualityAnalyzer.Analyze(new HandRigQualityRequest {
    AvatarPath = "Assets/Prefabs/Player/Optimized_MEF_Player.prefab",
    ReferenceAvatarPath = HandRigQualityCalibration.Cyborg,
    Side = UxrHandSide.Right,
    EyeHeightMeters = 1.72f,
    CalibrationPath = путьКалибровки
});
```

Статус `measured_static` означает завершённый статический захват. Балл, статус калибровки
и статус каждой метрики читаются отдельно. Ошибка калибровки сохраняет raw-измерения.

Актуальный прогон0.5 в worker184:89/89 тестов штатным Unity TestRunner,
Android PASS, шесть сравнений/экспортов PASS. SDK100 обе стороны; MEF75,77 слева/75,87
справа, по23 оценённых значения M4/M9/M10. M4/M9 MEF доступны по6 суставам каждой руки;
остальные9 сечений неоднозначны. M2/M3/M5 исключены из балла. Числа PCA сохраняются
как unreviewed: SDK-шкала M3 good≈102° не является чувствительным критерием.
[Отчёт справа](../../Docs/tasks/report/hand-rig-quality/20261007-200633-505-a5c3c5/index.html),
[слева](../../Docs/tasks/report/hand-rig-quality/20261007-200627-043-7efbd9/index.html),
[проверка](../../Docs/tasks/report/hand-rig-quality/static-verification.json).
Сохранность префабов/Selection/Undo/preview-сцен, общий descriptor и маркеры на24 PNG
проверены. Координаты исправленного capture ранее сверены с независимым LBS по bindposes
(max<0,001 мм); тот же класс ошибки исправлен в SDK Editor preview патчем59.
Отрицательные контроли на временном SDK-захвате: M4 при сдвиге сустава на4 радиуса
снижает семейство100→87,5; thumb/proximal +50% получает0 при good3%/bad9%,
семейство M10 снижается100→36,52. [Контроли](../../Docs/tasks/report/hand-rig-quality/sensitivity-verification.json).
Среднее семейства может оставаться высоким при одном плохом суставе: смотреть raw,
применимость и конкретные диапазоны, а не только итог. Широкий диапазон пястных отражает
различия положительных эталонов, не доказанную допустимость произвольной геометрии.
Старые изображения0.1/0.2 имеют ошибку масштаба и не используются как визуальный эталон.
