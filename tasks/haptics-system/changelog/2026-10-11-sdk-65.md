# SDK-патч UltimateXR 65: перехват вибрации контроллеров

Дата: 2026-10-11. Задача: haptics-system. Этап: sdk-routing. Тип: sdk.
Статус: реализовано, в шлеме не проверено. Номер выдан `coordination.py patch-reserve` 2026-10-08 (ключ
`sdk-patch-57-haptic-routing`; в старых документах — «патч 57»).

## Зачем

На Quest каждый вызов мотора обрывает текущую вибрацию, а режим SDK `Mix` ничего не смешивает. Чтобы у мотора был один
писатель (`HapticService` → `UnityXRHapticDevice`, инварианты 25–28), все вибрации UltimateXR должны идти через игровой
сервис. События `HapticRequesting` для этого не годятся: переопределения `UxrUnityXRControllerInput` не зовут `base`, а
клики UI и сорванного хвата зашиты в код SDK. Спецификация — `tasks/haptics-system/Details.md` §5.2–5.3.

## Что изменено

- Новый файл `Runtime/Scripts/Haptics/UxrHapticRouting.cs`: `UxrHapticRequestKind` (Clip, ClipType, Raw, Stop),
  `UxrHapticRequest` (вид, компонент-источник, рука, клип, тип, частота, сила, длительность, режим; фабрики `ForClip`,
  `ForClipType`, `ForRaw`, `ForStop`), `UxrHapticRouting.Router` (`Func<UxrHapticRequest, bool>`) и `TryRoute`.
- Первая строка четырёх методов — `if (UxrHapticRouting.TryRoute(...)) return;` с меткой `VR Battlegrounds patch 65`:
  - `Runtime/Scripts/Devices/UxrControllerInput.cs` — `SendHapticFeedback(side, UxrHapticClipType, …)`, до `StartCoroutine`
    (UI-клики, сорванный хват, `UxrHapticOnImpact`, запасной путь клипов);
  - `Runtime/Scripts/Devices/Integrations/UxrUnityXRControllerInput.cs` — override `SendHapticFeedback(side, UxrHapticClip)`
    (выстрел, помпа, хват/укладка, `UxrControlFeedback`), override `SendHapticFeedback(side, freq, amp, dur, mode)`
    (манипуляция планшета, перетаскивание UI, `UxrFixedHapticFeedback`), override `StopHapticFeedback(side)`.

Ввод, трекинг, `UpdateInput` и порядок кадра не тронуты (условие zone-ack avatar-ik, событие 3708).
`Router == null` — SDK работает как до патча (выделенный сервер, batch mode, до установки сервиса).
Маршрутизатор игры принимает каждый запрос, поэтому корутина SDK для принятых запросов не стартует, а её шаги повторно
не маршрутизируются. Сервис пишет в мотор через свой `UnityXRHapticDevice`, не через SDK, — рекурсии нет.

## Что не патчится

- `UxrSteamVRControllerInput` (свои override вибрации): не входит в Android-сборку Quest.
- Базовые virtual-методы `UxrControllerInput` (поднимают `HapticRequesting`) — наши контроллеры их не зовут.
- `UxrFirearmWeapon`, `UxrShotgunPump`, `UxrWeapon*`, `UxrGrabManager*` — их вибрации приходят в перехват через четыре
  точки выше, сами файлы не меняются (зоны weapon-system и других этапов).

## Игровая сторона

`Assets/Scripts/Haptics/SdkHapticRouter.cs` (ставит/снимает `HapticService`, статический сброс в
`RuntimeInitializeOnLoadMethod(SubsystemRegistration)`), запасные клипы по типу — `Assets/Resources/SdkHapticFallbacks.asset`
(`SdkHapticFallbacks`), интерфейс `IWeaponRecoilHapticsOwner`.

## Как повторить при обновлении SDK

Вернуть файл `UxrHapticRouting.cs` (и его .meta с тем же GUID) и четыре строки `TryRoute` первыми в перечисленных методах.
