# Задача: система вибрации (хаптиков)

Постановка для основного агента worktree `F:/CodexWorktrees/haptics/Vr_Battlegrounds_ai` (ветка `haptics`,
база origin/dev 06624cb9, LFS настроен). Ты работаешь как обычный агент проекта по `AGENTS.md`: режим worktree,
брокер редактора, вливание в origin/dev после приёмки пользователем, конвейер согласования.

## Цель

Одна система вибрации контроллеров. У вибромоторов один владелец — сервис. Остальной код просит сигнал по имени
из каталога. Сигналы разделены на классы с приоритетом, вибрация — только на руке локального игрока.

## Что уже известно

Исследование — [research.md](research.md): возможности Quest и UltimateXR, пакет из Asset Store (не брать),
рекомендации Meta, все 15 текущих источников вибрации и их проблемы.

**Решения пользователя (обязательны, раздел 8 исследования):**

| Тема | Решение |
|---|---|
| Классы | положительный — тихий, малой амплитуды, может быть непрерывным; отрицательный — короткий и сильный, рисунком «двойной импульс»; физический — отдача и механика |
| Приоритет на руку | отрицательный > физический > положительный; непрерывный положительный на время более важного встаёт на паузу |
| Карман | непрерывная вибрация всё время контакта руки с готовым карманом; сила настраивается, старт 10 %, подбор в шлеме |
| Отдача | принадлежит владельцу системы оружия (WeaponSystem); отдача SDK отключается, когда WeaponSystem её возьмёт |
| Настройки игрока | нет (уточнено 2026-10-07): параметры — настройка проекта, подбор в шлеме дебаг-экраном |
| Гибель | максимальная сила, 1,5 с |
| Платформа | на Unity OpenXR пока не переходим, проектируем на амплитуде и ритме |
| Отказ по темпу стрельбы | отрицательный сигнал + звук `UI_Error_Subtle_Deep_stereo.wav` (сигнал выдаёт WeaponSystem) |

**Факты из исследования, которые определяют устройство:**

- На Quest в нашем стеке каждый новый вызов обрывает текущую вибрацию; режим `Mix` из UltimateXR ничего
  не смешивает. Приоритет и паузу непрерывных сигналов ведёт сам сервис.
- Фильтр по `StateEventAuthority.IsAuthorOfItem` не годится: для ничейного предмета и ботов на хосте он даёт true.
  Цель — рука `UxrAvatar.LocalAvatar`.
- Встроенные вибрации SDK (отдача, клик хвата, клик UI) перехватываются одним SDK-патчем
  `UxrControllerInput`/`UxrUnityXRControllerInput`. Номер **57** зарезервирован в `pipeline.md`.

## Главное требование: писать под ближайшую архитектуру

Оружие сейчас переписывается в единую `WeaponSystem` (владелец — сессия weapon-system, план
`Docs/tasks/weapon-system-refactor-plan.md`, этапы C2 → D → E → F → H).

- Старые источники вибрации оружия — `AutomaticWeaponSlideFeedback`, `WeaponAttemptFeedback`,
  `WeaponChamberingReminder`, `WeaponMechanismVisuals` — **не переводить и не править**. Их удаляют этапы D и H.
- Машина оружия уже выдаёт вибрацию сигналом `IWeaponOutput.Haptic(WeaponHapticCue)`
  (`Assets/Scripts/Weapons/Core/WeaponOutput.cs`). На этапе D исполнитель `WeaponFeedbackExecutor` передаст его
  в твой сервис. Дай для этого публичный API (сигнал из каталога, рука или грабер, класс) и опиши контракт для
  владельца WeaponSystem до вливания. Отдача — физический сигнал, который будет выдавать WeaponSystem.
- SDK-патч 57 должен позволить отключить отдачу SDK, когда её возьмёт WeaponSystem, и до тех пор не ломать
  текущую отдачу.
- Перед переводом любого другого источника — `PocketHaptics`, `WallPassFeedback`, `WristDisplay`,
  `GhostViewEffect`, `DebugGestureInput`, `BarrelObstruction`, планшет и UI, гибель — проверь по планам в
  `F:/UnityProjects/Vr_Battlegrounds_ai/.agent-state/coordination/*.md`, не переписывает ли его сейчас другой агент.
  При пересечении не переводи сразу: впиши в план «после X» и договорись с владельцем.

## Порядок работы

1. **Дизайн, без кода.** [Details.md](Details.md) (при постановке — `Docs/tasks/haptics-system-design.md`):
   - модель: классы, параметры по умолчанию в числах, рисунки;
   - приоритеты и смешивание; непрерывные сигналы;
   - каталог — ScriptableObject по образцу `MenuTheme` или `MagazineAnchorSoundDefaults`;
   - API сервиса и контракт для WeaponSystem;
   - SDK-патч 57;
   - правило «единственный владелец» и тест-сторож против прямых вызовов вибрации (как запрет `Debug.Log`);
   - дебаг-экран подбора сигналов — по `/add-menu-screen` и `Docs/ui-design-system.md`;
   - сеть;
   - таблица всех источников со статусом «переводит haptics / удаляет WeaponSystem / после агента X»;
   - этапы реализации малыми вливаемыми пунктами;
   - проверки.

   Ссылка — в `Docs/README.md`. Дизайн утверждает пользователь.
2. **Координация.** Свой план — `F:/UnityProjects/Vr_Battlegrounds_ai/.agent-state/coordination/haptics.md`
   (формат — как у других планов, SDK-патч 57). Прочитай планы остальных. При пересечении ближайших пунктов
   договорись с владельцами и запиши итог в `pipeline.md`.
3. **Реализация по утверждённому дизайну.** Каждый пункт: компиляция и `AndroidCompileGate` через worker →
   проверка пользователем в шлеме → вливание в origin/dev. Сначала сервис, каталог и SDK-патч 57, затем перевод
   источников, не занятых другими агентами. Карман на 10 % — один из первых пунктов: пользователь будет
   подбирать силу в шлеме.
4. **Тесты.** Структурный тест-сторож можно писать сразу. Поведенческие тесты — после проверки механики
   пользователем (правило `AGENTS.md` от 2026-10-02).
