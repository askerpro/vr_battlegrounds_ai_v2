# КПП — пакет отдельной зоны, 2026-10-10

Владелец расстановки: принципал. Исполнитель пишет только `LobbyCheckpointZoneBuilder.cs`, собственные материалы и этот каталог. Интегратор единолично запускает Unity и пишет сцену.

Назначение: единый военный въезд у юго-восточного угла с небольшим постом охраны, воротами, исходными бетонными барьерами и вышкой. Только декорация, без физических препятствий и игровых компонентов.

## Геометрия

Все координаты XZ относительно фактического `arena.center`; опорная высота — `arena.max.y`. Пост охраны: центр (21; −32), корпус 4×4 м, ~3 м высота; северный вход обращён к базе, восточные окна смотрят на подъезд. Полный исходный doorway нельзя без проверки соединять с неподходящей дверью: фронт собирается под настоящую `SM_Door_single` по её измеренной геометрии.

Ворота: два настоящих `SM_Fence_long_4m`, открытые вдоль подъезда; столбы стоят с внешней стороны X24…32. Ни воротные створки, ни барьеры не уменьшают восьмиметровый коридор.

Принципал согласовал исправление: въезд и подъезд сдвинуты на метр влево, X24…32, Z−38…−27. Вышка теперь (34; −31), разрешённый envelope X32.2…35.9, Z−33…−29. Yaw строго 0: прежний поворот 18° увеличивал footprint. Uniform scale вычисляется как 8 / фактическая исходная высота; итоговый native footprint около 3.43×3.44 м, внутри ограды X36 и вне дороги X32 с зазором ~0.28 м. Проверка работает по фактическим all-LOD mesh bounds, не по этим округлённым оценкам.

## Источники и технические ограничения

`SM_WatchTower_01`, `SM_Building_wall_4x4m_A`, `SM_Building_wall_window_2m_A`, `SM_Building_roof_4x4_01`, `SM_Door_single`, `SM_Fence_long_4m`, `SM_Concrete_Barier_01`, `SM_Concrete_Barier_02`, `SM_Door_lamp_a`. Получение только через `LobbyMilitaryCampSources.Prefab`; source assets не меняются. Настоящие LOD и PBR сохраняются. Габариты измеряются через 8 углов каждого mesh bounds и полную матрицу prefab-иерархии.

Для заполнения над окнами/дверью допустимы простые архитектурные простенки с исходным материалом стен. Исходные mesh не растягиваются. Уменьшение вышки — только равномерное. Скрипты, Collider, Animator и Light удаляются только из созданных экземпляров. Освещение задаёт общий интегратор: сборщик предоставляет видимую настоящую настенную лампу и именованный сокет, не отдельное расписание источников.

Сборка должна транзакционно удалять только созданный корень `CheckpointZone` при ошибке. Проверяются реальные footprint всех групп, свободный road, шатёр/арена, соседние service yard и workshop. Повторная сборка поверх существующей зоны запрещена.

## Проверки и приёмка

Управляемая offline-компиляция проверяет API/C# против Unity 6000.4.1f1; она не подтверждает импорт/сборку сцены. Native build, фактические bounds, topdown/overview, арт-проверка принципалом, Unity/Quest и принятие пользователем остаются отдельными этапами. Игровые тесты не создаются/не переписываются до проверки пользователем. Принятого коммита нет.
