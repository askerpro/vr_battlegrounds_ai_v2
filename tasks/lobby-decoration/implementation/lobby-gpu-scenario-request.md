# Запрос launch-infra: сценарий замера GPU лобби на шлеме с 9 аватарами

2026-10-12, от lobby-decoration (owner level-design) по поручению пользователя. Адресат: задача
`quest-perf-pipeline` (owner launch-infra). Пункты в зоне performance (стресс-тест, формат отчёта) — согласовать
с performance (`performance-onboarding`, сессия опубликована в хабе).

## Цель

Пользователь не принимает оформление Lobby без замера на шлеме: нагрузка на GPU (`ovr_gpu`, также `ovr_cpu`)
сцены лобби при 9 удалённых аватарах (полное лобби — игрок + 9). Прогон одной командой через
`Tools/e2e/Run-QuestE2E.ps1` (client-топология, выделенный сервер на ПК), без рук.

## Что нужно

1. **Сценарий `perf-stress` без рук** (этап `perf-scenario` вашего плана; содержание — performance):
   клиент ждёт свою `PlayerSession.LocalSession` → `StressTestLauncher.TryStart(config)` из `-e2eArg` (`mode`,
   `puppets`, `clutter`, `phase_s`, `warmup_s`, `skin`) → ждёт Finished со всеми фазами → `AddArtifact` каталога
   `perf/<ts>/` и `perf/history.log` → `-e2eQuitOnFinish`. Сервер в разминке Lobby (`StressTestServer` принимает только
   в разминке, нужен аватар игрока).
2. **Расстановка кукол «внутри арены»** (новый режим раскладки, зона performance/`StressTestLayout`): 9 кукол по
   физическому полу арены (`PhysicalArenaDefinition.FloorBounds`, Lobby X ±7.75, Z ±9.48) с отступом от стен и
   станции арсенала, лицом в разные стороны — так стоят игроки в лобби. Режим «по карте» (кольцо 8–15 м) выставляет
   кукол за пределы навеса, «рядами» — плотной стенкой перед камерой; оба нерепрезентативны для лобби.
3. **Обход ракурсов** (шлем лежит неподвижно, взгляд один): сценарий клиента переставляет XR-риг (корень трекинга,
   позиция + yaw) по списку точек и держит каждую `hold_s` секунд, записывая `ovr_gpu`/`ovr_cpu`/кадр отдельно по
   точкам (p50/p95/max) — отдельным файлом `views.json` в артефактах или фазами отчёта. Список точек — аргументом
   `-e2eArg views=<preset>` с пресетом `lobby` (или JSON-файлом); пресет для Lobby (мир, глаза 1.6 м над полом y≈−0.01):
   - `center-north` (0, 1.6, 0) yaw 0 — на северное стрельбище;
   - `center-south` (0, 1.6, 0) yaw 180 — на южное стрельбище;
   - `center-east` (0, 1.6, 0) yaw 90 — через открытые пролёты навеса на базу;
   - `east-edge-se` (6.5, 1.6, −2) yaw 125 — с края навеса на мастерскую/казармы/КПП;
   - `east-edge-ne` (6.5, 1.6, 3) yaw 55 — на навес отдыха/контейнеры/вышки;
   - `west-station` (−5.5, 1.6, 0) yaw 90 — от арсенала через весь навес (куклы в кадре);
   - `north-edge` (0, 1.6, 8.5) yaw 0 и `south-edge` (0, 1.6, −8.5) yaw 180 — огневые рубежи.
   Фазы: каждая точка — сначала без кукол (база), затем с 9 куклами (или весь обход дважды) — чтобы отделить цену
   сцены от цены аватаров.
4. **run.json/условия**: ревизия сборки, сцена Lobby, число кукол, точки, FFR/уровни CPU/GPU — как в контракте
   `quest-device-run`; бюджетных порогов сценарий не ставит (оценка — performance).
5. **Сборка из ветки `lobby-decoration`** (основной checkout `F:/UnityProjects/Vr_Battlegrounds_ai`, LFS role main,
   арты лобби в LFS — 521 файл `Assets/Art/Lobby`): worker собирает свой worktree, поэтому нужен путь сборки пары из
   основного checkout (`-Build` при закрытом редакторе или `StartPairBuild` из открытого). Внимание: после rebase/checkout
   в основном checkout хук не восстанавливает LFS переписанных коммитов — перед сборкой проверить отсутствие указателей
   (`git lfs checkout -- Assets/Art/Lobby`), иначе сборка с битыми ассетами.

## Состояние сцены (для условий прогона)

- Окклюзия Lobby НЕ запечена (снята как устаревшая) — до перепекания замер пессимистичен; level-design перепечёт
  перед финальным замером.
- Ночь на ~15 realtime-источниках без запекания (худший случай); запекание — отдельный шаг level-design.
- Сцена: навес 5 пролётов, стрельбища 4+4 с экранами дорожек, зоны базы, вышки с прожекторами
  (`Watchtower_Lit`, `CommTower_Tall/Short`).
