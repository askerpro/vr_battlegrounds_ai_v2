## Проблема

1. Храповик. После `ResetState` (onlySyncOnChange, тишина дольше bufferResetMultiplier×sendInterval) `UpdateSyncData`
   берёт непришедшие оси из текущего трансформа. У удалённого аватара цель NT — кость запястья, её в том же кадре
   правят хват, IK и отдача. Локальная правка запекается в буфер, и запястья бота у наблюдателя ступеньками уезжают
   на 1–2,7 м (A/B bots: модель сверена с 35 177 снимками, без отдачи дрейф остаётся).
2. Потерянная ось. Отправитель шлёт только изменившиеся оси, полного снимка нет. Ось, которая потом не меняется
   (высота камеры), при потере единственного пакета не восстанавливается: камера бота у части наблюдателей на полу.
Оба дефекта касаются обоих направлений (сервер→клиент и владелец→сервер→наблюдатели), то есть и людей.

## Решение (Mirror patch, маркер `VR Battlegrounds patch`)

- Приёмник хранит последнее полученное значение осей отдельно от буфера интерполяции. `ResetState` его не
  сбрасывает, начальное значение — из `OnDeserialize` при спавне, телепорт его обновляет. Непришедшие оси берутся
  из него, трансформ — только пока ничего не получено.
- Отправитель раз в `keyframeInterval` (1 с) шлёт полный снимок всех синхронизируемых осей; первая отправка — полная.
- Формат `SyncData` не меняется, трафик +~25 Б/с на NT.
