# UltimateXR patch 80 — кеш рефлексии SyncState; ограничитель уровней логов UltimateXR

2026-10-14, задача `network-sync-hardening`, этап `statesync-cost` (находка 5871). Номер получен через
`patch-reserve`. Маркер в коде: `VR Battlegrounds patch 80`. Файл SDK: `Core/StateSync/UxrStateSyncImplementer_1.cs`.
Вне SDK (не патч, тот же этап): `Assets/Scripts/Network/UxrLogLevelPolicy.cs`.

## Что

### Патч 80 (SDK)

- `SyncState`, ветка свойства: `PropertyInfo` берётся из кеша `(рантайм-тип компонента, имя)` вместо `GetProperty`
  на каждое событие.
- `SyncState`, ветка метода: запись `MethodEntry` на пару `(рантайм-тип компонента, имя)`. В ней — число методов с
  этим именем (считается один раз), результат `GetMethod(name, flags)` (общий для веток «без аргументов» и «метод
  один»: вызов тот же), перегрузки по точным рантайм-типам аргументов, перегрузки по числу параметров (ветка с null).
  `Parameters.Any()`/`Any(p => p == null)` заменены циклом по массиву без замыкания.
- Порядок веток, вызовы рефлексии, исключения и тексты логов те же. Код патча 74 в файле не тронут.

### Вне SDK: `UxrLogLevelPolicy`

- `RuntimeInitializeOnLoadMethod(BeforeSceneLoad)`: в плеере (Release и Development) каждый из 10 уровней
  `UxrGlobalSettings` = min(уровень из ассета, Warnings). Уровни из ассета возвращаются, пока включён
  `DebugMode.Enabled` (подписка на `DebugMode.Changed`) или есть флаг командной строки `-uxr-log-verbose` (без учёта
  регистра). Одна строка `GameLog.Network.Info` «[UxrLogLevelPolicy] …» только при изменении уровней.
- В редакторе ничего не делает: сеттер правил бы ассет проекта в памяти. Сам ассет не меняется.

## Зачем

В `Resources/UxrGlobalSettings.asset` Avatar/Core/Locomotion/Manipulation/Networking = Debug (5). Поэтому
`UxrManager.ExecuteStateSyncEvent` писал лог со стектрейсом на каждое событие, разбор снимка — на каждый компонент,
`UxrGrabManager` — на каждый захват. Сам `SyncState` на каждое событие искал свойство/метод рефлексией: `GetProperty`,
`GetMethods` + LINQ `Count`, `Select(GetType).ToArray()` + binder, `GetMethods` + `GetParameters` — аллокации и обход
метаданных на каждом выстреле, хвате и перезарядке.

## Поведение

- Кешируются только найденные `PropertyInfo`/`MethodInfo` и ненулевое число методов. null и исключения
  (`ArgumentNullException`, `AmbiguousMatchException`, NullReferenceException на `Invoke`/`SetValue`, «Could not find a
  method with the given name and parameter count») не кешируются и повторяются как раньше. Запись `MethodEntry`
  попадает в словарь только с первым положительным результатом: имена из сетевого события не копят мусорные записи.
- Ключ перегрузки — точные рантайм-типы аргументов: результат стандартного binder зависит только от типа, имени и
  этих типов. Ветка с null берёт первый метод в порядке `GetMethods` — как раньше.
- Только main thread, без lock: `SyncState` вызывается из `UxrManager` на главном потоке.
- Политика логов не трогает уровни ниже Warnings и не повышает их; Errors/Warnings UltimateXR видны всегда.
