# Подготовка gpu-tool-phases — 2026-10-14

Состояние: исследование исходников, без реализации. Этап остаётся planned и зависит от merged `view-tour`.
Принятое требование: `--phases <имена>` для произвольных фаз в `Tools/Perf/quest_gpu_breakdown.py`,
с сохранением прежнего поведения без этой опции. Аппаратного замера этого расширения нет.

## Наблюдения

- Сейчас listener понимает четыре точных имени: `база`, `куклы: по карте`, `куклы: арена`, `куклы`.
- Стресс-тест также пишет `куклы+хлам`, `куклы: <имя скина>`, `база: <точка>`, `куклы: <точка>`.
  Фазы успокоения заканчиваются на `~успокоение`; для точного селектора это отдельные имена.
- `ShotPipelineBudgetScenario` не пишет маркеры `=== фаза «…»`. Само добавление `--phases` не позволит
  захватывать его стадии. Согласовать источник маркеров с weapon-system; чужой сценарий не менять из этой задачи.
- Ответ weapon-system 6903: T23/T24 не используется для нового Quest shot-cost. Будущий `ShotCostScenario`
  зависит от `BotShotCostDriver` и должен выдавать `shot-cost: bot` / `shot-cost: away` через
  `GameLog.Perf.Info` с форматом `[Perf] === фаза «имя»`. Сейчас runtime-маркеров нет;
  synthetic Editor probe рекордера не является замером GPU/оружия. Realtime-окно должно укладываться
  в фактическую фазу стрельбы; detailed без подтверждённых runtime boundaries не принимается.
- View-tour по умолчанию измеряет точку 20 с. GPU-инструмент по умолчанию ждёт 10 с и снимает realtime 30 с:
  захват выходит за пределы точки. Для будущего прогона задавать короткое окно с запасом или длинные фазы;
  точные границы подтверждаются только runtime-данными, а не суммой настроек.
- Detailed выполняет четыре последовательные команды с таймаутами 120/180/180/180 с. `--seconds` их не ограничивает.
  Этот режим измеряет доли и не гарантирует нахождение в одной короткой фазе.
- Синхронный захват блокирует чтение logcat: следующий маркер может обрабатываться уже устаревшим.
  Сейчас `seen` отмечается до успешного захвата, код выхода 0 означает лишь непустой `seen`.
- README сообщает, что drawcalls не снимаются; код уже пытается снять две разновидности, но их успех не проверен.

## Рекомендуемый срез реализации после допуска этапа

- Один или несколько точных имён через `--phases` (отдельные quoted аргументы), явная опция заменяет default.
  Без CSV, regex, нечёткого совпадения и подмены регистра/пробелов. Пример:
  `--phases 'база' 'куклы: по карте' --settle 2 --seconds 10`.
- Сохранить прежние имена выходных файлов для default. Новым фазам дать безопасные ASCII ключи
  по порядку уникальных имён, с manifest «исходное имя → ключ»; не использовать имя фазы как путь.
- Различать найденные, успешно захваченные и отсутствующие фазы; не выдавать найденный маркер за GPU-результат.
- Обновить README с условиями коротких фаз, realtime/detailed и отдельными каталогами `--out` для прогонов.
- Offline-проверки: синтаксис, CLI/default/Unicode, exact match и дедупликация, безопасные ключи,
  последовательности маркеров, ошибки профайлера и выключение detailed в cleanup. Это не аппаратный PASS.
