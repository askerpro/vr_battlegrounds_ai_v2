# Профиль детализации сцены: проект

2026-10-14, владелец level-design, участие performance (бюджеты, QualitySettings, замеры).
Решение пользователя: инструмент детализации нужен для всех сцен и дальше — регулируемые
параметры, позже правила на префаб и на предмет. Первое применение — Lobby (обход 8 точек 6467:
худшая center-north 10,83 мс при бюджете базы 7 мс).

## Что было (прототип LobbyDetailTuner, lobby-decoration)

Подбор в шлеме показал: дальний план можно на худших LOD и текстурах, особенно ночью; средний
план без видимых изменений (его текстуры общие с ближним — группа текстуры по ближайшему
использованию); дефекты прототипа: `ForceLOD` снимает отсечение LOD (появлялись деревья),
розовые куски домов — у `SM_Wall_*`, `SM_Building_wall_window_*` материалов больше подмешей
(лишний слот рисует последний подмеш ещё раз). Прототип только в отладке и только Lobby.

## Архитектура

- **`SceneDetailProfile`** (ScriptableObject, `Assets/Scenes/<Сцена>/<Сцена>DetailProfile.asset` — рядом с данными освещения сцены) —
  единственный источник параметров сцены: границы планов (средний, дальний; дистанция по
  горизонтали от края пола `PhysicalArenaDefinition`), правило каждого плана — пропуск уровней
  LOD (0…«только худший»), смещение mip текстур, порог отсечения мелочи (≤ 0,6 м, решение
  пользователя), позже — ярус шейдера; список исключений (префаб по GUID, объект по
  GlobalObjectId: план, «не трогать», своё правило).
- **`SceneDetailApplier`** (MonoBehaviour в сцене) — единственный писатель состояния
  детализации в рантайме: при загрузке сцены во всех сборках применяет профиль к записям,
  которые заранее посчитал редактор (LODGroup, рендерер, дистанция, размер, источник-префаб).
  LOD — обрезкой списка уровней с сохранением порога отсечения (не `ForceLOD`), обрезанные
  рендереры выключаются; при выгрузке — восстановление.
- **Текстуры** — группы mipmap limit по полосам дистанции (`Detail` + полоса), текстура в полосе
  своего ближайшего использования; общие с ближним планом не ухудшаются (ограничение: нужен
  отдельный ассет текстуры). В импорт (Android) — итоговые лимиты, рантайм-смещение — только
  если правило его требует (условие performance 5934/6057).
- **Отладка** — секция «Детализация сцены» в планшете «Отладка» (вместо «Детализация лобби»):
  правка профиля вживую в Development-сборке, без записи в ассет; «Сохранить» пишет JSON в
  persistentDataPath, редакторская команда забирает его со шлема (adb) в ассет профиля.
- **Редактор** — `Tools/VR Battlegrounds/Detail/…`: собрать записи сцены, проверка слотов
  материалов (больше подмешей — отчёт и обрезка override), отчёт плана по сцене.

## Этапы

| Этап | Суть | Проверка |
|---|---|---|
| `contract` | этот проект + согласие performance (рантайм в Prod, группы mipmap limit, бюджеты) | ACK performance |
| `core` | профиль, применитель, сбор записей, секция планшета; LobbyDetailTuner удаляется | компиляция Android, EditMode, Play Lobby: уровни меняются без появления отсечённых объектов |
| `lobby-apply` | профиль Lobby: дальний план — худший LOD, мелочь ≤ 0,6 м; обрезка лишних слотов материалов; общие материалы стрельбищ (setpass) | осмотр пользователем в шлеме; обход 8 точек performance, худшая ≤ 7 мс |
| `shader-tier` | ярус шейдера дальнего плана (Simple Lit / Unlit с запечённым светом) — эксперимент | замер 8 точек: выигрыш против роста setpass |
| `overrides` | правила на префаб и предмет в профиле и на планшете | EditMode на разрешение правил |
| `docs` | раздел в Docs (уровень и зоны), правило для новых сцен | ревью performance |

Тесты — после подтверждения пользователем каждого этапа (правило 2026-10-02).
