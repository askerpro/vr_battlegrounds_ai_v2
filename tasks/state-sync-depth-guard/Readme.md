# Сторож глубины StateSync: единая стопка кадров (C2)

Обновлено: 2026-10-12. Владелец: эксперт `network`. Worktree: `F:/CodexWorktrees/network/Vr_Battlegrounds_ai`,
ветка `claude/network`. Решение пользователя 2026-10-12 через сопровождающего (событие хаба 4653): план B
отложить, C2 запустить задачей network раньше C1 (avatar-ik, RenderMode).
Основание: [журнал](../../experts/network/journal/2026-10-12-state-sync-depth.md), вердикт 4625.

## Проблема

`UxrStateSyncImplementer.SyncCallDepth` — статический счётчик процесса, а стек опций у каждого компонента
свой. Исключение в теле между `BeginSync` и `End`/`Cancel` оставляет глубину больше нуля навсегда. При
`UseTopLevelStateChangesOnly` в сеть уходят только события глубины 1, поэтому одна утечка глушит канал
состояния UXR всего процесса до перезапуска. Заодно отказывают проверки вложенности (учёт оружия,
`UxrInstanceManager`).

## Решение

- Одна глобальная LIFO-стопка кадров «владелец-реализатор + опции». Глубина равна размеру стопки,
  публичный `SyncCallDepth` сохраняется для читателей.
- `End`/`Cancel` снимает только свой верхний кадр. Если сверху лежит чужой, пишется `GameLog.Error` с
  обоими владельцами, и стопка снимается до своего кадра.
- Сторож на границе кадра в `UxrManager`: вне `IsInsideStateSync` и вне стадий обновления аватаров (условие
  avatar-ik 4629). Если стопка не пуста — `GameLog.Error` с владельцами открытых кадров, очистка, счётчик утечек.
- Формат сообщений, порядок и момент доставки событий, фильтры Relay не меняются. Состояние упавшей операции
  остаётся локальным, отката нет.
