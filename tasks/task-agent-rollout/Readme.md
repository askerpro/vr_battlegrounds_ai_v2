# Завершение перехода на схему «задача = агент»

2026-10-18. Продолжение прерванного выпуска Claude. Задача создана штатной `task-new` от свежей `origin/dev` (`192eb34f8d1b`), ветка `task/task-agent-rollout`, отдельный worktree.

## Цель и мотивация

Завершить одобренный пользователем переход без пилота: отдельная цель получает свою задачу, агента, worktree и ветку. Эксперты сохраняют знания и независимое ревью по затронутым зонам. Статическое владение файлами больше не определяет исполнителя. Цель, мотивация, план и текущий статус ведутся в брифе хаба, прогресс этапов рассчитывается из их состояний.

Старый процесс приводил к межзонным согласованиям и накоплению независимых целей этапами постоянных задач. Это затрудняло понимание результата и текущего состояния работы.

## Состав выпуска

- Инфраструктура уже закреплена в `agent-infra` и развёрнута: runtime `bcd591040c02dff494b8fcff63d63c4c8260df14`, maintenance ticket 777 завершён `DONE`. Повторное развёртывание для этой документационной задачи не требуется.
- Продуктовые правила перенесены из candidate `724017ee3`, дополнены документацией фактического read-only ревью `a39f40022`.
- `task-new` создаёт ветку `task/<id>` от обновлённой `origin/dev`, worktree, регистрацию и бриф. Новая цель — новая задача; этап — продолжение критерия приёмки существующей. Завершение — `task-close`.
- Ревью: готовый неизменяемый `review-prompt`, ACK по SHA или неизменившемуся patch-id; владелец зоны может отозвать ACK. Read-only ревьюер возвращает дословный блок, автор/владелец записывает его с аудитом `recorded_by`. Такой аудит не является техническим доказательством независимости личности ревьюера.
- Общие FIFO, аренды и broker guards сохранены. Coordination mode остаётся `off`, как ранее решил пользователь.
