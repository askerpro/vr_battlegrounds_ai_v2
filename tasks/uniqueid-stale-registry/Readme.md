# Реестр UniqueId: записи уничтоженных компонентов

Обновлено: 2026-10-13. Владелец: эксперт `network`. Worktree: `F:/CodexWorktrees/network/Vr_Battlegrounds_ai`,
ветка `claude/network`. Решение пользователя 2026-10-13: «да чини реестр». Находка manipulation 5710/5714, bots 5706.

## Проблема

Компоненты в неактивных объектах регистрируются без Awake (`UxrManager.cs:2121-2125`). Объект, уничтоженный ни
разу не включённым, не получает OnDestroy, и запись реестра (`s_componentsById`) остаётся за трупом. После
перезагрузки сцены новый экземпляр получает id коллизии, а id сервера у клиента находит труп: состояние и события
таких объектов у опоздавшего уходят в мёртвый объект, при загрузке снимка — MissingReferenceException (12× Pin из
сэмпла UltimateXR ShootingRange в BotCombatStand/Lobby/TestMap1). Было и до патча 75, патч 75 сделал видимым.

## Решение (патч SDK UltimateXR, маркер `VR Battlegrounds patch`)

В `UxrUniqueIdImplementer<T>` владелец, ставший Unity-null, считается отсутствующим: поиск по id снимает его записи
и возвращает «не найден»; проверка коллизий при регистрации считает его id свободным (новый экземпляр получает
исходный id, как на сервере); перечисление реестра его пропускает. Правок `UxrManager` нет: снимок идёт по
штатной ветке «адресат не зарегистрирован».
