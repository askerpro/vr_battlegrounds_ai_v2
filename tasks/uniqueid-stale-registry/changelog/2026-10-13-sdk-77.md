# UltimateXR patch 77 — реестр UniqueId: записи уничтоженных владельцев

2026-10-13, задача `uniqueid-stale-registry`, этап `registry-fix`. Номер получен через `patch-reserve`.
Маркер в коде: `VR Battlegrounds patch 77`. Файл: `Core/Unique/UxrUniqueIdImplementer_1.cs`.

## Что

- `TryGetComponentByIdInternal`: найденный владелец, ставший Unity-null, — не адресат. Все его записи снимаются
  (`PurgeDeadOwner` по обратному индексу `s_idsByComponent`), поиск отвечает «не найден».
- `RegisterUniqueId`: проверка коллизий через `IsIdTakenByLiveOwner` — id уничтоженного владельца свободен,
  его записи снимаются. Новый экземпляр того же объекта сцены получает исходный id, а не `CollisionN`.
- `GetAllComponentsInternal`: уничтоженные владельцы пропускаются.

## Зачем

Компоненты неактивных объектов регистрируются без Awake (`UxrManager.cs:2121-2125`). Объект, уничтоженный ни разу
не включённым, не получает OnDestroy, и `Unregister` не выполняется — запись остаётся за трупом. После перезагрузки
сцены новый экземпляр получал id коллизии, а id сервера у клиента находил труп: у опоздавшего 12× «Cannot
deserialize … UxrGrabbableObject has been destroyed» (Pin из сэмпла ShootingRange в BotCombatStand/Lobby/TestMap1),
состояние и события таких объектов уходили в мёртвый объект. Находка manipulation 5710/5714, bots 5706. Было и до
SDK-патча 75, он сделал это видимым (grabbable теперь всегда в снимке).

## Поведение

- Живые компоненты, в том числе неактивные, не затронуты: проверка — Unity-null (уничтоженный объект).
- Снимок у опоздавшего идёт по штатной ветке «адресат не зарегистрирован», правок `UxrManager` нет.
- Снятие записи при поиске меняет словарь; ленивое перечисление `UxrUniqueIdImplementer.AllComponents` в проекте не
  используется, поэтому конфликта с перечислением нет.
