# SDK-патч Mirror 2: публичный аксессор порта Discovery

Дата: 2026-10-11. Задача: vr-test-stand. Этап: e2e-run-isolation. Тип: sdk.
Статус: реализовано, не проверено. Номер выдан `coordination.py patch-reserve` (Mirror / 2).

## Что

`Assets/ThirdParty/Mirror/Components/Discovery/NetworkDiscoveryBase.cs` — рядом с полем
`serverBroadcastListenPort` добавлено свойство без логики:

```csharp
public int ServerBroadcastListenPort { get => serverBroadcastListenPort; set => serverBroadcastListenPort = value; }
```

Метка в коде — `VR Battlegrounds patch 2`. Поведение Discovery не меняется: смена порта во время
`AdvertiseServer`/`StartDiscovery` вступает в силу только после их перезапуска (так и записано в xml-doc).

## Зачем

E2E-прогон собранных плееров (`Tools/e2e/Run-E2E.ps1`) получает свою пару UDP-портов, чтобы не
конфликтовать с редактором, worker и плеерами других worktree на 47777 и не находить через Discovery
чужой сервер. Порт Discovery в Mirror — `protected` поле; редактор меняет его через `SerializedObject`,
а в плеере такого пути нет. Пишет порт только `E2EPlayerPorts` (шов `DebugBootstrapGate.PlayerBeforeNetworkStart`).

## Как повторить при обновлении SDK

Вернуть свойство `ServerBroadcastListenPort` рядом с `serverBroadcastListenPort` в `NetworkDiscoveryBase`.

## Как откатить

Удалить свойство и комментарий `VR Battlegrounds patch 2`, затем убрать его единственного
потребителя — `Assets/Scripts/Debug/E2E/E2EPlayerPorts.cs` (строка `discovery.ServerBroadcastListenPort = ...`);
без него e2e-плееры вернутся на порт Discovery сцены (47777).

## Проверка

Не выполнена: компиляция и прогон e2e — на worker вместе с этапом.
