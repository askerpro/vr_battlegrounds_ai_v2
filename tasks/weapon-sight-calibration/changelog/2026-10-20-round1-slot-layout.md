# 2026-10-20 — раунд 1: стенд раскладки с одним стволом

Запрос: кнопка «Открыть стенд раскладки с этим оружием» (окно «Настройка оружия», вкладка «Раскладка в слоте»)
открывала `Assets/Scenes/Debug/ArsenalLayoutAuthoring.unity` со всем ассортиментом и лишь выделяла ручку. Нужно —
только выбранный ствол в слоте своего вида.

## Решение

- Режим «один ствол» — свойство самого стенда, а не копия пресета. Carrier `ArsenalLayoutAuthoringStand` получил
  поля `_focusWeapon` / `_focusRow` (HideInInspector, сериализуются со сценой и переживают domain reload).
  Единственный писатель — `ArsenalLayoutAuthoring.WriteFocus` (через `SerializedObject`, как остальные поля carrier).
- `ArsenalLayoutAuthoring.ProjectedEntries(stand)` — записи проекции: одна (оружие + ряд) в режиме «один ствол»,
  иначе `Preset.Entries`. Им пользуются `ValidateStand`, `SourceFingerprint`, `RequireCleanInputs`, Restore.
  Bake, «Отдельная раскладка», отпечатки и stale-проверки не менялись по смыслу: Bake пишет в действующую раскладку
  слота (своя у оружия или умолчание слота), как в полном стенде.
- `FocusPrepared(stand, weapon, discardStaged)` — включает режим и пересобирает проекцию из раскладок; `weapon = null`
  возвращает весь ассортимент. Ряд берётся из пресета стенда, иначе из первого `ArsenalPreset` проекта, где ствол есть.
  Ошибка пересборки до разрушения проекции возвращает прежний режим.
- `ValidateStand` разделён на `ValidateOwnership` (EditMode, свой carrier, своя сцена, один корень, сцена вне build,
  масштаб, стиль) и `ValidateProjection` (ручки ↔ записи). Restore/Focus с явным discard проверяют только владение
  и пересобирают проекцию, даже если ручки не проходят проверку. Причина: сохранённая в Git сцена стенда устарела —
  у её 20 слотов нет коробки приёма (`PlaceZone`), из-за чего `ValidateStand` и прежний Restore падали с
  «Ручка утрачена…», стенд нельзя было ни запечь, ни восстановить.
- `ConfirmRebuild(stand, action)` — один диалог перед пересборкой: незапечённые позы или устаревшая проекция.
  Используют инспектор (Restore, смена режима) и окно.
- Инспектор стенда: в режиме «один ствол» — строка режима и «Показать весь ассортимент»; в полном — «Только этот ствол
  на стенде».
- `WeaponSetupWindow.OpenLayoutStand`: уже открытый стенд не перечитывается с диска; иначе сохранение сцен по
  запросу и открытие стенда. Затем `ConfirmRebuild` → аренда `AcquireAuthoringLease` → `FocusPrepared`, выделяется
  корень стенда (инспектор с ручками и Bake), Scene View кадрирует слот.

## Сохранённая сцена стенда

Сцена — производная проекция; источник поз — ассеты `ArsenalSlotLayout`. Переключение режима делает сцену dirty, но
не сохраняет её. Если человек сохранит её в режиме «один ствол», в файле останется один слот и поле режима: стенд
не ломается — «Показать весь ассортимент» пересобирает все слоты. Git-diff сцены при сохранении большой (как и при
любом Restore). Рекомендация: сцену стенда не сохранять, запекать позы кнопкой «Запечь».

## Раунд 1b — один режим: раскладка выбранного ствола (решение пользователя 2026-10-20)

Общего режима «весь ассортимент» больше нет. Режим «один ствол» из первой части заменён этим.

- Carrier `ArsenalLayoutAuthoringStand`: `_owner`, `_style`, один `_slot` (оружие, вид слота, ручки), `_stagedBaseline`,
  `_sourceBaseline`. Убраны `_preset`, список `_slots`, `CommittedBaseline`, `_focusWeapon/_focusRow`. Стиль нужен для
  вида опор. Вид слота: ряды записей ствола во всех `ArsenalPreset` проекта, ключ ряда переводится в вид по корпусу
  лобби (`KindsOf`); ствола нет ни в одном ассортименте — вид его собственных раскладок. Префаб слота (панель,
  карточка) — ряд этого вида в корпусе лобби, как раньше (в корпусе по одному ряду на вид).
- `ArsenalLayoutAuthoring`: `OpenPrepared(stand, weapon, kind, discard)` строит только слот этого ствола;
  `RestorePrepared(stand, discard)` пересобирает текущий ствол; `BakePrepared(stand)` и `SeparateLayoutPrepared(stand)`
  работают с единственным слотом; `ClearPrepared(stand)` — пустой стенд; `PopulatePrepared(scene, style)` — первичная
  fixture без пресета. `ConfirmRebuild` спрашивает только при незапечённых позах исправного текущего слота; пустой
  или устаревший слот пересобирается без вопроса.
- Убрано: «Запечь все → их раскладки», выбор слота (Popup), «Показать весь ассортимент» / «Только этот ствол на
  стенде», проекция по `Preset.Entries`, групповая проверка «общая раскладка — разные позы» (слот один).
- Проекция временная: все объекты слота получают `HideFlags.DontSaveInEditor`. Сцена стенда пересохранена пустой:
  carrier + свет + камера (2 096 496 → 9 650 байт; diff +156/−71 506 строк). Если человек сохранит сцену с
  открытым стволом, в файл попадут только ссылка на оружие, вид и два отпечатка (объекты слота — нет); после
  открытия такая сцена показывает «Стенд пуст».
- Bake без сдвигов писал шум Эйлера (`AK105_Pegboard`: 280 → 279.99994, 10 → 9.999999): ручка хранит кватернион.
  `SetPose` теперь не переписывает позу, совпадающую с сохранённой (позиция ≤ 1e-6 м, угол < 0.001°); то же для
  коробки приёма. Изменённый проверкой `AK105_Pegboard.asset` восстановлен `git checkout`.
- Окно: кнопка на каждый вид слота ствола (у всех текущих — один вид), стенд не перечитывается с диска, если уже
  открыт.
- Точки входа: `ArsenalEditorWindow` стенд не вызывает. `Tools/Probes/arsenal-authoring-*` (23 tracked-файла,
  не компилируются) — исторические пробы старого общего стенда (Bake в Style, 20 слотов); они устарели и до этой
  правки, не изменялись. `Docs/Arsenal/layout-authoring-stand.md`, `Docs/README.md` (строка про Stand20),
  `Arsenal_Code_Architecture_RU.md` описывают общий стенд — нужна правка владельцем Docs.
