# SDK-патч 76: видимый отказ replay фиксации учёта (ledger-spawn-ready)

2026-10-12. Номер зарезервирован штатным `patch-reserve` для weapon-system, ключ
`ledger-spawn-ready`. Решение пользователя 2026-10-12: «чини сразу».

Причина. Клиент обрабатывал spawn ствола и фиксацию Initialize автора одной пачкой
`NetworkEarlyUpdate`: объект активен, `WeaponSystem.Start` ещё не вызван, учёт спуска
не включён. `ValidateReadinessCommit` отклонял replay молча, ствол оставался на
ревизии 0, каждый следующий Shot у наблюдателя давал RevisionFork без поправки
(сервер публикует её только при своём форке, В-Л6).

Изменены два SDK-файла: `UxrFirearmReadinessTypes.cs` и `UxrFirearmWeapon.Readiness.cs`.
- `UxrFirearmReplayDivergenceKind.ReplayRejected` (дописан в конец) и перечисление
  `UxrFirearmReplayRejectReason` (LedgerDisabled, NoRuntimeTrigger, Reentrant,
  MalformedCommit, MagazineUnresolved, MagazineNotAllowed, StateMismatch); поле
  `UxrFirearmReplayDivergence.RejectReason`.
- `ValidateReadinessCommit`: каждый отказ replay, кроме форка ревизии и принятой
  фиксации с DeltaMismatch, возвращает ReplayRejected с причиной через существующий
  `ReadinessReplayDiverged`. Порядок и условия проверок не менялись; отказ команды
  у автора по-прежнему просто false без события.

Формат фиксации, поправки и StateSave не менялся: расхождение — локальное событие,
в сеть и снимок не попадает. Игровая часть: `WeaponLedgerIntegrity` пишет
`GameLog.WeaponSystem.Error` один раз на ствол и причину (повторы — Verbose,
счётчик `ReplayRejectedTotal`); `WeaponSystem` подключает учёт в `OnEnable`
(пассивная часть), T01 остаётся в `Start`.

Проверки и ревью — в Readme задачи и отчётах `reports/ledger-spawn-ready/`.
